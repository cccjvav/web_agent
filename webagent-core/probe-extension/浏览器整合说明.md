# 浏览器整合包 0.5.1

## 安装与第一条参考

1. 在桌面 VSCode 集成 CMD 中激活既有 Conda 环境，执行 `python webagent-core\probe-extension\package_browser.py --verify`。
2. 解压 `dist/webagent-arena-inspector-0.5.1.zip`。浏览器扩展管理页打开开发者模式，加载内层 `webagent-arena-inspector` 文件夹。
3. 停用单独的旧 Probe/Inspector，只留这个采集器。在 https://arena.ai 页面明确开启监听；浏览器 debugger 提示是预期行为。
4. 正常发一条有权测试的消息。HUD/弹窗分别显示 trace/run/span 标签、调用/用量、独立响应协议/行为参考。不同请求不强行合并；模型标签和分数都不是认证。
5. 需要实时跨端控制时，按 Companion README 的8步配对流程。只有已保存 `/agent/ID` 才能建立远控会话；其他 Arena 页可被动采样，但不能用伪会话ID取得写操作权限。

## 新增控制

- 弹窗输入配对JSON：15分钟内存凭据，可选 `http://127.0.0.1/*` 权限从明确点击申请。不要把配对内容当观察文件，也不要发给模型。
- 公开目录刷新：提交 WebAgent 审批后读取固定公开 leaderboard 页面，不携带 Cookie，不走原 Probe 的 credentials-include 刷新入口。状态显示目录日期、源、冲突数；可导出目录用于 VSCode 精确UUID历史回填。
- 主动题组：先选择题目、查看全文，再申请；本机批准后网页还需确认。已有草稿、多个输入框、多个“发送”按钮、页面切换、超时或取消都会拒绝发送，不猜测目标。拒答题已安全替换，不能沿用原题的比较解释。
- 改名/归档：配对期间原页面适配器提交队列，不把“待审批”显示为已成功。归档执行成功后删除该会话浏览器本地历史；不删除 VSCode 副本。手工未配对的原控制保持原有明确点击路径。
- 断开与撤销：不保证回滚已经点击的操作。浏览器失联/重启/MV3休眠要重新配对；不会用持久化密钥自动恢复。

## 采集与数据边界

只有 Inspector 拥有 debugger。原实时会话流继续提供限定 run/span 的 trace 证据；新增同源 Fetch/XHR/EventSource 和文本 WebSocket 被动样本。优先 CDP `streamResourceContent`，不可用时才在完成后请求已有响应体，**不重发网站请求**。不读取/转发 Cookie、Authorization 或原始响应到主机。

弹窗可选标准（8并发/15秒/256KiB）或轻量（2并发/5秒/64KiB）预设，只影响新请求，重启恢复标准；64条待关联请求元信息，二进制WS省略并标记截断。CDP 的 `getResponseBody` 本身没有有界部分读取：编码体积检查不能保证解压返回的瞬时分配大小；返回后再次限制解析。原 trace 读取器仍保留自身更严格的会话/运行范围和预算。这些是采样，不保证捕获所有流量。

原历史面板的批量 JSON 可导入 Companion；原单次“导出证据”仍可离线分析。浏览器不会自动导出全部私人历史；实时只共享明确配对 tab 的当前快照。Companion 0.5.1 的离线分析入口能转换原Probe buildDump导出，只取当前响应，不混用全局历史证据；不是将dump当作trace单run证据或连接挑战。

## 打包与验证

`package_browser.py` 只读白名单源文件，拒绝符号链接，保留两个原型目录，不生成第二个采集器。补丁锚点必须唯一，支持CRLF；清单记录输入与交付文件SHA256，`--verify` 从解压包运行测试。0.5增加 bridge、DOM adapter、公开目录、通用采样和弹窗模块。页面选择器、Chrome localhost权限、实际公开目录和真实账户仍需桌面验收，不能由合成测试推断。
