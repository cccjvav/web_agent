# bind.js：逐个交互回调与提交数据

[bind.js](bind.js)是页面事件连接层。**onClick(id,handler)**找不到节点就返回，找到赋onclick；**bind()**执行一次大批绑定，最后ui.bind引用它。多数其他直接`$('#id').onclick`要求HTML节点存在，不能把onClick的容错推广到整个文件。

HTTP普遍没有统一res.ok/业务错误/异常捕获包装。下表的“提交/刷新/提示”是实际动作，不保证服务器保存成功；关键后端验证见API详解。本文件不应当被当作授权边界。

## 2. 模型与Chat回调

- model-pick-btn→openModelPicker；**onPick(id)**更新model-select、调用其onchange、更新按钮标签。btn-mm-pick→带mergeMark的picker，onPick仅改待保存merge/display值；btn-mm-active回active，不立即写后端。

## 3. Bridge与身份回调

| 控件 | API/动作 | 错误及限制 |
|---|---|---|
| btn-bridge-toggle / btn-stop-bridge-rb | 按status.start/stop；直接stop | 状态快照可能过时，后端需幂等保护 |
| btn-reset-round | resetRound | 清统计不重置全部授权 |
| btn-copy-url/prompt/rules | clipboard.writeText | URL含secret；rules无内容仅提示；提示按客户端适配，没有“已连上”证明 |
| btn-reset-secret | POST reset-secret→refreshStatus→toast | 未检查HTTP业务结果，旧链接是否失效要验证后端 |
| open-site各按钮 | openSite(data-site) | 本地连接指引，不真实浏览器自动登录 |
| btn-gh-login | POST bridge/login空JSON→loggedIn=true→refreshStatus | 明确演示授权不是GitHub |
| btn-gh-token | POST token，解析后清token输入；success false提示返回 | 成功才刷新并显示username；网络失败在清空前可能保留输入 |
| btn-gh-device | POST device；失败提示；成功显示verificationUri/userCode，安排tick | 不自动填写用户设备码授权 |
| btn-gh-clear | POST github/clear→refreshStatus | 清GitHub身份，提示保留演示授权 |
| btn-refresh-auth | paintBridge+提示 | **不fetch新状态**，只是用当前state重绘 |

设备码闭包 **tick()** POST device/poll→json；done刷新/通知结束，pending setTimeout(tick,5000)，否则提示终结错误。首次按服务端interval或5秒延后。没有前端全局设备码计时器去重/abort，重复点击可产生多个轮询链；网络错误没在tick内catch。

## 4. Skill与定制配置回调

**skillMarkdown(name,when,steps)**trim名称或untitled，description替换换行截200，组装front matter、何时使用/步骤并join；这是普通文本拼接，不是YAML通用安全序列化。SKILL_TPL三个固定模板fix-tests/review/release只产生说明，不自行运行命令。

**fillSkillPreview()**不存在正文框或dataset.dirty=1就返回，否则用三个字段生成。name/when/steps.forEach注册input；正文input标dirty保护手改；skill-templates.onclick找data-tpl、填三个字段、清dirty再生成。

## 5. Provider探测与添加

**probeProvider()**取trim baseUrl/apiKey，POST `/api/providers/probe`并返回res.json，不自行验证HTTP状态。

btn-test-api.onclick设Testing、await探测，按success显示模型数量或错误。btn-save-model.onclick再探测；失败且有manualId则使用一个手动模型记录；无记录则错误返回。取首模型group，保留builtin（apiKey强制空），discovered.map生成新ID/名字/protocol/baseUrl/apiKey/modelId/上下文/caps/pricing，vision来自用户勾选或caps.some。find首个非builtin且modelId不含video/image为firstChat，否则models[1]，POST **整个models数组**和activeModelId。

因此“Add API”当前构建的是builtin+本次探测结果，并非把所有旧provider都合并保留；不应仅凭按钮名讲成增量追加。API key仍在表单和提交对象里，本回调不清字段。没有业务成功检查就显示已添加，所以实际连接需重新测试。btn-use-builtin是用户明确点击才POST切内置，不是模型失败自动回退。

## 6. 文件、终端、搜索与站点栏

- lnk-new-file：prompt名称→PUT files/content(path,content:'')，不带expectedHash/覆盖确认；后端负责已有文件拒绝，随后刷新树/openFile，不主动覆写旧内容。open-file/open-folder只切explorer，并非操作系统选目录对话框。
- term-form.onsubmit：preventDefault、trim非空、清输入/回显，POST tool/call，name run_command、mode code、arguments.command；解析result.stdout/stderr输出。此回调不提供危险确认字段，也未显示所有业务error，故拒绝不等于命令成功但无输出。
- btn-search：query trim后POST search_files/ask，matches.map出文件/行/正文，escape文件与正文（行号依赖后端数值）；search-results.onclick委托openFile。没有分页UI和总结果数提示，也不跳到具体行。
- br-go：读地址，只有当前browser tab才更新url并renderBrowser；br-reload同样重绘。它们不创建真实外部会话、不执行本机Agent任务。

## 7. 验证

```bat
npm test --prefix webagent-core/agent-host -- --filter=workbenchRuntime
npm test --prefix webagent-core/agent-host -- --filter=workbenchHtml
```

两个fixture方向分别关注交互运行与HTML绑定，但不能把它们推广成所有未命名回调的逐分支全覆盖。本讲解按控件列出匿名回调，避免只列bind一个函数造成“函数都有名字便算全量”的误导。
