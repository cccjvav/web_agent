# code-server准备、认证与双进程编排

覆盖[ensure-code-server.js](ensure-code-server.js)、[codeServerAuth.js](codeServerAuth.js)、[run-code-oss.js](run-code-oss.js)、[install-desktop-extension.js](install-desktop-extension.js)。这是可选网页VS Code/桌面扩展路径，不等同主安装器的Program Files+用户运行目录设计。此处旧编排仍有仓库相对写入位置，不能据此改写已确认的Windows安装布局。

## 1. ensure-code-server.js全部函数

VERSION固定4.135.0，repoRoot为仓库根，runtimeRoot为bin/code-server-runtime；本文件被require时不会自动下载，CLI分支才ensure+syncExtension。

| 函数 | 参数/返回 | 实现/失败 |
|---|---|---|
| npmCmd() | 无→命令名 | Windows npm.cmd，否则npm |
| abortedError() / checkSignal(signal) | 无/signal→Error/undefined | 固定ABORT_ERR，signal已abort时抛错，不依赖DOMException的reason |
| runNpm(args,cwd,{timeoutMs=180000,signal}={}) | 参数/目录/选项→Promise<void> | await preparation.runPreparation，继承终端/环境，加FORCE_NODE_VERSION主版本；Windows shell；前后检查signal，timeout/退出未确认拒绝；不把kill当成功 |
| findEntry() | 无→路径/null | candidates.find依次npm布局/版本目录/Linux-amd64目录；只是存在性检查 |
| vscodeDirFromEntry(entry) | entry→目录 | 从out/node回到lib/vscode；不扫描任意安装 |
| ensureVscodeDeps(entry,{signal}={}) | entry/选项→Promise<void> | @microsoft/1ds-core-js marker存在即跳过；无package.json报不完整；否则npm install omit-dev/ignore-scripts等，120秒超时；marker不是全部依赖校验 |
| ensure({signal}={}) | 选项→Promise<entry> | 检查signal，mkdir runtime，找不到entry才建缺失package.json并npm install固定code-server 180秒超时；再次找不到抛错；ensureVscodeDeps后返回，不证明平台可运行 |
| extensionVersion() | 无→字符串 | 委托productVersion读extension/package.json，错/空/非法版本抛错 |
| syncExtension() | 无→dest | extRoot可注入临时目录；复用copyTree复制全部扩展文件（仅根README排除），pruneOld只清理本产品旧版本；写extensions.json登记单个扩展，返回dest |

准备阶段现为异步：runNpm委托installer/preparation.js（主解释在installer函数详解），ensure依次await下载和ensureVscodeDeps，并在跨阶段再次检查取消。默认180秒下载/120秒VS Code依赖预算不变，停止时只强制终止本次直接子进程并另观察至多1秒；未知退出拒绝，不保证npm后代停止，不回滚部分安装。

syncExtension与桌面安装共享copyTree/pruneOld；Markdown与子目录README不会漏拷，其他扩展目录保留。不是跨文件事务安装，同版本已存在时仍逐文件覆盖。CLI注册SIGINT/SIGTERM的onSignal控制器，await ensure后检查取消才syncExtension/打印entry；catch置exitCode=1、finally移除监听，不立即process.exit跳过异步收尾。

## 2. codeServerAuth.js全部函数

**trustedOrigins(port)**Number(port)或3000，返回127.0.0.1/localhost两HTTP origin逗号串；没有公网预览域名，也不支持自动wss推断。因此此可选启动器默认本机使用，不拿它直接作为Arena预览服务。

**resolveAuth({userData,env=process.env}={})**读取CODE_SERVER_AUTH，只有none显式无密码，否则password。目录默认仓库.local/share/code-server，passwordFile=webagent-password；CODE_SERVER_PASSWORD非空优先返回（**并不在这个分支写文件**）；否则尝试读现有非空文件；最后randomBytes(12).base64url生成、mkdir、write mode0600并返回。

已有文件读取错误被吞，若随后写失败会抛错；写入非原子/无锁，不保证并发首次生成一致。0600不等价完整Windows ACL。返回password字段为敏感值，运行器当前会打印；分享日志前要去掉，不把这些文件提交Git。CODE_SERVER_AUTH=none是用户显式配置，不是默认模式。

## 3. run-code-oss.js全部函数与启动副作用

顶层从argv[2]/WORKSPACE_ROOT/默认repoRoot选路径，端口parseInt；工作区不存在立即exit1，尚无本轮子进程。文件尾无require.main保护，require也会运行main，不适合作纯工具模块导入。测试只截去Acorn定位的最后一个CLI调用表达式，执行真实函数，不借测试导出触发下载。

### waitHealth(url,timeoutMs,{signal}={})：整个轮询的期限

正数有限timeoutMs才受理；main仍传15000。内部使用performance.now单调到期时间与独立setTimeout，不再只有响应/error回调才检查elapsed；连接建立却没有HTTP头也会以ETIMEDOUT结束。onAbort产生ABORT_ERR，预先取消零请求；这是健康探测期限，不包括ensure/npm准备时间，也不是实时系统调度保证。

- **tick()**先检查settled/到期，再http.get，agent:false不留可复用池；只检查HTTP200，不读取或无限drain响应体，不跟随重定向。200不证明主机实例/工作区匹配，也不证明MCP/PTY/IDE功能全部就绪。
- **release()**先清当前request/response引用，再destroy两者。已处置请求的迟到error/response不能冒充当前尝试；迟到response仍销毁。
- **retry()**处置本次连接，未到期限才安排200ms重试；始终共享原总期限，连接错误及非200不会无限积累未结束的响应体。这是只读健康GET重试，不重放用户工具/写请求。
- **finish(error)**单次结算，清deadline/retry、退订abort、释放当前连接，再resolve/reject。响应回调另查单调时间，防计时器尚未被调度时迟到200获胜。

### run与stopChild：启动不代替资源所有者处理失败

**run(command,args,opts)**只spawn并返回ChildProcess：stdio inherit/windowsHide、显式shell/cwd、环境浅合并；不再在error回调中直接process.exit。调用者launch立即注册error/exit并保存本轮对象。

**stopChild(child,graceMs=9000,forceMs=1000)**只接本编排保存的直接ChildProcess，不接磁盘收据或任意PID。没有成功spawn的pid，或exitCode/signalCode已经表明退出，立即true且不再kill。killed=true仅代表曾发送信号，不能据此跳过退出观察。

内部**send(signal)**检查仍活跃后调用同一ChildProcess.kill；先SIGTERM，9秒后仍未退出才SIGKILL，再最多观察1秒。9秒保留了主机已有8秒shutdown预算，没延长15秒health或Windows命令/worker期限。**onExit()**确认观察到退出；**onError()**不把kill失败当退出；**finish(observed)**单次清两个timer/临时监听并返回布尔。Windows的ChildProcess.kill不是POSIX式优雅SIGTERM保证。

删除了原Windows按PID派生taskkill /t /f的路径；只处理保留的直接子进程对象，不按名称/端口/旧PID补杀。**本合同不保证npm脚本、code-server worker、PTY或隧道等所有孙进程退出**，也不是R5稳定句柄残留回收的替代。真实进程树/窗口和实际PID复用仍须另验。

### main()：单次停止与统一finally

内部**stop(code,error)**只接受第一次结果，abort健康检查并唤醒等待；**onSignal()**请求正常停止0，重复SIGINT/SIGTERM不重复清理。**checkRunning()**在异步恢复后及launch前拒绝已取消的继续启动。

可选app模式由**sendApp(message)**通过IPC发送控制消息，失败只记录不直接exit；**onAppMessage(message)**处理isAppControl类型，webagent-app-stop请求停止，webagent-app-release在已prepared且未取消时标记已释放；**onAppDisconnect()**在未释放时同样停止。WEBAGENT_APP_BOOTSTRAP=1且存在process.send才进入受控分支，否则要求私有IPC通道才允许该模式。

1. 建children、AbortController、stopped Promise，注册SIGINT/SIGTERM为onSignal，受控时另注册message/disconnect。
2. ensure/syncExtension准备运行时和扩展。express marker缺失才npm install；这次异步安装也由**launch(command,args,opts,role)**登记，不再落在children之外。安装finished与停止竞争；失败/取消不继续启动主机。ensure内部下载/安装由preparation原语独立持有并异步等待，main的SIGINT/SIGTERM或受控IPC stop/disconnect会取消它；await ensure后checkRunning才继续。其cleanupUnconfirmed必须覆盖普通停止码为非零并打印，不在children表重复清理。后端依赖缺失fallback**不再**走launch登记：它改由`installer/preparation.js`的runPreparation直接持有，带**独立的120秒deadline**与controller.signal取消。理由是依赖准备不是常驻服务——它没有优雅关闭的宽限合同，却在修前既无任何期限（registry卡住就无限期堵住启动，已实测）又被登记进children，导致停止路径对一个runPreparation已经持有的进程再套一层服务器形状的9秒TERM宽限，两个清理策略叠加。现在超时/取消只强制终止该直接子进程并另观察至多1秒，未确认退出按cleanupUnconfirmed覆盖为非零并打印，main不再对同一句柄二次发信号。不得把本批外层ci/内层下载修复说成整段启动总期限。
3. launch使用run，立即保存对象；finished只表示该直接子进程的exit/error。error记录失败，不从低层立即exit；agent任何意外退出（包括0或signal）都停止依赖它的编辑器，非零code保留；editor正常0可正常结束，signal不能被code||0变成成功。退出事件在已stop后不覆盖首个原因。
4. agent使用当前Node、src/index.js、WORKSPACE_ROOT/AGENT_HOST_PORT/WEBAGENT_SKIP_WORKBENCH=1。15秒health成功且仍未取消，才创建userData、resolveAuth并启动code-server；中途mkdir/auth/spawn失败都落到同一清理。
5. code-server仍带auth/bind（默认127.0.0.1）、disable telemetry/update、trustedOrigins、app名、userData/extensions/config/workspace；PASSWORD只由既有认证规则放入环境。控制台仍显示密码（环境密码不写文件），日志需保密。spawn后发送webagent-app-prepared，受控分支才发；等待停止，不自动重启失败进程。
6. finally中取消探测，并发等待全部已登记直接子进程的stopChild。未确认退出则报告、返回非零并unref该对象避免编排自身被无限挂住；**unref不是终止证明**，不自动升级为PID/树清理。退订本轮信号及受控message/disconnect监听，保留首个失败信息；先前写入的目录/口令等磁盘副作用不回滚。受控时尝试disconnect。
7. main返回最终退出码；文件尾then写process.exitCode、意外reject记录错误/置1，允许收尾和输出完成，不在启动异常处跳过finally强制exit。

## 4. install-desktop-extension.js全部函数

| 函数 | 参数/返回 | 作用与边界 |
|---|---|---|
| readManifest() | 无→publisher/name/version/folderName/id | 解析源package.json，缺字段给默认；JSON坏直接抛，不按路径安全规范校验publisher/name |
| copyTree(from,to) | 两目录→undefined | mkdir，readdir循环；仅根README.md跳过；lstat拒绝符号链接，目录递归否则copyFile，目的地旧文件不清 |
| pruneOld(extensionsDir,keepName) | 目录/保留名→removed数组 | 只匹配固定webagent.webagent-core-前缀且非keepName才rm recursive/force，避免删其他扩展；如果manifest改publisher/name，固定前缀不自动跟变 |
| defaultExtensionDirs() | 无→目录数组 | WEBAGENT_VSCODE_EXTENSIONS优先唯一resolve路径；否则home/.vscode/extensions；检测.vscode-insiders存在才加其目录 |
| installTo(extensionsDir) | 目录→dest、host及manifest | read→mkdir→copyTree→写host.json→pruneOld→返回；复制失败不会先删旧版，但已存在同版目的地可能部分更新，非事务安装 |
| contentHash(dir) | 目录→sha256十六进制 | 按相对路径排序逐个文件哈希（路径+内容），跳过根README.md与host.json，因此源码目录与安装目录可直接比较；任何文件变化都会改变结果 |
| sourceCommit(root) | 仓库根→40位提交号或null | `git rev-parse HEAD`，非Git（安装版）或git不可用返回null |
| hostLocation(root=repoRoot) | 仓库根→host.json对象 | `{format:1, root, commit, contentHash, installedAt}`；root是本脚本所在仓库/安装目录的绝对路径，插件据此找到`installer/launch.js`（R6一键启动）。installTo在复制后写入目标目录的host.json，也用于R8偏差c：插件发现主机仓库提交与安装时不同会提示重新安装 |
| installAll(dirs=defaultExtensionDirs()) | 数组→结果数组 | dirs.map(installTo)，同步顺序执行，中间失败抛，前面安装不回滚 |

CLI require.main保护内try installAll，逐结果打印安装路径、来源提交、内容hash前16位与主机位置，下一步说明为重载VS Code→打开项目文件夹→侧栏“主机”卡片点【启动】（不需要CMD或浏览器）→仓库更新后重新运行；catch打印并exit1。此脚本不启动VS Code、不为用户自动激活Conda、不判断目标编辑器版本真的合格。

codeServerLifecycle用真实回环HTTP、可控时钟/子进程及真实Node子进程验证期限、取消、启动失败/同伴退出与有界清理；codeServerAuth/NotRunnable及扩展副本检查保留。没有安装或运行真实code-server，不能替代Windows原生模块、网页VS Code信任源、Conda、窗口与全部进程树验收。
