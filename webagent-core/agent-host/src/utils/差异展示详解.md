# diff.js：差异展示与行数统计

## 职责与流程

[diff.js](diff.js)依赖npm包diff；它**生成展示差异，不执行补丁写入**。真正的路径/版本/修改规则在tools/patchEngine与fileOps。

字节在预算内不代表CPU在预算内：差异算法对"不同行数"是超线性的，而且同步跑在宿主事件循环上。几百KiB的全文替换就能让一次调用占住宿主好几秒，期间取消请求排不进来。所以这里除了展示逻辑，还持有一份显式的计算预算。

## DIFF_TIMEOUT_MS 与 DIFF_MAX_EDIT_LENGTH

导出常量。前者是单次差异计算的挂钟上限，默认1500毫秒，环境变量`WEBAGENT_DIFF_TIMEOUT_MS`可覆盖；后者是编辑距离上限，默认20000，环境变量`WEBAGENT_DIFF_MAX_EDIT`可覆盖。两者都直接传给jsdiff的`timeout`/`maxEditLength`选项。它们限制的是**本次计算的代价**，与boundedFile那8MiB的读取字节预算是两件事；也不保证某个具体行数的输入一定能算完，实际取决于差异的形状与机器速度。

## diffBudgetExceeded(filePath)

内部工厂，构造`ExecutionError('E_DIFF_BUDGET', …)`。消息里写清哪个文件、当前两个上限是多少，并建议改用外部diff工具查看；detail带`filePath/timeoutMs/maxEditLength`，**不带任何文件正文**，避免超大或敏感内容经由报错回流。

## createUnifiedDiff(filePath,oldContent,newContent)

输入显示用文件路径及新旧全文，返回 `{patch,additions,deletions,hunks}`。

1. 调用`jsdiff.structuredPatch`**一次**，标题为`a/<filePath>`、`b/<filePath>`，header标记current/patched，并带上上述两个预算选项。以前这里跑两遍算法（`createTwoFilesPatch`出文本、`diffLines`出统计），对同一对输入付两份代价。
2. jsdiff触碰任一预算时返回`undefined`而不是抛错，所以显式检查结果与`hunks`数组是否存在，缺失就抛`E_DIFF_BUDGET`。**不能把undefined当成"空差异"**——那会让"算不完"伪装成"没有变化"。
3. 遍历hunk里的行，行首`+`计入additions、`-`计入deletions，上下文行不计。统计与补丁文本来自同一次计算，必然自洽；空行同样按行计数。
4. `jsdiff.formatPatch`把同一个结构渲染成统一差异文本，与旧的`createTwoFilesPatch`输出逐字符一致，因此前端与补丁预览显示格式没有变化。返回值无磁盘/网络副作用。

统计包含纯空行，不改写输入行尾。也不校验filePath是否安全（这里只用作标题），不读文件、不验证expectedHash。

## 调用方合同

`E_DIFF_BUDGET`的含义是"差异太大、这里渲染不出来"，**不是"文件没有变化"**，不能据此跳过hash校验或放行写入。patchEngine在新建与改写两条路径上都**先渲染差异再落盘**，所以预算拒绝始终对应零次写入；新增调用方必须保持这个顺序，否则会出现"报了错但文件已经改了"。

## 验证与复盘

从调用createUnifiedDiff的文件写入/补丁测试追踪返回字段：

```bat
npm test --prefix webagent-core/agent-host -- --filter=patchEngine
npm test --prefix webagent-core/agent-host -- --filter=diffBudget
```

`diffBudget.test.js`断言小差异照常渲染、超预算在接近上限处被拒、被拒的补丁（含dryRun）让目标文件逐字节不变。stateIntegrity包含只增/删空行的回归，但不宣称穷举所有换行组合。复盘练习：在临时样例中比较仅增加空行与增加有文字行，说明为什么文件变化与additions数字不能简单等同；真正写盘结果仍以读取/hash和测试为准。
