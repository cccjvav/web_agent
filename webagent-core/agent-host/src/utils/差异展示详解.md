# diff.js：差异展示与行数统计

## 职责与流程

[diff.js](diff.js)只有createUnifiedDiff，依赖npm包diff；它**生成展示差异，不执行补丁写入**。真正的路径/版本/修改规则在tools/patchEngine与fileOps。

## createUnifiedDiff(filePath,oldContent,newContent)

输入显示用文件路径及新旧全文，返回 `{patch,additions,deletions,changes}`。

1. jsdiff.createTwoFilesPatch生成统一diff文本，旧/新标题分别`a/<filePath>`、`b/<filePath>`，header标记current/patched。
2. jsdiff.diffLines拿按行分组的changes，每组包含value及added/removed等信息。
3. 遍历change，`change.value.split('\n').filter(Boolean).length`计算该组非空行片段数；added加到additions，removed加到deletions。
4. 返回diff文本、统计和原changes数组，无磁盘/网络副作用。

**统计不是严格的全部变更行数**：filter(Boolean)会跳过空行，CRLF片段含回车时与纯LF空行还可能表现不同。也不校验filePath是否安全（这里只用作标题），不读文件、不验证expectedHash、不做预算裁剪。大文本的CPU/内存成本依赖diff库算法和调用方输入限制。

## 验证与复盘

从调用createUnifiedDiff的文件写入/补丁测试追踪返回字段：

```bat
npm test --prefix webagent-core/agent-host -- --filter=patchEngine
```

这不是宣称已经有独立测试覆盖所有空行/换行统计组合。复盘练习：在临时样例中比较仅增加空行与增加有文字行，说明为什么文件变化与additions数字不能简单等同；真正写盘结果仍以读取/hash和测试为准。
