# diff.js：有界差异展示与行数统计

## 职责与流程

[diff.js](diff.js)生成展示差异，不执行磁盘写入、路径校验或hash审批。真正修改仍由tools/patchEngine/fileOps负责；调用方必须在任何写入之前完成这个可能失败的预检。

## createUnifiedDiff(filePath, oldContent, newContent)

输入显示用路径及新旧全文，返回`{patch, additions, deletions}`。内部旧`changes`字段没有生产消费方，现不再重复调用diffLines构造第二份结果；MCP/REST公开字段不变。

1. 两侧必须各为UTF-8编码不超过1MiB、按LF计不超过20000行的字符串。这里的字节预算是展示输入预算，不替代read_files/write_file的8MiB预算。
2. 调用一次jsdiff.structuredPatch：标题`a/<filePath>`、`b/<filePath>`，header为current/patched；`timeout:100`、`maxEditLength:4000`限制差异搜索。
3. 若算法返回undefined，内部fail()抛ExecutionError/E_DIFF_LIMIT；不把超限当空差异或成功。
4. 遍历structured.hunks中的行，`+`计additions、`-`计deletions；空行也计数，`\\ No newline at end of file`标记不计。不再计算第二次全量diff。
5. formatPatch复用已计算结构；UTF-8输出超过256KiB同样fail()。成功返回正文及两个计数，没有磁盘/网络副作用。

## 写入顺序与边界

patchEngine对新建和已有文件、dryRun和实际修改均先调用本函数。新建文件先预检diff，之后才建父目录/排他发布，避免“已经写入才发现展示超预算”。现有文件失败保留原文；不会自动改用无hash覆盖或重放。

100ms是库在搜索中的合作检查，不是可抢占的硬实时期限；分词、格式化和计字节仍是同步工作，输入/行数/输出预算分别限制这些阶段。不是worker隔离、进程总内存上限或最坏耗时证明。经典编辑预览、单次回退和跨文件检查点仍有各自更小的64KiB/2000行等合同，不被这里的上限放宽。

## 验证

```bat
npm test --prefix webagent-core/agent-host -- --filter=diffBudget
npm test --prefix webagent-core/agent-host -- --filter=patchEngine
npm test --prefix webagent-core/agent-host -- --filter=stateIntegrity
```

新增diffBudget用独立子进程检查8000行不相交文本得到预算错误，并验证输出/输入上限、空行/无尾换行/CRLF统计、补丁可应用性及新建/已有文件的失败前零写入。stateIntegrity原有空行统计继续保留；真实磁盘冲突与最终写入仍以调用方hash和读取验证为准。
