# editorUndo：经典编辑器单次保存的受保护回退

[editorUndo.js](editorUndo.js)只为本机文件编辑器的显式保存保留旧正文，不是全工具审计、持久备份或自动错误恢复。用户必须先看回退diff，再确认；不存在force入口。

## 状态和边界

内存Map最多16项，旧正文每项最多64KiB，约1MiB正文上限（不含对象/临时计算开销）。记录15分钟有效，按访问清理；新增满额时淘汰最旧项。重启丢失，页面刷新/关闭源标签会丢掉界面中的句柄，当前没有历史列表恢复入口。目标路径仍使用resolveSafePath，敏感文件/工作区外访问不放宽。

只记录已有文件、有正确expectedHash、保存前后内容不同且两份正文都不超过64KiB的保存。新建、无版本号、无变化、超预算不会生成记录，但原保存仍按原规则成功或失败。记录绑定创建时的workspaceRoot与hostInstanceId，不保存文件权限/时间戳/目录结构。

## 逐函数

- **prune()**：遍历删除过期项，再在容量≥16时删Map最早项，供remember插入一项。不是后台计时器，也不是LRU读取刷新。
- **capture(filePath,expectedHash,content)**：检查版本号及新正文预算；安全路径有界读取旧正文，核对hash且内容确有变化，返回待提交快照。失败返回null，不抢走真实write_file的错误判定。此时没有登记回退，也没有写盘。
- **remember(snapshot,hash)**：只有快照新hash与实际保存返回hash一致才登记UUID/到期时间，返回不含旧正文的句柄。API仅在保存验证为verified时调用；可选记录分配失败不会把已经成功的保存改报失败。
- **inspect(id)**：检查存在/到期/主机/工作区，不符删除对应项并拒绝；再次安全读取磁盘，要求当前正文hash恰好是本次保存后的hash。不是对全部文件历史的检测；外部改动后又恢复相同正文的ABA变化不可由hash识别。
- **preview(id)**：inspect后再次读取并核对，双方≤2000行；diff timeout=100ms、maxEditLength=4000、结果≤256KiB。返回path/expectedHash/diff/expiresAt，不执行回退、不更新记录时效。预算不是Worker硬实时隔离。
- **restore(id,input)**：confirmed必须严格true；inspect当前磁盘版本、核对调用方expectedHash。发起工具调用前删除记录，再通过共享callTool(write_file)用旧正文和保存后hash写回。工具的路径/锁/版本/原子写/结果验证仍有效；要求success=true且verification=verified。未知/失败也不能拿同一记录重放；调用前的验证拒绝尚未消费记录。成功返回旧正文及新hash供编辑器回读，不创建redo或新的undo记录。

## API与界面合作

PUT /api/files/content在保存前capture，保存成功后按verified结果remember，响应undo可能为null。GET /api/files/undo/:id只预览；POST同路径还要求workspaceRoot/hostInstanceId绑定，并把确认/版本交给restore。所有接口继承本机控制面，不提供远端MCP回退工具；人工编辑/回退不是同时启动一个Chat模型。

文件菜单“预览回退本次保存”调用tabs.previewUndo：源文件不能有未保存草稿，必须持有最近保存句柄；await后核对标签/正文/hash/句柄未变，才显示diff。“确认回退这次保存”进入savePreview的undo分支，消费页面快照/句柄、设saving，POST绑定与确认。响应到达后更新hash/savedContent；只有缓冲区仍等于请求前正文时替换缓冲区，否则保留期间写的新草稿并标dirty。关闭源标签被saving门禁挡住，重放/自动回退均不存在。

只恢复单次保存前的文件正文。后续文件变化、文件删除、记录过期、预算超出均停止；不静默覆盖并发写入，不强制恢复，不承诺外部进程竞态下的OS级事务，也不撤销shell、删除、改名、补丁工具或多文件操作。

## 验证

apiFiles真实HTTP覆盖：保存生成句柄、预览无写入、错主机/非布尔确认拒绝、外部改动拒绝、明确恢复旧正文/哈希、重复请求拒绝。模块夹具覆盖敏感路径/无变化/超大正文不记录、16项淘汰和15分钟过期。editorRuntime运行真实ES模块验证句柄、回退期间编辑保留、脏草稿拒绝；workbench.browser操作实际菜单/diff/确认并查磁盘。CI不是用户真实Windows/VS Code原生撤销验收。

## fileCheckpoints.js：任务前检查点与任务后跨文件内容恢复

这是与editorUndo独立的**主动备份选定文件**机制：用户任务前建立检查点，任务后可以恢复Agent、外部编辑器或命令修改的这些文件正文；不知道任务前版本就不能补造检查点。仅本机控制面提供，不新增远端MCP创建/恢复工具，不自动执行恢复或事务补偿。

### 内存、路径与逐函数

- **prune()**惰性清理15分钟到期记录，正在running的记录不被清掉。**read(filePath)**先resolveSafePath、realpath，再以真实工作区根的相对路径重过安全策略（不能把Windows盘符绝对路径直接交给拒盘符的策略）。fd/fstat要求普通文件，读取最多65537字节，超过64KiB拒绝；严格UTF-8，拒NUL/BOM。finally关fd。O_NOFOLLOW/O_NONBLOCK按平台支持启用；父目录替换等恶意OS并发仍不是沙箱或锁。
- **metadata(record)**仅输出ID、路径、时间、状态及深拷贝逐文件结果，不输出备份原文。**get(id,input)**要求严格工作区/host绑定，清过期并核对记录所属主机/工作区。
- **create(input)**必须confirmed严格true。最多8个检查点，每个1–12个已有文件、原文合计256KiB；真实路径重复（Windows忽略大小写）拒绝。全文件读取/预算检查成功才入Map，失败无半条记录。各文件快照是分别读取的时点，不是全仓同一瞬间的一致性快照；硬链接/外部进程不构成隔离保证。
- **preview(id,input)**仅ready可用，先作废旧ticket，再读取所有当前文件并核对真实路径；双方各≤2000行，单diff timeout100ms/maxEditLength4000，总diff≤256KiB。返回current→checkpoint差异和expectedHash/targetHash，生成新的随机previewId，服务端保存不可变路径/hash/差异。预览不写盘，不延长检查点期限；页面不能替换目标正文或当前hash。
- **restore(id,input)**要求严格确认、最新previewId和ready。先消费ticket，持有当前Chat/Bridge同类型执行lease，防止中途切换模式；这是本机人工文件操作，不新启动Chat模型，不代远端绕过ACL。对**全部文件先预检**，任一缺失/漂移则零写入，需重新预览。开始执行后state=running；每个变化文件在写入前再次检查绑定/路径/hash，再调用共享write_file附expectedHash。共享写入还会再做版本检查和读回验证，hash必须等于备份hash才标restored。
- 任一执行异常/取消/不可信结果即停止。已经verified的保留restored；发出调用但效果未确认的是unknown；还未发出的保留not-started；无变化是unchanged。state最终consumed，部分失败/unknown都不能再次preview或restore，不自动补偿此前恢复。写入前失败可为failed，实际发出而未确认则unknown。finally释放执行lease。检查并非锁，检查之后仍可能遭遇外部并发；即使全部succeeded，也只是各文件写后时点证据，不是持续状态证明。
- **list()**返回当前主机/工作区的metadata，刷新页面可找回还未过期的记录及部分执行清单。**remove(id,input)**拒绝移除running；其他记录可删。主机重启、过期、主动移除后无法恢复，程序内存和编辑器已打开的副本不保证安全擦除。

### 操作、API与限制

在经典工作台Bridge→工具接入与审批中，“跨文件内容检查点”每行填一个工作区路径，确认暂存原文。开始Agent任务前完成这一步。任务后刷新列表，先“只预览”，核对所有diff再“恢复一次”。取消确认不会写入；收到错误先看逐文件记录与磁盘，不换ID/自动重试。可先用两个无重要内容的临时文本试验。恢复前另行保留未保存编辑器草稿，避免后来保存草稿覆盖恢复结果。

GET /api/checkpoints只列元数据；POST同路径建立；POST /:id/preview、/:id/restore、/:id/remove均要求workspaceRoot/hostInstanceId。create/restore另外要求confirmed严格true，restore还要求previewId。全部继承已有本机/跨站控制面拒绝，不开放隧道MCP接口。operationApi错误返回400；restore返回HTTP200也必须查看result.success/status与逐文件结果，不拿HTTP成功当全部恢复成功。

上限为8×256KiB备份正文加最多8×256KiB差异，不含对象、临时读取、JSON/网络副本。不是磁盘永久备份、任意全项目回滚、OS原子事务或redo。**不恢复新文件、删除/改名、权限/时间戳/目录结构、数据库、外部服务或shell其它副作用**；选定文件消失时拒绝，不按旧路径重建。无检查点前史不能凭空撤销。全部失败也不自动创建新检查点重试，需人工查证并决定后续工作。
