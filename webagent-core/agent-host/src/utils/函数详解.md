# 请求取消与有界读取：逐函数讲解

## 职责与依赖

本篇展开 [requestScope.js](requestScope.js) 与 [boundedFile.js](boundedFile.js) 的所有具名函数；其他 utils 文件仍以[模块说明](README.md)为入口，尚未在这里逐函数展开。requestScope 解决异步链上的信号传递，boundedFile 限制并严格解码普通文本文件；它们都不是完整业务权限检查器。差异渲染的计算预算见[差异展示详解](差异展示详解.md)。

## 1. requestScope.js 的执行流程

Node 的 `AsyncLocalStorage` 把当前信号附着在异步执行链，不用在每层函数都显式传 signal。它不是全局唯一“当前任务”；不同 run 建立的异步上下文可分别取回各自的值。`DEFAULT_TIMEOUT_MS` 为120秒，`DEFAULT_RESPONSE_MAX_BYTES` 为8MiB；它们是工具缺省值，不代表每个调用方都采用同一响应预算，模型调用会显式收紧到1MiB。

### runWithSignal(signal, fn)

调用 `scope.run(signal, fn)` 并返回其结果。fn 若同步返回，结果同步；fn 若返回 Promise，返回该 Promise，不在这里自动 await 或吞错。signal 由调用者创建和取消；本函数既不创建计时器，也不自动取消任意系统调用。作用域外不会因此永久改变其他请求。

### currentSignal()

返回 `scope.getStore()`，没有上下文时可能为 undefined。无 I/O、无状态修改。调用方必须处理不存在的信号，不能直接无条件读取 aborted。

### checkCancelled()

读取 currentSignal；存在且已 aborted 时构造 Error，message 为任务取消/超过截止时间，code 为 `E_CANCELLED` 并抛出。没有取消则返回 undefined。这是主动检查点，不是中断任意同步代码的抢占机制。

### 响应预算辅助函数

| 函数 | 输入/输出 | 语义与边界 |
|---|---|---|
| `responseTooLarge(maxBytes)` | 字节上限→Error | 生成固定的`E_RESPONSE_TOO_LARGE`，只附maxBytes，不拼接URL或远端正文；它本身不取消流 |
| `responseBudget(limits)` | 可选`{maxBytes}`→正安全整数 | 缺省取8MiB；显式值必须为正安全整数，否则抛TypeError。这里只校验受信调用参数，不解析HTTP输入 |
| `chunkBytes(value)` | Uint8Array/ArrayBuffer/view/其它值→字节视图 | 标准二进制尽量零复制；非标准值按字符串转Buffer，主要兼容旧实现/测试替身 |
| `readWebStream(body,maxBytes)` | WHATWG ReadableStream→Promise文本 | reader逐块累计原始字节，超过预算尝试cancel但不等待其Promise，消费拒绝并立即抛稳定预算错误；TextDecoder流式解码避免把跨块UTF-8切坏，finally释放锁 |
| `readNodeStream(body,maxBytes)` | async-iterable Node流→Promise文本 | 同样逐块计字节；超限时可用则destroy并抛预算错误。不是所有自定义流都能证明底层资源已经退出 |
| `readResponseText(response,limits)` | Response样对象→Promise文本 | 优先WHATWG reader，再用Node异步迭代；只有无流的旧fetch/测试替身才退到`text()`并在完整读取后计算UTF-8字节。生产Node fetch的标准Response走逐块分支，不能把fallback的事后检查说成预缓冲保护 |

TextDecoder不是fatal模式，坏UTF-8可产生替代字符；这些函数限制原始响应字节，不验证JSON、HTTP状态或内容类型。字符串拼接/解码仍会分配额外内存，8MiB预算不是进程总内存上限。

### fetchText(url, options, timeoutMs = DEFAULT_TIMEOUT_MS, limits, fetchFn = fetch)

返回Promise<{response,text}>，body已消费，不要再读一次。fetchFn是受信内部/测试依赖注入，缺省仍原生fetch，不通过HTTP参数选择实现。

1. `checkCancelled`，避免已取消任务再发请求。
2. 读取parent signal，新建AbortController；父取消注册一次性监听，同时创建覆盖fetch与body读取的deadline。
3. 再核对parent状态后发请求；本函数的controller.signal覆盖options里同名signal。传输解析顺序是`options.fetchImpl` → 第5个位置参数`fetchFn` → 全局fetch，且**惰性**取全局：调用方自带传输时不要求运行环境存在全局`fetch`（裸`vm`上下文正是如此）。`fetchImpl`在发出前被剥离，不会混进请求init。这样那些公开`fetchFn`注入点的模块——auth/github、usage/tracker和它们的测试——可以保留注入能力，同时照样获得超时、父取消与字节预算；注入传输不是绕过预算的后门。
4. `readResponseText`按`limits.maxBytes`或8MiB缺省逐块读取；标准流刚越界即取消/销毁并抛`E_RESPONSE_TOO_LARGE`。
5. 读取后再次`checkCancelled`，再返回response/text；finally无论成功、网络失败、超限或解析前失败都清timer和父监听。

HTTP错误状态仍由调用者解释；未取消/未超时的网络错误不全部转换。模型另传1MiB/拒跳转，GitHub另传10秒/64KiB/拒跳转并归一公开错误，不能说所有fetch调用都自动获得这些合同。只有显式runWithSignal才继承父取消。

**checkDeadline()**在响应头到达后与响应体读完后各核一次：`controller.signal`已abort或`performance.now()`越过`expires`就abort并抛`E_TIMEOUT`。两次都查是必要的——缓慢滴流的响应体可以让流在技术上一直"活着"却远超预算。

**期限由本机强制，不依赖对端配合。** `abort()`只是**请求**传输停止，并不保证它照做：一个忽略`signal`的实现（测试替身、行为不良的polyfill）会让Promise永远挂起，期限形同虚设。因此超时侧自己`reject`一个`E_TIMEOUT`，并与`send(...)`和`readResponseText(...)`分别`Promise.race`。这是合并01a0c932时实测发现并修复的真实缺陷：黑洞传输下`fetchText`原本会无限期挂起。注意这保证的是**调用方一定会拿到结果**，**不**保证底层socket已经释放——那仍需I/O层配合。

其余期限语义仍要求底层I/O合作响应AbortSignal；不承诺任意自定义fetch被抢占终止，或者操作系统实时调度。读响应发生超限时，readWebStream尝试cancel但不await其Promise，接住其拒绝后立即抛E_RESPONSE_TOO_LARGE，finally释放reader锁。合成WHATWG流的cancel永不完成也不能阻塞错误返回；这不等于已确认底层资源退出。

## 2. boundedFile.js 的执行流程

### MAX_TEXT_BYTES

导出常量 `8 * 1024 * 1024`，是默认 8 MiB 字节预算，不是字符数。UTF-8 中文字符占用多字节；返回的 JS 字符串长度和文件大小不相等。

### EncodingError

`Error` 子类。其 constructor(message) 先 super(message)，再设 `name='EncodingError'` 与 `code='E_ENCODING'`；除此之外不附带文件正文或字节。表示目标文件不是合法 UTF-8，属于**文件本身的属性**而非瞬时故障，因此工具层把它归到 `E_ENCODING` 并且不应重试。它不描述文件真实是什么编码，也不做编码猜测。

### decodeStrictUtf8(buffer, file)

用 `TextDecoder('utf-8',{fatal:true,ignoreBOM:true})` 解码。任何非法序列——孤立代理半体、截断的多字节序列、过长编码、超出 U+10FFFF 的前导字节——都抛 EncodingError，消息里带文件名，不带文件正文。

**`ignoreBOM` 的语义是反直觉的**：`true` 表示"忽略 BOM 的特殊含义"，即把它当作普通字符 U+FEFF **保留**；`false` 才会**剥掉**它。这里必须取 `true`，因为严格解码的全部意义就是"解码出的字符串重编码 == 磁盘字节"，hash 才能真正标识那些字节。取 `false` 时一次普通的 read→patch→write 会把用户文件的 BOM 静默删掉（实测首三字节 `efbbbf` 消失）。BOM 保留为字符，由上层决定是否处理——JSON 上层必须用 readBoundedJsonText。

### stripBom(text)

去掉**至多一个**前导 U+FEFF；非字符串或无前导 BOM 时原样返回。只剥一个是有意的：第二个 U+FEFF 属于真实内容，静默丢弃它就是本文件着力防止的那类缺陷的重演。

### readBoundedJsonText(file, maxBytes = MAX_TEXT_BYTES)

`stripBom(readBoundedText(...))`。给**即将交给 `JSON.parse`** 的读取专用。

存在理由是两条需求直接冲突：readBoundedText 必须保留 BOM 才能保证字节往返，而 `JSON.parse` 遇到前导 U+FEFF 会直接抛 `Unexpected token`。Windows 上的编辑器（记事本、PowerShell 默认 `Out-File`）写配置文件会带 BOM，于是"保留 BOM"的修复一落地，带 BOM 的配置就被当成损坏文件报给用户——实测 Windows CI 三个 Node 版本全红而 Linux 全绿，因为 Linux 侧的夹具恰好不带 BOM。

把剥离**只放在 JSON 这一侧**，两条需求就不再打架：文本读取仍然字节往返、hash 仍然忠实，带 BOM 的配置也能正常加载。当前调用方：`models/customizations.js`、`models/profile.js`、`tools/board.js`。新增任何 `JSON.parse(readBoundedText(...))` 都应改用本函数。


### removeScratch(tmp, failure)

所有“先写临时文件再rename”的原子写入（patchEngine.atomicWriteText、store.save、customizations.writeCustomFile、board.saveBoard、admin-host saveReports）在finally里共用它删除临时文件。F70修复的问题：旧的内联写法`try { unlink } catch (e) { if (e.code !== 'ENOENT') throw e }`位于finally中，清理失败会**顶替正在传播的写入错误**——实测磁盘满ENOSPC变成了无关的EPERM，调用方据此无法判断真实原因。规则：ENOENT（临时文件已不在）直接返回；调用方把try块的错误作为failure传入，failure非空时吞掉清理错误、保留原错误（残留临时文件是较小的问题）；只有写入成功而清理失败时才抛出清理错误，因为那时它确实是第一个问题。不重试、不改变任何发布语义。
### readBoundedText(file, maxBytes = MAX_TEXT_BYTES, options = {})

同步返回 UTF-8 字符串；调用失败直接抛错，不返回错误结果对象。`options.strict` 默认 true。

1. statSync 先确认路径当前指向普通文件，减少误开非文件对象的风险。
2. openSync(file,'r') 打开 fd。成功打开后立即进入 try/finally，确保后续所有出口都关闭它。
3. fstatSync 对已打开对象再确认类型/大小。超过预算就拒绝，不能只相信第一次路径 stat。
4. 每轮最多读 65536 字节，实际还允许读到预算的下一字节，防止文件在 stat 后增长却被当作完整成功。
5. 读到 0 表示结束；累计超过 maxBytes 就抛错，否则保留本轮有效字节切片。
6. Buffer.concat 得到完整字节后**一次性**解码，因此跨 64KiB 块边界的多字节码点不会被拆坏；`strict` 为 true 走 decodeStrictUtf8，为 false 走 `toString('utf8')`。finally closeSync(fd)。open 自己失败时没有 fd，也不会走一个不存在句柄的关闭。

**为什么默认严格。** `Buffer#toString('utf8')` 会把每个非法字节替换成 U+FFFD，于是不同字节序列解码成同一字符串。上层对解码结果取 sha256 当版本号，就会出现"磁盘字节变了、hash 没变"，过期写入因此被接受（F61-02 已用真实文件复现：`41 ff 0a` 与 `41 fe 0a` 同 hash）。严格解码让"被接受的读取"始终满足 hash 与字节一一对应；对非法文件宁可拒绝，也不自动"修复"用户的字节。

**strict:false 的使用条件。** 只有**既不取 hash、也不回写**的纯扫描路径才可以传 false，目前是 `fileOps.grepFile`（搜索命中行）与 `memory.recall`（笔记召回）。它们把混合编码文件按替换字符扫过去，而不是让整次搜索失败。任何会产出 hash、参与覆盖确认或写回磁盘的调用都必须保持严格。

边界：这不是路径沙箱，调用方仍要做工作区/敏感路径检查；stat/open 之间的外部竞争并未被彻底消除；不会提供跨进程快照。严格解码保证的是"UTF-8 合法性"，不是"文件语义正确"或"编码一定是用户想要的那种"。函数未专门验证 maxBytes 的类型/范围，当前调用方应传合理的非负整数字节预算，不能把它当外部参数校验器。

内存方面：分块读取限制文件总字节，但 concat 和字符串转换会另分配内存，不是整个进程只占 8 MiB。同步读期间阻塞当前 Node 线程，也没有在循环里接入请求取消。

## 3. 协作、错误分支与验证

典型协作是 API 建立 signal scope → 模型适配器调用 fetchText → HTTP 断开/总时限触发 parent abort → fetch 被取消并释放监听。它只有接入的路径才有效，不能推出 MCP 取消通知已接到任务执行。

文件读取则通常是上层先验证路径与权限，再调用 readBoundedText；上层决定怎样把抛错映射为工具/HTTP 返回。

```bat
npm test --prefix webagent-core/agent-host -- --filter=fileReadSafety
npm test --prefix webagent-core/agent-host -- --filter=resourceBudget
npm test --prefix webagent-core/agent-host -- --filter=modelLifecycle
npm test --prefix webagent-core/agent-host -- --filter=githubNetwork
```

测试必须结合其具体断言读，不把文件名当作全分支覆盖率。真实网络取消、平台文件行为另按[验收清单](../../../../review/CHECKLIST_WINDOWS.md)记录。

复盘练习：比较“parent 已取消”“fetch 返回 500”“文件读取中增长”“maxBytes 被误传字符串”四种情况，指出哪个函数会检查、哪个错误由谁接住，哪些行为尚无保证。


## 4. workspaceBinding.js：启动时的项目一致性

**assertWorkspaceBinding(input,config)**先确认主机workspaceRoot为存在目录，再确认客户端绝对workspaceRoot和当前hostInstanceId。内部**normalize**用path.resolve消除相对段，Windows转小写、其他平台保留大小写；比较不一致抛中文Error。它不创建目录、不写配置，也不切换运行中主机；符号链接别名可能被保守拒绝，不提供文件锁。

/api/bridge/start在bridgeGeneration、store或隧道变化之前调用，/api/chat对vscode-extension调用；失败409/success:false。工作台与扩展从实时status取得实例，但仍必须与用户打开的项目一致。验证：workspaceEntry测试缺字段/相对路径/过期实例/不存在及文件路径；bridgeTunnel验证真实HTTP拒绝无副作用。这里只防意外错绑，原控制面鉴权和工具审批仍必需。
