# 请求取消与有界读取：逐函数讲解

## 职责与依赖

本篇展开 [requestScope.js](requestScope.js) 与 [boundedFile.js](boundedFile.js) 的所有具名函数；其他 utils 文件仍以[模块说明](README.md)为入口，尚未在这里逐函数展开。前者解决异步链上的信号传递，后者限制普通文本文件读取；它们都不是完整业务权限检查器。

## 1. requestScope.js 的执行流程

Node 的 `AsyncLocalStorage` 把当前信号附着在异步执行链，不用在每层函数都显式传 signal。它不是全局唯一“当前任务”；不同 run 建立的异步上下文可分别取回各自的值。

### runWithSignal(signal, fn)

调用 `scope.run(signal, fn)` 并返回其结果。fn 若同步返回，结果同步；fn 若返回 Promise，返回该 Promise，不在这里自动 await 或吞错。signal 由调用者创建和取消；本函数既不创建计时器，也不自动取消任何系统调用。作用域外不会因此永久改变其他请求。

### currentSignal()

返回 `scope.getStore()`，没有上下文时可能为 undefined。无 I/O、无状态修改。调用方必须处理不存在的信号，不能直接无条件读取 aborted。

### checkCancelled()

读取 currentSignal；存在且已 aborted 时构造 Error，message 为任务取消/超过截止时间，code 为 `E_CANCELLED` 并抛出。没有取消则返回 undefined。

这是主动检查点，不是中断任意同步代码的抢占机制。中间有一段很长的同步 CPU 工作而不检查，不会因为调用者 abort 就立即退出。

### fetchText(url, options, timeoutMs = 120000)

返回 `Promise<{response,text}>`，内部完整读取响应体；返回的 response body 此时已经消费，调用方不要再读一次。默认 120 秒，不等于所有上层请求的总时限。

执行顺序：

1. checkCancelled，避免已取消任务再发请求。
2. 取 parent signal，新建 AbortController。内部 `cancel()` 只执行 controller.abort，没有显式携带自定义 reason。
3. 若有 parent，注册一次性 abort 监听；同时创建 timeoutMs 定时器执行 cancel，支持时 unref。
4. try 中再次检查 parent.aborted，覆盖注册附近状态变化；调用 fetch，options 中的 signal 被本函数的 controller.signal 覆盖。
5. await response.text，随后再次 checkCancelled，才返回 response/text。
6. finally 清定时器并移除 parent 监听，不论成功、fetch 失败还是读取响应失败。

**关键边界：** HTTP 4xx/5xx 不会自动被此函数变成业务异常，调用方要检查 response 状态；网络/abort 可能原样抛出底层错误，不保证全部转成 E_CANCELLED。这里没有限制响应体字节数，也不逐块返回流；有时限不等于内存预算。options 自带的另一 signal 不会被合并，真正继承的是 AsyncLocalStorage 中的 parent。

## 2. boundedFile.js 的执行流程

### MAX_TEXT_BYTES

导出常量 `8 * 1024 * 1024`，是默认 8 MiB 字节预算，不是字符数。UTF-8 中文字符占用多字节；返回的 JS 字符串长度和文件大小不相等。

### readBoundedText(file, maxBytes = MAX_TEXT_BYTES)

同步返回 UTF-8 字符串；调用失败直接抛错，不返回错误结果对象。

1. statSync 先确认路径当前指向普通文件，减少误开非文件对象的风险。
2. openSync(file,'r') 打开 fd。成功打开后立即进入 try/finally，确保后续所有出口都关闭它。
3. fstatSync 对已打开对象再确认类型/大小。超过预算就拒绝，不能只相信第一次路径 stat。
4. 每轮最多读 65536 字节，实际还允许读到预算的下一字节，防止文件在 stat 后增长却被当作完整成功。
5. 读到 0 表示结束；累计超过 maxBytes 就抛错，否则保留本轮有效字节切片。
6. Buffer.concat 后解码 UTF-8 返回；finally closeSync(fd)。open 自己失败时没有 fd，也不会走一个不存在句柄的关闭。

边界：这不是路径沙箱，调用方仍要做工作区/敏感路径检查；stat/open 之间的外部竞争并未被彻底消除；不会提供跨进程快照。解码不是严格 UTF-8 校验。函数未专门验证 maxBytes 的类型/范围，当前调用方应传合理的非负整数字节预算，不能把它当外部参数校验器。

内存方面：分块读取限制文件总字节，但 concat 和字符串转换会另分配内存，不是整个进程只占 8 MiB。同步读期间阻塞当前 Node 线程，也没有在循环里接入请求取消。

## 3. 协作、错误分支与验证

典型协作是 API 建立 signal scope → 模型适配器调用 fetchText → HTTP 断开/总时限触发 parent abort → fetch 被取消并释放监听。它只有接入的路径才有效，不能推出 MCP 取消通知已接到任务执行。

文件读取则通常是上层先验证路径与权限，再调用 readBoundedText；上层决定怎样把抛错映射为工具/HTTP 返回。

```bat
npm test --prefix webagent-core/agent-host -- --filter=resourceBudget
npm test --prefix webagent-core/agent-host -- --filter=modelLifecycle
```

测试必须结合其具体断言读，不把文件名当作全分支覆盖率。真实网络取消、平台文件行为另按[验收清单](../../../../review/CHECKLIST_WINDOWS.md)记录。

复盘练习：比较“parent 已取消”“fetch 返回 500”“文件读取中增长”“maxBytes 被误传字符串”四种情况，指出哪个函数会检查、哪个错误由谁接住，哪些行为尚无保证。
