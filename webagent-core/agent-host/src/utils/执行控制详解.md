# executionControl：工作模式租约与Bridge权限

本篇逐函数解释[executionControl.js](executionControl.js)，并核对它与执行入口的合作；不是OS安全认证。操作步骤见[权限与工作模式](../../../../docs/guides/Bridge权限与工作模式.md)。

## 状态与数据

state只在单个agent-host进程内保存mode=idle/chat/bridge及两类active计数。lease表示一个尚未结束的执行Promise；不是MCP连接数、任务板todo数或操作系统进程总数。权限存store的bridge.permissions，四个严格布尔值。缺省四项全开兼容旧配置；错误配置拒绝而不是悄悄回退全开。

READ列出读取工具，EDIT列出文件/记忆/任务板修改，CONTROL只列不赋予任意读写能力的协议/报告/取消/预览操作。workflow_request属于Read；未知、shell、外部与浏览器不透明工具要求全部四项。Edit需要Read；Execute需要所有类别。Capture控制已有命令回图，不增加截图工具。

## 逐函数

- **fail(code,message)**：抛带业务code和status=409的ProtocolError，供本机接口反馈冲突；不是所有RPC都返回HTTP409，JSON-RPC走既有错误封装。
- **validate(value)**：必须恰好四个键且都是布尔值，拒绝数组/字符串布尔和相互矛盾的依赖。重建固定顺序对象，避免保存调用方额外键。
- **permissions()**：每次从store.load读取当前bridge.permissions并validate；只有字段不存在才返回兼容全开。不是把远端params当权限。
- **revision(policy)**：固定顺序JSON的SHA256，用于防止旧本机窗口覆盖不同的新策略；不是密码或签名，也不区分改回相同策略的历史。
- **snapshot()**：返回模式、active副本、权限和revision。active只统计租约中的请求；后台程序另外检查。
- **blockers(includeWaiting=true)**：延迟require避免模块初始化环；检查executor.activeCount、operatorQueue运行/可选等待审批、stdioTransport.snapshot中未closed传输、PTY.activeCount。stdio不能用已删除的注册列表冒充进程已退出。
- **assertIdle()**：任一租约或blockers存在即E_BUSY。Bridge重新启动也先调用它，防止在任务执行中隐式重启隧道。
- **selectMode(mode)**：验证chat/bridge；同模式幂等回读，不取消工作。真正转换须assertIdle；切Chat还要求bridgeRunning=false。只改内存模式，不自动启停隧道/终端。
- **enter(mode)**：idle时首次占用（已经有运行隧道则归Bridge）；跨类型E_MODE_CONFLICT。同类型计数递增，返回幂等release闭包，避免重复释放扣负数。调用点传受控常量，不接远端任意模式名。
- **run(mode,fn)**：enter后await fn，在finally释放；异常仍向上传递。多个同类型Promise可以并行，不是全局串行锁。
- **updatePermissions(value,expectedRevision)**：先验证新值，再比当前revision；在途/后台/运行审批期间拒绝。等待审批不阻止撤权。store.patch成功才返回新快照，不声称fsync或多资源事务。
- **requirements(tool)**：按标准名返回所需类别；未分类保守返回四项。CONTROL不是远端所有者能力。
- **assertAllowed(tool)**：当前权限缺项即E_FORBIDDEN，必须在实际执行前调用；不会修改策略或自动申请审批。
- **allowed(tool)**：读取当前权限判断工具是否可列出。只用于工具列表辅助过滤，不能替代执行门禁。

## 入口与异步边界

runChat包裹run(chat)，本机/tool/call和consensus同样检查；手动编辑器文件接口不被误称为Chat模型执行。MCP认证后的HTTP分发包裹run(bridge)，GET入口同样占用/检查模式；直接工具单元函数不等于HTTP会话入口。resources/read、prompts/get/list补Read限制，Read关时initialize不加载完整自定义指令。tools/list、get_capabilities及capabilities资源过滤远端当前可用工具，dispatchTool在别名归一后执行assertAllowed，远端自报Code/remote字段不能提升权限。截图收集前再看Capture，run_command别名同样走回图链。

Bridge/start通过授权/工作区检查后预占Bridge，跨全部隧道await保留租约，finally释放；失败不自动切回Chat。停止隧道仍是独立操作，不等于清理所有任务。

operatorQueue.submit按来源占用/检查模式，approve重新取得同来源租约并查最新权限；工作流每个callTool仍查标准工具类别。权限拒绝按失败终态保存，不重放；其他未知中断保留unknown和检查既有副作用提示。等待审批本身不是活Promise，但阻止模式切换。

executor.activeCount取运行记录数与实际children.size的较大值，避免cancelled记录掩盖未close子进程。PTY.activeCount包含cancelRequested；prune不再删未确认取消项，enqueue的32项限额也覆盖这些未确认项。PTY确认依赖客户端报告，不能证明任意脱离系统进程已结束。

## 验证

[executionControl.test.js](../../tests/executionControl.test.js)通过真实HTTP和临时工作区构造模式/权限请求，验证保存、过期revision、绑定错误、别名和远端伪造参数、tools/list/get_capabilities/capabilities资源目录完全一致只读过滤、恢复权限后目录即时更新、资源/提示词拒绝；批准前撤Edit阻止嵌套写且步骤execution=not-started（工作流调用前的显式复查），opaque-fixture证明未获权限不调用handler。两个悬挂HTTP工具验证Bridge同类型并发和在途拒绝切换/撤权，两个Chat租约验证同类型并行。真实Node后台命令验证accepted仍阻止切换，并证明另一peer按显式ID/缺省最近记录均读不到、不能取消，get_logs也只含自己的sessionId，原所有者仍可查询并明确取消；PTY模拟所有者确认、stdio未closed快照和隧道暂停启动夹具覆盖等待边界。子Node进程重新加载临时配置证明权限持久化、工作模式重新idle。不等于真实Windows/手机界面或完整OS进程隔离验收。

本机人工提交审批沿用当前工作模式（idle时归Chat），任务保存workMode供批准时复核；远端始终Bridge。人工审批不是启动另一个Chat模型，所以不因本机操作者使用Bridge区审批面板就强制跨模式。远端权限仅检查remote任务，不限制本机人工编辑权限。

测试函数：**main()**等待临时HTTP服务后顺序执行上述断言；**post(url,body,headers)**真实发送JSON并读取状态/响应头/正文；**rpc(method,params)**生成递增RPC ID并携带密钥和初始化会话；**policy(permissions)**用当前revision及正确工作区/主机绑定调用保存接口。夹具finally清PTY、关闭HTTP连接和临时目录，子进程验证只读取该临时工作区。

F54第四批：executionControl的main通过同IP同凭据、不同初始化会话报告REMOTE_A/B，Local由可信内部progressTracker设置。workspace资源只读自己的step/progress，与get_task_status相同；远端remote:false/callerKey/_meta伪装不改变归属。Local模块默认仍读Local；空闲peer只得到idle且不建报告槽位，删除SID后404，缺SID资源读取E_SESSION_REQUIRED；移除远端全局recentEvents。协议资源断言不得建议直接复用错误hash。Read关闭时workspace/capabilities/protocol无正文，Edit关闭时原写调用拒绝断言继续保留。共享根/指令/记忆仍属于Read授权，不把这些断言外推为完整多租户隔离。
