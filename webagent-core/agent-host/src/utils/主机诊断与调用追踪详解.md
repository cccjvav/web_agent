# 主机诊断、任务上下文和读回核验

## hostDiagnostics.js

- **hostIdentity()**从config取本次进程的hostInstanceId、startedAt、工作区、版本和两端口。UUID在进程启动生成，不持久化，不等于installId或访问密钥；status、ping、workspace_info、initialize元数据、Bridge快照共用。
- **findExecutable(name)**按PATH和Windows扩展名候选做stat/access，只返回发现的路径，不执行候选程序。找到解释器不等于已验证运行，更不是安装或提权授权。
- **diagnostics()**只检查目录读写权限、PTY匹配心跳及Windows PowerShell候选。返回ready/unverified/unavailable及原因；写权限只初检，不能充当真实写文件验收。不会启动命令、截图、安装或创建探针文件。GET /api/diagnostics与其他API共用本机边界；get_capabilities给认证MCP同一能力表。

## toolTrace.js

- **withTask(info,fn)**用AsyncLocalStorage为本次Chat/工作流保持任务上下文，缺taskId生成UUID；不是权限上下文。
- **taskId(value)**只接受受限t编号或UUID形状，否则新建UUID。可把MCP `_meta["webagent/taskId"]`设为任务板ID来关联，但关联不等于认领权或任务完成。
- **beginCall(tool,options)**限制最多64个running调用，生成callId；callerKey用本进程ID盐化SHA256后截断为会话标识，不保存令牌/原sessionKey。source区分Bridge-Remote、Chat、Local等受控调用来源。保留至多200条（新建时清旧完成项），不驱逐活动项；发tool_execution_start。
- **finishCall(record,result,error)**更新结束时间、耗时、execId及成功/失败/取消/accepted/unknown状态，记录核验状态；错误只存受限错误码，不存错误正文、命令、参数或文件内容。命令仍运行时标accepted，不把已提交命令当完成任务。发tool_execution_end，返回副本。
- **snapshot(source)**按来源过滤并复制记录，最新在前；**clearCompleted()**清已完成项但保留running。主机重启会丢历史，清轮不取消在途操作。
- **verifyMutation(tool,input,result)**对write_file/apply_patch读取磁盘并对比hash/newHash；delete_file验证不存在，rename_file验证源消失且目标存在。dryRun不核验写入。失败返回success/ok=false和verification=unknown，明确可能已经写入，不能自动重放。只证明核验时刻的条件，不保证随后无人修改、目录内容事务或业务目标已完成。

## 工具入口与前端

callTool包围原分发逻辑dispatchTool；权限/危险命令/路径校验仍在dispatchTool，追踪不能绕过它。未知工具记录为unknown-tool，不把任意输入当日志名称。结果带trace；异常带err.trace供MCP响应_meta关联。Bridge快照含执行记录，可在RPC尚未完成时显示running；完成计数仍按MCP完成事件，不能把数量当任务成功证据。

## 验证

hostDiagnostics.test.js用隔离工作区验证只读诊断不创建文件、身份一致、能力模式公开、私有会话键不进记录；同Chat任务的两调用有相同taskId/不同callId；真实写盘读回verified，错误hash为unknown且不重写；Ask拒写及Abort取消状态可见，清轮保留活动项。runChat.test.js验证显式文件优先读取、摘要含证据、不存在不猜测。真实Windows能力仍需人工验收。

## 持久登记的真实浏览器回归
workbench.browser.js由独立test:browser运行，**freePort()**申请临时回环端口，**main()**创建隔离工作区、启动真实host并finally关闭浏览器/进程与清理目录。**receive(chunk)**等真实监听日志；**rpc(name,args)**向认证MCP发tools/call，凭据只在测试内存不输出。页面实际点击帮助、核对身份正反例，认证写文件及读回trace，主动关闭WS验证轮询和刷新；CDN阻断后用纯文本编辑器Ctrl+S写盘，内置Ask返回显式文件证据，深浅主题小窗口检查菜单边界，最后失败计数和清轮。pageerror非空即失败。它不是Windows桌面键鼠/手机蜂窝验收。可用CHROMIUM_PATH指定本地浏览器；CI下载Playwright Chromium，不把浏览器文件提交Git。


## 受控执行增量

受控执行扩展：waiting-approval/running归accepted；unknown、denied、expired、failed明确分类，operationId关联审批。approve另建approved_workflow/approved_external_call执行记录，避免把提交记录当已执行；子步骤共享taskId。Bridge的RPC计数与执行记录数量不同。真实浏览器另验证工作流预览/提交不写入、确认批准后实际文件存在。

真实浏览器增补：初始化认证HTTP MCP取得Mcp-Session-Id，通过该会话提交workflow_request，确认批准前零写入，再从本机页面点击批准并核对磁盘内容。endpoint、session、initialized、queued、pending是该测试main内的局部数据，不是额外服务。

### Skills浏览器与认证MCP回归
main额外创建带长SKILL.md、references、scripts/run.js、workflow.json的隔离fixture。页面搜索/点击来源ID、连续分页拼接、读取引用/脚本源码且检查无脚本副作用；转Ask保留草稿且不POST聊天；完整读取workflow.json后只预览，磁盘未写目标。认证MCP真实load_skill分页与hash比对，并在正文修改后拒绝旧hash续页。另验证查看REST未知404、参数错误400、旧hash409；pageerror和原所有端到端断言继续保留。

浏览器新增审批时文件漂移用例：main填入before.exists=false的工作流，预览/提交后由测试进程创建目标文件，再从真实页面批准；等待E_PRECONDITION并核对磁盘仍是另一程序写入的内容。不是只调用DOM替身，也不宣称无竞争文件锁。

### stdio诊断与浏览器证据
diagnostics的external-mcp说明现区分回环HTTP与本机预览/确认stdio启动，不将发现当授权。浏览器main新增真实启动及认证远程申请/本机批准/移除，检查预览无进程、取消确认无进程、只有批准后写一次调用计数；env值不显示，跨站管理请求拒绝。

stdio停止后诊断不再因保留了注册记录就称接入可用：仅有discovered服务才标unverified，全部stopped则unavailable。本机进程元信息显示固定stopReason帮助区分取消/超限/退出，不保存原始stderr。
