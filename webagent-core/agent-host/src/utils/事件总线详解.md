# eventBus.js：事件、日志、WebSocket 与脱敏副本

## 职责、对象和流程

[eventBus.js](eventBus.js)定义BridgeEventBus并导出一个实例，另挂sanitizePayload供测试/调用，以及WS资源常量WS_MAX_BUFFERED（1 MiB）与WS_HEARTBEAT_MS（30秒）。事件同时走两个通道：**WS/日志的脱敏副本**，以及**进程内EventEmitter原始payload**。两者保证不同，不能说“进入总线就全部脱敏”。

```text
broadcast(type,payload)
 → sanitizePayload → 日志最近500条 → JSON → 就绪WS客户端
 → this.emit(type,原payload) → 内部同步订阅者
```

## 1. clipStr(s,max=4000)

String转换，超max先截前段加省略号，再用SECRET_RE替换常见PAT/API Key/Bearer形式为redacted。不是识别所有秘密的通用扫描器；先截后匹配可能使跨截断位置的模式不再完整。不要因为用过它就主动把凭据写进事件。

## 2. sanitizePayload(value,depth=0)

nullish原样；字符串clipStr；数字/布尔原样。其他类型到深度6返回省略标记；数组取前40，map递归。对象只取前40个键，SECRET_KEYS命中直接redacted，CLIP_KEYS（diff/patch/content/chunk/stdout/stderr/args/body/command等）且值为字符串时先限500，再递归；其他类型String后限200。

这是展示摘要，会丢数组成员/对象键，**不同于MCP预算保留结构**；不适合拿摘要还原业务数据。SECRET_KEYS是精确命名集合，不是任何“含token”字段都识别。深度限制能终止常见循环对象递归，但读取getter/键等仍可能抛错，并非永不失败。

## 3. BridgeEventBus 的所有方法与回调

### constructor()

super建立EventEmitter；wsClients Set、idleTimers WeakMap、wsAlive WeakMap（客户端是否回应了上一轮ping）、heartbeat=null（共享心跳interval）、logs数组，maxLogs=500。创建实例不监听TCP，真正WS入口在src/index.js。

### _clearIdle(ws)

从WeakMap取timer，存在就clearTimeout并删除映射。只清该客户端的计时器，不关闭socket。

### _touchIdle(ws)

先_clearIdle，再建立30分钟timeout；回调尝试ws.close(1001,'idle')，关闭异常吞掉；支持时unref，再保存timer。这里的活动是在后续broadcast成功发送时刷新，不是任何浏览器键盘动作或网络ping都刷新。因此只要有事件在发，停止读取的客户端永远等不到这个计时器；那类客户端由下面的积压闸门和心跳回收。

### addWsClient(ws)

Set已32个就尝试close(1013,'too many sockets')并返回false（不启动心跳）。否则加入，wsAlive记true，设idle，注册pong匿名回调（把wsAlive记回true）和close匿名回调（清timer、从Set删除、_stopHeartbeatIfEmpty），再_startHeartbeat，返回true。没有在此验证来源/身份，那是在握手/入口中完成。

同一对象重复注册可能再加监听，容量也没有对重复调用特别分支；当前入口应每次连接注册一次。正常关闭时close事件触发前仍占Set项；被_dropWs回收的客户端则当场移出。

### _dropWs(ws)

回收一个无响应客户端：_clearIdle、从Set删除，再terminate()直接销毁socket（不等对方可能永远不回的关闭握手）；对象没有terminate时改用close(1001,'unresponsive')，异常吞掉。最后_stopHeartbeatIfEmpty。稍后到来的close事件重复删除无害。被丢弃的是工作台：它在任何close后按退避重连，并通过HTTP重读状态，所以不会丢失权威数据，只会漏掉断开期间的提示性事件。

### _heartbeatRound()

一轮心跳，直接遍历Set（遍历中删除当前项在JS Set中是明确定义的，后续项仍会访问）。readyState不是1的跳过，由其自身close事件移除；wsAlive为false（上一轮ping没回pong）的交_dropWs；其余记false并ping()，ping抛错立即_dropWs。所以一个静默对端最迟在两个间隔（约60秒）内让出名额；浏览器在协议层自动回pong，工作台代码无需改动。

### _startHeartbeat()

已有interval直接返回；否则setInterval每WS_HEARTBEAT_MS跑_heartbeatRound，支持时unref，不让心跳单独维持进程。所有客户端共用这一个interval。

### _stopHeartbeatIfEmpty()

Set为空且有interval时clearInterval并置null；下一个客户端注册会重新启动。没有客户端时进程里不留心跳计时器。

### broadcast(type,payload={})

生成含type/ISO时间/脱敏payload的eventObj，logs.unshift，新长度超maxLogs就pop。JSON.stringify一次后遍历wsClients，只给readyState===1发。发送前若该客户端bufferedAmount已超过WS_MAX_BUFFERED（恰好等于仍发送），说明它已停止读取，交_dropWs且不再为它排队；其余在try中send后_touchIdle，send异常吞掉，不自动从Set移除。

最后this.emit(type,payload)传**原对象**给内部订阅者。EventEmitter监听同步执行，监听器抛错可使broadcast抛错；此前日志/WS可能已发送，不是全通道原子事务。内部监听器也可能修改原对象，调用者不能将其当不可变消息。积压闸门在发送前检查，所以单个客户端最多约1 MiB加一条事件的排队字节；它不限制内部订阅者，也不限制日志数组以外的其他内存。

### getRecentLogs(limit=50)

返回logs.slice(0,limit)，新到旧；数组是浅拷贝，事件对象仍共享。没有对limit单独做数值范围验证；API调用者需约束展示参数。

## 4. 验证与复盘

```bat
npm test --prefix webagent-core/agent-host -- --filter=eventBus
npm test --prefix webagent-core/agent-host -- --filter=resourceBudget
npm test --prefix webagent-core/agent-host -- --filter=auditControl
```

检查脱敏/裁剪/容量相关断言；eventBus用假socket覆盖心跳、积压闸门与interval启停，auditControl在真实/ws上验证超大帧1009、畸形帧不致宿主崩溃、静默对端和停读客户端被回收而正常客户端收到全部事件。真实浏览器断线重连和长挂仍看人工清单B3/B4。复盘时分别画出raw payload与sanitized副本，解释为什么get_logs中的内容可能不全，以及为什么它不适合作为补丁原文恢复来源。

## Bridge统计快照（0.7.0）
constructor以config.hostInstanceId作为本次进程bridgeEpoch（不另生成另一主机身份），再调用**resetBridgeActivity()**：递增bridgeRevision，清零stats与独立logs。**getBridgeActivity()**返回epoch/revision、stats副本和日志数组副本，不重新计数。

broadcast保留原广播/脱敏流程，并只对source=Bridge-Remote的tool_call_end累计calls/fail/totalMs/lastTool/lastToolAt；独立摘要仅tool（限200字符且遮蔽已知密钥格式）、success、durationMs、timestamp，最近100条环形上限，累计数不因裁剪而减少。bridge_round_reset调用resetBridgeActivity。其他日志挤满原500条队列不会挤掉独立统计。全部仅进程内存；无持久化、多租户或跨进程聚合保证。

## 执行追踪补充
bridgeEpoch与config.hostInstanceId统一。getBridgeActivity同时返回identity和toolTrace.snapshot的远程执行记录；执行start/end递增revision，允许看到进行中。bridge_round_reset清除已完成追踪但不取消running；原RPC完成计数保持。

resetBridgeActivity(reason)登记resetAt/resetReason；构造器默认host-started，bridge_round_reset显式operator-cleared。getBridgeActivity返回这些字段帮助识别重置，普通GET和页面刷新不写统计、不改变起点。仍是进程内状态，不新增磁盘或浏览器持久计数。


0.7.2 getBridgeActivity增加taskStates（远程任务报告快照）；Bridge-Remote的todos_updated/progress_updated也推进revision。任务读取不依赖WS历史截断，本地Chat报告不混入。报告自身有16会话/50项/30分钟预算，统计清除不会抹掉计划。验证taskProgress和eventBus；任务文字可能含用户信息，只在现有本机控制边界内提供。
