# 受控外部工具与工作流：从提交到批准

这是有限能力的 HTTP/stdio MCP 客户端和固定工作流，不是任意插件执行器，也不是第二套持久化任务板。现有 taskId 串联工具调用；审批状态独立表达“尚未执行”。本指南覆盖 operatorQueue.js、externalClient.js、workflows.js、operations.js 和 approvedOperations.test.js。

## 用户怎么用

1. 在本机工作台打开 Bridge，点“工具接入与审批”。本页不对隧道公开。
2. HTTP方式默认登记已经自行启动并信任的回环 HTTP(S) MCP 服务；公网HTTPS另需勾选、外发确认与工作区/主机绑定；stdio方式见后节，须另行预览/确认程序启动。输入名称、地址和可选令牌，点击登记。此时真实发送 initialize、notifications/initialized、tools/list；不是只保存备注。旧“外部 MCP 地址备注”仍只是备注，不自动迁移或授权。
3. 外部 Agent 先建立并保留 MCP 会话，再调用 external_servers 查元数据；Code 模式调用 external_request，传 serverId、tool、arguments、稳定的 requestKey。Ask/Plan 只能查看，不能提交执行。
4. 收到 waiting-approval 后应停止，通知本机用户审阅；不要生成新 key 重复提交。用户刷新请求列表、选中请求，核对完整参数，点击批准并确认对话框。登记过服务器不代表每个工具自动获准。
5. 用 operation_result 查同一个 requestId 的结果。external-reported 只表示外部服务自报，并非独立验证副作用。
6. 工作流文本框可先使用默认 ping 示例：只预览→提交新审批→选中并批准。预览不执行任何步骤。写文件示例应使用临时工作区；不把测试输出当成自己的 Windows 验收。

## operatorQueue.js：进程内审批状态机

- `register` 把固定 kind 对应到宿主执行函数，远程接口不提供登记任意函数的入口。`handlers`、`jobs` 都是内存 Map。
- `clone` 做 JSON 深拷贝，防止提交者改动已展示的输入。`submit` 先 checkCancelled，再清理旧记录、校验 kind/requestKey/32 KiB 输入；摘要把 kind 和输入序列化一起哈希。同一 owner/key/摘要返回原请求，输入不同则冲突。
- `owner` 对 remote 要求 peer: 会话标识。这个值来自服务端会话，不把用户传入 taskId 当权限。`resultRequest`只接受字符串requestId包装，autoRetry等未知字段先拒绝，再由`result`检查归属；`inspect` 和 `list` 只供本机管理路由，前者含完整输入结果，后者只有元信息。
- `publicJob` 输出 requestId、taskId、状态、创建/可选开始/结束时间、当前保留截止时间和下一步提示；详情按需克隆。不会输出内部owner或客户端登记的Bearer令牌；用户自己写进arguments的敏感文本仍属于所展示输入。输入和结果可含用户文件正文，保留在内存并明确展示给本机操作者，不写调用追踪日志。
- `prune` 把创建后超过15分钟仍待批的请求标记expired并记录finishedAt；终态从finishedAt起完整保留15分钟，避免临近审批期限才完成的结果立即消失，也让expired可被查询。最多20个未完成、40条总记录。容量满时仍允许同owner/requestKey/摘要命中原记录，但拒绝新的不同请求，直到完整保留窗口届满后惰性清理；不再为腾位置提前删除可查询结果并破坏窗口内去重。它不是定时删除或持久承诺；窗口届满淘汰或主机重启后相同key仍可能成为新请求并须重新批准，绝不能声称永久exactly-once。
- REST和内部`approve`均要求confirm严格为true，只允许waiting-approval→running，同一个运行中或终态记录重复批准不会再执行。并发最多4个，60秒AbortController定时器，通过runWithSignal / withTask继承取消和已有taskId；结果最多256KiB。空/非对象/数组结果、running/waiting-approval/accepted/pending等未完成状态、非终态trace或unknown验证保守记unknown（本队列不接管handler的后台轮询）；随后保留cancelled，其余经共享isToolFailure判断failed或succeeded，包括非零exitCode与isTimeout。handler调用前的E_FORBIDDEN是failed；已经调用handler后的抛错一律unknown，即使错误码叫E_FORBIDDEN，也不能推断没有副作用。完整原结果仍保留供核对。批准不等于执行成功。
- `cancel` 先prune；已超期的待批请求保持expired，不会被迟到取消改写成denied。仍在期限内的待批请求才变denied并记录finishedAt；运行中只发abort，不保证外部服务器撤回副作用。计时器也不是事务回滚。执行后finally清计时器/控制器并保留cancelRequested，供之后查询；标志仅表示曾请求取消，不把已确认的成功改成失败，不自动重试。

## externalClient.js：真实但有意收窄的 MCP 客户端

- `endpoint` 仅接收2048字符以内 HTTP(S)，限定127.0.0.1、::1、localhost，localhost固定改成127.0.0.1以免依赖DNS；拒绝用户信息、查询串、片段、本宿主已知端口。显式publicHttps=true时只接受非回环HTTPS，实际每次连接另走publicHttps的DNS全答案校验/固定socket lookup/正常TLS验证，不接受当前已知公网隧道origin。默认仍不接受互联网地址，也不通过URL启动stdio或npx/uvx安装；stdio另走明确的启动审阅，环境不作无条件透传。
- `add` 最多登记8个服务；publicHttps必须布尔，公网还要求confirmedPublic严格true及assertWorkspaceBinding；Bearer token限制长度与换行，只留内存。服务器先进入connecting；三段握手和发现成功才是discovered。协议允许2024-11-05、2025-03-26、2025-06-18，支持有界工具分页；整个initialize/initialized/发现流程共30秒截止时间，登记控制器连接父取消与remove。成功后才发布完整目录，失败调用 `remove` 清理，finally清总计时器和监听器。
- `discoverTools` 最多10页、100工具，全部分页JSON合计256KiB；续页cursor必须是非空≤1024字符字符串且不重复，缺失/null表示结束。跨页重复名称、非对象inputSchema/type不是object、超页/条目/总字节预算均拒绝整个登记，不发布部分结果；缺schema兼容为空对象schema。这是结构检查，不是完整JSON Schema参数校验或安全证明。
- `rpc` 每次随机JSON-RPC id，POST带内容协商、内存会话和协议头。`abort` 连接父级取消和30秒计时器；禁止重定向，HTTP异常不重试。finally中止剩余响应、清计时器、移除监听器及控制器。初始化请求本身确实会访问服务，不保证不可信服务收到握手后没有内部副作用。
- `responseMessage` 用流式reader累计字节，不先无限读入全文。最多256 KiB，支持JSON和SSE的data帧；UTF8严格解码，支持跨字节中文/emoji、LF/CR/CRLF及跨块换行，忽略注释和不匹配通知；只取对应id；无匹配、坏JSON/UTF8、超限会失败，finally取消reader。不是完整的服务器推送/采样/roots实现。
- `list` 深拷贝工具schema，调用方不能经返回对象改注册表；只输出元数据，本机可见endpoint，远程不含endpoint/token/session；模式/描述是第三方不可信数据，不是授权规则。
- `request`只接受serverId/tool/arguments/requestKey四个包装字段，autoApprove等未知字段在入队前拒绝；要求已发现serverId和工具名、对象参数，把不可变输入放审批队列，绝不调用工具。`execute` 仅由批准路径调用；服务器移除后明确未执行，不能悄悄改投另一个服务。返回必须先对**原始外部对象**调用共享`isToolFailure`，汇总isError/ok:false/success:false/失败status/非零exitCode及unknown验证，再替换不可信验证说明；普通结果标`external-reported`，外部明确`verification.state=unknown`则保留宿主unknown说明并使ok=false。这个顺序防止覆盖验证字段时把第三方原有ok:false或unknown误写成成功；unknown进入审批终态后不可重放。它仍是外部自报，不证明副作用独立成功或未发生。`remove`中止宿主侧请求并删除注册，返回removed布尔；stdio另回stopping:true，仅表示发起停止而不是已观察到退出，HTTP方式不负责关闭外部服务本身。

## workflows.js：固定schema与受限数据流

- `validate` 要求顶层只有steps，限制32 KiB、1–12步、唯一字母开头ID，工具名只能属于READ/WRITE静态集合。允许读目录/文件/搜索/git状态等，以及write_file/apply_patch；禁止命令、删除、嵌套工作流和外部调用。拒绝retry及未知字段，写路径与content/patch必须为字面字符串供审批；`exists:false`不能与必须读取现有文件的contains/sha256组合。
- 参数中完整的 `$steps.read.hash` 或 `$steps.read` 可引用前序步骤字段/整个输出。`validateReferences`递归扫描真正以`$steps.`开头的参数串，在审批前拒绝自引用、前向/未知步骤、空路径段及__proto__/prototype/constructor；普通正文中间出现同样文字仍是字面量。`resolveValues`执行时再要求每段属性自有，不拿undefined凑成功。写入路径/正文不能由上一步内容动态生成。
- `preview`只验证结构，返回完整步骤、reads-workspace或writes-workspace风险和约束；不会读取文件、检查工具实际参数全部语义或推断运行成功。HTTP/MCP入口经`previewRequest`只接受definition包装；`request`只接受definition/requestKey，再验证、提交而不执行，autoApprove等未知包装字段不能静默进入流程。
- `hasPartialReadFailure(tool,output)`只识别read_files多路径结果中的显式逐项error；单独使用read_files仍保留成功项和失败项供普通调用者处理，但固定工作流不能把部分读取当作已满足前序。命中后步骤记failed/E_PARTIAL_READ，后续写入不启动。
- `execute`批准后每步先checkCancelled、检查before、解析引用，并对remote步骤显式复查当前Read/Edit权限，之后才标记dispatched并调用callTool（中央授权仍保留）。write用Code、read用Ask，继承身份/taskId。缺失/非终态trace、未完成status或unknown验证都停止为unknown；取消保留cancelled，显式部分读取及其他共享isToolFailure结果为failed，只有已确认succeeded的完整输出才能供后步引用。摘要保留callId/status/verification与execution；部分读取只加错误码，不复制可能含正文的全部输出。写工具一旦交给callTool，后续抛错保守unknown，即使E_CANCELLED也不能证明尚未写入；这可能包含工具自身参数检查拒绝，不能仅凭错误码猜测副作用。调用前的取消/权限/引用错误是not-started，分别cancelled或failed；只读调用抛错仍按取消/失败分类。所有非成功立即停止，无补偿、无自动重放。
- `checkExpectation` 对显式安全工作区路径检查exists、contains或sha256；至少要有一个条件。读文件走8 MiB边界。工具运行后条件不满足记unknown，因为前面的副作用可能已发生。它和中央写入read-back都是时点证据，不是并发事务或通用目标完成证明。
- 最终succeeded仅说明声明的步骤/条件通过，绝不代表任意自然语言业务目标已经验收。取消只能阻止后续步骤，不能撤回已完成步骤；若最后一步已取得可靠成功与所需核验，仍可succeeded且cancelRequested=true。

## operations.js 与页面协作

- `api(path,method,body,signal)`只访问同源/api，HTTP错误及顶层ok/success:false均拒绝；独立controller/onAbort衔接父取消，期限覆盖fetch和JSON读取，普通请求10秒、批准70秒（服务端60秒只是取消信号预算），HTTP接入登记/stdio启动40秒以容纳后端30秒初始化。finally清计时器/监听器；中止HTTP不是撤销服务端操作，也不是强制终止不配合取消的handler。没有浏览器localhost跨服务调用。
- `action`执行回调，明确false时不继续刷新；异常只显示错误，其余才refreshOperations。`button`用textContent建按钮，默认走action；refresh=false用于自管确认/刷新的接入移除，防止重复刷新。`invalidateReview(message)`递增reviewGeneration、abort旧详情GET，并立即清掉旧控件/替换正文；预览草稿和提交新审批也走此屏障。
- `review(id)`读取完整请求，只有当前代次且未中断、requestId精确匹配、合法状态和对象input才可发布；以textContent展示，不执行外部文本。待批提供批准，待批/运行中提供拒绝或停止。失败没有旧按钮可沿用，旧响应和旧失败不能覆盖新审阅；finally回收当前读取控制器。
- `actOnReview(id,ticket,operation)`绑定已展示的ID与代次；批准需confirm，发送前消费审阅，使双击/已脱离DOM的旧按钮失效。POST返回后仅当前代次重新读取同一ID；切去其它审阅时旧批准/停止回包不能拉回旧对象。丢响应/超时显示未确认、保留ID供查询，不自动再次批准。批准在途若要停止，须从列表重新读取该请求，看到running后请求停止；取消不撤回副作用。
- `refreshOperationList`与`refreshCheckpoints`各有独立列表代次，开始先清旧列表控件，校验完整数组/ID/状态及重复项后才整批发布；HTTP/JSON/结构错误清掉该区旧列表并显示失败，迟到回包不覆盖新状态。列表按钮也绑定该次代次，脱离DOM的旧按钮不能再操作。`refreshOperations`用Promise.all并行等待两区各自处理，不让检查点失败阻断审批区显示；返回两区是否都成功，不保存令牌/结果到localStorage。列表代次不是取消网络、后端锁或跨页面事务。`initOperations`绑定接入、预览、提交、刷新和Bridge入口；刷新按钮直接调用对应loader，避免action回调刷新后又自动刷新一次。工作流预览先失效旧控件，只有当前回包展示；提交用workflowSubmitting挡在途重复，不再连点产生多个requestKey。每次明确的新提交仍是新UUID；响应丢失时先刷新列表核对，不能靠换key重放，当前内存去重不是重启后的永久保证。坏JSON在POST前提示未提交；已POST但未确认则单独提示未知。
- HTTP登记捕获表单快照，在实际发送时只清仍与该快照相同的令牌，保留等待中编辑的新草稿。公网复选框默认关闭，确认告知初始化/可选凭据及批准参数会离开本机，提交带当前工作区/hostInstanceId。app.js导入模块，bind初始化，bridge.js轮询快照更新待批数量；刷新不自动批准。stdio与检查点的独立流程见下节，不因本批审批修复认证全部接入/UI。

## REST 与工具入口

所有 /api/operations、/api/external、/api/workflows 路由仍受入口 rejectUnlessLocalControl + rejectCrossSiteApi 限制，不把管理权限给远程MCP。POST批准需confirm:true；拒绝/取消不能伪装批准。operationApi只做统一JSON成功/400错误封装。tools/index.js新增external_servers、external_request、operation_result、workflow_preview、workflow_request，中央包装产生的taskId传给handler；waiting-approval在调用追踪中是accepted，不是任务成功。operationId用于关联审批记录；子工具追踪不增加MCP RPC计数，二者不要混淆。

## 验证与限制

`approvedOperations.test.js` 使用临时目录和真实HTTP MCP夹具，验证握手/发现、无批准零调用、Ask拒绝、远程会话归属、重复批准只一次、拒绝后不执行、移除服务器不执行、工作流批准前不写、写后验证、条件失败停止、引用原型屏障、SSE和响应超限；实际悬挂HTTP响应在取消后标unknown，重复批准不重放。夹具另让第三方tools/call分别返回无isError但ok:false，以及只以verification.state=unknown表达的不确定效果；前者要求终态failed，后者要求宿主覆盖验证说明后仍为unknown/ok:false，两者都保留原结果且重批不调用第二次。outcome-fixture及outcomes表覆盖失败/非零退出/超时/取消/未知/成功，还包括未完成状态、trace未知和null，验证原结果保留与终态不重放；非布尔confirm不执行，throw-after-effect真实写盘后抛E_FORBIDDEN必须unknown。retention-fixture控制Date.now，证明临近待批期限完成后仍从finishedAt保留完整15分钟、旧createdAt期限不会立即删结果，并证明迟到cancel只能观察expired而不能改成denied。`operatorQueueCapacity.test.js`再填满40条终态，证明第一条仍可查询、原key仍只执行一次、新key明确拒绝，并在15分钟后恢复容量。不是持久队列或第三方厂商兼容性认证。

`tests/workbench.browser.js` 使用真实Chromium点击工作流预览/提交/确认，检查批准前文件不存在、批准后真实内容；同时仍检查Help、MCP写入、断WS轮询和重载。运行：`npm test --prefix webagent-core/agent-host`；`npm run test:browser --prefix webagent-core/agent-host`（先安装Playwright Chromium）。11.3协作说明已由用户确认关闭；不能用Linux夹具或CI替代手机到真实Windows机器的人工验收。

## 文件前置条件：把检查放在副作用之前

`validateCondition(condition,label)`供before和expect复用，严格要求对象、非空字面path，至少有exists/contains/sha256之一；拒绝null、数组、未知键、非布尔exists、超过2000字符/非字符串contains及非64位小写十六进制sha256。exists:false若再带contains/sha256属于不可能同时成立的合同，提交前直接拒绝。definition顶层只接受steps，step只接受id/tool/arguments/before/expect；拼错字段不再被静默忽略。validate仍不访问磁盘或推断条件会通过；validateReferences只消除结构上必定失败/危险的步骤引用，实际字段是否存在仍在执行到该步骤时按已取得输出核对。

可选`step.before`在批准执行后、**该步骤调用工具之前**，通过已有checkExpectation和工作区路径约束读取/检查。失败返回failed、E_PRECONDITION、execution=not-started并停止后续步骤；当前步骤没有调用工具，不记为执行后unknown。若先前步骤已有副作用则保留，结果明确提醒，不自动回滚或重试。原expect仍在工具执行之后检查，失败仍为unknown。

preview新增writeChecks，逐个写步骤列出explicit-precondition/tool-hash/unguarded，完整条件仍在steps内供审阅。explicit-precondition不保证检查的就是写入目标，必须核对path和具体条件；contains不是版本hash。没有before的旧工作流兼容，不虚称自动获得版本保护。原生write_file/apply_patch的expectedHash检查不被代替或绕过。

这些是时点检查，不是文件锁或多步骤事务；检查与工具调用之间仍可能有并发变化。现有文件修改应同时使用工具expectedHash，前置exists:false用于明确创建意图，但不承诺恶意并发改盘下的原子独占创建。

### workflowPreconditions.test.js
writeStep构建显式写入夹具；main在隔离工作区验证预览不修改、提交后输入不可变、批准前文件变化拒绝且后续不执行、恢复旧内容后重复批准仍不重放、正确hash成功、先前写入保留、越界路径拒绝、顶层/步骤/前后条件严格schema、拼错字段及exists:false与读取条件矛盾组合拒绝。新增真实双路径read_files先取得一个成功项和一个missing/error，要求该步failed/E_PARTIAL_READ且后续文件零创建。另外在真实file_written订阅中故意抛错：磁盘确已写入后，无论普通错误或E_CANCELLED，都unknown/dispatched，后步不执行、重批不重放。两步间取消保留第一步成功，第二步cancelled/not-started；最后一步已核验成功则succeeded且保留cancelRequested。临时替换tools.callTool验证null/accepted/running/验证unknown不得启动后步，finally恢复函数；其它断言仍是真实文件IO。最终还原配置并清理临时目录。

## stdio MCP：程序启动与工具调用是两次不同的授权

### 使用与边界
本机工具接入页新增JSON启动配置→只预览→本机确认启动。HTTP旧入口不变；远程MCP没有启动配置/批准工具，仍只能列已登记服务器、external_request、等待本机批准、operation_result取回。同样最多8个服务器，启动与工具发现共30秒；不会自动安装npx/uvx包、自动重启或自动重放。

**程序启动本身会执行第三方代码，握手不是只读安全操作。**该程序拥有当前OS用户权限，包括工作区外文件、网络及本机控制面。按工具审批不是对恶意本机进程的隔离。环境过滤、hash和Job Object均不是OS沙箱；依赖代码、动态导入、文件竞态仍由操作者信任/审阅负责。

### stdioLaunch.js：只读审阅与一次性令牌

### stdioTransport.js：有界JSON行协议

`open(launch,onStopped)`以shell:false启动产品自己的监督器，不把第三方参数拼成Shell命令。POSIX用当前Node+stdioSupervisor.js，建立新进程组；Windows用系统Windows PowerShell+固定stdioBridge.ps1。环境只带经审阅的允许值及内部启动说明；说明不包含env值，目标程序前移除内部变量。活进程集合live负责关闭。

- `send`将JSON-RPC编码为UTF8单行，单条输入最多32KiB、stdin缓冲最多256KiB；写入失败停止整个传输。
- `frame`严格UTF8/JSON-RPC对象，每进程最多4096帧；匹配pending id后resolve/reject。不匹配响应/通知不驱动工具。服务器主动sampling/roots/elicitation等请求返回-32601，不代表授权；错误协议失败不重放。
- stdout data回调先按字节/换行切块，未完成一行最多256KiB，不用无限readline。stdout+stderr累计8MiB；stderr额外1MiB上限，只计数、不保留正文。超限/畸形/非UTF8停止进程；这是进程生命周期总量，长会话到限也会停止，需本机明确重审启动，不自动重连。
- `request`最多8个并发在途请求；每个30秒，父Abort/超时触发`stop`，使整个stdio进程及其他在途请求失败。notification仅写入，不等待RPC响应；初始化总截止时间仍由externalClient控制。
- `settle`清计时器、父监听与pending，然后完成Promise；`stop`幂等拒绝全部pending、销毁stdin、杀监督器/进程组并通知状态；`finish`在error/close收尾、移出live并完成closed Promise；`status`只给PID、状态、计数和固定stopReason，不给stderr/凭据。
- `closeAll`停止并等待所有受管stdio传输；process exit钩子做同步终止尝试。它不负责整个宿主其他模块的事务式排空。

### stdioSupervisor.js（POSIX）
独立监督进程读内部启动说明，删除说明环境变量，校验实际父PID；以stdio:inherit和shell:false启动目标，自己不读写协议内容。目标exit/error或SIGTERM/SIGINT调用`terminate`杀整个本进程组；每500ms检查父PID变化，宿主被SIGKILL时也回收普通同组子孙。主动setsid/脱离组的恶意代码可能逃离，**不是Linux容器/namespace隔离**。启动异常不降级为裸执行。

### stdioBridge.ps1 与 stdioBridge.cs（Windows）
stdioBridge.ps1用NoProfile/NonInteractive固定产品脚本读取内部JSON后移除变量，Add-Type同时编译已有commandJob.cs和stdioBridge.cs；失败只输出固定错误到stderr并退出125，无无保护fallback。

WebAgentStdioBridge的`Quote(value)`按Windows CRT规则处理空字符串、空格、引号及末尾反斜杠；不是PowerShell字符串插值。`Run(program,args,cwd,parentPid,envKeys)`先调用WebAgentCommandJob.Attach建立KILL_ON_JOB_CLOSE，再取得宿主Process句柄，后台Thread等宿主退出并结束监督器。只有这些保护成功才Process.Start第三方目标；UseShellExecute=false、明确WorkingDirectory，清空子进程环境后仅复制审阅的envKeys。三条BaseStream以二进制复制stdin/stdout/stderr；`Pump`为每个方向单独启动后台Thread，同步Read/Write后Flush，避免任一流的异步实现/初始化阻塞其他方向启动，以及小包停留在缓冲区。避免PowerShell文本编码损坏中文/emoji；等待目标退出，每条输出泵最多再等2秒，返回退出码，监督器退出关闭Job并终止后代。目标进程非零退出仍不会自动重启。

这利用Windows内置.NET/PowerShell，不下载编译器或第三方程序；源码/命令保护失效则拒绝启动。Job控制进程树生命周期，不限制已信任代码读取文件、联网或访问本机API。

### externalClient.js 接入变更
`startStdio`仅消费已确认预览，构造受管传输后交`establish`；后者复用initialize/initialized/有界分页发现与总截止时间。`rpc`在stdio时走传输request，HTTP仍走原回环fetch。停止后status=stopped、禁止新请求；移除不暗中登记新服务器，`remove`同步撤登记并发起终止，stopping:true不是closed；`closeAll`等传输结束且清预览。stdioMcp回归在取消清理时先断言移除返回removed:true/stopping:true，再由closeAll和真实PID检查证明最终退出，不把移除回包当退出证明。list对工具及本机启动元数据深拷贝；远程不含程序路径/参数/env/PID。仍经原审批队列执行工具，取消后结果可能unknown，重复批准不重放。

## connectionCheck：连接证据而非模型身份
`digest`对固定字符串做SHA-256；`prune`按120秒到期回收所有状态，无后台计时器。`observation`只接受五字段/2048字节内的最小格式，origin固定https://arena.ai、pageKind枚举、64位hex路径摘要、十分钟以内且未来不超过30秒的时间，拒绝额外token/任意原始dump；时间与来源均是自报，不是认证。
`create`清理后检查8项上限，生成32字节随机challenge、16字节checkId，只保留challengeHash，返回一次明文挑战供本机操作者转交。按固定字段顺序生成observationHash，避免输入字段顺序差异。`view`返回克隆元数据/收据/主机身份，不返回保存的挑战hash。`inspect`按本机checkId取记录，过期/未知明确失败。
`confirm`要求remote且callerKey为已初始化peer会话，严格单一challenge字段，匹配后先改变状态/删除hash，不能重复或跨会话二次消费。收据包含时间与callerKey的SHA-256而非原始会话键；返回modelIdentityVerified=false/permissionsChanged=false。挑战可转交，不证明浏览器来源/人类账户/实际模型。`clear`清空核对记录，不注销MCP、不改审批权限。模块只有内存状态，未挂全局记忆或自动恢复。
本机POST/GET/DELETE /api/connection-checks由现有localControl及跨站策略守护；远程工具只可confirm，不能创建/查询别人原始页面摘要。工具trace照常生成；事件脱敏键新增challenge。

界面operations.initOperations内的`connectionAction`负责把创建/查询/清除的异常显示到连接结果区，清空输入后才解析；checkGeneration避免过期成功响应覆盖新请求。connectionCheck.test的`node`只构造隔离DOM对象，用于模拟可选用户脚本点击生成；没有启动原型、浏览器账号或真实平台服务。MCP server对confirm_connection/external_request/workflow_request和board写操作统一先检查实际绑定的HTTP会话，不让clientInfo里伪造peer:前缀绕过会话门槛。

测试DOM桩的append/setAttribute/focus/select仅为空实现以接受脚本DOM操作；getElementById固定返回null模拟首次安装，createElement使用node收集节点，body.append不挂真实页面；fetch桩直接抛错确保不联网。onclick仅由测试显式调用，验证未点击无摘要，点击后不含原始路径/query/hash中的秘密。

connectionAction为每次操作分配递增generation，成功、清除回执和错误都只更新当前generation；旧网络响应不能覆盖较新操作的页面状态。它不是服务器事务锁，交错创建/清除仍以实际查询结果为准。

页面摘要pageDigest必须是字符串，不能利用正则隐式转换把单元素数组当字符串接收；用户脚本在点击时一次抓取origin/pathname/observedAt后再异步计算hash，避免SPA切页导致摘要和页面类型来自两次读取。

会话门槛按resolveToolName规范化名称（含去首尾空格）判定，并把实际initializedSession布尔值传入confirm再校验；仅自报peer:前缀、工具名加空格都不能伪装已初始化。该布尔值由服务端会话表产生，不取请求参数。

## 源码根evidence-check/workflow.json示例迁移

.webagent/skills/evidence-check/workflow.json现放在默认源码根工作区，不再放在计算器里。唯一顶层steps数组依次含host、workspace两步；每步id用于结果定位，tool分别为ping和workspace_info，arguments都是空对象。不含写操作或自动执行入口；读取Skill、预览和本机审批仍分开。这是固定声明式样例，不表示工具自报就是主机/模型的绝对证明。验证时从目标工作区加载、预览，确认审批前无执行事件；其他项目不会越界自动扫描本仓库Skills。

## 审批与新模式/权限的合作

submit按options.remote检查Bridge或Chat；approve在改变running前取得对应模式租约，finally释放。在途请求/审批阻止切换或保存权限，等待审批阻止切换但允许撤权。远端批准前复查：workflow_request需Read，其他不透明操作需四项；工作流实际步骤继续调用共享callTool检查Read/Edit，不能审批一次便永久绕过策略。工作流在调用callTool前再显式复查步骤权限；这种调用前E_FORBIDDEN保存failed/not-started，其他已派发写入或handler抛错保守unknown（不按同名错误码推断未执行）；所有终态仍不重放。验证executionControl覆盖待批撤权和handler未调用。

本机人工提交审批沿用当前工作模式（idle时归Chat），任务保存workMode供批准时复核；远端始终Bridge。人工审批不是启动另一个Chat模型，所以不因本机操作者使用Bridge区审批面板就强制跨模式。远端权限仅检查remote任务，不限制本机人工编辑权限。

公网逐函数/DNS/TLS/测试边界见[公网出站详解](../mcp/公网出站详解.md)。回环、显式公网HTTPS与stdio是三个传输入口，不把新增传输当作免审批。

### operations.js的跨文件检查点入口

- `checkpointBinding`从当前status取workspaceRoot/hostInstanceId；`sameCheckpointBinding`要求非空且仍与当前status一致，在展示预览、点击恢复和发布恢复结果前检查。服务端真实绑定/路径/hash守门仍必须保留，浏览器检查不是认证替代。
- `validCheckpointRecord`核对非空ID、ready/running/consumed、1–12条非空且不重复路径；`validCheckpointPreview`另核对所请求ID、ready、非空previewId、逐文件与paths完整对应、64位小写十六进制hash字符串、changed与hash差异一致、非空diff字符串。它验证响应合同，不独立证明diff正文忠实或磁盘安全。
- `reviewCheckpoint`先递增checkpointGeneration、清旧控件并显示读取中；只有当前代次、绑定和完整预览通过才显示恢复按钮。预览失败/错误ID/缺失差异没有可沿用的按钮，过期回包和错误不覆盖新审阅。恢复前confirm，先消费代次再POST，绑定已变化时零恢复请求；双击旧按钮不能重放。
- `validCheckpointRestore`核对同一ID、consumed、路径清单/顺序、逐文件状态；succeeded必须success:true且每个changed文件restored、无变化文件unchanged。failed/unknown必须success:false，unknown还须有未知文件；不会因为HTTP200或孤立success:true就确认全部完成。验证后的原始部分失败/成功照实展示。无效/丢失响应只显示含检查点ID的未取得可信结果，提示刷新与核对磁盘，不自动重放；旧结果不覆盖新审阅。
- `refreshCheckpoints`只显示元数据和逐文件结果，ready才给预览、running不给移除。列表代次与预览代次独立：刷新元数据不自动重新预览或恢复；移除时作废预览，响应必须removed:true。创建单独走createCheckpoint，见下项；本页其它接入写请求的确认/幂等边界仍需逐项审查。
- `refreshOperations`并行刷新两区，各自失败可见；恢复结果正文不会因列表刷新失败被改成成功或抹掉。检查点不是工作流自动补偿，完整后端状态机见[编辑回退详解](编辑回退详解.md)。

### createCheckpoint：创建确认与后续列表读取分开

`createCheckpoint`由initOperations直接绑定创建按钮，不再借action默认刷新两类列表。checkpointCreating先占在途标志并禁按钮，程序化重复调用也返回false；捕获trim/去空行后的paths和checkpointBinding快照。清旧恢复控件、递增checkpointGeneration，避免创建状态正文旁还留着另一个恢复授权。要求当前非空绑定、1–12条字面不重复路径及每条≤2048字符；本地检查不读取磁盘、不能识别符号链接别名，真正的文件/规范路径/预算校验仍在后端。

confirm明确这是新的内存检查点，不是永久备份，上次未知应先查列表。取消或本地校验失败是未发送；确认后再次核对绑定，才POST confirmed:true。沿用api的10秒fetch/正文期限，不自动重试。返回必须当前代次、绑定仍一致、validCheckpointRecord通过、ready、result:null且规范路径条数等于提交数才展示创建确认。返回paths由服务端规范化，可能与./别名的输入拼写不同；这里只验元数据/条数并展示规范路径，不独立证明服务器读取内容或强行要求原始路径字符串相等。

POST失败、超时、坏JSON/形状或绑定已变显示“创建未确认，可能已经建立”，保留输入并提示刷新原列表；不因失败再创建。确认后仅刷新检查点列表一次，不自动恢复/刷新其它审批。列表失败或被新刷新取代时仍保留已确认ID/元数据，单独note提醒不重建；后续绑定变化则提示到原工作区核对，不让创建确认变成当前工作区授权。新的预览/创建代次已取代本次时，迟到成功或失败都不改新正文。finally释放在途标志和按钮，始终不清路径草稿。

这是本页面在途互斥，不是requestKey去重、跨标签页锁或断网后的exactly-once。创建确认只证明服务端回报该内存快照；每文件仍是分别读取时点，非多文件原子快照。用户之后明确确认新的创建仍会建立新记录；上次未知先核对，不用“重试”生成另一个时间点的备份。检查点原有8条/15分钟/内存边界未改变。

### HTTP接入登记与移除：确认、未知与停止分开

`externalHttpEndpoint(value,publicHttps)`仅做前端URL/2048字符、凭据/query/fragment及回环HTTP(S)/显式公网HTTPS形式检查；把localhost规范为127.0.0.1供结果比对，不访问目标。后端仍负责本机端口/隧道排除、公网DNS/固定连接/TLS等安全决策，本函数不是SSRF认证。

`addExternalServer`通过externalMutation登记，捕获名称/地址/令牌/公网选项/绑定；校验令牌4096字符和CR/LF，公网要求当前绑定、明确外发confirm，确认后再核对绑定。取消/前端拒绝未发送且不清令牌；真正发送只清仍相同的旧令牌。validExternalRegistration要求非空serverId、http/discovered、端点等于本次规范地址、publicHttps一致及≤100条唯一工具名/对象inputSchema/requiresApproval:true。空工具列表可成立，不等于已执行工具或验证效果；不显示整个返回对象或异常正文作成功证明。

`externalMutation(label,callback,key)`以externalPending做页内互斥：登记用register键，移除用各自remove:ID键。登记在途禁登记按钮，同一ID移除在途也不能经刷新后的新按钮重复发送；**允许移除正在connecting的接入**，不让一个全局锁阻断停止请求。callback经send发请求，记录是否已派发；登记沿用40秒、移除10秒完整HTTP/JSON期限。前端拒绝提示未发送；派发后错误/坏合同仅提示未确认、查原列表，不重放。固定提示不回显该写请求的服务端/解析异常，避免不可信服务把Bearer值反射到操作提示；不是对整个UI/所有日志的秘密不泄漏认证。

externalMutationGeneration决定独立ops-external-result区域只展示最新接入操作；旧成功/失败不能覆盖较新移除结果。确认后仅刷新接入/审批列表一次，列表错误/刷新被取代不抹掉已确认ID及停止不确定性。finally只释放自己的key，并按是否仍有登记恢复按钮。其它并行操作的较晚完成需从列表核对；不是跨标签页、后端去重、持久事务或所有stdio操作的共享锁。

`removeExternalServer(id)`要求removed严格true；removed:false/缺失/异常不是本次移除确认。可选stopping只能为true，显示“登记记录已移除，已请求停止stdio，尚未确认退出”；无该字段则明确仅请求中止宿主连接，不代表外部HTTP服务停止或效果撤回。refreshOperationList的removeButton绑定列表代次和removalUsed，发送前消费/禁用按钮；未知结果必须先刷新再人工决定，不沿用旧按钮重发。列表刷新不会清除独立操作结果。stdio预览/启动的前端消费已在第37组补复核，见上面的UI段；不因这些回归宣称OS隔离或启动授权全链都已审完。
