# 受控外部工具与工作流：从提交到批准

这是有限能力的 HTTP MCP 客户端和固定工作流，不是任意插件执行器，也不是第二套持久化任务板。现有 taskId 串联工具调用；审批状态独立表达“尚未执行”。本指南覆盖 operatorQueue.js、externalClient.js、workflows.js、operations.js 和 approvedOperations.test.js。

## 用户怎么用

1. 在本机工作台打开 Bridge，点“工具接入与审批”。本页不对隧道公开。
2. 只有已经自行启动并信任的回环 HTTP(S) MCP 服务才能登记。输入名称、地址和可选令牌，点击登记。此时真实发送 initialize、notifications/initialized、tools/list；不是只保存备注。旧“外部 MCP 地址备注”仍只是备注，不自动迁移或授权。
3. 外部 Agent 先建立并保留 MCP 会话，再调用 external_servers 查元数据；Code 模式调用 external_request，传 serverId、tool、arguments、稳定的 requestKey。Ask/Plan 只能查看，不能提交执行。
4. 收到 waiting-approval 后应停止，通知本机用户审阅；不要生成新 key 重复提交。用户刷新请求列表、选中请求，核对完整参数，点击批准并确认对话框。登记过服务器不代表每个工具自动获准。
5. 用 operation_result 查同一个 requestId 的结果。external-reported 只表示外部服务自报，并非独立验证副作用。
6. 工作流文本框可先使用默认 ping 示例：只预览→提交新审批→选中并批准。预览不执行任何步骤。写文件示例应使用临时工作区；不把测试输出当成自己的 Windows 验收。

## operatorQueue.js：进程内审批状态机

- `register` 把固定 kind 对应到宿主执行函数，外部工具不能登记任意函数。`handlers`、`jobs` 都是内存 Map。
- `clone` 做 JSON 深拷贝，防止提交者改动已展示的输入。`submit` 先 checkCancelled，再清理旧记录、校验 kind/requestKey/32 KiB 输入；摘要把 kind 和输入序列化一起哈希。同一 owner/key/摘要返回原请求，输入不同则冲突。
- `owner` 对 remote 要求 peer: 会话标识。这个值来自服务端会话，不把用户传入 taskId 当权限。`result` 检查归属，别的会话无法读取；`inspect` 和 `list` 只供本机管理路由，前者含完整输入结果，后者只有元信息。
- `publicJob` 输出 requestId、taskId、状态、时间、下一步提示；详情按需克隆。不会输出 owner/令牌。输入和结果可含用户文件正文，保留在内存并明确展示给本机操作者，不写调用追踪日志。
- `prune` 把超过15分钟的待批请求标记过期，淘汰终态；最多20个未完成，终态按约40条总量修剪。保留窗口是上限，不是持久承诺。淘汰或重启后相同 key 可能成为新请求，仍须重新批准，绝不能声称永久 exactly-once。
- `approve` 要求显式 true，只允许 waiting-approval→running，同一个运行中或终态记录重复批准不会再执行。并发最多4个，60秒 AbortController 定时器。通过 runWithSignal / withTask 继承取消和已有 taskId；结果最多256 KiB。输出失败/未知/取消分别落状态，异常保守记 unknown。
- `cancel` 将待批请求拒绝；运行中只发 abort，不保证外部服务器撤回副作用。计时器也不是事务回滚。执行后 finally 清计时器和控制器，不自动重试。

## externalClient.js：真实但有意收窄的 MCP 客户端

- `endpoint` 仅接收2048字符以内 HTTP(S)，限定127.0.0.1、::1、localhost，localhost固定改成127.0.0.1以免依赖DNS；拒绝用户信息、查询串、片段、本宿主已知端口。不支持互联网服务、stdio启动、npx/uvx安装或子进程环境透传。
- `add` 最多登记8个服务；Bearer token限制长度与换行，只留内存。服务器先进入connecting；三段握手和发现成功才是discovered。协议允许2024-11-05、2025-03-26、2025-06-18，不支持工具分页；最多100个工具，拒绝非法/重复工具名，描述截短。注册失败调用 `remove` 清理。
- `rpc` 每次随机JSON-RPC id，POST带内容协商、内存会话和协议头。`abort` 连接父级取消和30秒计时器；禁止重定向，HTTP异常不重试。finally中止剩余响应、清计时器、移除监听器及控制器。初始化请求本身确实会访问服务，不保证不可信服务收到握手后没有内部副作用。
- `responseMessage` 用流式reader累计字节，不先无限读入全文。最多256 KiB，支持JSON和SSE的data帧；只取对应id；无匹配、坏JSON、超限会失败，finally取消reader。不是完整的服务器推送/采样/roots实现。
- `list` 只输出元数据，本机可见endpoint，远程不含endpoint/token/session；模式/描述是第三方不可信数据，不是授权规则。
- `request` 要求已发现serverId和工具名、对象参数，把不可变输入放审批队列，绝不调用工具。`execute` 仅由批准路径调用；服务器移除后明确未执行，不能悄悄改投另一个服务。外部调用返回失败或 external-reported，不伪造独立验证。`remove` 中止现有连接并删除注册。

## workflows.js：固定schema与受限数据流

- `validate` 限制32 KiB、1–12步、唯一字母开头ID，工具名只能属于READ/WRITE静态集合。允许读目录/文件/搜索/git状态等，以及write_file/apply_patch；禁止命令、删除、嵌套工作流和外部调用。拒绝retry字段，写路径与content/patch必须为字面字符串供审批。
- 参数中完整的 `$steps.read.hash` 可引用前序步骤字段。`resolveValues` 递归处理数组/对象，要求属性自有，禁止__proto__/prototype/constructor；不存在的引用失败，不拿undefined凑成功。写入路径/正文不能由上一步内容动态生成。前向引用预检查是保守规则，包含引用语法的字面正文也可能被拒绝。
- `preview` 只验证结构，返回完整步骤、reads-workspace或writes-workspace风险和约束；不会读取文件、检查工具实际参数全部语义或推断运行成功。`request` 再验证、提交，不执行。
- `execute` 批准后逐步调用现有callTool，不复制文件实现。write步骤用Code、read步骤用Ask，继承请求身份/taskId；读取输出只在本次执行供引用。步骤摘要保留callId/status/verification，不把全部读取内容放进追踪。工具失败立刻停止，无补偿、无自动重放。
- `checkExpectation` 对显式安全工作区路径检查exists、contains或sha256；至少要有一个条件。读文件走8 MiB边界。工具运行后条件不满足记unknown，因为前面的副作用可能已发生。它和中央写入read-back都是时点证据，不是并发事务或通用目标完成证明。
- 最终succeeded仅说明声明的步骤/条件通过，绝不代表任意自然语言业务目标已经验收。取消只能阻止后续步骤，不能撤回已完成步骤。

## operations.js 与页面协作

`api` 用同源/api和JSON访问本机路由，拒绝HTTP错误；没有浏览器localhost跨服务调用。`action` 汇总错误并刷新列表；`button` 用textContent创建按钮；`review` 读取完整请求，以textContent展示（外部描述不能注入HTML），只为待批状态提供批准按钮，confirm后POST confirm:true；运行中可请求取消。`refreshOperations` 重建服务器和请求列表，不保存令牌或结果到localStorage；`initOperations` 绑定接入、预览、提交、刷新和Bridge入口。输入令牌发送时清空输入框。app.js导入模块，bind调用初始化，bridge.js轮询快照更新待批数量。刷新不会自动批准，工作流提交按钮明确创建新请求。

## REST 与工具入口

所有 /api/operations、/api/external、/api/workflows 路由仍受入口 rejectUnlessLocalControl + rejectCrossSiteApi 限制，不把管理权限给远程MCP。POST批准需confirm:true；拒绝/取消不能伪装批准。operationApi只做统一JSON成功/400错误封装。tools/index.js新增external_servers、external_request、operation_result、workflow_preview、workflow_request，中央包装产生的taskId传给handler；waiting-approval在调用追踪中是accepted，不是任务成功。operationId用于关联审批记录；子工具追踪不增加MCP RPC计数，二者不要混淆。

## 验证与限制

`approvedOperations.test.js` 使用临时目录和真实HTTP MCP夹具，验证握手/发现、无批准零调用、Ask拒绝、远程会话归属、重复批准只一次、拒绝后不执行、移除服务器不执行、工作流批准前不写、写后验证、条件失败停止、引用原型屏障、SSE和响应超限；实际悬挂HTTP响应在取消后标unknown，重复批准不重放。不是第三方厂商兼容性认证。

`tests/workbench.browser.js` 使用真实Chromium点击工作流预览/提交/确认，检查批准前文件不存在、批准后真实内容；同时仍检查Help、MCP写入、断WS轮询和重载。运行：`npm test --prefix webagent-core/agent-host`；`npm run test:browser --prefix webagent-core/agent-host`（先安装Playwright Chromium）。用户Windows第11.3仍未完成；不能用Linux夹具或CI替代手机到真实Windows机器的人工验收。
