# 文件操作与搜索：函数、递归和 Worker 生命周期

## 职责与流程

本文展开[fileOps.js](fileOps.js)、[findFiles.js](findFiles.js)、[searchWorker.js](searchWorker.js)。共同依赖路径/敏感检查；读窗口限制、扫描预算与输出预算是不同层。

## 1. 读取与修改函数

| 函数 | 输入/输出 | 执行顺序与关键失败 |
|---|---|---|
| readFiles({filePath,paths,offset=1,limit=400}={}) | 单个结果或{files} | 合并paths与filePath（不去重）；无路径报错，超过20拒绝；单项直接readFile，多项map逐项catch为error，不使整批拒绝 |
| readFile({filePath,offset=1,limit=400}) | 带行号内容/hash/总行数 | 安全路径、存在且非目录、8MiB有界全文读取；hash全文，再切行窗口并map加1基行号；广播file_read、rememberHash。窗口小不代表只读这些字节 |
| deleteFile(opts={}) | Promise | withWriteLock后闭包调用deleteFileBody |
| deleteFileBody({filePath,confirm=false}) | success/路径/类型 | 拒绝工作区根、要求confirm、必须存在；目录只允许空目录，文件unlink；广播后清两种路径key的hash。没有验证“之前确实list过”，提示语不等于额外记录 |
| renameFile(opts={}) | Promise | 从from/filePath、to/dest取两路径，双锁后renameFileBody |
| renameFileBody({from,to,filePath,dest}) | success/from/to | 两端安全路径、源存在、目标不存在；建父目录再rename，广播；不在这里迁移/清理所有旧hash缓存，不是跨磁盘copy回退 |
| writeFile(opts={}) | Promise | 单路径锁后writeFileBody |
| writeFileBody({filePath,content,expectedHash,confirmOverwrite=false,confirm_overwrite=false,createOnly=false}) | success/hash/size | 字符串≤8MiB；createOnly先做友好存在检查，最终仍以atomicWriteText(exclusive:true)的同目录临时文件+原子硬链接竞争目标，EEXIST统一映射E_FILE_EXISTS，不自动覆盖。该字段已登记进write_file schema并供工作台新建使用。有expectedHash但目标已删拒绝重建。已有文件读全文/hash，显式确认或匹配expectedHash或匹配sessionHash才可覆盖；即使已确认，显式旧hash仍拒绝。建目录、原子写、广播、记hash |

readBoundedText拒绝非法UTF-8，保留合法BOM/CRLF及原字节hash；写前遇到损坏编码同样拒绝，不因confirmOverwrite绕过。搜索目录逐文件失败仍按原catch策略跳过，不保证返回每个编码错误。readFile未统一将offset/limit转合法整数，调用者应提交schema约定的数字；size是字符串length，不是UTF8字节。删除/改名/写入后若广播失败不能推断磁盘未动。只有明确createOnly的新建走exclusive；普通write仍用rename并允许符合覆盖合同的替换，不能把createOnly保证套到所有写入。exclusive依赖同文件系统硬链接原语，跨平台实际文件系统兼容性仍由测试矩阵和实机核对。

## 2. listDir({dirPath='.',recursive=false,maxDepth=3})

安全路径并要求存在；深度Number或3钳到1–8。内部 **scan(currentPath,currentDepth)** 使用opendir/readSync，finally关闭目录句柄；全树累计访问超过1000项标truncated，跳过越界、软链接、isHidden；目录按需递归，普通文件stat给size/mtime。扫描完成后经 **sortItems(items)** 排序再返回dirPath/items/truncated。

**sortItems(items)**（F70，外部复审P3-18）：readdir顺序由文件系统决定（有的按哈希、有的按创建顺序），同一目录在不同调用/平台上次序不同，对模型和文件树都不友好。现目录在前、文件在后；名称用`Intl.Collator('en',{numeric:true,sensitivity:'base'})`比较（不区分大小写、数字感知：file2在file10之前），比较相等时再按码点定序保证稳定；递归作用于children。排序在扫描之后进行，1000项预算照样提前停止枚举；被截断时排的是已看到的条目，并由truncated如实标明。

达到maxDepth只是正常窗口，不一定标truncated；文件并发消失/权限异常可能抛出。不是全盘快照，也没有跳过所有错误的承诺。

## 3. 内容搜索所有函数

**isUnsafeRegex(src)**用三个启发式模式识别连续量词、嵌套量词、重复通配；不是证明正则线性复杂度，真正时间隔离靠Worker。

**grepFile(fullItemPath,pattern,matches,budget)**：stat，单文件>1.5MiB返回large，累计将超8MiB返回budget；先计入bytes再有界读，含NUL返回binary。逐行test，命中放相对路径/1基行号/trim后前400字符，并重置pattern.lastIndex；累计2000条后停止。不是每个匹配位置一条，只按行。

**scanSearch({query,searchPath='.',isRegex=false,caseSensitive=false,limit=20,cursor=0}={})**：非空query≤200字符；regex≤120并拒绝启发式危险形态；普通查询先转义正则；编译失败抛错。建立matches、扫描/跳过计数及字节预算。

内部 **noteSkip(kind)**更新large/binary或预算truncated；**searchInDir(dir)**递归枚举，跳越界/hidden/软链接，最多800文件、2000命中；目录读取错误跳过，单文件错误catch后继续，不逐一返回错误清单。文件模式只扫描一个文件。分页在本轮收集结果上slice，limit钳1–100，cursor下限0，返回totalMatches/matches/nextCursor/扫描统计。每次请求重新扫描，cursor不是稳定数据库快照；truncated与nextCursor含义不同。

**grepSearch(args={})**：检查取消，activeSearches≥4返回E_BUSY；启动Worker时传workspaceRoot/args并设64MiB老生代限制。构造失败立即退计数。内部 **finish(err,value)**只执行一次，清startupTimer/scanTimer、移除abort，发起worker.terminate并给其Promise挂finally，终止结算后才退activeSearches；本次请求立即resolve/reject，不等待终止确认。**abort()**产生E_CANCELLED；timeout产生E_TIMEOUT；message回调映射worker错误，error回调直接失败，exit而没结果亦失败。terminate拒绝被吞但finally仍释放计数。64MiB不是整进程所有内存上限。

**searchWorker.js顶层**：只在Worker中使用workerData/parentPort，先覆盖config.workspaceRoot并加载模块，发ready后用once等待父端start，才同步scanSearch；成功postMessage result，失败只传message/code，不传Error原型与stack。它没有独立函数声明，但整个入口流程必须理解；不要直接当普通CLI执行。

## 4. findFiles.js：按名称找文件

**globToRegExp(glob)**：缺省双星通配、转斜杠；转义正则特殊符号，处理双星目录、双星、单星和问号；首尾锚定。简化glob，不支持所有shell扩展。

**findFiles({glob='**/*',searchPath='.',maxResults=40}={})**安全根、存在检查、cap限1–200。内部 **walk(dir)**递归，目录读取错误跳过，全树最多访问10000项，跳越界/隐藏/软链接。对相对工作区路径或basename匹配；多于cap的下一次实际命中才truncated，不是恰好cap就判截断。显式根是文件时直接把路径加入，不再做glob匹配；目录遍历非目录项也不额外要求isFile，消费者不能泛称每项都已普通文件类型认证。

返回glob/searchPath/total/files/truncated，total是已返回数量，不是全树总命中。没有worker deadline，扫描预算与内容搜索不同。

## 5. 验证

npm test --prefix webagent-core/agent-host -- --filter=workspaceTools
npm test --prefix webagent-core/agent-host -- --filter=resourceBudget

重点检查批量读错误、覆盖旧hash、空目录删除、搜索上限/Worker取消。完整测试不等于所有外部文件系统竞争已覆盖；返回空结果也可能是跳过了不可读文件，而非确实没有匹配。

### 搜索启动/扫描预算拆分
旧grepSearch从构造Worker即计2秒，错误无法区分Windows冷启动/模块加载还是扫描耗时。现在searchWorker先加载config/fileOps并报告ready，再等父线程start才调用scanSearch。父线程最多给启动10秒；收到首个ready清启动timer，设独立2秒扫描timer后发start。重复ready不重置预算，结束后的消息不恢复结果。超时detail.phase标startup/scan；总等待上限现在约12秒，不再宣称总壁钟2秒。扫描字节/文件/结果数量与2秒计算上限都未放宽，仍无自动重试。

searchWorkerLifecycle.test的harness通过createRequire加载实际fileOps，只有worker_threads和时钟替换为桩；FakeWorker继承EventEmitter，constructor记录实例，postMessage记录start，terminate计数并返回Promise。setTimeout/clearTimeout管理可手动触发的timer，main验证启动前不扫描、10000/2000分阶段预算、重复ready不能延时、成功/超时清理、迟到结果不能覆盖失败。不声称已证明此前Windows失败的具体阶段。

生命周期夹具的require只替换worker_threads，其余请求交给定位到真实fileOps文件的fromFile，避免整套文件工具变成虚构实现。fake timer不等待真实10秒/2秒，但核对实际代码设置的两个限额；真实搜索另由patchEngine/resourceBudget回归覆盖。

覆盖未批准/STALE_FILE的retryHint改为停止、重读并核对新意图，不要求盲用错误中的currentHash重放。哈希仍返回作诊断，不是授权或无需阅读的版本凭证。未改写入/覆盖门禁。

R4诊断：grepSearch内trace(event,code)仅在WEBAGENT_DEBUG_PROCESS=1输出固定process lifecycle记录，字段为kind/event、PID/threadId、单调elapsedMs、online/ready、activeSearches和整数exitCode。不记录workspaceRoot、query/pattern或命中文本。online表示线程开始执行，不代表config/fileOps已加载；ready才表示worker已发就绪。记录created/online/ready/scan-start、cancel/timeout/error/result或failed、exit及释放计数后的released，terminate拒绝记录termination-error但沿用既有finally释放合同。10秒启动/2秒扫描/最多4 worker/64MiB限制均未改变，没有重试；新增诊断不证明历史Windows卡在具体模块。
