# 工具注册、参数别名与危险命令策略

## 职责与流程

[index.js](index.js)是共享工具入口，[normalize.js](normalize.js)兼容参数写法，[dangerous.js](dangerous.js)按显式策略检查命令。流程：取消检查 → 名称解析/注册查找 → 模式锁 → 参数正规化 → 远程限制/命令策略 → handler → 超时标记/软预算。

## 1. index.js全部函数与声明

**tool(def)**原样返回对象，方便声明，未校验schema。TOOLS每项name/aliases/description/mode/inputSchema/handler，hidden控制发现；顶层双循环把标准名及别名映射同定义。数量以当前TOOLS/getToolList及权限过滤为准，另有隐藏send_command_input；schema描述不是自动JSON Schema运行验证器。

| 工具组 | 路由到的实现/输入 | 权限与返回 |
|---|---|---|
| ping/workspace_info/get_capabilities | pingHost/workspaceInfo/getCapabilities，无主要参数 | Ask/Plan/Code；主机/环境/能力，不执行修复 |
| get_logs/get_task_status | maxLines或无参 | 日志摘要/任务状态，不是完整执行证据 |
| remember/recall/load_skill | text；limit/day；name | 三模式可用，remember确实写内部记忆；只读模式不等于没有任何内部状态写入 |
| list_directory/find_files/search_files/read_files | 目录/深度；glob/数量；query/分页；路径/行窗口 | 三模式，参数语义见文件搜索详解 |
| git_status/git_diff | 无参或filePath/staged/stat | 三模式，只读Git |
| peers_list/board_list/create/claim/update | 无参；title/note；id/owner；id/status/note | 三模式均可写任务元数据；状态所有权另由board检查 |
| apply_patch/write_file/delete_file/rename_file | 单文件补丁/hash；正文/hash/确认/createOnly；路径/确认；from/to | Code；写入handler箭头兼容两个确认字段并委托writeFile；createOnly要求目标原子不存在 |
| run_command/start_command | command/cwd/timeoutSec/confirm_dangerous | Code；等待或立即返回execId |
| get_command_output/cancel_command | execId/commandId/tail；execId | 前者三模式，后者Code；显式ID及缺省最近命令均绑定local/远程peer所有者 |
| send_command_input | execId/input | 隐藏、Code、本机PTY，远程无条件拒绝 |
| wait/report_progress/set_todos | ms；message/percentage/stepName；todos数组 | wait与todos三模式；progress仅Plan/Code |

**pingHost()**返回时间+session快照；**getLogs({maxLines=50}={},options={})**限1–200；本机读取最近宿主事件，远程最多扫描有界500条且只留sessionIdFor匹配的tool_execution起止记录，再从payload只保留LOG_KEEP白名单字段。返回count仍是请求上限n而非实际日志长度；**getCapabilities(_args,options={})**工具map留name/description/modes加会话；远程复用getToolList的当前ACL过滤，不再把tools/list已隐藏的禁用工具重新广告出来，也不真的调用工具；**getTaskStatus(_args,options)**把可信调用上下文交给getTaskState，只返回本机或当前远程peer的进度对象，in_progress给建议等待2秒及按百分比粗猜ETA，不是测得剩余时长。

**getToolList(currentMode=null,opts={})**两个filter限制模式及hidden，再map输出name/description/inputSchema；输出没有mode字段，不代表未按mode筛选。includeHidden仅用于明确内部调用。

**dispatchTool(name,args={},currentMode=null,opts={})**是执行主体，外层callTool负责追踪/最终预算：checkCancelled；resolveToolName后查注册，未知E_UNKNOWN_CMD附公开名字；有currentMode且不被允许→E_BAD_ARGS。无mode不会自动变只读。normalizeToolArgs；remote拒绝stdin输入，run/start调用assertCommandAllowed；远程timeout限制最高60秒、非法默认30。await handler(input,opts)，isTimeout时补E_TIMEOUT/suggestedWaitMs=0，交verifyMutation读回核验；外层callTool完成追踪、附trace后clipJson返回，异常也附追踪而不伪装成功。

不会统一把业务ok:false变抛错；MCP/Chat/REST包装各自决定成功语义。工具schema的required并非在这里统一执行，最后由handler实际检查，不能仅据JSON字段声明断言所有坏输入都被拒绝。

## 2. normalize.js全部函数

**isTruthy(v)**：true、数字1或trim后true/yes/1字符串为真，其他false；不是普通Boolean转换。**firstDefined(obj,keys)**按顺序取非null且非空字符串，保留0/false。**resolveToolName(name)**trim，优先精确别名再小写别名，未知保留原字符串；不是所有标准工具名均自动转小写。

**normalizeToolArgs(toolName,args)**：仅非数组对象作为src，浅拷贝；snake_case补camelCase但不覆盖已有字段。按工具归并路径、目录、查询、glob、补丁、hash、正文、rename两端、command/timeout、execId等别名。apply_patch.dryRun、确认标志、recursive、isRegex/caseSensitive用isTruthy；不是所有number字段都转换或所有unknown字段都删除。write_file额外同步confirmOverwrite。空正文原始content仍可保留，但firstDefined不会从空text别名产生正文。

TOOL_NAME_ALIASES将常见bash/shell/cat/read/ls/grep/glob/edit_file/write/rm/mv等映射到标准工具，**别名并不赋予绕过模式/确认的权限**；解析后同一个工具定义仍受检查。

**覆盖范围（F70）。** 覆盖：破坏性命令本身；前面的argv包装器（`sudo -n`、`env VAR=x`、裸`VAR=x`、`timeout 5`、`busybox`、`wsl`…）；交给shell解释器的**字面**脚本文本（`bash -c "…"`、`cmd /c …`、`powershell -Command …`），按同一规则有界再扫描。不覆盖：需要**求值**才知道真实命令的形式——`eval`、`$(…)`命令替换、变量（`bash -c "$CMD"`）、别名、反斜杠转义命令名（`r\m`）、解释器正文（`python -c`、`node -e`）。这些在dangerousCommands测试中逐条钉住，防止误以为检测器是沙箱；真正兜底的是进程组终止与工作区路径限制。

**零误报同样是合同。** 测试以表驱动矩阵同时断言90条必须拦截（26a167e基线实测漏掉其中69条，含外部复审列出的19条）与135条日常命令必须放行（`npm test`、`git branch -M main`、`git restore --staged`、`kill -1 1234`、`curl … | python -m json.tool`、`npm test &> log.txt`等），且放行表不得短于拦截表；误报会逼用户整个关掉保护，比漏报更糟。基线把`git push --dry-run`/`-n`误报为危险，现已放行。`git push`本身仍拦截（发布行为，历来如此）。

提示"危险命令"不是精确风险评级；策略可能误报/漏报。Conda/PATH并不会改变该策略，遇拒绝不要指导用户关闭全部保护。

## 共享检测器落点

危险命令的词法函数都在[extension/dangerousPolicy.js](../../../extension/dangerousPolicy.js)，逐个解释见上表；tools/dangerous.js只导入检测并实现assertCommandAllowed（远程拒绝、本机要求显式确认字段）。PTY policy也导入同一检测，再叠加更保守的内容读取/复合命令/发布限制，不能通过同类/会话授权绕过。两入口的审批动作不同是设计，不再维护两份基本破坏性命令词表；词法策略仍不是沙箱。

## 追踪与核验更新
原callTool分发主体改名**dispatchTool()**，保持模式、路径、危险命令、remote超时边界；外层**callTool()**生成追踪、执行分发、完成记录并将trace附结果/异常，再clipJson。dispatchTool成功后调用verifyMutation读回核验文件写入；无法核验返回unknown，不自动重放。getCapabilities返回同一主机诊断及每个工具的modes；pingHost含identity。详见utils主机诊断与调用追踪详解。


## 受控执行增量

external_servers/external_request/operation_result/workflow_preview/workflow_request及confirm_connection均已接入；历史35/36等数量不作为当前接口合同，实时目录受hidden、模式及Bridge权限过滤。Ask/Plan禁止执行请求；中央callTool生成taskId后传入handler供审批关联。完整语义见../utils/受控工具与工作流详解.md。

### load_skill渐进参数
load_skill仍在Ask/Plan/Code可用，新增resource/offset/limit/expectedHash及目录cursor/pageSize。目录用source-qualified ID消歧，正文单页最大8000 UTF16字符；续页需hash，资源限定Skill内部文本。它不是run_skill，不授权命令，不自动安装依赖；执行工作流仍走独立preview/request/approve路径。

### recall查询参数
recall新增可选query（≤200字符），在有界当前工作区日记中做NFKC/大小写规范化后的字面词匹配，返回文件行号来源和不完整标记。不是语义事实库；read-only召回不会新增记忆。remember原来的显式磁盘副作用不变。

workflow_preview说明新增step.before（执行前）与step.expect（执行后），两者是显式文件条件。预览writeChecks提示缺少版本保护的写步骤，但不读取文件或授权执行；批准、原生expectedHash和失败不重放边界不变。

### 已登记stdio工具
external_servers现包含明确本机启动的stdio服务，仍只是元数据。external_request模式/审批入口不变，无远程启动配置或批准工具；启动后也不能凭readOnlyHint绕过审批。

## Bridge权限上限

getToolList在opts.remote时按executionControl.allowed过滤；dispatchTool在标准名/别名解析及输入归一后对remote调用assertAllowed。远端Code不能覆盖所有者权限。未知/不透明类别要求全部权限，嵌套工作流沿用remote选项逐步复查。过滤列表仅辅助，直接调用仍拒绝。验证见executionControl.test；Execute全开仍不是OS沙箱。

apply_patch工具描述已去掉“currentHash for an immediate retry”；必须先读取并重新规划，不自动重放修改。这是远端真实可见说明修正，不只是文档末尾覆盖。
