# 工具注册、参数别名与危险命令策略

## 职责与流程

[index.js](index.js)是共享工具入口，[normalize.js](normalize.js)兼容参数写法，[dangerous.js](dangerous.js)按显式策略检查命令。流程：取消检查 → 名称解析/注册查找 → 模式锁 → 参数正规化 → 远程限制/命令策略 → handler → 超时标记/软预算。

## 1. index.js全部函数与声明

**tool(def)**原样返回对象，方便声明，未校验schema。TOOLS每项name/aliases/description/mode/inputSchema/handler，hidden控制发现；顶层双循环把标准名及别名映射同定义。公开30项加隐藏send_command_input；schema描述不是自动JSON Schema运行验证器。

| 工具组 | 路由到的实现/输入 | 权限与返回 |
|---|---|---|
| ping/workspace_info/get_capabilities | pingHost/workspaceInfo/getCapabilities，无主要参数 | Ask/Plan/Code；主机/环境/能力，不执行修复 |
| get_logs/get_task_status | maxLines或无参 | 日志摘要/任务状态，不是完整执行证据 |
| remember/recall/load_skill | text；limit/day；name | 三模式可用，remember确实写内部记忆；只读模式不等于没有任何内部状态写入 |
| list_directory/find_files/search_files/read_files | 目录/深度；glob/数量；query/分页；路径/行窗口 | 三模式，参数语义见文件搜索详解 |
| git_status/git_diff | 无参或filePath/staged/stat | 三模式，只读Git |
| peers_list/board_list/create/claim/update | 无参；title/note；id/owner；id/status/note | 三模式均可写任务元数据；状态所有权另由board检查 |
| apply_patch/write_file/delete_file/rename_file | 单文件补丁/hash；正文/hash/确认；路径/确认；from/to | Code；写入handler箭头兼容两个确认字段并委托writeFile |
| run_command/start_command | command/cwd/timeoutSec/confirm_dangerous | Code；等待或立即返回execId |
| get_command_output/cancel_command | execId/commandId/tail；execId | 前者三模式，后者Code |
| send_command_input | execId/input | 隐藏、Code、本机PTY，远程无条件拒绝 |
| wait/report_progress/set_todos | ms；message/percentage/stepName；todos数组 | wait与todos三模式；progress仅Plan/Code |

**pingHost()**返回时间+session快照；**getLogs({maxLines=50}={})**限1–200，从eventBus.map只保留LOG_KEEP白名单字段，返回count是请求上限n而非实际日志长度；**getCapabilities()**工具map留name/description加会话，不真的调用工具；**getTaskStatus()**返回进度对象，in_progress给建议等待2秒及按百分比粗猜ETA，不是测得剩余时长。

**getToolList(currentMode=null,opts={})**两个filter限制模式及hidden，再map输出name/description/inputSchema；输出没有mode字段，不代表未按mode筛选。includeHidden仅用于明确内部调用。

**callTool(name,args={},currentMode=null,opts={})**：checkCancelled；resolveToolName后查注册，未知E_UNKNOWN_CMD附公开名字；有currentMode且不被允许→E_BAD_ARGS。无mode不会自动变只读。normalizeToolArgs；remote拒绝stdin输入，run/start调用assertCommandAllowed；远程timeout限制最高60秒、非法默认30。await handler(input,opts)，isTimeout时补E_TIMEOUT/suggestedWaitMs=0，clipJson返回。

不会统一把业务ok:false变抛错；MCP/Chat/REST包装各自决定成功语义。工具schema的required并非在这里统一执行，最后由handler实际检查，不能仅据JSON字段声明断言所有坏输入都被拒绝。

## 2. normalize.js全部函数

**isTruthy(v)**：true、数字1或trim后true/yes/1字符串为真，其他false；不是普通Boolean转换。**firstDefined(obj,keys)**按顺序取非null且非空字符串，保留0/false。**resolveToolName(name)**trim，优先精确别名再小写别名，未知保留原字符串；不是所有标准工具名均自动转小写。

**normalizeToolArgs(toolName,args)**：仅非数组对象作为src，浅拷贝；snake_case补camelCase但不覆盖已有字段。按工具归并路径、目录、查询、glob、补丁、hash、正文、rename两端、command/timeout、execId等别名。apply_patch.dryRun、确认标志、recursive、isRegex/caseSensitive用isTruthy；不是所有number字段都转换或所有unknown字段都删除。write_file额外同步confirmOverwrite。空正文原始content仍可保留，但firstDefined不会从空text别名产生正文。

TOOL_NAME_ALIASES将常见bash/shell/cat/read/ls/grep/glob/edit_file/write/rm/mv等映射到标准工具，**别名并不赋予绕过模式/确认的权限**；解析后同一个工具定义仍受检查。

## 3. dangerous.js全部辅助与策略函数

这些都是尽力检测，不是完整shell语法解析或操作系统沙箱；这里解释识别规则，不提供绕过方式。

| 函数 | 输入/返回 | 职责 |
|---|---|---|
| stripEmptyQuotes(s) | 字符串→字符串 | 循环去空单双引号直到不变 |
| normalizeRaw(cmd) | 命令→规范文本 | 去空引号、控制/特殊空白与多余空白；不展开变量/执行脚本 |
| splitStages(cmd) | 命令→阶段数组 | 按连接符/管道等简化切分，map trim/filter空；不完整尊重所有引号语法 |
| tokenize(stage) | 一阶段→token数组 | 正则识别单双引号和非空白token，去包裹引号 |
| cmdName(tok) | token→命令名 | 去路径/常见Windows扩展名，小写 |
| shortLetters(tok) | 短选项→字符数组 | 只接受单横线非双横线形式 |
| hasShort(tokens,letter) | tokens→boolean | 嵌套some比较短选项字母，不区分大小写 |
| hasLong(tokens,name) | tokens→boolean | some精确比较小写长选项 |
| hasWinSwitch(tokens,letter) | tokens→boolean | 检查Windows斜杠选项并按前缀匹配 |
| rmDangerous(tokens) | tokens→boolean | 识别递归删除标志 |
| findDangerous(tokens) | tokens→boolean | 识别find中的删除/执行动作 |
| gitDangerous(tokens) | tokens→boolean | 推送、硬重置、路径checkout、强制clean等；filter去选项后取verb，是简化识别 |
| powershellDangerous(tokens) | tokens→boolean | 递归删除、动态表达式/下载/启动进程与编码执行等策略类别 |
| windowsDangerous(tokens) | tokens→boolean | 递归删除、格式化、电源、系统注册/账户/计划任务等类别 |
| alwaysDangerousName(name) | 名称→boolean | 直接磁盘/擦除/截断/格式化类工具名 |
| stageDangerous(tokens) | tokens→boolean | 逐个策略或数据库删除短语；空阶段false |
| pipelineDangerous(stages) | 阶段→boolean | map命令名，记录前面下载器，后面出现shell则危险；不证明数据流实际连接 |
| redirectDangerous(raw) | 命令→boolean | 检查重定向到特定设备路径类别 |
| isDangerousCommand(command) | 命令→boolean | 空false，重定向/管道/阶段任一危险即true |
| assertCommandAllowed(command,{remote=false,confirmDangerous=false}={}) | 无返回或抛错 | 非危险通过；危险远程E_FORBIDDEN；本机未确认E_BAD_ARGS；本机明确确认才放行 |

提示“危险命令”不是精确风险评级；策略可能误报/漏报。Conda/PATH并不会改变该策略，遇拒绝不要指导用户关闭全部保护。

## 4. 验证

```bat
npm test --prefix webagent-core/agent-host -- --filter=mcpProtocol
npm test --prefix webagent-core/agent-host -- --filter=dangerousCommands
npm test --prefix webagent-core/agent-host -- --filter=workspaceTools
```

检查注册/别名/模式及危险命令真实分支；不要从测试绿灯推出任意shell语法已被完整解析。注册描述里旧peer key与owner“override”措辞应以任务板实现为准：当前已初始化key是peer ID，owner不能冒充他人。
