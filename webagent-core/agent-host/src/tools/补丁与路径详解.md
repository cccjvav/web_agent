# patchEngine.js：路径、写锁、补丁与落盘

## 职责与主流程

[patchEngine.js](patchEngine.js)负责路径边界、同进程写锁、文本替换和补丁应用。调用链是 `callTool → applyPatch → withWriteLock → applyPatchBody → atomicWriteText`。读缓存、差异展示和事件另由对应模块负责。以下解释全部具名函数及闭包，不把“原子写”描述成跨进程数据库事务。

## 1. 路径与字符辅助函数

| 函数 | 输入→返回 | 实现与边界 |
|---|---|---|
| computeHash(content) | UTF8文本→SHA256 hex | 对全文而不是当前阅读窗口求摘要，无文件I/O |
| tempSibling(fullPath) | 目标→临时同级路径 | PID、时间、随机4字节组合，仍需wx保证不覆盖 |
| toPosixRel(p) | 路径→正斜杠字符串 | 只改分隔符，不做安全认证 |
| looksLikeUncOrDrive(relPath) | 路径→boolean | 检查NUL、盘符及UNC形式；最终工作区判断另做 |
| existingAncestor(absPath) | 路径→最近已存在祖先 | lstat，从不存在的末级向父级找；只忽略ENOENT，其他异常抛出 |
| realPathOrJoin(absPath) | 路径→规范目标 | 祖先realpath后接回不存在的后缀，支持新文件；不是永远固定的文件句柄 |
| isInsideWorkspace(absPath) | 路径→boolean | 工作区和目标都按真实祖先规范化，relative不能离开根 |
| resolveSafePath(relPath) | 路径→绝对逻辑路径 | 拒绝不允许形式；Windows拒绝歧义片段；检查逻辑和真实目标均在根内，且两种相对路径均非敏感；返回不是文件内容 |
| detectEol(text) | 文本→LF或CRLF | 只要包含CRLF就选择它，混合换行不逐行保留 |
| toLf(text) | 文本→LF文本 | CRLF与单CR归一 |
| applyEol(text,eol) | 文本/目标换行→文本 | 先toLf，必要时全体转CRLF |
| countOccurrences(haystack,needle) | 字符串→次数 | 非重叠indexOf计数，空needle返回0 |
| replaceOccurrence(haystack,needle,replacement,occurrence) | 指定第几次→新文本 | 同样按非重叠匹配计数，找不到返回原文；调用者必须先拒绝空needle |

resolveSafePath检查时与真正写盘时之间仍可能有其他进程改变目录；不是OS沙箱或任意竞态的形式化消除。普通shell命令字符串也不会因为这里验证cwd就被限制所有访问。

## 2. 写锁与临时替换

**writeLockKey(filePath)**：resolveSafePath、realPathOrJoin得到真实目标，Windows再小写。不同拼写指向同目标时尽量用同key。

**lockOne(key,fn)**：取上一条Promise；创建held，其执行器保存release；两个then回调无论前项成败都排到held。存tail，等待prev（catch吞前项失败但不吞本项），异步回调先checkCancelled再await fn；finally release，只有当前Map仍指tail才删key。失败不会永久卡住下一次同路径写入。

**withWriteLock(paths,fn)**：单路径转数组，map key、Set去重、排序；reduceRight返回一串按相同顺序获取锁的闭包，减少双路径改名互相等待。锁只属于本Node进程，不保护另一个编辑器/进程。

**atomicWriteText(fullPath,content,{exclusive=false}={})**：检查取消与8MiB结果字节预算；已有目标用realpath，记原权限位。wx写同级临时文件，恢复原可执行权限，再检查取消；普通写rename，exclusive新建用hard link让已存在目标不会被覆盖。finally删临时文件，ENOENT忽略，其他清理异常会抛出。

此函数不建立父目录、不独立校验工作区、不fsync；取消发生在发布之后不能撤销修改。已有目标权限保留与Windows ACL完整继承不是一回事。发布成功后清理/事件失败也可能表现为异常，不能断言异常必然意味着磁盘未变化。

## 3. 格式检测与 SEARCH/REPLACE

**looksLikeUnifiedDiff(text)**：去BOM/前导空白，在开头片段看diff header或文件头及hunk标记；只是检测线索。

**looksLikeV4A(text)**：检测另一种Begin/Update/Add/Delete/Move Patch标记。**rejectUnsupportedPatchFormat(filePath,patch,blocks)**：已有SEARCH块就返回，否则检测到V4A抛E_BAD_ARGS及转换提示；不是V4A解释器。

**parseSearchReplaceBlocks(patchText)**：全局正则逐块提取search/replace数组，允许一定数量的标记字符与LF/CRLF。没找到返回空，不等于“输入无效”已经判定。

**applySearchBlocks(currentContent,blocks,{filePath,occurrence}={})**：记录原换行，按块顺序在当前中间文本上替换。occurrence转换为有限≥1整数；先精确匹配，零匹配且search非空时尝试trim search与replace。空SEARCH在现有文件拒绝；零匹配冲突；多匹配而无occurrence→E_CONFLICT；越界序号也失败。最后恢复选择的换行风格。trim回退可能改变替换段两端空白，不能说绝不调整任何格式。

## 4. applyPatch / applyPatchBody

**applyPatch(opts={})**返回withWriteLock(opts.filePath,闭包applyPatchBody)。它是异步函数，错误可能在获取key/锁或执行体发生。

**applyPatchBody({filePath,patch,expectedHash=null,dryRun=false,occurrence}={})**先要求patch字符串且≤8MiB，安全路径、解析块、格式拒绝。

### 新文件

有空SEARCH首块则用第一块replace；看起来是统一diff且没有空SEARCH则拒绝；其他情况用patch本身作为正文。这不是把所有非空SEARCH新建请求都正确转换为内容，调用者应明确用空SEARCH或正文。dryRun只返回通过/新文件提示，不真正发布。

正式创建：让出一次微任务，建父目录，atomicWriteText(exclusive:true)，生成diff、广播file_patched、rememberHash，返回success/isNewFile/newHash/摘要。新文件只使用第一空SEARCH块，不进行多文件事务。

### 已有文件

readBoundedText读全文，computeHash；未显式给expectedHash则尝试recalledHash。非dryRun无hash→HASH_REQUIRED；有hash不一致即E_STALE_FILE，dryRun也不绕过显式错误hash。

有SEARCH块走applySearchBlocks；否则统一diff经diff.parsePatch，要求恰好一个含hunk的已有文件补丁，拒绝/dev/null新建删除形式；applyPatch返回false即失败。补丁头不是实际文件选择器，filePath才是目标。其余文本作为整文件替换，保留选定换行。

生成展示diff；dryRun返回diff但不写。正式atomicWriteText，再记新hash、广播、返回diff/newHash/摘要。实际写入之前没有与其他进程的最终compare-and-swap，锁仅串行本进程。dryRun不证明之后正式提交时文件仍未变。

## 5. 验证

```bat
npm test --prefix webagent-core/agent-host -- --filter=patchEngine
npm test --prefix webagent-core/agent-host -- --filter=sandbox
npm test --prefix webagent-core/agent-host -- --filter=auditStorage
```

分别读唯一SEARCH/CRLF/格式、工作区边界及落盘断言；Windows链接权限/外部进程并发需要额外实际证据。复盘练习：顺着一次旧hash、一段重复SEARCH、一次exclusive新建竞争说明拒绝在哪一层，哪些副作用已经发生。
