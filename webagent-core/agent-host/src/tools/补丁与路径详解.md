# patchEngine.js：路径、写锁、补丁与落盘

## 职责与主流程

[patchEngine.js](patchEngine.js)负责路径边界、同进程写锁、文本替换和补丁应用。调用链是 `callTool → applyPatch → withWriteLock → applyPatchBody → atomicWriteText`。读缓存、差异展示和事件另由对应模块负责。以下解释全部具名函数及闭包，不把“原子写”描述成跨进程数据库事务。

## 1. 路径与字符辅助函数

| 函数 | 输入→返回 | 实现与边界 |
|---|---|---|
| computeHash(content) | UTF8文本→SHA256 hex | 对全文而不是当前阅读窗口求摘要，无文件I/O |
| tempSibling(fullPath) | 目标→临时同级路径 | PID、时间、随机4字节组合，仍需wx保证不覆盖 |
| toPosixRel(p) | 路径→正斜杠字符串 | 只改分隔符，不做安全认证 |
| looksLikeUncOrDrive(relPath) | 路径→boolean | 检查NUL、盘符及UNC形式；最终工作区判断另做 |
| existingAncestor(absPath) | 路径→最近已存在祖先 | lstat，从不存在的末级向父级找；只忽略ENOENT，其他异常抛出 |
| realPathOrJoin(absPath) | 路径→规范目标 | 祖先realpath后接回不存在的后缀，支持新文件；不是永远固定的文件句柄 |
| isInsideWorkspace(absPath) | 路径→boolean | 工作区和目标都按真实祖先规范化，relative不能离开根 |
| assertNoShortNameAlias(root, resolved) | 根与已解析路径→无返回/抛E_BAD_ARGS | 仅Windows：含`~`、在磁盘上存在、却不在父目录真实条目里（不分大小写）的片段是8.3短名别名（如`WEBAGE~1`），拒绝并提示用长名。内置敏感规则按名字匹配，JS版realpath保留传入拼写，2026-09-25审计前Windows CI证实经别名可读出`.webagent/config.json`；只对含`~`的片段读一次父目录；看不到管理员设置的不含`~`的自定义短名 |
| resolveSafePath(relPath) | 路径→绝对逻辑路径 | 拒绝不允许形式；Windows拒绝歧义片段和8.3短名别名；检查逻辑和真实目标均在根内，且两种相对路径均非敏感；返回不是文件内容 |
| detectEol(text) | 文本→LF或CRLF | 只要包含CRLF就选择它，混合换行不逐行保留 |
| toLf(text) | 文本→LF文本 | CRLF与单CR归一 |
| applyEol(text,eol) | 文本/目标换行→文本 | 先toLf，必要时全体转CRLF |
| countOccurrences(haystack,needle) | 字符串→次数 | 非重叠indexOf计数，空needle返回0 |
| replaceOccurrence(haystack,needle,replacement,occurrence) | 指定第几次→新文本 | 同样按非重叠匹配计数，找不到返回原文；调用者必须先拒绝空needle |

resolveSafePath检查时与真正写盘时之间仍可能有其他进程改变目录；不是OS沙箱或任意竞态的形式化消除。普通shell命令字符串也不会因为这里验证cwd就被限制所有访问。

## 2. 写锁与临时替换

**writeLockKey(filePath)**：resolveSafePath、realPathOrJoin得到真实目标，Windows再小写。不同拼写指向同目标时尽量用同key。

**lockOne(key,fn)**：取上一条Promise；创建held，其执行器保存release；两个then回调无论前项成败都排到held。存tail，等待prev（catch吞前项失败但不吞本项），异步回调先checkCancelled再await fn；finally release，只有当前Map仍指tail才删key。失败不会永久卡住下一次同路径写入。

**withWriteLock(paths,fn)**：单路径转数组，map key、Set去重、排序；reduceRight返回一串按相同顺序获取锁的闭包，减少双路径改名互相等待。锁只属于本Node进程，不保护另一个编辑器/进程。

**atomicWriteText(fullPath,content,{exclusive=false}={})**：检查取消与8MiB结果字节预算；已有目标用realpath，记原权限位。wx写同级临时文件，恢复原可执行权限，再检查取消；普通写rename，exclusive新建用hard link让已存在目标不会被覆盖。finally删临时文件，ENOENT忽略，其他清理异常会抛出。

此函数不建立父目录、不独立校验工作区、不fsync；取消发生在发布之后不能撤销修改。已有目标权限保留与Windows ACL完整继承不是一回事。发布成功后清理/事件失败也可能表现为异常，不能断言异常必然意味着磁盘未变化。

## 3. 格式检测与 SEARCH/REPLACE

**looksLikeUnifiedDiff(text)**：去BOM/前导空白，在开头片段看diff header或文件头及hunk标记；只是检测线索。

**looksLikeV4A(text)**：检测另一种Begin/Update/Add/Delete/Move Patch标记。**rejectUnsupportedPatchFormat(filePath,patch,blocks)**：已有SEARCH块就返回，否则检测到V4A抛E_BAD_ARGS及转换提示；不是V4A解释器。

**parseSearchReplaceBlocks(patchText)**（F70重写为按行解析）：没有任何SEARCH/REPLACE标记行就返回空数组（只有`=====`行的新文件正文、如Markdown setext标题，是内容而不是补丁）。否则按行切分并保留每行自己的换行符：开头标记`<<<<<<< SEARCH`（5个以上`<`，长度记为N）必须独占一行，块的范围到下一个同长开头标记为止；在其中优先找**恰好N个**`=`的分隔行和N个`>`的`REPLACE`结束行，找不到才退回任意长度（兼容模型混用5/7字符标记）。分隔符前后紧邻的那个换行属于标记行而非正文。每块返回search、replace及replaceEmpty（空REPLACE=删除，与“替换成一个空行”区分）。旧实现是单个正则，分隔符前的换行可选且接受任意5个以上`=`：SEARCH里的`# ==========`注释横幅或setext下划线会提前结束SEARCH，写坏文件还报成功；也无法表达空REPLACE。拒绝情况（都抛E_BAD_ARGS、零写入）：孤立的分隔/结束行、缺结束行或分隔行（malformed）；同一块内有多条同长分隔行（如SEARCH里含Git冲突标记）为ambiguous，retryHint建议改用更长标记（9字符）或unified diff——不再猜测第一条分隔符。块内的局部helper：**bare(line)**去掉行尾换行后做标记匹配；**markerLines(re,from,to,sameLength)**返回范围内匹配某类标记的行号（可要求与开头同长）；**join(from,to)**拼接正文行并去掉紧贴标记的最后一个换行。**malformedPatch(message,hint)**统一构造上述E_BAD_ARGS与retryHint。

**wholeLineDeletionNeedle(haystack,needle,block)**：仅当REPLACE为空（replaceEmpty）时生效。若SEARCH的**每一处**匹配都覆盖完整行（前后只有空格/制表符到行首/行尾），就把needle扩成“缩进+匹配+一个换行”（文件最后一行则带上前一个换行），删除后不留空行或只剩缩进的行；只要有一处是行内匹配、各处缩进不同，或扩展后出现次数变化，就退回原needle，从而匹配次数、唯一性与occurrence语义与普通needle完全相同。含空行（`\n\n`）的SEARCH不扩展。

**applySearchBlocks(currentContent,blocks,{filePath,occurrence}={})**：记录原换行，按块顺序在当前中间文本上替换。occurrence转换为有限≥1整数；needle先经wholeLineDeletionNeedle处理，先精确匹配，零匹配且search非空时尝试trim search与replace（同样经整行删除处理）。空SEARCH在现有文件拒绝；零匹配冲突；多匹配而无occurrence→E_CONFLICT；越界序号也失败。最后恢复选择的换行风格。trim回退可能改变替换段两端空白，不能说绝不调整任何格式。

## 4. applyPatch / applyPatchBody

**applyPatch(opts={})**返回withWriteLock(opts.filePath,闭包applyPatchBody)。它是异步函数，错误可能在获取key/锁或执行体发生。

**applyPatchBody({filePath,patch,expectedHash=null,dryRun=false,occurrence}={})**先要求patch字符串且≤8MiB，安全路径、解析块、格式拒绝。

### 新文件

F54第三批修复：路径不存在时，显式expectedHash非null即E_STALE_FILE，currentHash=null；空文件的SHA256也是“文件存在”的前提，不是缺失标记。dryRun同样拒绝，提示停下核对删除/重建意图，不能去掉hash自动重放。只允许完整正文或恰好一个空（trim后）SEARCH块：多块E_BAD_ARGS整体拒绝，单个非空SEARCH为E_CONFLICT；无块的unified diff仍拒绝。错误发生在mkdir、写入、file_patched和rememberHash之前。已有文件的多块处理不变。未给hash的新建不会自动套用历史readCache；有意重建须由调用方重新核对计划，不声称跨进程删除检测或授权。dryRun对合法新建返回diff/baseHash=null/proposedHash且不发布。原始缺陷证据仍见[独立报告](../../../../review/INDEPENDENT_AUDIT_2026-09-20.md)。

正式创建：先计算有界diff（与dryRun共用），通过后让出一次微任务、建父目录、atomicWriteText(exclusive:true)，再广播file_patched、rememberHash，返回success/isNewFile/newHash/摘要。展示超限E_DIFF_BUDGET发生在建目录/写入之前；不在写完后才检查预算。新文件的单块/正文已在写入前验证；不进行多文件事务。

### 已有文件

**格式门（F70，外部复审P1-1）**：既没有SEARCH/REPLACE块、也不像unified diff的正文，在读取文件和hash门**之前**就抛E_BAD_ARGS（format:'unmarked'，retryHint指向SEARCH/REPLACE、unified diff或write_file的confirm_overwrite/expectedHash），零写入、不发布hash或事件、dryRun同样拒绝。旧实现把这种正文当成**新的整文件内容**写回；由于未给expectedHash时会自动套用recalledHash，漏写标记的一次调用就能把文件替换成片段并报成功（基线实测3行文件→`+1 -3`）。整文件替换是write_file的显式合同，apply_patch只做补丁。格式门放在hash门前，是因为换一个新hash重发同样的正文永远不可能成功，调用方应先得知真正的问题。

readBoundedText严格UTF-8读全文（保留BOM/CRLF；非法编码E_ENCODING），computeHash；未显式给expectedHash则尝试recalledHash。非dryRun无hash→HASH_REQUIRED；有hash不一致即E_STALE_FILE，dryRun也不绕过显式错误hash。

有SEARCH块走applySearchBlocks；否则（此时必为unified diff）经diff.parsePatch，要求恰好一个含hunk的已有文件补丁，拒绝/dev/null新建删除形式；applyPatch返回false即失败。补丁头不是实际文件选择器，filePath才是目标。保留选定换行。

生成展示diff：每侧1MiB/20000行、1500ms/20000编辑（可由WEBAGENT_DIFF_TIMEOUT_MS/WEBAGENT_DIFF_MAX_EDIT调整）、输出256KiB；超限E_DIFF_BUDGET先拒绝，算法仅算一次，详见[差异展示](../utils/差异展示详解.md)。dryRun返回diff但不写。正式atomicWriteText，再记新hash、广播、返回diff/newHash/摘要。实际写入之前没有与其他进程的最终compare-and-swap，锁仅串行本进程。dryRun不证明之后正式提交时文件仍未变。

## 5. 验证

```bat
npm test --prefix webagent-core/agent-host -- --filter=patchEngine
npm test --prefix webagent-core/agent-host -- --filter=sandbox
npm test --prefix webagent-core/agent-host -- --filter=auditStorage
```

分别读唯一SEARCH/CRLF/格式、工作区边界及落盘断言；Windows链接权限/外部进程并发需要额外实际证据。复盘练习：顺着一次旧hash、一段重复SEARCH、一次exclusive新建竞争说明拒绝在哪一层，哪些副作用已经发生。


## 有版本依据的只读编辑预览（0.7.2）

applyPatchBody的dryRun现在对新文件也用createUnifiedDiff返回可读diff/diffSummary，baseHash=null表明预览时不存在，proposedHash是拟写内容SHA256；不mkdir、写文件或更新readCache。已有文件dryRun返回baseHash=currentHash及proposedHash，提交仍需原expectedHash并重查当前文件；漂移拒绝，不自动重放。hash不是预览授权票据，不能锁住外部编辑器，更不等于已经做完受保护回退。验证taskProgress.test覆盖新建/已有/漂移，原patchEngine套件继续覆盖各种补丁。

HASH_REQUIRED和STALE_FILE的提示不得将错误currentHash当立即重放凭证；现改为停止本次补丁、读取并核对变化，冲突与操作者协调。仍保留currentHash诊断和既有recalledHash机制，不放宽检查。
