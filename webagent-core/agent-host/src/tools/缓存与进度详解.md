# 读取哈希缓存与任务进度：逐函数讲解

## 职责与状态

[readCache.js](readCache.js)区别“曾读取版本”和“本进程本会话确实读取”，供补丁/写入前置条件使用；[progressTracker.js](progressTracker.js)存进程内UI任务进度。两者不是数据库或命令退出码来源。

## 1. readCache.js全部函数

状态hashes是可落盘版本Map，session是会话Map，loadedRoot用于工作区切换时重载；MAX_ENTRIES=400只对rememberHash更新后的hashes执行限额，不是所有状态全面有界。

| 函数 | 参数/返回 | 作用与边界 |
|---|---|---|
| norm(filePath) | 路径→字符串key | 反斜杠转正斜杠、去首个./；不是realpath/大小写/父目录规范器，不作为安全路径验证 |
| hashFile() | 无→路径 | workspaceRoot/.webagent/read-hashes.json |
| ensureLoaded() | 无→undefined | root相同直接返回；否则先重置两个Map并记root，再读JSON对象逐键norm/String填hashes；读/解析失败吞掉；不会从磁盘恢复session |
| persist() | 无→undefined | 建目录，hashes转普通对象，直接writeFileSync；异常吞掉，无临时rename/事务；调用者得不到持久化失败状态 |
| rememberHash(filePath,hash) | 路径/hash→undefined | ensureLoaded；空key/hash返回；hashes已有key先删再set（更新插入顺序），session也set；hashes超400删首项，最后persist |
| recalledHash(filePath) | 路径→hash或null | ensureLoaded后查可持久化Map；不是确认当前磁盘仍等于该hash |
| sessionHash(filePath) | 路径→hash或null | 查本会话Map；跨重启不恢复，某些覆盖权限需要它而非磁盘旧hash |
| forgetHash(filePath) | 路径→undefined | 两Map删除并persist；不删业务文件 |
| clearSession() | 无→undefined | 仅换空session Map；不删hashes/磁盘，也不改loadedRoot |
| resetHashes() | 无→undefined | 清两Map、记录当前root、尽力unlink缓存（错误吞掉）；若unlink失败，重启可能读回旧磁盘缓存 |

ensureLoaded加载旧JSON时没有马上裁到400，session也没有这里的容量淘汰；不能把MAX_ENTRIES当所有缓存都硬上限。norm不是canonical路径，调用方需要一致的路径语义；不以此做权限判断。

## 2. progressTracker.js：任务报告与会话归属

Tasks是Agent通过set_todos显式上报的计划，不是工具调用自动生成的任务，也不是持久任务板。report_progress报告百分比和步骤，不会自动修改todo状态。Local Chat继续有一份本地主机计划；Bridge另按MCP服务端解析的callerKey隔离，不靠模型提供的title/clientInfo决定归属。

- **initialState(source,sessionId)**创建idle/0/空消息和todos。**cleanStates()**在工作区变化时清理旧状态，清除30分钟未更新的远程报告；不是取消真实任务。
- **stateFor(options,create=true)**默认返回本地状态；remote时以hostInstanceId+callerKey的SHA256前16位作公开会话摘要，与工具轨迹sessionId一致，不暴露原始会话键。最多16个有报告的远程会话，满时新会话明确拒绝；create=false读取未知peer只构造未保存的idle快照，不消耗报告槽。旧会话仍可更新。未初始化的兼容客户端沿用服务端已有caller归属，不能保证每个浏览器标签都独立。
- **text(value,field,max)**要求有界字符串；标题/消息/步骤500字符、ID80字符。**snapshot(state)**复制对象和每条todo，调用者不能通过返回值修改内部状态。
- **setTodos({todos},options)**先checkCancelled，再一次性校验数组<=50、对象条目、唯一ID和pending/in_progress/completed/failed/cancelled/blocked状态；全部通过才替换所属会话计划、更新时间、广播带source/sessionId的todos_updated。返回快照，不接受无界/非法状态后部分写入。
- **reportProgress(input,options)**要求有限数百分比，夹到0–100；100标记报告状态completed，不证明测试通过。文字先校验，再更新和广播progress_updated。原工具模式权限不变，report_progress仍需Code；set_todos允许Ask/Plan/Code。
- **getTaskState(options={})**通过stateFor(options,false)返回本机或当前远程peer快照，纯读取未知peer不登记状态；工具入口getTaskStatus传入调用上下文，因此远程get_task_status不再误读Local计划。`/api/status`不传options，仍明确取得本地快照。**getBridgeTaskStates()**返回独立远程快照数组。刷新或断WS可重读；进程重启丢失，30分钟未更新的报告会过期。不是长期历史。
- **resetTaskState()**清本地与远程报告并通知两种消费者；不取消命令、不改任务板。清Bridge工具统计不清Tasks。

## 3. 协作与验证

callTool把可信remote/callerKey传入handler；/api/status同时提供taskState和bridgeTaskStates；/api/bridge/activity提供taskStates并在任务事件时增加revision。经典工作台通过3秒轮询恢复远程计划，WS只提前触发；本地Chat只画本地任务。桌面/code-server共享核心BridgeView，通过4秒单飞刷新取bridgeTaskStates。Tasks无计划时显示上报说明，错误时标未知而不宣称完成。

taskProgress.test验证本机/两远程peer隔离、每个peer经真实callTool只读回自己的get_task_status且未知peer读取不占报告槽、HTTP重复读取、快照不可变、非法输入无状态变化、容量/TTL；workbenchRuntime/webviewRuntime验证真实渲染逻辑和转义；workbench.browser验证认证MCP上报、断WS及刷新恢复。VM不是桌面VSCode实机验收。旧readCache语义仍以第1节为准。
