# 读取哈希缓存与任务进度：逐函数讲解

## 职责与状态

[readCache.js](readCache.js)区别“曾读取版本”（落盘、所有调用者共用）和“本进程中这个调用者确实读取”（按读者分开），供补丁/写入前置条件使用；[progressTracker.js](progressTracker.js)存进程内UI任务进度。两者不是数据库或命令退出码来源。

## 1. readCache.js全部函数

状态hashes是可落盘版本Map（MAX_ENTRIES=400）；session以“读者+换行+路径”为键（MAX_SESSION=4000，超出淘汰最久未读的一条）；loadedRoot用于工作区切换时重载。读者由readerOf按服务端构造的调用选项决定，不来自工具参数。

| 函数 | 参数/返回 | 作用与边界 |
|---|---|---|
| readerOf(opts) | 调用选项→读者或null | operator为真返回null（人在工作台打开、保存、撤销、新建Skill、恢复检查点，F96起还有人在操作面板提交的工作流和直接/api/tool/call，都不算任何模型读过；operator优先于remote）；remote且`initializedSession === true`返回`remote:`加callerKey（缺callerKey时共用`remote:`）；**remote但没有已初始化MCP会话返回null**（F112，第110组交接第3项：这类调用只按“客户端名@来源地址”归属，经隧道时来源都是127.0.0.1，两个客户端会共用一份读取记录并替对方满足write_file的免确认条件；现在它们和人一样不记录也不享受“读过即可覆盖”，写已有文件须带read_files返回的expectedHash或confirm_overwrite）；其余（本机Chat、插件Chat的工具转发）返回local。F95之前没有读者概念：编辑器保存会记下保存后的hash，读过旧版的模型随后可以不确认就用write_file覆盖人的修改 |
| sessionKey(reader,key) | 读者/路径→字符串 | 读者与路径以换行拼接；路径不含换行，所以不同读者不会撞键 |
| norm(filePath) | 路径→字符串key | 反斜杠转正斜杠后经path.posix.normalize：`src//a.js`、`./src/./a.js`、`lib/../src/a.js`与`src/a.js`同一个key（F99：此前读过`src/a.js`再用`src//a.js`写会被当成没读过而要求confirm_overwrite——写侧始终对比当前内容，所以只是摩擦不是授权漏洞）；空串/`.`/`./`归空不记录；尾斜杠与大小写保留；不是realpath，不作为安全路径验证 |
| hashFile() | 无→路径 | workspaceRoot/.webagent/read-hashes.json |
| ensureLoaded() | 无→undefined | root相同直接返回；否则先重置两个Map并记root，再读JSON对象逐键norm/String填hashes；读/解析失败吞掉；不会从磁盘恢复session |
| persist() | 无→undefined | 建目录，hashes转普通对象，写带pid+随机后缀的临时文件再rename发布；崩溃或磁盘满不会在原位留下半截JSON（截断JSON会被解析成"一条hash都没有"，导致之后每次apply_patch都得重读）。异常吞掉并清理临时文件，调用者得不到持久化失败状态 |
| rememberSession(reader,key,value) | 读者/路径/hash→undefined | 先删后set，使重复读取刷新年龄；超过MAX_SESSION从最旧一条淘汰 |
| rememberHash(filePath,hash,reader='local') | 路径/hash/读者→undefined | ensureLoaded；空key/hash或reader为null（人的操作）直接返回，两张表都不记。**若该key已是最新一条且hash未变，只更新该读者的session就返回，不落盘**——重复读同一个未改动文件是最常见的情形，而整张表每次都要重写，空转会白白放大写入。否则hashes已有key先删再set（更新插入顺序），rememberSession记该读者；hashes超400删首项，最后persist |
| recalledHash(filePath) | 路径→hash或null | ensureLoaded后查可持久化Map；不是确认当前磁盘仍等于该hash |
| sessionHash(filePath,reader='local') | 路径/读者→hash或null | 只查该读者的记录；另一远程会话或本机Chat的读取查不到。跨重启不恢复，write_file免确认覆盖只认它而非磁盘旧hash；reader为null时查不到任何记录（从不以null记录） |
| forgetHash(filePath) | 路径→undefined | 删落盘条目，并删**所有读者**对该路径的session记录（删除文件后，之后同内容的新文件不算任何人读过）；只有确实删掉了落盘条目才persist；不删业务文件 |
| clearSession() | 无→undefined | 仅换空session Map；不删hashes/磁盘，也不改loadedRoot |
| resetHashes() | 无→undefined | 清两Map、记录当前root、尽力unlink缓存（错误吞掉）；若unlink失败，重启可能读回旧磁盘缓存 |

ensureLoaded加载旧JSON时没有马上裁到400，不能把MAX_ENTRIES当落盘文件的硬上限。落盘记录不分读者：apply_patch在没给expectedHash时仍可凭任何调用者（包括上次运行）留下的记录省掉重读，补丁内容对不上照样失败。norm不是canonical路径，调用方需要一致的路径语义；不以此做权限判断。

## 2. progressTracker.js：任务报告与会话归属

Tasks是Agent通过set_todos显式上报的计划，不是工具调用自动生成的任务，也不是持久任务板。report_progress报告百分比和步骤，不会自动修改todo状态。Local Chat继续有一份本地主机计划；Bridge另按MCP服务端解析的callerKey隔离，不靠模型提供的title/clientInfo决定归属。

- **initialState(source,sessionId)**创建idle/0/空消息和todos。**cleanStates()**在工作区变化时清理旧状态，清除30分钟未更新的远程报告；不是取消真实任务。
- **stateFor(options,create=true)**默认返回本地状态；remote时以hostInstanceId+callerKey的SHA256前16位作公开会话摘要，与工具轨迹sessionId一致，不暴露原始会话键。最多16个有报告的远程会话，满时新会话明确拒绝；create=false读取未知peer只构造未保存的idle快照，不消耗报告槽。旧会话仍可更新。未初始化的兼容客户端沿用服务端已有caller归属，不能保证每个浏览器标签都独立。
- **text(value,field,max)**要求有界字符串；标题/消息/步骤500字符、ID80字符。**snapshot(state)**复制对象和每条todo，调用者不能通过返回值修改内部状态。
- **setTodos({todos},options)**先checkCancelled，再一次性校验数组<=50、对象条目、唯一ID和pending/in_progress/completed/failed/cancelled/blocked状态；全部通过才替换所属会话计划、更新时间、广播带source/sessionId的todos_updated。返回快照，不接受无界/非法状态后部分写入。
- **reportProgress(input,options)**要求有限数百分比，夹到0–100；100标记报告状态completed，不证明测试通过。文字先校验，再更新和广播progress_updated。原工具模式权限不变，report_progress允许Plan/Code、不允许Ask；set_todos允许Ask/Plan/Code。
- **getTaskState(options={})**通过stateFor(options,false)返回本机或当前远程peer快照，纯读取未知peer不登记状态；工具入口getTaskStatus传入调用上下文，因此远程get_task_status不再误读Local计划。`/api/status`不传options，仍明确取得本地快照。**getBridgeTaskStates()**返回独立远程快照数组。刷新或断WS可重读；进程重启丢失，30分钟未更新的报告会过期。不是长期历史。
- **resetTaskState()**清本地与远程报告并通知两种消费者；不取消命令、不改任务板。清Bridge工具统计不清Tasks。

## 3. 协作与验证

callTool把可信remote/callerKey传入handler；/api/status同时提供taskState和bridgeTaskStates；/api/bridge/activity提供taskStates并在任务事件时增加revision。经典工作台通过3秒轮询恢复远程计划，WS只提前触发；本地Chat只画本地任务。桌面/code-server共享核心BridgeView，通过4秒单飞刷新取bridgeTaskStates。Tasks无计划时显示上报说明，错误时标未知而不宣称完成。

taskProgress.test验证本机/两远程peer隔离、每个peer经真实callTool只读回自己的get_task_status且未知peer读取不占报告槽、HTTP重复读取、快照不可变、非法输入无状态变化、容量/TTL；workbenchRuntime/webviewRuntime验证真实渲染逻辑和转义；workbench.browser验证认证MCP上报、断WS及刷新恢复。VM不是桌面VSCode实机验收。旧readCache语义仍以第1节为准。
