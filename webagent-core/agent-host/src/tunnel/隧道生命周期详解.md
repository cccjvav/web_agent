# Cloudflare与ngrok：查找、启动、竞争与停止

覆盖[cloudflared.js](cloudflared.js)、[ngrok.js](ngrok.js)；进程退出等待辅助见[stopProcess详解](停止进程详解.md)。隧道只负责转发，MCP认证和公共/API隔离仍在HTTP入口，不能把隧道URL当已授权会话。

## 1. 状态与调用顺序

每模块各有child、generation、cancelPending、stopping Promise及URL。启动前先stopTunnel，拿当前generation作ticket，await停止完成再检查ticket。更新过generation说明已有另一个start/stop替代本轮，旧启动抛superseded。子进程回调同时检查child===proc及ticket，阻止旧退出/旧输出污染新实例。

stopping串联旧停止、当前stopProcess、另一provider停止，**停止失败向await调用者传播**；旁支catch只防未处理拒绝，不把原Promise改为成功。旧停止Promise一旦拒绝也可能让后续链继续拒绝，不能描述成自动恢复所有停止失败。

## 2. cloudflared.js所有顶层函数

| 函数 | 参数/返回 | 实现/副作用 |
|---|---|---|
| parseTunnelUrl(chunk) | 日志文本→URL或null | 只匹配https随机trycloudflare域名，去末斜杠 |
| findCloudflared() | 无→路径或null | CLOUDFLARED_PATH存在优先，再where/which stdout split/map trim/find存在项，再平台常见路径guesses.find；exists不是可执行性或版本认证 |
| installHint() | 无→提示字符串 | Windows winget/手动PATH，其他系统安装提示；函数不下载安装 |
| stopTunnel() | 无→停止Promise | generation++，调用/清cancelPending，detach child和URL，置bridgeRunning=false；调用ngrok.stopNgrok，Promise.all等已有停止与stopProcess；全局状态先清不代表OS已退出 |
| canonicalNamedUrl(hostname) | 输入→https规范URL或null | trim小写、去http前缀、截路径、去数字端口/方括号，验证多标签域名；不是DNS解析/域名所有权验证，路径被忽略 |
| startNamedTunnel(options={}) | hostname/token/port/timeoutMs→Promise结果 | 详见下段；无效域名E_NAMED_HOSTNAME、空token E_NAMED_TOKEN |
| startQuickTunnel(options={}) | port/timeoutMs→Promise结果 | 停旧→ticket检查→查二进制，缺失E_NO_CLOUDFLARED，spawn Quick参数并等日志URL |
| snapshot() | 无→binary/url/running | 尝试ngrok.snapshot，优先实际cf实例，否则ngrok；URL回退config；running根据child且!killed，不是实时公网探针 |

### startNamedTunnel回调逐项

检查参数后stop/await/ticket；bin缺失E_NO_CLOUDFLARED。target只用于说明/返回，实际spawn args是`tunnel --no-autoupdate run --token tok`，**Public Hostname目标转发要在Cloudflare配置**，port不自动改远程映射。Windows只有.cmd/.bat路径才shell=true。

Promise内保存proc到child，buf尾65536字符，settled=false。timer按timeoutMs（默认25秒）触发：未settled才标终结，若仍是当前进程尝试stopTunnel，再reject；错误文案固定“25秒”，自定义超时时文案不随参数变。

**onData(chunk)**：过期回调返回；追加buf，按本chunk中完整tok替换日志后仅广播前400字符；NAMED_READY_RE检测连接注册日志，未settled才清timer、写quickUrl/config URL、广播tunnel_ready并resolve(url,binary,target,named:true)。这证明连接日志出现，不证明配置域名从手机可达。日志脱敏是chunk内文本替换，跨块敏感文本并不保证被替换；token作为进程参数也可能被有权限的系统进程查看。

**cancelPending箭头**：未settled才置true/清timer/reject cancelled。**clearActive()**：仅当前proc/ticket才清child/URL/bridgeRunning并广播stopped。stdout/stderr共用onData。error回调：无pid时clearActive，有pid且当前时stop；尚未settled则清timer/reject启动错。exit回调：clearActive，若启动还在等待则reject code+安装提示；成功后退出只更新状态，不再改变已兑现Promise。

### startQuickTunnel回调逐项

spawn args增加`--url target`，不需要Token。timer/cancelPending/clearActive/error/exit与Named同生命周期，独立闭包防互相使用错误proc。**onData**同样跨chunk累积尾缓冲、日志前400广播，parseTunnelUrl(buf)找到地址即标settled、清timer、写URL、broadcast/resolve；没有Named的token替换步骤。

### 进程级匿名回调

process.exit调用stopTunnel.catch，但Node exit事件不能可靠等异步清理完成。SIGINT/SIGTERM则stopTunnel.then，成功process.exit(0)、失败exit(1)。不要把exit监听解释为崩溃/强杀后必然无孤儿进程。

## 3. ngrok.js全部函数

| 函数 | 参数/返回 | 说明 |
|---|---|---|
| parseNgrokUrl(chunk) | 日志→URL/null | 优先JSON url字段，再url=/Forwarding标签（去标点），再通用https正则且必须ngrok域名族；前两种允许自定义域名，不是严格JSON解析 |
| resolveNgrokToken(token) | 参数→trim token | 非空参数优先，否则NGROK_AUTHTOKEN；未导出但启动使用 |
| findNgrok() | 无→路径/null | NGROK_PATH→where/which的split/map/find→平台guesses.find，与cf类似 |
| installHint() | 无→字符串 | 安装说明，不运行安装器 |
| stopNgrok() | 无→Promise<void> | generation++、cancelPending、清child/ngrokUrl/config/bridgeRunning，Promise.all等待旧链与stopProcess；不反向调用stopTunnel，避免循环递归 |
| startNgrokTunnel(options={}) | hostname/token/port/timeoutMs→Promise结果 | 见下段 |
| snapshot() | 无→binary/url/running | 查二进制+本模块URL+child状态，不读实际公网健康 |

**startNgrokTunnel**：resolve token空→E_NGROK_TOKEN；可选hostname规范失败→E_NGROK_HOSTNAME；require cloudflared.stopTunnel停两个provider，取得ngrok自己的ticket后await/校验；find缺失E_NO_NGROK。args为http+127.0.0.1:port+日志参数，named时加--url。token通过环境NGROK_AUTHTOKEN传入，不作为这里的命令行参数。

Promise内timer默认25秒、settled与child如cf。**finish(url)**一次性清timer、写ngrokUrl/config URL、broadcast tunnel_ready、resolve带ngrok:true；**onData**校验proc/ticket、累积65536、日志token替换/400裁剪；named且ready日志出现用用户规范域名，否则parsed URL即finish。**cancelPending/clearActive/error/exit**同cf语义，但停止委托stopNgrok。

所有broadcast同步调用都有可能被订阅者异常打断；例如已标settled/写URL后尚未resolve时抛错，没有本地try包装保证Promise必达终态。不要用文档保证强于当前eventBus实现的异常隔离。

## 4. 验证

```bat
npm test --prefix webagent-core/agent-host -- --filter=tunnel
npm test --prefix webagent-core/agent-host -- --filter=bridgeTunnel
```

大小写filter含具体文件名时以测试运行器匹配规则为准；tunnel相关用例检查解析、停止/替代竞争与生命周期，bridgeTunnel检查路由层。真实Cloudflare/ngrok账号、域名映射、Windows进程树和手机公网MCP仍是人工步骤，不由日志正则通过替代。
