# stopProcess：停止旧隧道的逐函数与回调讲解

## 职责与调用关系

源码 [stopProcess.js](stopProcess.js) 导出一个 stopProcess，供隧道模块在停止/替换子进程时等待。调用方仍需管理隧道代次、URL 和状态，见[模块说明](README.md)。本函数不建立隧道、不校验公网可用性、不关闭浏览器。

## 主函数 stopProcess(proc, graceMs = 1500)

输入 Node ChildProcess 和宽限毫秒，返回 Promise；**resolve 表示观察到退出或已无待运行进程，发出 kill 信号不是 resolve 的充分条件**。无 proc、exitCode/signalCode 已非 null 时直接返回已完成的 Promise。

其余情况新建 Promise，闭包保留 proc、resolve/reject 与 force/deadline 计时器。默认约 1500ms 后升级强制信号，约 3000ms 未观察到退出就拒绝。graceMs 本身没有范围校验，调用者应传合理值；unref 的计时器不会单独让 Node 进程保持存活。

## 执行流程与每个回调

| 函数/回调 | 何时执行 | 做什么、为什么 |
|---|---|---|
| Promise 执行器 | stopProcess 调用时同步执行 | 先注册事件/定时器再发信号，避免先退出而漏掉事件 |
| cleanup() | 已观察到退出或最终超时 | 清 force/deadline，并移除本函数安装的 exit/error 监听；不清理其他模块的监听 |
| exited() | proc 的一次性 exit 事件，或 errored 判断无进程 | cleanup 后 resolve；不检查退出码为 0，因为这里只需要确认旧进程不再占用 |
| errored() | proc 的一次性 error 事件 | 仅当没有 pid 且未 killed 时按“未产生可运行进程”走 exited；其他 error 不能证明已经退出，继续等 |
| force 定时回调 | graceMs 后仍等待 | 尝试 proc.kill('SIGKILL')；发送异常被捕获，不据此宣称成功 |
| deadline 定时回调 | graceMs * 2 后仍等待 | cleanup 后 reject，提示拒绝启动替代进程；调用方不能忽略失败再并行开一个 |
| Windows killer 的 error 回调 | 启动 taskkill 失败等发出 error | 尝试 proc.kill('SIGTERM')；本函数不把 taskkill 进程退出状态作为旧 proc 已退出的证明 |

安装完监听和计时器后，平台分支如下：

- Windows 且有 pid：启动 `taskkill /pid <pid> /t /f`，隐藏窗口、忽略输出。这是针对该 PID 的进程树，不是结束系统所有 Node。
- 其他情况：调用 proc.kill('SIGTERM')。
- 最外层发送动作抛错：捕获但仍等真实退出或 deadline。不能只因为 kill 返回/抛错，就断言进程已经停止。

## 正常与失败例子

正常：旧隧道 proc 收到停止 → 发 exit → exited 清理监听/计时器 → Promise resolve → 调用者才准备下一代隧道。

失败：停止信号未能结束进程 → force 尝试升级 → 仍无 exit → deadline reject → 调用者应暴露失败、不启动替代。这里的“拒绝替代”错误不是网络不可用的等价表述，而是进程生命周期没有得到确认。

## R5首包：只读隧道归属记录，不是残留回收器

`processIdentity.js`与`tunnelRegistry.js`不调用kill/taskkill，不按名称/端口扫描全系统，不改变bridgeRunning、URL或stopTunnel。新启动的cloudflare quick/named及ngrok各接一次observeTunnel，异步元数据失败不能阻止正常Bridge启动，固定警告也不打印Token/路径。旧版无记录进程不会被认领；没有图形清理按钮/API，只读报告cleanupAvailable/canCleanup恒为false；独立Windows终端入口见末节。

### processIdentity.js

- **validPid**只接受1–2147483647整数；**sameIdentity**同时比pid/start/executable，不把PID相等视为同一进程。
- **linuxIdentity**只读指定PID的/proc/stat、exe和系统boot_id；start为boot_id加启动ticks，读取exe前后复查启动ticks，僵尸/消失归absent，权限/中途变化或其他失败为unknown。它不是持有pidfd的原子终止能力。
- **inspectProcesses**最多64个PID，去重；Linux异步读取，Windows以系统目录PowerShell -NoProfile/-NonInteractive查询指定Process对象的StartTime UTC ticks和MainModule.FileName，路径小写规范，固定UTF8输出；不读取命令行/环境。每批8秒/128KiB，宿主最多两个并发Windows查询，超限/失败降为unknown；不插入非数字参数，不请求提权。macOS等尚未实现，返回unknown，不能据此认定不存在。Windows读取是诊断辅助进程，不是任意命令执行接口，也未证明消除了PID查询竞争。

### tunnelRegistry.js

- **validIdentity/validRecord**校验版本、UUID、平台、固定provider、正整数PID、有限身份字符串和不同宿主/目标PID；内容始终是不可信磁盘线索，不是清理授权凭据。
- **classify**先核对目标：absent→exited，不可读→unknown，身份不同→identity-changed。目标匹配但宿主无法确认或其PID被复用→unknown；宿主确认消失才orphan-candidate，身份匹配且活着则按instanceId分active-current/active-other。所有状态仍不可自动清理。
- **createRegistry**默认共用当前OS用户home下`.webagent/tunnel-processes-v1`；测试通过代码参数注入临时baseDirectory/inspect/instanceId/ownerPid，CLI不允许传路径/PID。不同项目的活宿主被识别为active-other，不扫其他用户。
- **directory(create)**解析home/base的真实路径，逐级拒绝子目录符号链接；POSIX还检查归属UID及不可组/其他写；创建mode0700。Windows模式位不是ACL认证，未来终止操作不能只信这些文件。没有对同UID恶意篡改作认证保证。
- **readRecords**opendir最多处理32个目录项，多余标complete=false，不无限readdir；每个合法UUID.json只读最多12KiB+1，检查普通文件、链接数、lstat/fstat身份及POSIX文件权限，拒绝静态链接/超限/坏JSON并统计invalidRecords。不会删除坏记录/旧记录或打印其正文；扫描与写入并发时可能看到暂不完整记录。v1继续读取但标unverified，v2载荷经批量解封和文件名UUID绑定验证后才标os-user-protected；标签取自本次验证，不读取记录自报的integrity/canCleanup。
- **scan/snapshot**只对记录内PID查询，snapshot共享一次在途扫描；返回固定provider/PID/状态/id，不暴露exe、时间标识、实例UUID或错误原文。缺目录为空且不创建目录；读取失败返回registry-unavailable/complete=false。complete只指这次有界记录扫描，并非全系统没有残留。
- **observe**接收已spawn的ChildProcess，不接收argv/Token，核对OS身份与实际可执行路径，拒绝cmd/bat包装器。每条随机UUID记录以wx/mode0600写入，无覆写；Windows新记录先做CurrentUser DPAPI封装，失败不降级明文，其他平台仍为未验证v1。写前复查exit及最终12KiB字节预算；容量不足/查询不可用只返回未记录状态，不停止隧道。多个宿主并发登记不是跨进程严格容量事务，扫描超32仍明确不完整。退出回调**clear**只异步移除本次创建的记录；查询/写入期间退出也复查，不能迟到写入有效存活记录。异常宿主退出未收到该回调时保留记录供后续检查。
- **observeTunnel**为三个provider调用点提供失效隔离，只输出固定“归属记录不可用，检测可能不完整”警告。没有守护隧道或自动回收的新承诺；原stopProcess行为不变。

### 回归与未完成项

`tunnelRegistry.test.js`的**main**在临时目录验证状态分类、PID/路径变化、权限未知、共享扫描、记录白名单且无Token、32项/12KiB边界、坏文件/链接、错误脱敏及迟到exit；实际OS读取自身和另一个存活Node，检测不得发信号。`tunnelOwnerFixture.js`只由测试fork，在临时目录登记显式detached的Node子进程并通过IPC报告（仅夹具如此，保证Windows也可构造实际孤儿，产品spawn不变）；测试强杀夹具宿主后，必须报告orphan-candidate且子进程和另一个存活进程均不被杀。夹具子进程凭私有stop文件自行退出并有60秒兜底；正常路径观察退出后删临时目录，失败时保留stop文件，不对未知PID补杀。Windows/Linux CI测试是受控Node夹具，不是真实Cloudflare/ngrok长挂或桌面验收。

`tunnelLifecycle.test.js`另用observeTunnel spy检查quick/named/ngrok每个spawn恰好接一次，不改变原启动/替换/取消/退出断言。Windows终端入口已接稳定句柄、清理前复核、有限预览、本机确认和结果核验，见末节；其他平台/图形入口仍待；不能把orphan-candidate直接接taskkill，更不能复用会关闭当前Bridge的stopTunnel。

命名辅助补充：linuxIdentity内部**readStat**两次读取同一指定PID的stat，第二次只核对启动ticks；Windows Promise内**unknown**把整批降为unknown而不传播原始错误。测试main中的**live**仅包装合成identity为alive，用于可控分类矩阵，不替代真实OS查询。


## R5第二包：Windows用户范围的记录完整性保护

保护模块本身不开放清理。DPAPI CurrentUser保护只说明数据能由该OS用户上下文解封、未被不知密钥的写文件者直接改写；**不证明记录一定由WebAgent生成，不隔离同用户任意代码执行者/管理员，也不能单独授权终止进程**。没有跨真实用户登录测试或权限提升。独立终端回收还须固定启动链、稳定句柄与清理前身份/活宿主复核及本机确认，见末节。

### receiptProtection.js / receiptProtection.ps1

- **supported**仅Windows为true。**unavailable**统一构造固定错误，不回显原始错误/记录。**validPayload**限定非空、≤16384字符的标准base64。
- **run(operation,items)**只接受protect/unprotect、最多32项；protect每项UTF8≤8192字节，整体JSON≤512KiB。宿主最多两个在途保护查询，超限直接失败，不排无限队列。仅调用系统目录PowerShell和随产品打包的固定ps1，NoProfile/NonInteractive，ExecutionPolicy Bypass只在该辅助进程参数中，不修改系统策略，也不能绕过组策略；失败不切换到不受保护方案。
- 数据仅经stdin，不放argv/env或拼接进脚本。8秒截止与512KiB捕获上限，辅助进程退出后校验结果数组等长、每项null或有界字符串。stdin错误不原样输出，finally释放在途计数。PS脚本设UTF8、载入System.Security，限定用途熵为WebAgent/tunnel-receipt/v2，以ProtectedData的CurrentUser进行Protect/Unprotect；逐项无法解封返回null，整批脚本失败只打印固定提示。
- **protect(record)**将JSON记录封装成仅version=2/protection/payload的载荷。单项失败抛错，禁止写回明文替代。**unprotect(envelopes)**一次批量解封并解析各JSON；非Windows全部返回null，不能因复制了v2文件就授信。Windows真实回归通过独立辅助进程往返中文/emoji数据与翻转密文字节；这不是跨用户/所有域策略实测。

### registry接线和兼容

目录名tunnel-processes-v1保留，代表旧目录布局，不意味着所有文件仍是v1明文。readRecords先有界读盘，将v2载荷收集后一次解封；**protectedIds**只由解封成功、validRecord及文件名ID匹配产生。伪造明文integrity或canCleanup无效；合法旧v1不会被扫描重写/升级。损坏/不可解封项计invalidRecords，整批保护辅助不可用则返回registry-unavailable/complete=false。snapshot新增integrity=unverified或os-user-protected，原分类、清理禁用不变。

**hasCapacity(root)**只有限枚举目录项，不为启动准入解封旧文件；达到32项拒绝新增记录，保留原跨实例非事务容量边界。observe在原OS身份检查后执行保护，保护等待期间若目标退出，写前复查阻止迟到记录；完成载荷仍须≤12KiB。任何封装错误只影响记录覆盖，不调用stopTunnel或修改Bridge状态。

### tunnelReceiptProtection.test.js

**main**以可控authority模拟验证边界，**live**包装身份行；fixture **protect/unprotect**用随机载荷到内存记录的映射，不冒充DPAPI密码学。覆盖保护标签、改密文、改文件名ID、伪造明文可信标签、旧记录不升级、不可用/失败不降级、保护中退出不写迟到记录；所有canCleanup仍false。Windows另走真实DPAPI跨辅助进程往返和坏密文、字节/批次预算；其他平台只测试明确拒绝保护，不能据Linux通过宣称Windows接口可用。tunnelRegistry原真实进程/孤儿/活实例测试保留，并在Windows解封后检查原记录字段与无Token合同。发行回归明确要求JS/PS保护辅助都在载荷中。


## R5第三包：Windows稳定句柄与本机确认回收

这是独立CLI路径，不给普通snapshot增加执行权，也不新增HTTP/MCP工具。信任边界是同OS用户的受保护记录与产品代码，加明确终端确认；**不防同用户任意代码/管理员伪造DPAPI或修改产品代码**。仅处理新版本记录的直接子隧道根进程，不回收任意子孙、旧版无记录、明文v1、cmd/bat包装器或非标准文件名。当前/其他宿主只要活着就跳过，哪怕UI已显示停止；不保证找全全机残留。

### 输入与租约控制（tunnelRegistry.js / tunnelCleanup.js）

- **cleanupSource**是内部本机入口：复用有界读盘/DPAPI验证，仅取protectedIds对应载荷，按id排序并对载荷清单算SHA256；旧明文/损坏统计skipped，扫描不完整则拒绝。不是公共API数据，不在普通报告返回载荷/路径。
- **failure**区分E_CLEANUP_NOT_STARTED和E_CLEANUP_UNKNOWN，不回显原始错误。**bounded**为来源读取设12秒等待预算，迟到结果不触发确认。**launchHelper**只启动固定系统PowerShell及tunnelCleanup.ps1，无用户脚本/PID参数，载荷走stdin，不提权。
- **createController/prepare**仅win32，实例内单个在途租约；最多32项、唯一UUID、v2载荷、≤512KiB消息。辅助启动/编译预览限15秒，stdout+stderr合计64KiB，严格UTF8/两帧JSON；错误、多帧、错nonce、结果改PID/provider均失败。**arm**切阶段计时器，**fail/stopHelper**只结束本次辅助进程，不向目标PID发信号。
- preview返回冻结records/skipped与**confirm/cancel/closed**。60秒内confirm只能消费一次，先锁checking，再重读来源指纹；变化/过期不得确认。通过后私有nonce送回同一辅助，8秒内等result帧及正常close，不仅凭一帧成功结案。确认后断连/异常退出/重复结果统一unknown，不自动重放。
- cancel/过期仅关辅助进程及其句柄；确认后取消不能撤销终止，可能unknown。closed在close后释放busy。只读snapshot继续canCleanup=false，因为没有持有执行租约。

### 原生对象身份与动作（tunnelCleanup.cs）

**WebAgentTunnelLease**构造器排除自身/CLI控制进程、无效PID和非标准映像名（cloudflare/named仅cloudflared.exe、ngrok仅ngrok.exe）。OpenProcess一次取得query/synchronize/terminate权限的SafeProcessHandle，非candidate立即**Dispose**，不提权或按PID补杀。

**Matches**在该句柄用GetProcessTimes取FILETIME转UTC ticks、QueryFullProcessImageName取路径，逐项比记录。**Check**先WaitForSingleObject，再核对身份，以NtQueryInformationProcess的BasicInfo核对实际PID/原始父PID；父PID必须是记录owner，不只信文件自报归属。**OwnerState**重新打开宿主查询句柄：任何仍活着的同PID对象（含复用）都阻止终止；明确不存在，或已退出且匹配原创建时间/路径，才gone。访问拒绝/失败为owner-unknown，不等于死亡。

**Commit**每个租约只消费一次，在原目标句柄重新Check，通过才对**同一句柄**TerminateProcess；不重开目标PID、不taskkill /t、不枚举进程名/端口。每项最多等500ms，PS循环总4秒，预算用尽后项not-started；观察退出才terminated，自行退出为exited，超时unconfirmed，发送失败failed。异常保守unconfirmed，finally关句柄。仅根进程，不承诺清掉未登记后代或回滚远端效果。

### 两消息协议（tunnelCleanup.ps1）

固定脚本Add-Type编译C#，独立CurrentUser DPAPI解封并核对文件名ID/平台/provider/数字创建标识，以PID+start去重防同批重复。仅输出id/provider/PID/status；私有nonce和preview发送后持有候选句柄。stdin EOF/坏确认不Commit，finally关闭全部租约；只有相同nonce的confirm才有限执行并发result。辅助被强杀时OS关闭句柄不等于TerminateProcess；确认已送达后的结果仍可能未知。

### 回归边界

`tunnelCleanup.test.js`的**helper/frame**用流模拟辅助，**main**验证无确认不动作、预览冻结、单租约/单次确认、来源漂移、重复结果unknown、提前退出、60秒过期、取消和管道CLI拒绝；不是Windows原生效果证据。

`tunnelCleanupWindows.test.js`的**main/startOwner/checkSkipped/stopped**只在Windows把Node复制为临时cloudflared.exe（未下载/运行真实隧道），验证活宿主、伪造父PID、错创建/映像、取消、来源变化、同名无关活进程保留、持有期间自行退出，以及确认后观察终止。Node夹具不是签名/Cloudflare功能验收，不涵盖所有权限环境或实际PID复用时序，用户桌面仍待。owner夹具仅新增可选测试程序路径，旧默认程序和60秒自退不变。图形按钮/非Windows回收仍待。
