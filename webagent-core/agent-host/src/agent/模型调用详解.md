# 模型调用、能力探测、截图与工具标签

## 职责与调用关系

本文展开 [openai.js](openai.js)、[providers.js](providers.js)、[computerUse.js](computerUse.js)、[toolLabel.js](toolLabel.js)。Chat 调度调用 OpenAI 兼容 API；设置页探测模型是另一条网络路径；截图辅助同时被 Chat 与 MCP 使用。逐函数阅读从[调度详解](Chat调度详解.md)衔接。

## 1. openai.js：全部函数与执行流程

### Provider响应与请求预算辅助器

| 函数 | 输入/返回 | 合同与边界 |
|---|---|---|
| isResponseRecord(value) | 任意值→boolean | 只接受非null、非数组对象；用于Provider响应和已解析arguments的运行时形状，不是权限证明 |
| encodeModelRequest(body) | 请求对象→JSON字符串或抛错 | 先JSON.stringify，再按UTF-8原始字节限制`MODEL_REQUEST_MAX_BYTES=12MiB`；超限抛`E_MODEL_REQUEST_TOO_LARGE`并在fetch前停止。不是Token估算，也不控制JS序列化瞬时内存 |
| normalizeAssistantMessage(data) | Provider JSON→`{message,calls}`或抛错 | 要求choices首项message；role只准缺省/assistant，content只准缺省/null/字符串；tool_calls只准数组且≤64项，逐项校验唯一有界ID、function类型/名字及≤256KiB arguments字符串，再要求JSON解析结果为非数组对象。返回message仅含固定role/content/tool_calls投影，内部calls另带已解析args；未知Provider字段不进入下一轮请求 |

### modelSeesImages(model)

无对象返回 false；vision===true 则 true；否则选 caps 数组（即使为空），只有 caps 非数组才退到 capabilities，再 some 匹配包含 vision 的字符串。是声明检查，不调用模型试图像；caps 的匹配不是严格枚举，不能当已验证视觉质量。

### systemPrompt(mode)

返回 system 文本，且读取 customizations、扫描画像/技能，**不是完全纯格式化**。mode==='code' 时提示允许文件修改与命令，其他 mode 提示只读；plan 另加方案指令。结合 resolveEnvironment 选择回复语言和 shell 提示，拼 workspace instructions 与 formatWorkspaceContext，filter(Boolean) 去空段。

提示词不是安全边界，权限仍靠工具执行层。环境偏好只改变提示，不会切换实际 Python/Conda/终端。mode 调用者必须提供合适字符串；这里调用 toUpperCase，不负责任意输入校验。

### temperatureFor(level)

low→0.1，medium→0.4，其余→0.7；返回普通数字。它只设采样温度，不等价于供应商的 reasoning token/思考预算参数。

### gptVersion(modelId)

从modelId取`gpt-<主>[.<次>]`版本号，允许任意层提供方前缀（`openai/`、`openrouter/openai/`）；次版本缺省为0。gpt-4o、gpt-4.1、非gpt名称返回null。只看名称，不联网查询模型能力。

### isReasoningModel(modelId)

o系列（o1、o3-mini、o4-mini-2025-04-16等，o后紧跟数字）或gpt-5及以后（含gpt-6）返回true。`omni-model`、`llama-3.1-o1-distill`、deepseek-reasoner等其他名称返回false，维持temperature。

### toolsNeedNoEffort(modelId)

gpt-5.4及以后（含全部gpt-6）返回true。这些模型在chat/completions上同时收到function tools与非`none`的reasoning_effort会返回`400 Function tools with reasoning_effort are not supported for <model> in /v1/chat/completions. To use function tools, use /v1/responses or set reasoning_effort to 'none'`；gpt-5.5起默认effort为medium，所以**不发该字段同样失败**。gpt-5/5.1/5.2与o系列仍可带工具使用effort，返回false。依据：OpenAI模型页（gpt-6-luna写明Chat Completions仅在reasoning_effort为none时支持函数调用）、Azure推理模型文档与多个开源项目的真实400报告；未对真实OpenAI账号实测。

### samplingParams(modelId, level, withTools=false)

决定请求体里承载“思考 低/中/高”的字段（F70）。推理模型族（isReasoningModel）拒绝自定义temperature，OpenAI返回`400 Unsupported value: 'temperature' ... Only the default (1) value is supported`；而本模块刻意不回显提供方错误正文，用户只看到“模型 HTTP 400 请求失败”，每次请求都失败。规则按顺序：

1. 非推理模型维持temperatureFor映射。
2. 名称含`-chat`段的推理族变体（gpt-5-chat-latest、gpt-5.2-chat-latest等）是非推理模型但同样不接受自定义温度，两者都不发。
3. 本次请求带工具且toolsNeedNoEffort为真：发`reasoning_effort:'none'`。这是只走chat/completions时唯一能带工具的取值，代价是这类模型在带工具请求里**不做推理**、思考强度不生效；runOpenAI会在首条status里写明。要让它们带工具推理需改走/v1/responses，属于另一工作包。
4. 其余推理模型发送同三档`reasoning_effort`（缺省high），不发temperature。

两个字段在chat/completions中都是可选的。只按配置的modelId判断，名称不匹配的兼容端点（例如自建代理把推理模型换了名）仍按名称处理；未对真实OpenAI账号实测。不处理：`-pro`变体（如gpt-5.5-pro）只在Responses API提供，本模块无法调用；o1-mini不接受reasoning_effort，但已于2025-10-27下线，不专门分支。

### runOpenAI({mode,message,history=[],emit,model,thinkLevel,allowTools=true,extraSystem}={})

返回 Promise<{text}>；服务/格式错误抛出。内部 send 选 emit 函数或空箭头回调；model非对象会明确报配置无效，空baseUrl仍报错，不自动生成模型配置。message/extraSystem存在时必须是字符串；缺省消息兼容为空字符串。

**准备阶段：** 去 baseUrl最后一个斜杠；allowTools 时 getToolList(mode).map 成 OpenAI function schema。history只保留非数组对象中content为非空字符串且角色为user/assistant的项，slice取最后12条，再map留role/content；不做按Token裁剪，也不保留历史tool消息或调用方未知字段。system+extraSystem合并，追加当前user。

**请求循环：** 最多10轮，每轮发status、checkCancelled，先以encodeModelRequest序列化完整model/messages/采样字段（samplingParams按是否带工具决定temperature或reasoning_effort；effort被强制为none时首轮status附“思考强度本次不生效”）/tools并限制`MODEL_REQUEST_MAX_BYTES=12MiB`；超限在fetch前失败。随后经fetchText POST `<base>/chat/completions`，带Bearer与JSON。请求显式`redirect:'error'`，不会把3xx跟到另一端点；响应在解析前以原始字节逐块限制为`MODEL_RESPONSE_MAX_BYTES=1MiB`，刚越界即尝试取消reader并抛`E_RESPONSE_TOO_LARGE`。成功和HTTP错误正文共用此上限；120秒deadline覆盖fetch和body并继承Chat父取消。这里没有`stream:true`：有界读完整份JSON后才处理，**不是逐token SSE模型流**；上层NDJSON的status/tool/message是另一层“流”。模型列表探测使用providers自己的15秒/512KiB reader，不复用本路径。

**解析：** 非2xx只抛固定的模型HTTP失败及数字状态，不拼接远端正文；因此runChat向UI传错时也不会反射Provider错误页中的Token或任意文本。非JSON/缺choices[0].message分别抛固定错误。normalizeAssistantMessage在追加上下文前完成整份assistant/tool-call验证：错误role/content、非数组或超过64项tool_calls、重复/非法ID、非function调用、非法名字、非字符串/超过256KiB/非对象JSON arguments都会使整轮失败，且不会执行前面看似合法的调用。形状通过后还逐项要求function.name属于本轮实际发送的工具声明；隐藏、当前模式未声明或allowTools=false下的任何调用都在追加message与callTool前失败。成功后只把固定投影message加入下一轮；Provider附带的任意authorization/metadata或function未知属性不会被回送。状态码、形状、预算与固定错误仍不证明端点内容可信。

**工具循环：** 遍历最多64个已经完整验证的tool calls；前8项用预先解析的对象args执行，其余每个ID都回复一个“未执行/上限8”的JSON错误，避免悬空ID。arguments解析失败不再退为`{}`或触发任何工具；它属于模型协议失败并终止本次runOpenAI。

每项记录耗时并callTool(name,args,mode)，再用共享`isToolFailure`覆盖ok/success=false、isError/isTimeout、非零退出、失败/取消/unknown状态或trace及unknown核验。确认成功发`ok:true`工具事件；返回式失败发`ok:false`并保留result与归一错误。两者都把`clipJson(result,12000)`作为tool消息，因此模型能看到operation_result等终态详情，而不是把“正常return”画成成功，也不把原结果替换成无上下文异常。真正抛出的异常仍发失败事件并回复`ERROR: ...`。之后可执行其余工具/下一轮；不是“一个工具失败就整个Chat停止”。allowTools=false现在产生空的已声明工具集合，Provider即使自行返回tool_calls也会在工具循环前被拒绝；执行层的mode检查仍是第二道边界，不替代声明集合门禁。

只有非失败的run_command才调用collectShot：过大时加入诚实不可见提示；有dataUrl且模型声明支持视觉时追加带image_url的user消息；不支持则提示无法看图。失败结果即使带路径也不进入成功截图分支。状态事件不包含base64。截图处理/emit出错仍可进入工具异常catch，先前已执行的命令不会回滚。

无tool_calls时取已验证的字符串content或占位文本，emit message并返回；null/缺省content规范化为null，数组/对象等错误类型在此之前已拒绝。10轮用完发“已达到最大工具轮次”并返回文本，不提供自动任务成功认证，也不验证最终回答是否与磁盘一致。

## 2. providers.js：模型发现与仅追加登记

此处是用户配置Provider时的 `/models` 发现，不是暂停的身份/轨迹探针。网络读取和配置写入是两个独立动作；发现列表不证明Chat、工具、视觉或订阅兼容性。

| 函数 | 参数/返回 | 关键处理与失败 |
|---|---|---|
| normalizeBase(url) | URL样文本→字符串 | trim，去末尾斜杠，再去尾部 `/chat/completions`（忽略大小写）；单独调用不是URL安全校验 |
| probeCaps(m) | 对象→字符串数组 | 按非空capabilities、supported_features、caps优先级map(String)；不凭名字猜能力 |
| probeContext(m) | 对象→展示字符串 | 取上下文声明；有限数≥百万显示M、≥千显示K，否则String；声明不证明真实可用预算 |
| providerError(message,status=400) | 固定文案→Error | 400/E_BAD_PROVIDER或409/E_PROVIDER_EXISTS，不拼接原始凭据/响应正文 |
| providerEndpoint(value) | ≤2048字符→规范化HTTP(S)base | 拒控制/内部空白、userinfo、query、fragment及其他协议；URL规范化主机/默认端口，去尾斜杠；不禁止用户明确指定的本机端点，不是SSRF/网络隔离证明 |
| providerKey(value) | 输入→trim后Key | 非空、原输入≤4096字符，拒脱敏四圆点及非可见ASCII；不验证Key真实有效，不写日志 |
| providerCatalog(list) | 列表→新展示对象列表 | 1–100项；每项只接受id/name/contextSize/caps/pricing；模型ID非空、trim后唯一、≤256且无控制字符；name≤256、contextSize≤64、pricing≤256，caps≤32个≤128字符字符串；拷贝白名单字段和caps，不保留任意远端或调用方属性 |
| fetchProviderText(base,key,timeoutMs) | 已校验配置→Promise文本 | 15秒默认期限由调用方传入，覆盖headers/body；GET models禁止重定向，Bearer只发明确端点；reader逐块累积≤512KiB，超限拒绝不解析；不回显HTTP错误正文 |
| listRemoteModels(baseUrl,apiKey,{timeoutMs=15000}={}) | 配置→Promise展示列表 | 校验Endpoint/Key，读取JSON，接受顶层数组或data数组；对象含id或name、上下文/能力声明，经providerCatalog统一验证；非字符串pricing舍弃。只读，不保存、不自动手动回退 |
| addProvider(input) | {baseUrl,apiKey,vision?,models}→保存结果 | 不联网；包装及每条目录项先按固定schema拒绝未知字段，再验证并构建标准chat.completions记录，仅追加整个已验证批次；旧目录加本批总计不得超过100项；返回success/added/原activeModelId，不返回Key |

**fetchProviderText生命周期**：checkCancelled读取父scope，内部abort连接父信号和deadline，headers取得后拿reader；每次read前后检查取消。累计原始字节后统一UTF8解码，避免切断中文。finally清timer/父监听、abort并取消reader；失败不重试。15秒期限早已存在，本批新增流式字节预算及实际路由断连传播，不能把旧超时重复算新增。单chunk由底层传输提供，预算限制应用累计，非进程总内存上限。

**addProvider保存边界**：group取规范Endpoint的host（含非默认端口）；本地ID为provider-加SHA256(JSON.stringify([baseUrl,远端ID]))，不同端点/原ID不再因标点替换碰撞，也不靠Key命名。vision由本次显式勾选或声明caps给出，未测试真实能力。读取当前store保存记录保留旧Key，检测同ID或旧版同规范Endpoint/modelId，任一冲突409且不写；不能用Add更新旧密钥。旧目录加本批总数超过100也在保存前400，不能靠多个各≤100的批次绕过整表预算。全部预检后同步load/check/save，在同一host无await，保留旧模型、活动模型、Bridge及其他配置。普通POST models现另经modelSettings严格校验，而非开放历史整表覆盖；两者都不是跨进程CAS、通用撤销或fsync保证，保存未知效果先核对，不自动重放。

## 3. computerUse.js：七个函数与图片数据

常量 COMPUTER_USE_DIR 指产品 computer-use 根，MIME 只收 PNG/JPG/JPEG，MAX_BYTES=6MiB。

| 函数 | 输入 → 输出 | 做什么与限制 |
|---|---|---|
| stripQuotes(s) | 文本→去首/尾引号文本 | 正则仅处理两端，不是 shell 解析器，也不解转义 |
| findShotCandidates({command='',stdout=''}={}) | 命令/输出→路径列表 | 依次提取命令 `-Out`、输出JSON out字段、裸图片token；out字段先按JSON字符串解码（mark.cs自F72起输出转义路径），解码结果不同且不含控制字符才作为候选，原文也保留一份以兼容旧脚本副本（旧原样路径如`C:\temp\new.png`会被误解成制表符/换行而丢弃解码结果）；filter(Boolean)，不去重，不能精确理解所有复杂引号/空格 |
| realOrSelf(p) | 路径→realpath或原路径 | realpath 异常吞掉并返回输入；不代表输入已存在/安全 |
| inside(child,parent) | 两路径→boolean | 同路径或带分隔符的子路径前缀比较；不单独做大小写归一 |
| resolveShotPath(raw,roots={}) | 候选→允许的绝对真实路径或null | 相对路径按工作区；扩展名允许，且 realpath 位于工作区或已存在的 computer-use 根；不读图片正文 |
| readShotAsDataUrl(abs) | 路径→{dataUrl,bytes,mime}或null | stat 普通非空≤6MiB，readFileSync 转base64；异常吞掉。**独立调用不检查白名单**，主入口先 resolve |
| collectShot(input={},roots={}) | 命令/输出→第一张结果、tooBig或null | 遍历候选，resolve后尝试读取；成功附 abs/相对工作区 rel；读取失败再stat，过大则立即返回 tooBig，不继续挑后面的图；其他失败继续 |

白名单内可能有与本次命令无关的旧图片；找到路径不证明图片是刚生成的。readShotAsDataUrl 用 stat 后整文件读取，没有复用 boundedFile；外部文件在 stat/read 间增长或替换不是这里完全消除的风险。rel 指向允许的 computer-use 外部目录时可能带 `..`，这不等于该图片越过了允许根。

Chat 把 dataUrl 进请求体，MCP 转成 image 内容；既不是 OCR，也不证明点击/输入成功。只看本文件早期注释或 openai 旧注释推断“MCP 只回文本”会读错当前调用链。

## 4. toolLabel(name,result,ok)

返回显示标签，不改变结果、不判业务成功；ok 来自调用方。失败的目录/读文件返回泛化标签，其余返回工具名。成功按工具名分支：目录用 dirPath，find_files 用 total（空值才退 files.length），search 用 totalMatches，read 用 files 数或路径，命令用 command，Skill 用命中名字或目录数量，补丁用 filePath，git_status/set_todos 用固定短词，其他保留 name。

别名 list_dir/read_file/grep_search/execute_command 在部分分支兼容；标签中的 Found/Patched 不是文件已验证的独立证据。长命令未在这里裁剪，UI负责展示安全。

## 5. 验证与学习练习

```bat
npm test --prefix webagent-core/agent-host -- --filter=modelLifecycle
npm test --prefix webagent-core/agent-host -- --filter=providers
npm test --prefix webagent-core/agent-host -- --filter=chatVision
npm test --prefix webagent-core/agent-host -- --filter=toolLabel
```

这些测试涵盖工具反馈、能力字段、截图附加与标签；真实 API/图片客户端/Windows 桌面另按人工清单验证。练习：说明为什么模型列表成功不等于模型调用成功；为什么9个 tool_call 得到9个反馈但最多执行8次；为什么不能从标签判断磁盘修改/测试通过。

toolLabel在目录读取失败时返回Explore failed，文件读取失败返回Read failed，避免失败记录仍暗示成功。
