# 模型调用、能力探测、截图与工具标签

## 职责与调用关系

本文展开 [openai.js](openai.js)、[providers.js](providers.js)、[computerUse.js](computerUse.js)、[toolLabel.js](toolLabel.js)。Chat 调度调用 OpenAI 兼容 API；设置页探测模型是另一条网络路径；截图辅助同时被 Chat 与 MCP 使用。逐函数阅读从[调度详解](Chat调度详解.md)衔接。

## 1. openai.js：全部函数与执行流程

### modelSeesImages(model)

无对象返回 false；vision===true 则 true；否则选 caps 数组（即使为空），只有 caps 非数组才退到 capabilities，再 some 匹配包含 vision 的字符串。是声明检查，不调用模型试图像；caps 的匹配不是严格枚举，不能当已验证视觉质量。

### systemPrompt(mode)

返回 system 文本，且读取 customizations、扫描画像/技能，**不是完全纯格式化**。mode==='code' 时提示允许文件修改与命令，其他 mode 提示只读；plan 另加方案指令。结合 resolveEnvironment 选择回复语言和 shell 提示，拼 workspace instructions 与 formatWorkspaceContext，filter(Boolean) 去空段。

提示词不是安全边界，权限仍靠工具执行层。环境偏好只改变提示，不会切换实际 Python/Conda/终端。mode 调用者必须提供合适字符串；这里调用 toUpperCase，不负责任意输入校验。

### temperatureFor(level)

low→0.1，medium→0.4，其余→0.7；返回普通数字。它只设采样温度，不等价于供应商的 reasoning token/思考预算参数。

### runOpenAI({mode,message,history=[],emit,model,thinkLevel,allowTools=true,extraSystem}={})

返回 Promise<{text}>；服务/格式错误抛出。内部 send 选 emit 函数或空箭头回调；model 不提供时会在读 model.baseUrl 时出错，而不是自动生成模型配置。

**准备阶段：** 去 baseUrl 最后一个斜杠，空值抛错；allowTools 时 getToolList(mode).map 成 OpenAI function schema。history 的 filter 只保留有 content 的 user/assistant，slice 取最后12条，再 map 留 role/content；不做按 Token 裁剪，也不保留历史 tool 消息。system+extraSystem 合并，追加当前 user。

**请求循环：** 最多10轮，每轮发 status，checkCancelled，经 fetchText POST `<base>/chat/completions`，带 Bearer、JSON、model/messages/temperature，非空工具列表才加 tools/tool_choice。这里没有 `stream:true`：读取整个响应 JSON，**不是逐 token SSE 模型流**；上层 NDJSON 中的 status/tool/message 事件是另一层“流”。fetchText 有120秒默认截止及父取消，但模型列表探测不复用它。

**解析：** 非2xx 抛 HTTP状态和前240字符；非JSON/缺 choices[0].message 分别抛错；将 msg 追加本轮上下文。有非空 tool_calls 时要求数组、每项有字符串 id、id 唯一，some/map/Set 回调完成校验。

**工具循环：** 遍历全部 tool_calls；前8项执行，其余每个 id 都回复一个“未执行/上限8”的 JSON 错误，避免悬空 ID。参数 JSON 解析失败会退为 `{}`，随后交工具参数检查，而不是把原始解析错误直接返回。

每项记录耗时并 callTool(name,args,mode)；ok/success=false 转成失败。成功发 tool 事件（原始结果），把 clipJson(result,12000) 作为 tool 消息。异常发失败 tool 事件并回复 `ERROR: ...`，之后仍可执行其余工具/下一轮；不是“一个工具失败就整个 Chat 停止”。allowTools=false 主要是不发送工具声明，响应分支仍存在；若供应商自行返回 tool_calls，最终限制仍依赖 callTool 的 mode，不能把它当独立执行断路器。

run_command 成功还调用 collectShot：过大时加入诚实不可见提示；有 dataUrl 且模型声明支持视觉时追加带 image_url 的 user 消息；不支持则提示无法看图。状态事件不包含 base64。由于本段在工具 try 内，截图处理/emit 出错也可进入工具失败 catch，先前已执行的命令不会回滚。

无 tool_calls 时取 msg.content 或占位文本，emit message 并返回；10轮用完发“已达到最大工具轮次”并返回文本，不提供自动任务成功认证。没有严格验证 content 的运行时类型，也不验证最终回答是否与磁盘一致。

## 2. providers.js：探测不是兼容性认证

| 函数 | 参数/返回 | 关键处理与失败 |
|---|---|---|
| normalizeBase(url) | URL样文本→字符串 | trim，去末尾单斜杠，再去尾部 `/chat/completions`（忽略大小写）；不是完整URL规范器 |
| probeCaps(m) | 对象→字符串数组 | 按非空 capabilities、supported_features、caps 优先级，map(String)；都没有返回[]，不凭模型名猜 |
| probeContext(m) | 对象→展示字符串 | 取 context_length/context_window/max_model_len/contextSize 第一个真值；有限数≥百万显示M，≥千显示四舍五入K，否则 String；不验证是真正可用上下文 |
| listRemoteModels(baseUrl,apiKey) | 配置→Promise<模型展示列表> | normalize，缺URL/Key拒绝；GET `/models`，非成功含状态/前200字符，非JSON给指引；接收 data 数组或顶层数组，空表拒绝 |

listRemoteModels 的立即执行匿名函数从 URL 主机名去 api. 前缀后取首段作为 group，失败返回 provider。map 每项用 id 或 name，附 probeContext/probeCaps/pricing；不生成本地唯一模型ID，不验证每个元素是完备对象。

**网络边界：** 这里直接 fetch/read text，没有显式 timeout、父取消、响应体字节上限；不能把 runOpenAI 的120秒保证套到设置页探测。列表里出现模型也不证明聊天、工具调用或图片真的支持。

## 3. computerUse.js：七个函数与图片数据

常量 COMPUTER_USE_DIR 指产品 computer-use 根，MIME 只收 PNG/JPG/JPEG，MAX_BYTES=6MiB。

| 函数 | 输入 → 输出 | 做什么与限制 |
|---|---|---|
| stripQuotes(s) | 文本→去首/尾引号文本 | 正则仅处理两端，不是 shell 解析器，也不解转义 |
| findShotCandidates({command='',stdout=''}={}) | 命令/输出→路径列表 | 依次提取命令 `-Out`、输出JSON out字段、裸图片token；filter(Boolean)，不去重，不能精确理解所有复杂引号/空格 |
| realOrSelf(p) | 路径→realpath或原路径 | realpath 异常吞掉并返回输入；不代表输入已存在/安全 |
| inside(child,parent) | 两路径→boolean | 同路径或带分隔符的子路径前缀比较；不单独做大小写归一 |
| resolveShotPath(raw,roots={}) | 候选→允许的绝对真实路径或null | 相对路径按工作区；扩展名允许，且 realpath 位于工作区或已存在的 computer-use 根；不读图片正文 |
| readShotAsDataUrl(abs) | 路径→{dataUrl,bytes,mime}或null | stat 普通非空≤6MiB，readFileSync 转base64；异常吞掉。**独立调用不检查白名单**，主入口先 resolve |
| collectShot(input={},roots={}) | 命令/输出→第一张结果、tooBig或null | 遍历候选，resolve后尝试读取；成功附 abs/相对工作区 rel；读取失败再stat，过大则立即返回 tooBig，不继续挑后面的图；其他失败继续 |

白名单内可能有与本次命令无关的旧图片；找到路径不证明图片是刚生成的。readShotAsDataUrl 用 stat 后整文件读取，没有复用 boundedFile；外部文件在 stat/read 间增长或替换不是这里完全消除的风险。rel 指向允许的 computer-use 外部目录时可能带 `..`，这不等于该图片越过了允许根。

Chat 把 dataUrl 进请求体，MCP 转成 image 内容；既不是 OCR，也不证明点击/输入成功。只看本文件早期注释或 openai 旧注释推断“MCP 只回文本”会读错当前调用链。

## 4. toolLabel(name,result,ok)

返回显示标签，不改变结果、不判业务成功；ok 来自调用方。失败的目录/读文件返回泛化标签，其余返回工具名。成功按工具名分支：目录用 dirPath，find_files 用 total（空值才退 files.length），search 用 totalMatches，read 用 files 数或路径，命令用 command，Skill 用命中名字或目录数量，补丁用 filePath，git_status/set_todos 用固定短词，其他保留 name。

别名 list_dir/read_file/grep_search/execute_command 在部分分支兼容；标签中的 Found/Patched 不是文件已验证的独立证据。长命令未在这里裁剪，UI负责展示安全。
