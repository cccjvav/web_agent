# store.js：配置读取、校验、保存与秘密文件保护

## 职责与数据流

[store.js](store.js) 同步读写当前工作区 `.webagent/config.json`。调用方包括启动身份持久化、模型设置、Bridge身份和用量身份查询。它不存 OAuth access/refresh token，也不管理 customizations 的四文件写入。

```text
load → 读取/JSON/validateConfig → 默认值合并与normalize → 返回对象
patch → load → 合并部分字段 → save
save → validate新值 → 若旧文件存在先load确认可读 → 临时文件 → rename
     → 尽力设置权限/忽略规则 → 返回cfg
```

所有读取/写入都是同步；单文件临时替换不等于跨进程锁、fsync持久性或多文件事务。

## 1. 路径、默认值和正规化函数

| 函数 | 输入→返回 | 关键细节 |
|---|---|---|
| dir() | 无→绝对路径 | workspaceRoot下.webagent；只算路径、不创建 |
| storePath() | 无→绝对路径 | dir()/config.json，不是项目源码目录下固定配置 |
| defaults() | 无→新对象 | 内置活动模型、multiModel与local-demo Bridge默认；每次创建，不共享一个默认对象 |
| clampBranches(n) | Number转换→2–8整数 | 非有限默认4，其余四舍五入限幅 |
| normalizeMultiModel(mm) | 部分对象→新对象 | 合并默认，钳制maxBranches；enabled/mergeAllowsRead非布尔重设true，mergeModel/thinkLevel假值回默认；不是全部枚举校验 |
| isFakeGithub(b) | bridge对象→boolean | provider=github但无githubId且用户名空/demo/local时为真；b应是对象，不处理undefined |
| normalizeBridge(bridge) | 部分对象→新对象 | 合并默认，旧license迁local-demo；假GitHub迁回local-demo；local-demo/demo改local；provider仍为github就设loggedIn/deviceAuthorized=true |

normalizeBridge 是历史兼容与本地身份展示，不会联网重新认证 GitHub。默认 local-demo 的 loggedIn=true 也不是“已通过 GitHub/OAuth/模型认证”。

## 2. validateConfig(value)

返回原对象引用，非法则抛 Error。要求顶层为非数组对象；bridge/multiModel若非null必须是非数组对象；models若给出必须数组，每个模型需要非空字符串id且不重复，name/protocol/baseUrl/apiKey/modelId给出时须为字符串；activeModelId给出时须字符串。

这只是选择性的 schema 检查：不要求 activeModelId 必然存在、不检查所有嵌套字段类型、URL真实性或Key有效性。没有将“字段是字符串”和“完整可调用模型”混为一谈。

## 3. load() 与 save(next)

### load()

readFileSync → JSON.parse → validateConfig。输出合并 defaults/raw，models为空或未设就补内置默认；bridge与multiModel单独normalize。保留未特别处理的顶层字段。

任何 ENOENT 走 defaults，不写文件；其他读取/JSON/schema错误统一抛 code=E_CONFIG_CORRUPT 并提示原文件保留。没有偷偷备份后重置，也不输出配置正文；权限问题同样不可误认为“没有配置”。

### save(next)

先验证新对象；若目标已存在先 load，防止覆盖坏/不可读旧配置。因此 reset 也不是损坏配置的强制修复入口。

合并新值中的bridge/multiModel正规化结果，创建目录。临时文件名含随机8字节hex，用 wx 防覆盖、mode0600写入格式化JSON；rename替换目标。finally尝试unlink临时文件，ENOENT忽略、其他错误抛出；写入/rename失败不被伪装为成功。若rename已成功而清理遇到异常，错误也可能发生在新内容已落地之后，不能推断抛错必然“什么都没改”。

最后 restrictFileMode、protectWorkspaceSecrets，返回cfg。不存在fsync调用，也没有对另一进程的read-modify-write做事务锁；突然断电/跨进程写入行为不能只靠rename推断。

### patch(partial)

load当前值，顶层浅合并；bridge单独浅合并并normalize，multiModel浅合并随后save时normalize，models使用partial.models或旧数组。不是递归合并全部字段，模型数组整体替换。空数组是真值，可保存为空，但下次load会补默认模型。

### reset()

`save(defaults())`，会覆盖正常配置为默认并保留save全部保护规则；旧配置坏了仍拒绝写。不是删除全部 `.webagent` 用户数据。

## 4. Git 忽略与权限：全部辅助函数

固定保护名单 SECRET_REL 是 config/read-hashes/usage 三个文件；NESTED_NAMES为同样的文件名。不是所有敏感材料的自动发现器。

| 函数 | 参数/返回 | 操作及失败处理 |
|---|---|---|
| restrictFileMode(file) | 路径→undefined | 尽力chmod0600，失败吞掉；Windows ACL不能因此宣称隔离完成 |
| gitignoreLines(text) | 文本→有效行数组 | split换行，map trim，filter去空/注释；不实现完整Git模式语法 |
| lineCovers(pattern,rel) | 模式/相对路径→boolean | 归一分隔符，对常见精确路径、.webagent目录、basename等写死规则比较；不是Git自身解析器，不完整处理否定/规则顺序 |
| alreadyIgnored(text,rel) | 文本/路径→boolean | some调用lineCovers，任一认为覆盖即true；不能替代git check-ignore的完整语义 |
| detectEol(text) | 文本→CRLF或LF | 只要包含CRLF就选CRLF，否则LF |
| ensureNestedIgnore() | 无→undefined | 创建.webagent，读取其.gitignore（错误当空）；filter缺失名单，保留风格并追加保护块；可能写磁盘 |
| ensureWorkspaceGitignore() | 无→undefined | 只有workspaceRoot/.git存在才处理根.gitignore；读取错误当空，filter缺失规则后追加；不能解决已跟踪文件 |
| protectWorkspaceSecrets() | 无→undefined | 依次确保两层ignore、已有config权限；整个try错误吞掉，一步失败可跳过后续；属于尽力保护，不是保证 |
| trackedSecretFiles() | 无→路径数组 | 有.git时spawnSync git ls-files -z查固定名单，4秒超时；非0/异常返回[]；split/map归一/filter空项。不扫描所有Git历史或未知秘密 |
| warnTrackedSecrets(log) | 可选日志函数→命中数组 | 调trackedSecretFiles，非空才打印“gitignore不能阻止已跟踪文件”的提示；不自动修改索引/删除文件 |

trackedSecretFiles返回空可能是“没有命中”，也可能Git不可用/超时，不能充当无秘密认证。append ignore不等于撤回已推送凭据；日志只给路径，仍要按安全流程处理泄露。

## 5. 验证与复盘

```bat
npm test --prefix webagent-core/agent-host -- --filter=auditStorage
npm test --prefix webagent-core/agent-host -- --filter=hostPersist
npm test --prefix webagent-core/agent-host -- --filter=stateIntegrity
```

检查坏配置保留、身份持久化、选择性的结构与状态回归；不是所有磁盘故障排列或Windows ACL验证。练习：逐步解释load不存在、load坏JSON、patch模型列表、reset坏配置、git已跟踪秘密这五条路径。再与[定制/画像/记忆详解](画像与记忆详解.md)比较，不要把store的保证套到其他文件。
