# 定制、画像与记忆：逐函数和字段解释

## 职责与协作

[customizations.js](customizations.js) 存设置与配套Markdown；[profile.js](profile.js) 从偏好/目录线索生成环境和技术栈描述；[memory.js](memory.js) 管按UTC日期的Markdown记忆。三者不共享 [store](配置存储详解.md) 的持久化保证。

## 1. customizations.js

### file() 与 defaults()

file通过resolveSafePath取得工作区`.webagent/customizations.json`路径，检查敏感/忽略策略及已有路径的真实目标，不再裸拼接绕过边界。defaults每次给新对象：preference自由文本；environment的os/shell默认auto、回复/提交语言中文；techStack提供语言/框架/包管理器/测试命令/备注；instructions为指令正文；agents/prompts内置模板；hooks/mcpServers/plugins/quickLinks默认空；voice/dictation空；codex为未登录占位。

有一个配置字段不等于已经有对应运行插件/语音/Codex功能。消费者决定哪些字段真正生效，不能从JSON模板推断产品能力。

### 固定schema辅助函数

- **invalidCustom(message)**只抛ProtocolError `E_BAD_ARGS`；消息描述字段类别而不拼接输入值。
- **isRecord(value)**只接受非null、非数组对象。
- **text(value,field,maxBytes)**要求字符串、UTF-8字节不超预算且无NUL；失败经invalidCustom。preference/instructions单字段最多沿用MAX_TEXT_BYTES，环境/技术栈字段64KiB，名称/URL等列表字段使用更小预算；最终输出仍另受8MiB总预算。
- **fixedStringRecord(value,fields,label,strict)**按fields逐项类型/预算验证并新建固定投影。strict时拒绝未知键；读取历史文件时strict=false会忽略未知键，但已知键错类型仍失败，不把损坏值伪装成默认。
- **fixedList(value,label,strict)**要求数组且最多100项，再按agents、prompts、hooks、mcpServers、plugins、quickLinks各自字段表调用fixedStringRecord；plugins兼容有界字符串旧项，其它项必须对象。未知项字段不会进入投影。
- **normalizeCustom(value,{strict=true})**固定顶层为defaults声明的preference/environment/techStack/instructions、六类列表、voice/dictation/codex；写请求严格拒绝未知顶层/嵌套/列表项/codex字段并验证类型，返回新对象。历史读取用strict=false，仅舍弃未知属性；codex仍只允许布尔loggedIn和有界account。

这些辅助器验证的是持久化/公开形状，不证明hook、MCP、插件、语音或Codex功能已经实现，也不把任意URL或命令登记解释为已执行。

### loadCustom()

有文件时先readBoundedText+JSON.parse，再用normalizeCustom(strict=false)建立固定投影，与defaults顶层合并，environment/techStack/codex再逐字段补默认；因此历史未知顶层、嵌套和列表项属性不会从GET接口或后续合法往返发布，已知槽位的对象/数组错类型仍按损坏失败。仅ENOENT退defaults；坏JSON、已知schema错误、超预算、权限或路径问题抛E_CUSTOM_CORRUPT，保留原文件。不自动改写或“修复”磁盘。

### saveCustom(next)

next默认空对象；先normalizeCustom(strict=true)并loadCustom，拒绝未知/错类型新输入或不可读旧配置。将规范化结果与defaults顶层合并，environment/techStack/codex各补默认；这是完整保存接口，省略旧字段会回默认，局部更新应使用patchCustom。先解析全部目标路径、JSON序列化并通过profile格式化两篇Markdown，所有输出逐个检查UTF-8字节不超过8MiB，才创建目录并顺序写：customizations.json → instructions.md → preference.md → tech-stack.md，返回merged。序列化转义和默认字段也占JSON预算，不能只按输入字符串长度判断。

形状/路径/预算/格式化错误在第一份文件写入前拒绝，已知损坏原文保留。经writeCustomFile逐文件原子替换仍不是四文件事务。后续派生文件失败时前面可能已经写好，调用方应记录部分成功而非宣称全回滚。用户直接改派生Markdown也不必然改回JSON；读取偏好的是loadCustom，不是所有消费者统一读Markdown。

### patchCustom(partial)

先normalizeCustom(strict=true)，且规范化后必须至少有一个字段；空对象、数组、未知字段或错类型均在读取/写入前E_BAD_ARGS。随后loadCustom；顶层以partial覆盖，environment/techStack/codex分别按字段合并当前值，再交saveCustom复核。只传environment.notes会保留原shell/语言等字段；空字符串是有效文本，但resolveTechStack仍可能对空值回退探测。六类列表仍是整体替换，不是任意层递归深合并。同步函数在单个Node事件循环内没有await穿插；没有版本号、跨进程锁或与外部编辑器的竞态隔离。

## 2. profile.js：探测不是实际运行环境

| 函数 | 输入/返回 | 过程、边界 |
|---|---|---|
| detectEnvironment() | 无→环境对象 | process.platform映射Windows/macOS/其他Linux；Windows猜powershell，其他bash；不检测实际shell版本、不激活Conda |
| readJson(file) | 路径→解析值或null | 拒绝最终文件符号链接，readBoundedText最多256KiB，只接受非数组对象；缺失/超限/解析或读取异常均返回null，不提供store式错误报告 |
| exists(root,rel) | 根/相对名→boolean | path.join后lstatSync.isFile，仅认普通文件，目录/最终符号链接/异常返回false |
| detectTechStack(workspaceRoot) | 可选根→技术栈对象 | 只读有限根清单，规则见下文；不递归分析整个工程 |
| resolveEnvironment(custom) | 定制→解析环境 | 非auto且真值的os/shell覆盖探测，语言/备注取定制或默认；只是描述，不切换系统 |
| resolveTechStack(custom,workspaceRoot) | 定制/可选根→技术栈 | 每个字段用定制真值优先，否则探测；空字符串不能强制禁止探测到的测试命令 |
| languageLabel(code) | 代码→显示名 | zh/zh-CN中文，en English，follow-user跟随；未知原样，假值空 |
| osLabel(os) | OS代码→显示名 | windows/macos/linux转友好名，未知原样 |

### detectTechStack(workspaceRoot) 的分支

根有可解析package.json时加入JavaScript；有普通tsconfig.json才加入TypeScript，jsconfig.json不再被当作TS证据。从生产+开发依赖识别Next/React、Nuxt/Vue、Express；pnpm-lock优先于yarn.lock，否则npm；scripts.test为非空白字符串时选对应包管理器test，不执行或直接返回脚本正文。

有pyproject.toml/requirements.txt/pytest.ini普通文件就加入Python，包管理器还空时猜pip；只有pytest.ini存在且测试命令还空时才提示`python -m pytest -q`，不再仅凭Python标记推断pytest。**仍不证明依赖已安装或命令可用，也不解析pyproject中的pytest配置、不识别Conda环境。** Cargo/go.mod同理，在空项时补cargo test/go test；根index.html加HTML。混合工程优先级按此顺序，不保证列出所有语言/框架。

内部 uniq(arr) 以filter(Boolean)+Set去空去重，再join成展示字符串；不改变项目依赖。

### formatWorkspaceContext(custom,skills)

调用两个resolve生成Markdown的Environment preference/Tech stack/Skills三段；未声明语言和命令时提醒检查工作区。技能数组为空给load_skill指引；非空只取前20项，显示id/source；description优先、preview回退，按换行split后的find回调找第一条非空非标题文本，截80字符作简介。更多目录由load_skill分页。只是目录，不自动执行/全文加载技能，不是对用户偏好真实性的验证。

### markdownPreference(custom) 与 markdownTechStack(custom)

分别格式化环境/技术栈Markdown字符串，供saveCustom落盘。本身不写文件。filter回调只去null、保留刻意的空行；不会自动转义任意用户Markdown。tech-stack缺项写“未声明”，有值则列出，实际探测仍可能是猜测。

## 3. memory.js 的全部函数

### memoryDir()

通过工具沙箱resolveSafePath得到`.webagent/memory`，不自行创建。没有使用裸路径拼接绕过工作区约束。

### dayFile(day)

缺day取当前UTC日期；否则String后严格匹配YYYY-MM-DD，并要求Date.parse有限、ISO往返一致，否则ProtocolError E_BAD_ARGS。最后用resolveSafePath生成日期.md。它未导出但被remember/recall复用，不能因为是辅助函数就忽略路径约束。

### remember({text,day}={})

text若非null/undefined必须为字符串；trim后的正文最多16KiB（UTF-8字节），拒NUL，类型/预算失败抛E_BAD_ARGS且不建目录。空返回 `{ok:false,error:'text required'}`；随后dayFile可能抛错。准备当前ISO时间的Markdown列表项，连续CR/LF替换为空格；新文件加日期标题。lstat检查已有目标必须为普通文件（最终符号链接含悬空链接拒绝，不能用existsSync把悬空链接误当缺文件），旧字节数加本次追加内容（含时间/标题/分隔符）不得超过256KiB，否则保留原文并拒绝，不自动切换日期或轮转。通过才建目录、append，返回ok及相对路径；新文件请求0600模式，既有文件权限不更改，Windows模式不是完整ACL保证。

append是磁盘副作用，不是数据库事务。有单条和每日文件预算，但不是跨进程协调/锁；同用户外部写进程仍可能在检查与append之间改变目标或大小。写入错误继续抛出，不承诺部分I/O自动回滚。时间是执行时刻，day参数是归档日期，两者可不同。

### memoryFiles(dir,selectedFile)
指定day则返回该文件，不遍历目录。否则opendir逐条扫描最多512条目录项，只考虑普通日期.md；候选排序为新日期优先，dayFile验证失败跳过并标truncated，最多取30个文件。finally关闭目录句柄。超512时只是已扫描子集的新日期在前，不保证整个巨大目录的全局最新项；无目录时不创建。

### memoryScore(text,terms)
正文NFKC规范化并转小写，对每个去重查询词做includes，每个匹配词加1，不因重复出现加分。支持中文整词/短语和英文大小写、全角字符；不做分词、向量或语义推理。关键词匹配不证明记忆是真实事实。

### recall({limit=40,day,query=''}={})
指定日期仍先做路径验证，memoryDir仍保证工作区边界。query必须是≤200个UTF-16代码单元的字符串，规范化后按空白分隔、去重，超过20词拒绝（不默默截查询词）；limit沿用数值转换/默认40，夹在1–200并向下取整。

调用memoryFiles后，每文件通过readBoundedText最多256KiB，总计2MiB、最多5000文本行；超大/读取错误跳过并返回warnings，不覆盖或修复原文件。files只列实际成功读取的相对路径。目录异常仍可抛错；日期/工作区边界错误不当普通无结果处理。

无query保留日期倒序、同一天原行序，收集足够项后停止；有query扫描上述有限语料，按匹配词数稳定排序，同分保留日期/行序，并在正文项尾加`[文件:行号]`便于重新读取证据。最多保留limit项，拼接文本最多8000字符，超限取前7920加省略号。count是所选项数，不承诺每项都完整展示。返回ranking说明，不自动把结果加入长期系统提示或执行记忆里的命令。truncated表示目录/文件/行/结果至少一个边界不完整，不保证“没有匹配”就是整个历史没有。

remember仍是显式追加；本批不引入新的记忆数据库、跨工作区召回、自动保存/删除/轮转日记、embedding联网或持久身份。

## 4. 验证与实际使用

```bat
npm test --prefix webagent-core/agent-host -- --filter=profile
npm test --prefix webagent-core/agent-host -- --filter=stateIntegrity
npm test --prefix webagent-core/agent-host -- --filter=memoryRecall
npm test --prefix webagent-core/agent-host -- --filter=apiFiles
npm test --prefix webagent-core/agent-host -- --filter=auditStorage
npm test --prefix webagent-core/agent-host -- --filter=mcpProtocol
```

profile测试覆盖有界探测、局部字段保留、无效输入/旧坏数据保留、工作区外链接拒绝、派生Markdown及MCP画像消费；stateIntegrity覆盖损坏和rename失败；auditStorage覆盖记忆日期/路径；memoryRecall覆盖写入/读取预算；apiFiles以真实HTTP核对空/未知/嵌套未知写入零改动、历史未知秘密不出固定GET投影，以及坏JSON保留；协议测试覆盖记忆工具接入。它们不证明任意字段内容的业务真实性、四文件事务、任意巨大记忆文件或实际Conda解释器。业务测试命令不正确时应在技术栈中明确声明，并按Conda E3检查真正运行的Python，不因为探测字段显示Python就判通过。

**writeCustomFile(target,text)**用随机.tmp.同目录文件、wx与0600创建，rename发布；finally清理临时文件，仅忽略ENOENT。JSON与三个Markdown逐个发布，不宣称跨文件回滚或断电耐久性。

### Skill上下文预算补充
formatWorkspaceContext仅带前20项目录id/source及description（旧条目回退preview），说明目录为不可信发现元数据；更多用load_skill目录分页，正文与引用按需读。不会把全部Skill正文或脚本塞入systemPrompt，不以元数据或Skill里的指令扩大权限。真实工作区指令原逻辑不变。

### memoryRecall.test.js
隔离临时工作区，验证空库只读不创建、中文/英文/全角词的字面匹配、稳定排序、文件行号、日期过滤、查询上限、非匹配结果、256KiB单文件/2MiB总量/30文件/512目录条目/5000行预算与明确截断；各预算夹具分开清理，避免一个截断原因掩盖另一个。写入负例覆盖非字符串、NUL、UTF-8单条预算、CR/LF归一、每日256KiB边缘接受与超限保留，非法新条目不建目录；非Windows追加悬空链接负例确认不创建外部目标且保留链接，未代签Windows文件symlink权限。finally还原config并删临时目录。
