# 定制、画像与记忆：逐函数和字段解释

## 职责与协作

[customizations.js](customizations.js) 存设置与配套Markdown；[profile.js](profile.js) 从偏好/目录线索生成环境和技术栈描述；[memory.js](memory.js) 管按UTC日期的Markdown记忆。三者不共享 [store](配置存储详解.md) 的持久化保证。

## 1. customizations.js

### file() 与 defaults()

file只计算工作区`.webagent/customizations.json`路径。defaults每次给新对象：preference自由文本；environment的os/shell默认auto、回复/提交语言中文；techStack提供语言/框架/包管理器/测试命令/备注；instructions为指令正文；agents/prompts内置模板；hooks/mcpServers/plugins/quickLinks默认空；voice/dictation空；codex为未登录占位。

有一个配置字段不等于已经有对应运行插件/语音/Codex功能。消费者决定哪些字段真正生效，不能从JSON模板推断产品能力。

### loadCustom()

读JSON，与defaults顶层浅合并，environment/techStack再浅合并各自默认；返回对象。仅ENOENT退defaults；readBoundedText限制大小，坏JSON/非对象/权限问题抛E_CUSTOM_CORRUPT，保留原文件。不自动修复，也没有覆盖所有字段的完整schema校验。

### saveCustom(next)

将next与defaults顶层合并；若给environment/techStack再补其默认；创建目录后顺序写：customizations.json → instructions.md → preference.md → tech-stack.md，返回merged。后两篇通过profile格式化。

先loadCustom确认旧配置可读，再经writeCustomFile逐文件原子替换；不是四文件事务。后续派生文件失败时前面可能已经写好，调用方应记录部分成功而非宣称全回滚。用户直接改派生Markdown也不必然改回JSON；读取偏好的是loadCustom，不是所有消费者统一读Markdown。

### patchCustom(partial)

`saveCustom({...loadCustom(),...partial})`。**嵌套不是深合并**：只传environment.notes时，原environment其他定制字段会被整个新对象替掉，save再补默认而不是保留旧值。UI若想保留字段需提交完整嵌套对象；不在文档中虚构深合并。

## 2. profile.js：探测不是实际运行环境

| 函数 | 输入/返回 | 过程、边界 |
|---|---|---|
| detectEnvironment() | 无→环境对象 | process.platform映射Windows/macOS/其他Linux；Windows猜powershell，其他bash；不检测实际shell版本、不激活Conda |
| readJson(file) | 路径→解析值或null | 读取/解析异常吞掉；画像猜测允许缺失，不提供store式错误报告 |
| exists(root,rel) | 根/相对名→boolean | path.join后existsSync，不验证文件类型 |
| detectTechStack(workspaceRoot) | 可选根→技术栈对象 | 只读有限根清单，规则见下文；不递归分析整个工程 |
| resolveEnvironment(custom) | 定制→解析环境 | 非auto且真值的os/shell覆盖探测，语言/备注取定制或默认；只是描述，不切换系统 |
| resolveTechStack(custom,workspaceRoot) | 定制/可选根→技术栈 | 每个字段用定制真值优先，否则探测；空字符串不能强制禁止探测到的测试命令 |
| languageLabel(code) | 代码→显示名 | zh/zh-CN中文，en English，follow-user跟随；未知原样，假值空 |
| osLabel(os) | OS代码→显示名 | windows/macos/linux转友好名，未知原样 |

### detectTechStack(workspaceRoot) 的分支

根有可解析package.json时加入JavaScript；有tsconfig或jsconfig就加入TypeScript（启发式，jsconfig不证明使用TS）。从生产+开发依赖识别Next/React、Nuxt/Vue、Express；pnpm-lock优先于yarn.lock，否则npm；声明scripts.test时选对应包管理器test。

有pyproject/requirements/pytest.ini就加入Python、在包管理器/测试命令还空时填pip和`python -m pytest -q`。**这只是猜测，不证明项目使用pytest，更不识别Conda环境。** Cargo/go.mod同理，在空项时补cargo test/go test；根index.html加HTML。混合工程优先级按此顺序，不保证列出所有语言/框架。

内部 uniq(arr) 以filter(Boolean)+Set去空去重，再join成展示字符串；不改变项目依赖。

### formatWorkspaceContext(custom,skills)

调用两个resolve生成Markdown的Environment preference/Tech stack/Skills三段；未声明语言和命令时提醒检查工作区。技能数组为空给load_skill指引；非空只取前20项，显示id/source；description优先、preview回退，按换行split后的find回调找第一条非空非标题文本，截80字符作简介。更多目录由load_skill分页。只是目录，不自动执行/全文加载技能，不是对用户偏好真实性的验证。

### markdownPreference(custom) 与 markdownTechStack(custom)

分别格式化环境/技术栈Markdown字符串，供saveCustom落盘。本身不写文件。filter回调只去null、保留刻意的空行；不会自动转义任意用户Markdown。tech-stack缺项写“未声明”，有值则列出，实际探测仍可能是猜测。

## 3. memory.js 的全部函数

### memoryDir()

通过工具沙箱resolveSafePath得到`.webagent/memory`，不自行创建。没有使用裸路径拼接绕过工作区约束。

### dayFile(day)

缺day取当前UTC日期；否则String后严格匹配YYYY-MM-DD，并要求Date.parse有限、ISO往返一致，否则ProtocolError E_BAD_ARGS。最后用resolveSafePath生成日期.md。它未导出但被remember/recall复用，不能因为是辅助函数就忽略路径约束。

### remember({text,day}={})

text转字符串trim，空返回 `{ok:false,error:'text required'}`；dayFile可能抛错。创建memoryDir，追加一条带当前ISO时间的Markdown列表项，正文中的连续换行替换为空格；新文件先写日期标题。返回ok及相对路径。

append是磁盘副作用，不是数据库事务。没有正文总字节限制或跨进程协调；写入错误继续抛出。时间是执行时刻，day参数是归档日期，两者可不同。

### memoryFiles(dir,selectedFile)
指定day则返回该文件，不遍历目录。否则opendir逐条扫描最多512条目录项，只考虑普通日期.md；候选排序为新日期优先，dayFile验证失败跳过并标truncated，最多取30个文件。finally关闭目录句柄。超512时只是已扫描子集的新日期在前，不保证整个巨大目录的全局最新项；无目录时不创建。

### memoryScore(text,terms)
正文NFKC规范化并转小写，对每个去重查询词做includes，每个匹配词加1，不因重复出现加分。支持中文整词/短语和英文大小写、全角字符；不做分词、向量或语义推理。关键词匹配不证明记忆是真实事实。

### recall({limit=40,day,query=''}={})
指定日期仍先做路径验证，memoryDir仍保证工作区边界。query必须是≤200字符字符串，规范化后按空白分隔、去重，超过20词拒绝（不默默截查询词）；limit沿用数值转换/默认40，夹在1–200并向下取整。

调用memoryFiles后，每文件通过readBoundedText最多256KiB，总计2MiB、最多5000文本行；超大/读取错误跳过并返回warnings，不覆盖或修复原文件。files只列实际成功读取的相对路径。目录异常仍可抛错；日期/工作区边界错误不当普通无结果处理。

无query保留日期倒序、同一天原行序，收集足够项后停止；有query扫描上述有限语料，按匹配词数稳定排序，同分保留日期/行序，并在正文项尾加`[文件:行号]`便于重新读取证据。最多保留limit项，拼接文本最多8000字符，超限取前7920加省略号。count是所选项数，不承诺每项都完整展示。返回ranking说明，不自动把结果加入长期系统提示或执行记忆里的命令。truncated表示目录/文件/行/结果至少一个边界不完整，不保证“没有匹配”就是整个历史没有。

remember仍是原来的显式追加；本批不引入新的记忆数据库、跨工作区召回、自动保存/删除/轮转日记、embedding联网或持久身份。

## 4. 验证与实际使用

```bat
npm test --prefix webagent-core/agent-host -- --filter=profile
npm test --prefix webagent-core/agent-host -- --filter=stateIntegrity
npm test --prefix webagent-core/agent-host -- --filter=mcpProtocol
```

profile测试覆盖探测、派生Markdown及MCP画像消费；stateIntegrity含日期/路径等状态回归；协议测试覆盖记忆工具接入。它们不证明全部自定义JSON形状、任意巨大记忆文件或实际Conda解释器。业务测试命令不正确时应在技术栈中明确声明，并按Conda E3检查真正运行的Python，不因为探测字段显示Python就判通过。

**writeCustomFile(target,text)**用随机.tmp.同目录文件、wx与0600创建，rename发布；finally清理临时文件，仅忽略ENOENT。JSON与三个Markdown逐个发布，不宣称跨文件回滚或断电耐久性。

### Skill上下文预算补充
formatWorkspaceContext仅带前20项目录id/source及description（旧条目回退preview），说明目录为不可信发现元数据；更多用load_skill目录分页，正文与引用按需读。不会把全部Skill正文或脚本塞入systemPrompt，不以元数据或Skill里的指令扩大权限。真实工作区指令原逻辑不变。

### memoryRecall.test.js
隔离临时工作区，验证空库只读不创建、中文/英文/全角词的字面匹配、稳定排序、文件行号、日期过滤、查询上限、非匹配结果、256KiB单文件/2MiB总量/30文件/512目录条目/5000行预算与明确截断；各预算夹具分开清理，避免一个截断原因掩盖另一个。finally还原config并删临时目录。
