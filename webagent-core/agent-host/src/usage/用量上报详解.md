# tracker.js：日统计与可选上报逐函数讲解

## 职责与数据流

[tracker.js](tracker.js) 记录工具调用计数、失败数与最近时间，按UTC日保存`.webagent/usage.json`；不是Token计费系统，也不自动覆盖所有本机Chat路径。调用点应接着看MCP server。

模块状态timer是15分钟周期计时器，debounce是首个事件后4秒的一次性计时器；没有导入即启动，入口显式调用startReporter。

## 1. 读取、保存、身份与展示函数

| 函数 | 输入/返回 | 处理与边界 |
|---|---|---|
| usagePath() | 无→路径 | 当前workspaceRoot下.webagent/usage.json，不创建 |
| today() | 无→YYYY-MM-DD | ISO截日期，**UTC不是本机午夜** |
| emptyDay(day) | 可选日期→新统计对象 | 默认today，计数0，lastAt/lastReportAt为null |
| load() | 无→当日对象 | 读JSON；非对象、日期不是today、任何错误都回emptyDay；计数Number或0，无完整schema/负数检查 |
| save(next) | 统计对象→原next | 建目录，直接writeFileSync格式化JSON，无临时rename、无锁；失败抛出 |
| successRate(rec) | 记录→整数百分比或null | toolCalls假值返回null；否则round((1-fail/calls)*100)，不钳制脏数据到0–100 |
| snapshot() | 无→展示对象 | load加successRate、intervalMs、telemetryConfigured；后者只检查URL非空，**不检查token** |
| identity() | 无→安装/展示身份 | store.load；GitHub provider有username才填githubUser（去前导@）及githubId，其他情况空；坏store配置会抛出 |
| payload() | 无→上报对象 | load+identity，计数/安装ID/GitHub标记/产品版本/lastAt；不含模型Key、MCP secret或命令正文，但仍含身份标识 |

## 2. record({ok=true}={})

同步load当前日 → toolCalls+1 → !ok时fail+1 → 更新时间 → save → scheduleReport → 返回记录。写失败抛错，后续schedule不会执行；缺ok默认当成功，应由调用方正确传入业务判定。

跨日load回空，后续save覆盖为新日；不是保留历史日账本。单进程同步读改写减少异步交错，但没有其他进程写同文件的事务保护。

## 3. reportNow({fetchFn=fetch}={})

async，返回skip/成功/HTTP失败对象，网络或存储异常仍可能拒绝。

1. 同时要求WEBAGENT_TELEMETRY_URL和TOKEN，否则 `{skipped:true,reason:'not-configured'}`。
2. load无调用数时skip no-calls。
3. payload构建上报内容，Bearer POST JSON；不做客户端自动注册，也不包含全部用户文件。
4. 非2xx时读响应text（读取失败catch返回空），返回ok=false、status、前200字符error。
5. 2xx后取当前时间，再次load最新统计；只有仍是原日才save({...latest,lastReportAt})，防止把请求期间新增调用抹掉或把昨天覆盖今天。
6. 返回ok=true与lastReportAt；跨日不写旧日文件，但返回字段仍表示这次请求已成功。

这里没有网络timeout、在途请求去重或指数重试；周期与debounce可重叠发请求。请求体与初始rec由两次读取构成，也不是跨进程一致性快照。不能从“有上报计时器”推断网络永不挂起。

## 4. 三个计时器函数及回调

### scheduleReport()

已有debounce就返回。否则setTimeout4秒；回调先将debounce=null，再调用reportNow，catch空回调吞掉异常。它不是每次record都重新延期的尾沿防抖，而是第一条事件触发后4秒发送一回；支持时unref，不单独保活Node。

### startReporter()

已有timer返回；否则每INTERVAL_MS（15分钟）reportNow，异步catch吞错，支持时unref。不会立即报告，且不检查当前是否已有reportNow在飞。

### stopReporter()

清interval/timeout并设null；不取消已经发出的fetch，也不保证停止前尚未发送的计数都成功上报。不会删除usage文件。

## 5. 验证与实际边界

```bat
npm test --prefix webagent-core/agent-host -- --filter=usageTracker
npm test --prefix webagent-core/agent-host -- --filter=stateIntegrity
```

usageTracker检查日计数、成功率、身份payload和Bearer假请求；stateIntegrity覆盖上报期间新增计数等回归。真实统计后台、网络中断/长挂、隐私配置需分别验证。复盘练习：解释snapshot显示configured但reportNow仍skip的情况；说明为什么stopReporter不是取消所有网络任务。
