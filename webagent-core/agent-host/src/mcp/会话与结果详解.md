# MCP 会话、错误和返回预算：逐函数讲解

## 职责与两种会话

[session.js](session.js) 有两张Map：sessions是展示/统计的peer记录，httpSessions是随机ID的HTTP会话。它们都在内存，24小时TTL，容量阈值200。认证另由OAuth/长期secret完成；HTTP session ID在有效凭据之上关联客户端状态，不能单独登录，也不能作为公开peer标签泄露。生产HTTP会话另绑定已验证principal，公开peer另取随机值。

## 1. session.js 全部函数与回调

| 函数 | 参数/返回 | 状态变化和边界 |
|---|---|---|
| sessionKey(req) | 请求→client@ip或client@ip~tag | 无会话远程调用者的归属键。clientInfo.name由调用方自填：先去掉ASCII控制字符、截到64字符，空则mcp（2026-09-25第77组：此前含控制字符或超长的名字使整个key过不了touch的publicText，被换成常量`mcp@local`而丢掉凭据标签，不同凭据的调用方又合并成同一归属者，经真实HTTP可读到对方命令输出）；IP取req.ip（Express按显式trust proxy策略，主机未配置）、再socket.remoteAddress、最后local。F70起**不再读原始X-Forwarded-For头**：该头由客户端任意填写，req.ip为空时曾让调用方自选匿名调用计入的展示key（外部复审P3-13），与oauth.js clientIp同一规则。F71起请求带req.mcpPrincipal（requireAuth验证凭据后写入）时追加`~`与24位hex标签：用进程内随机32字节盐对principal做HMAC-SHA256截断，因此**不同凭据即不同调用者**，即使经cloudflared/ngrok时IP恒为127.0.0.1；标签不含凭据或principal摘要，盐不落盘、重启后重新生成（无会话调用者的命令与轨迹记录本来也只在内存）。无principal的直接模块夹具仍得纯client@ip。它不区分同一凭据下的多个对话——要按对话区分须initialize并保留Mcp-Session-Id |
| touch(req,extra={}) | 请求/增量→peer记录 | extra.key优先，否则sessionKey，经publicText限为512字符；过不了检查的key不再落成常量，而是`mcp@local~`加原key的sha256前24位，不同输入仍是不同归属者（与sessionKey的清洗互为冗余，两处同时去掉时mcpCallerIsolation变红）；保留connectedAt，更新lastSeen与调用/失败计数，busy每次重算。只存固定key/时间/clientInfo/calls/fail/busy，未知extra与incCall/incFail控制标记不落记录；clientInfo入库即经publicClientInfo。保存前清过期，超容量删Map首项（不是严格最久未访问） |
| publicText(value,maxLength) | 值/字符上限→字符串 | 仅接受上限内且无ASCII控制字符的字符串，否则空串；不是通用秘密扫描器 |
| publicClientInfo(value) | MCP clientInfo→固定对象 | 只投影有界name/title/version，未知键、对象/数组嵌套和错类型不发布 |
| publicSession(record) | 内部peer记录→固定对象 | 只给有界key/时间、非负安全整数calls/fail、严格busy布尔和publicClientInfo；不发布incCall/incFail或任意extra，并深建clientInfo |
| snapshot() | 无→展示快照 | sort回调按lastSeen新到旧；最新小于10秒视alive，展示最多8条，但clients是全部数；先清理过期客户端与HTTP会话，再给httpSessions当前size。latest与sessions均来自publicSession，latest另复制，不引用内部记录也不与sessions[0]共享嵌套对象 |
| allSessions() | 无→排序数组 | 先pruneSessions，同样排序但不截8条；每项也经publicSession重建并深建clientInfo，不向任务板等消费者暴露内部记录引用 |
| pruneHttpSessions() | 无→undefined | 跳过active>0的HTTP会话，其余lastSeen超过TTL则删；不是后台定时清理 |
| createHttpSession(extra={}) | 可选元数据→随机hex ID | 先prune，达到200只删最旧空闲会话；全部在途返回null，不驱逐忙会话，HTTP映射503。随机16字节ID，写createdAt/lastSeen/active:0与extra，生产入口在extra传入principal摘要；内部调用方应避免覆盖身份/时间字段 |
| beginHttpSessionWork(id) | ID→一次性release | 已知记录active+1，未知ID返回调用结果false的no-op；release仅一次减计数，最后一个工作结束刷新lastSeen，重新开始空闲TTL；不复活已删除记录、不延长OAuth凭据、不保证断线/重启恢复 |
| getHttpSession(id,principal) | ID/主体→记录或null | 只读查找并检查归属、空闲TTL（active>0保护）；不prune/续期，用于RPC准入版本识别。protocolVersion由合法initialize存入私有记录，不进入公开peer投影 |
| touchHttpSession(id,principal) | ID/可选主体摘要→记录或null | 空值null，先prune，再getHttpSession检查归属/有效期；匹配才更新lastSeen返回原对象 |
| destroyHttpSession(id,principal) | ID/可选主体摘要→boolean | 传principal且不匹配则false；匹配或内部省略检查时删除，不自动删展示记录或撤销OAuth token |
| setHttpSessionKey(id,key) | ID/peer key→boolean | 原记录存在才写key；不在此prune，不创建记录 |
| keyForReq(req) | 请求→peer key或null | 取req.mcpSessionId或头字段，带req.mcpPrincipal通过touchHttpSession查找；**没有匿名IP自动回退**，回退在server调用方 |
| reset() | 无→空快照 | 清两张Map，不清OAuth、磁盘任务板、外部进程 |

initialize为尚无key的会话单独生成`peer:<随机16字节hex>`，不是HTTP session ID的拼接/编码；同IP同显示名称也可区分。合法重复initialize保留原key，OAuth同client刷新不改变归属。远端提供的clientInfo在进入内部统计记录时就只保留name/title/version三个有界字符串，status/snapshot再按同一固定字段重建；未知凭据样键、嵌套对象及touch内部增量标记既不持久保留也不会被整对象展开。公开peers/board/ping只使用该peer标签，不因共享任务元数据而暴露会话能力。删除HTTP会话后展示记录可暂留到后续touch清理，alive只是10秒心跳观感，不是授权有效性的证明。

principal由server.requireAuth在凭据验证成功后构造：OAuth按kind+注册clientId取SHA256，长期secret按kind+实际密钥取SHA256；不把原始凭据存入HTTP会话。同OAuth client的新有效token可沿用会话，但跨client或轮换后的长期secret不继承旧会话。省略principal的函数调用仍供受信内部模块/直接测试使用；网络入口不能省略认证，不把这些导出函数本身当安全API。

这不是不同OS用户或持有同一凭据者之间的完整隔离。同一principal若同时持有真正的私有会话ID仍能使用它，客户端应保密；不要将会话头或密钥贴进公开日志。内存会话过期/被容量淘汰/重启后不会凭磁盘任务owner自动恢复身份。

## 2. errors.js 的类、构造器和函数

### ProtocolError / ExecutionError

两类均extends Error；各自constructor(code,message,detail)调用super，设name、layer（protocol或execution）、code，detail假值补{}。协议层表示调用形式/参数问题，执行层表示环境或动作失败；都是可抛的Error对象，不是已经格式化好的HTTP响应。

### classifyToolError(err)

已是两种类直接返回。普通错误若code为E_CANCELLED则保留执行层取消码；其余取message或String依次匹配：not found/No such file先判E_NOT_FOUND，再未知工具、模式锁、requires/required、HASH_REQUIRED、STALE_FILE、补丁冲突、Git不可用、timeout、敏感/禁止、确认标志，最后E_INTERNAL。顺序中的文件名匹配可能优先于required等字样，不是无序规则集合。

顺序会影响同时命中多个关键词的错误；它不是按所有底层err.code严谨映射，E_CANCELLED之外仍不保证识别所有第三方取消错误。原生Error的自定义detail不一定被保留。

### publicError(err)

classify后返回 `{layer,code,msg,detail}`，不给stack。**public不表示自动脱敏所有消息/详情**；抛错者仍需避免放入秘密，发送端另有日志处理。tools/call的isError包装和顶层JSON-RPC error由server决定。

## 3. budget.js 的函数与递归

MAX_CHARS=16000是字符软目标，不是真正Token硬限制。

### estimateTokens(text)

String(text||'')长度除4向上取整。是粗略估算，不是模型tokenizer，中文/代码差异不在这里测量。

### clipText(text,maxChars=MAX_CHARS)

nullish为空字符串；未超限返回 `{text,truncated:false}`。超限保留maxChars-80（下限0），追加带丢弃字符数/分页指引的标记，返回originalChars。标记自身可能超过很小预算，不能以此保证字节数/Token绝对上限。

### clipJson(value,maxChars=MAX_CHARS)

nullish原样返回；字符串走clipText只取text。其他先JSON.stringify，预算内直接返回**原对象**；超预算才JSON.parse复制。输入应是可JSON序列化的数据，循环引用/BigInt等会抛错，不是任意JS对象清洗器。

内部 **copy(node,protectedPage=false)**：

1. 原始值原样；对象自身含offset/cursor/nextCursor任一字段则将page保护传给整个子树（some回调检查own字段）。
2. 数组map递归，不丢元素；对象遍历键，通过defineProperty建立可枚举自有属性，再递归值。
3. 非分页保护区里的stdout/stderr/content/preview/text/diff/answer/description/summary字符串登记到leaves；不是所有字符串都截断。

复制后先将这些叶子清空，按剩余预算减150分摊share，再逐叶clipText填回。非数组根若截断加_truncated/originalChars，若仍超限加_budgetExceeded；数组根不加这些自定义元数据。标识符/分页/成员不为了满足预算被直接删除，因此结果可能仍很大。

这避免“裁断序列化JSON造成非法JSON”，但并不替代每个工具的读文件/搜索/命令输出硬限制。额外标记可能覆盖同名业务字段，调用方应按该返回契约理解。

## 4. 验证与复盘

```bat
npm test --prefix webagent-core/agent-host -- --filter=mcpBoard
npm test --prefix webagent-core/agent-host -- --filter=resourceBudget
npm test --prefix webagent-core/agent-host -- --filter=mcpProtocol
npm test --prefix webagent-core/agent-host -- --filter=apiFiles
```

前几项覆盖同IP任务板身份、预算结构和协议错误；apiFiles另以真实HTTP把带未知extra/clientInfo嵌套的内部peer记录送入status，断言固定投影不发布注入字段。它们不等于所有授权隔离/内存增长或秘密模式均已认证。练习：区分删除HTTP session与撤销token；说明为什么16k预算仍可能返回超过16k，而不能偷偷删掉数组成员。

classifyToolError保持ProtocolError/ExecutionError实例优先；普通Error的not found先于required/timeout，避免required.md等文件名改变错误分类。

pruneSessions()按lastSeen清理超过24小时的客户端条目；touch、snapshot、allSessions都调用，因此无新连接时读取展示也不会保留昨天的会话数。不是定时器，也不是实时TCP连接计数。
