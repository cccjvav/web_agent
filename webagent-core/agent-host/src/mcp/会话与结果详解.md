# MCP 会话、错误和返回预算：逐函数讲解

## 职责与两种会话

[session.js](session.js) 有两张Map：sessions是展示/统计的peer记录，httpSessions是随机ID的HTTP会话。它们都在内存，24小时TTL，容量阈值200。认证另由OAuth/长期secret完成，HTTP session ID不是登录凭据；两种状态不能混为一谈。

## 1. session.js 全部函数与回调

| 函数 | 参数/返回 | 状态变化和边界 |
|---|---|---|
| sessionKey(req) | 请求→client@ip | clientInfo.name缺省mcp；IP取req.ip优先、再转发头、最后local；只是后备展示key，不是可靠用户身份 |
| touch(req,extra={}) | 请求/增量→peer记录 | extra.key优先，否则sessionKey；保留connectedAt，更新lastSeen与调用/失败计数；busy每次重算，不传则false；保存前清过期，超容量删Map首项（不是严格最久未访问） |
| snapshot() | 无→展示快照 | sort回调按lastSeen新到旧；最新小于10秒视alive，展示最多8条，但clients是全部数；先清理过期客户端与HTTP会话，再给httpSessions当前size |
| allSessions() | 无→排序数组 | 先pruneSessions，同样排序但不截8条；数组内仍为记录对象引用，给任务板等使用 |
| pruneHttpSessions() | 无→undefined | 遍历，lastSeen超过TTL则删；不是后台定时清理 |
| createHttpSession(extra={}) | 可选元数据→随机hex ID | 先prune，达到200就查最旧lastSeen逐个删；随机16字节ID，写createdAt/lastSeen与extra；内部调用方应避免覆盖身份/时间字段 |
| touchHttpSession(id) | ID→记录或null | 空值null，先prune，命中更新lastSeen并返回原对象 |
| destroyHttpSession(id) | ID→boolean | 从httpSessions删除；不自动删sessions展示记录、不撤销OAuth token |
| setHttpSessionKey(id,key) | ID/peer key→boolean | 原记录存在才写key；不在此prune，不创建记录 |
| keyForReq(req) | 请求→peer key或null | 取req.mcpSessionId或头字段，通过touchHttpSession查找；**没有匿名IP自动回退**，回退在server调用方 |
| reset() | 无→空快照 | 清两张Map，不清OAuth、磁盘任务板、外部进程 |

initialize在server里把key设为 `peer:<随机会话ID>`，同IP的两个正常初始化客户端可以区分；不能再按旧注释把所有任务板归属概括成client@ip。删除HTTP会话后展示记录可暂留到后续touch清理，alive只是10秒心跳观感，不是授权有效性的证明。

## 2. errors.js 的类、构造器和函数

### ProtocolError / ExecutionError

两类均extends Error；各自constructor(code,message,detail)调用super，设name、layer（protocol或execution）、code，detail假值补{}。协议层表示调用形式/参数问题，执行层表示环境或动作失败；都是可抛的Error对象，不是已经格式化好的HTTP响应。

### classifyToolError(err)

已是两种类直接返回。普通错误若code为E_CANCELLED则保留执行层取消码；其余取message或String依次匹配：not found/No such file先判E_NOT_FOUND，再未知工具、模式锁、requires/required、HASH_REQUIRED、STALE_FILE、补丁冲突、Git不可用、timeout、敏感/禁止、确认标志，最后E_INTERNAL。顺序中的文件名匹配可能优先于required等字样，不是无序规则集合。

顺序会影响同时命中多个关键词的错误；它不是按所有底层err.code严谨映射，E_CANCELLED之外仍不保证识别所有第三方取消错误。原生Error的自定义detail不一定被保留。

### publicError(err)

classify后返回 `{layer,code,msg,detail}`，不给stack。**public不表示自动脱敏所有消息/详情**；抛错者仍需避免放入秘密，发送端另有日志处理。tools/call的isError包装和顶层JSON-RPC error由server决定。

## 3. budget.js 的函数与递归

MAX_CHARS=16000是字符软目标，不是真正Token硬限制。

### estimateTokens(text)

String(text||'')长度除4向上取整。是粗略估算，不是模型tokenizer，中文/代码差异不在这里测量。

### clipText(text,maxChars=MAX_CHARS)

nullish为空字符串；未超限返回 `{text,truncated:false}`。超限保留maxChars-80（下限0），追加带丢弃字符数/分页指引的标记，返回originalChars。标记自身可能超过很小预算，不能以此保证字节数/Token绝对上限。

### clipJson(value,maxChars=MAX_CHARS)

nullish原样返回；字符串走clipText只取text。其他先JSON.stringify，预算内直接返回**原对象**；超预算才JSON.parse复制。输入应是可JSON序列化的数据，循环引用/BigInt等会抛错，不是任意JS对象清洗器。

内部 **copy(node,protectedPage=false)**：

1. 原始值原样；对象自身含offset/cursor/nextCursor任一字段则将page保护传给整个子树（some回调检查own字段）。
2. 数组map递归，不丢元素；对象遍历键，通过defineProperty建立可枚举自有属性，再递归值。
3. 非分页保护区里的stdout/stderr/content/preview/text/diff/answer/description/summary字符串登记到leaves；不是所有字符串都截断。

复制后先将这些叶子清空，按剩余预算减150分摊share，再逐叶clipText填回。非数组根若截断加_truncated/originalChars，若仍超限加_budgetExceeded；数组根不加这些自定义元数据。标识符/分页/成员不为了满足预算被直接删除，因此结果可能仍很大。

这避免“裁断序列化JSON造成非法JSON”，但并不替代每个工具的读文件/搜索/命令输出硬限制。额外标记可能覆盖同名业务字段，调用方应按该返回契约理解。

## 4. 验证与复盘

```bat
npm test --prefix webagent-core/agent-host -- --filter=mcpBoard
npm test --prefix webagent-core/agent-host -- --filter=resourceBudget
npm test --prefix webagent-core/agent-host -- --filter=mcpProtocol
```

这些覆盖同IP任务板身份、预算结构和协议错误等场景，不等于所有授权隔离/内存增长情形均已认证。练习：区分删除HTTP session与撤销token；说明为什么16k预算仍可能返回超过16k，而不能偷偷删掉数组成员。

classifyToolError保持ProtocolError/ExecutionError实例优先；普通Error的not found先于required/timeout，避免required.md等文件名改变错误分类。

pruneSessions()按lastSeen清理超过24小时的客户端条目；touch、snapshot、allSessions都调用，因此无新连接时读取展示也不会保留昨天的会话数。不是定时器，也不是实时TCP连接计数。
