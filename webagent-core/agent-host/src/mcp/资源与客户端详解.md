# MCP 指令、资源与客户端卡片：逐函数和静态数据

## 职责与流程

[instructions.js](instructions.js)组织给模型的规则；[resources.js](resources.js)提供命名资源；[clients.js](clients.js)描述连接卡片。它们不建立真实远程连接，返回说明并不证明某外部产品版本支持MCP。身份/工具执行分别看OAuth及server。

## 1. instructions.js

### 静态常量

CONNECT_LINE为连接提示句，PAGE_RULES_LEAD说明第三方规则传递须按版本核对，不能假定自动注入。SERVER_INSTRUCTIONS是服务端规则模板，包含模式、搜读改测流程、错误/预算/安全/记忆。

模板是指导文本，不是实现校验：其中约4k tokens“capped”的措辞应按[预算详解](会话与结果详解.md)理解为软目标；错误后的重试也不能越过真实权限、版本和用户意图。不要把模型遵守提示作为路径安全的唯一保护。

### 三个函数

| 函数 | 参数/返回 | 行为与边界 |
|---|---|---|
| getBootstrapPrompt(mcpUrl) | 可选URL→文本 | URL加连接句；可能包含带secret地址，复制文本不是无敏感数据 |
| getPageRulesPrompt() | 无→文本 | 固定说明加getInstructions，与initialize同源；不负责让扩展真正注入 |
| getInstructions() | 无→完整规则文本 | loadCustom，加入自定义instructions、formatWorkspaceContext(custom,listSkills())与工作区路径；实时读设置/技能，可有磁盘读取与异常，不是永远固定字符串 |

## 2. resources.js：目录与每个分支

### listResources()

返回静态RESOURCE_DEFS数组本身，不深拷贝。每项uri/name/mimeType/description供资源发现；外部代码不应修改该数组。目录八项，资源正文在读取时生成。

### readResource(uri,options={})

同步switch，已知返回 `{uri,mimeType,text}`，未知返回null；不直接写HTTP。可信内部调用缺省options仍按Local读取；HTTP server固定传remote:true与keyForReq得到的已认证peer，不能把params里的remote/callerKey/_meta当上下文。remote调用在分支前assertAllowed(read_files)再次检查Read；它不自行认证token，不能把模块函数当独立网络入口。

| URI尾部 | 数据来源 | 注意 |
|---|---|---|
| instructions | getInstructions | 完整规则与偏好，可含用户自定义内容 |
| profile | loadCustom/listSkills/formatWorkspaceContext | 环境和技术栈描述，不代表实际Conda解释器 |
| protocol | 静态Markdown数组join | 握手/保留SID和版本；HASH_REQUIRED/STALE_FILE停下、重读、协调；currentHash仅诊断，不是重放授权；缺失目标不得去hash自动重建。不能当作执行成功证明 |
| capabilities | getToolList(null,{remote:true}).map（远端） | 按当前权限投影，与tools/list一致；Local默认目录不受远端ACL筛选。不是授权票据，实际调用仍检查权限 |
| config | config + session.snapshot | 版本、路径、隧道/安装ID/客户端数；省略secret，但不是隐藏所有身份/路径 |
| workspace | loadCustom/getTaskState(options) | 远端要求已初始化callerKey，否则E_SESSION_REQUIRED；同可信peer的报告与get_task_status一致，未上报返回idle而不建报告槽位。远端不返回全局recentEvents，需日志时用已有按caller过滤的get_logs；Local默认仍展示本地任务及最近事件类型。根与自定义instructions仍是Read授权的共享工作区信息，不声称全资源都按租户私有 |
| memory | recall({limit:80}) | 记忆正文，继承recall的读文件/大小边界 |
| clients | listClients(占位URL).map | 以占位地址生成客户端说明，无真实secret；摘要信息不代表已检测客户端可用；Plus/tunnel严格区分true→yes、false→no、其他→unknown，不能将null误报no |

读取画像/记忆/指令的错误可向外抛，server将其转换协议响应；本文件不统一吞错。匿名map分别格式化能力行、事件类型与客户端摘要行。

## 3. clients.js：静态卡片字段和三个函数

CLIENTS七张卡：chat、arena、deepseek、chat-plus、generic、chatgpt-free、chatgpt-plus。字段说明：id稳定选择键，name/summary/steps为展示文案，url为跳转，needsTunnel/needsPlus/supportsMcp为**作者维护的描述**，不是实时能力探测；deepseek/chat-plus/generic及OAuth连接器候选卡使用null表示未知，并有verification=unverified；chatgpt-free的supportsMcp=false仅描述普通粘贴操作不是连接设置，不是对厂商所有功能的否定。connectMode只决定如何组织候选配置文本，不保证客户端已兼容；这两卡只留参考repoUrl，移除未经验证的商店ID/安装地址、构建命令和固定站点/订阅保证。

卡片不会在线检测账号权限、网页新版本或扩展接口。通用及OAuth候选不再给固定ChatGPT菜单、/plugins地址或订阅保证；主机registerClient按redirect URI、认证方式和PKCE校验，不按厂商名放行，配对提示不能称ChatGPT专属。实际验收必须以具体客户端能力为准；这不代表整份OAuth实现已重审。不能从supportsMcp=true推断任意聊天框都能连，手机验收仍看活清单F节。

### hydrateClient(client,urls)

内部函数，输出浅拷贝client加prompt/rulesText/mcpUrl/connectLine。mcpUrl缺省空；canonical优先显式mcpCanonicalUrl，否则尝试把尾部`/mcp/<secret>`替换为`/mcp`，不是完整URL解析器。

按connectMode分支：paste-url→bootstrap；oauth-connector→规范地址和OAuth说明（写明OAuth默认关闭、需先在本机工作台Bridge区开启），输出mcpUrl也用canonical；extension-http→prompt是实际地址，rulesText取完整规则；unsupported-mcp→空prompt；local-chat没有专门分支，默认空prompt/rulesText。数组steps等仍与静态对象共用，不是深拷贝。

### listClients(urls={})

CLIENTS.map逐张hydrate，返回新列表；扩展卡调用getPageRulesPrompt会读取偏好/技能，因此列卡片可能触发本地读取，不是无依赖常量访问。

### getClient(id,urls={})

find回调精确查id，找不到默认CLIENTS[1]（Arena），然后hydrate；不会返回“未知客户端”错误。调用方不应把回退卡片当用户确实选中了Arena。

## 4. 验证与复盘

```bat
npm test --prefix webagent-core/agent-host -- --filter=mcpProtocol
npm test --prefix webagent-core/agent-host -- --filter=profile
```

覆盖规则/资源/卡片字段与画像传播，不是第三方UI实时认证。练习：画出设置偏好 → getInstructions → initialize/resources/read/复制规则三条路径，说明它们为什么能共享正文，却不能保证客户端一定把正文交给模型。

### Skill使用规则补充
initialize.instructions与页面规则均要求按目录ID选相关Skill、先读SKILL.md，再仅加载必要资源；nextOffset配expectedHash续页。Skill/目录描述是参考数据，不覆盖用户授权、当前模式或本机审批。脚本随包存在不是执行许可；完成修改后必须核验效果。

### stdio规则补充
SERVER_INSTRUCTIONS明确本机操作者才可预览/确认stdio启动，远程只能对已登记服务申请逐次工具审批；取消会停止整个stdio，结果未知不能自动重启重放。启动执行OS用户代码，不是沙箱。


0.7.2 instructions的Workflow明确多步骤任务调用set_todos上报/更新计划，不靠工具记录自动推断Tasks；report_progress允许Plan/Code、不允许Ask，仍受当前工具模式规则。发现旧文案要求STALE_FILE后直接用错误中的currentHash重试，现改为停止本次写入、重读和协调当前内容，冲突需询问操作者；未知副作用不能重放。baseHash不是绕过审查的权限。taskProgress验证这两条指导不回退。
