# MCP server.js：认证、HTTP/SSE 与 JSON-RPC 请求分发

## 职责与主流程

[server.js](server.js)创建Express router，挂在入口的`/mcp`下；同时支持规范地址与`/:secret`形式。返回router，并额外导出handleRpc/handlePost/promptsFromCustom/isAuthorized/rejectUnauthorized供调用或测试。

```text
入口Origin检查 → requireAuth → GET/POST/DELETE处理器
POST → 会话绑定 → 顺序dispatchOne → handleRpc → 工具/资源/提示
     → JSON-RPC envelope → JSON或单次SSE消息
```

三个结果层要分清：HTTP状态、JSON-RPC error/result、工具result.isError。HTTP200不等于工具成功；成功发送SSE也不等于任务通过。

## 1. 认证、会话与响应辅助函数

| 函数 | 输入/返回 | 顺序/边界 |
|---|---|---|
| extractToken(req) | 请求→token字符串 | Bearer优先，再URL参数secret，再x-mcp-secret，再query.secret；存在错误Bearer不会自动回退到正确URLsecret |
| isAuthorized(req) | 请求→boolean | oauth.verifyAccessToken；允许有效OAuth或当前长期secret，不在这里检查HTTP session归属 |
| rejectUnauthorized(req,res) | HTTP响应 | 401 JSON-RPC错误并附WWW-Authenticate发现地址；requestOrigin决定外部origin |
| requireAuth(req,res,next) | 中间件 | 不通过就拒绝，通过才next，GET/POST/DELETE都用它 |
| wantsSse(req) | 请求→boolean | Accept字符串includes text/event-stream，不是完整Accept质量权重解析 |
| sessTouch(req,extra) | 请求/增量→peer记录 | keyForReq有绑定就把key与extra合并再touch；否则普通touch；extra同名key可覆盖预设 |
| sessionKeyFallback(req) | 请求→client@ip | 缺clientInfo用mcp、缺req.ip用local；后备不是初始化peer身份 |
| incomingSessionId(req) | 请求→trim ID或null | 读Mcp-Session-Id头，不校验格式或权限 |
| bindHttpSession(req,{createIfMissing=false}={}) | 请求→{ok} | 已知ID刷新并绑定；未知ID在允许创建时替换新会话，否则false；无ID且不创建也返回true，即兼容部分无会话调用 |
| mcpEndpointPath(req) | 请求→路径 | 保持有secret的路径或规范/mcp；供GET SSE endpoint事件 |
| rejectUnknownSession(req,res) | 响应 | 404、-32001，提示重新initialize；与401认证失败不同 |
| sendJsonRpc(req,res,payload,httpStatus=200) | 响应 | 附会话ID；Accept SSE就发一条event:message并end，其他json；不是持续结果流 |
| rpcId(id) | 值→RPC id | 只把undefined变null，保留0/null等；不是完整JSON-RPC id类型校验 |
| invalidRpc(id,message) | 值→错误envelope | -32600，复用rpcId |

HTTP会话记录没有在此与OAuth clientId绑定；随机ID+前置有效凭据与“每个token只可用自己的session”是不同保证。任务板用peer key归属，不要宣称完整授权主体隔离。

## 2. 提示与协议选择函数

- **builtinPrompts()**：每次返回一张connect提示元数据，不执行握手。
- **promptsFromCustom()**：loadCustom，prompts.map为name=id或name、title、content前120字符的description，拼内置项；无完整schema检查，坏prompts类型可能抛错。
- **pickProtocol(params)**：支持2024-11-05、2025-03-26、2025-06-18；不支持/未给则回2025-03-26，不是严格拒绝版本不匹配。
- **remoteToolMode(params)**：_meta.mode或webagentMode转小写；ask/plan/code保留，其余回code。由调用者明确选只读模式，不靠未知模式字符串自动限制。

## 3. handleRpc(req)：每个方法分支

async返回业务result，不加JSON-RPC外壳。

### initialize

选clientInfo，取得已绑定/传入/新建HTTP session ID；touch时明确key=`peer:<id>`，setHttpSessionKey绑定。广播agent_connected，返回协议版本、tools/resources/prompts能力标志、serverInfo和getInstructions。能力里声明listChanged不意味着本文件已实现主动推送所有变更通知。

### notifications/initialized、notifications/cancelled、logging/setLevel

均返回{}。**cancelled没有映射请求ID到AbortController，logging/setLevel没有改变日志级别**；接受通知不等于动作已实现。

### ping / tools/list

ping sessTouch incCall并返回时间、busy:false及快照；这不检测所有后台任务是否忙。tools/list触碰会话后返回getToolList()，不按某个请求模式筛选，也不执行工具。

### tools/call

1. 要求params.name，否则抛协议E_BAD_ARGS。发tool_call_start、计时。
2. board_create/claim/update若keyForReq缺失直接返回isError的E_SESSION_REQUIRED文本；这条早退不走后面的统计/结束事件。其他工具可用fallback key。
3. touch记录caller，try await callTool(name,args或{},remoteToolMode,{remote:true,callerKey})。
4. 显式ok/success=false算failed；clipJson结果，更新session调用/失败计数、tracker，广播tool_call_end；字符串原样或JSON.stringify组成第一项text。
5. name严格等于run_command时，截图辅助collectShot检查command/stdout；有dataUrl则追加MCP image的裸base64/mimeType。截图错误局部吞掉，过大图不附但文字结果保留；截图不会进入eventBus。
6. 返回content与isError。工具抛错走catch：publicError、失败统计、结束事件、isError:true文本。

try也包着预算/统计/广播/序列化，因此工具已成功执行后这些步骤失败也可能转成错误；catch中的tracker再失败还可能向dispatchOne抛出。不能笼统承诺“统计永不影响工具响应”，也没有回滚先前修改。只有这个分支调用tracker.record，ping的session计数不等于用量计数。

### resources/list / resources/read

返回资源定义或readResource结果数组；未知资源抛ProtocolError E_NOT_FOUND。读资源的真实磁盘错误继续由外层处理。

### prompts/list / prompts/get

list取promptsFromCustom；get connect返回固定user提示与握手步骤。其他在custom.prompts.find按id或name查找，找不到协议E_NOT_FOUND，命中返回content。不渲染模板参数，也不真正开始工具循环。

### 默认方法

抛ProtocolError E_UNKNOWN_CMD；方法级错误与“存在tools/call但工具业务失败”不同。

## 4. dispatchOne(req,body) 与 handlePost(req,res)

**dispatchOne**拒绝空/非对象/数组body和jsonrpc非2.0，返回response+HTTP400。通知判定是无id或method以notifications/开头，故id:0保留为请求，带id的notifications也被当通知。没有单独完整校验method/params/id所有类型。

把req.body改成本项再handleRpc。正常请求返回result envelope/200；通知无论正常或catch错误都不回RPC。异常publicError后，未知方法HTTP404/-32601，其他按protocol→-32602、execution→-32603（err.rpcCode可覆盖），HTTP通常200。

**handlePost**空批次先400。items.some只看是否有initialize决定是否允许创建/替换session；这在逐项严格RPC校验之前发生。绑定失败404。保存原req.body，顺序await dispatchOne，每个response收集；finally恢复req.body。批次全部通知→204；有响应→200数组；单项按其状态返回；单通知→204。没有并行批次执行、每项独立会话隔离或批次事务，前项写入不因后项失败回滚。

## 5. hostStatus / GET / DELETE 与生命周期回调

**hostStatus()**返回online、产品/工作区、工具名map、资源URI map、完整instructions、会话与支持的传输/认证描述。状态在线不探测外网。

**handleGet(req,res)**先绑定session，SSE允许创建；非SSE无session也可读授权后的hostStatus。有SSE且当前连接数已32则503（绑定已在此前发生）；否则计数+1，写endpoint事件，15秒interval写注释心跳，10分钟timeout结束。

两个计时器支持unref；心跳/结束回调错误吞掉；req close回调减少连接数、清两个timer。名为SSE_IDLE_MS但**不是活动重置的空闲计时，而是固定10分钟寿命**。这条GET连接没有注册eventBus监听来推送全部工具日志；POST SSE则是一次响应立即关闭。

**handleDelete(req,res)**取传入ID并destroyHttpSession，已无也204；不撤销OAuth、不停止进程、不删磁盘任务板，也不主动清展示peer记录。
