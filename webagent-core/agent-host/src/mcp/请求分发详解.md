# MCP server.js：认证、HTTP/SSE 与 JSON-RPC 请求分发

## 职责与主流程

[server.js](server.js)创建Express router，挂在入口的`/mcp`下；同时支持规范地址与`/:secret`形式。返回router，并额外导出handleRpc/handlePost/promptsFromCustom/isAuthorized/rejectUnauthorized供调用或测试。

```text
入口Origin检查 → requireAuth → GET/POST/DELETE处理器
POST → 整份RPC/版本/批次准入 → 会话绑定 → 顺序dispatchOne → Bridge模式租约 → handleRpc → 工具/资源/提示
     → JSON-RPC envelope → JSON或单次SSE消息
```

三个结果层要分清：HTTP状态、JSON-RPC error/result、工具result.isError。HTTP200不等于工具成功；成功发送SSE也不等于任务通过。

## 1. 认证、会话与响应辅助函数

| 函数 | 输入/返回 | 顺序/边界 |
|---|---|---|
| extractToken(req) | 请求→token字符串 | Bearer优先，再URL参数secret，再x-mcp-secret，再query.secret；存在错误Bearer不会自动回退到正确URLsecret |
| isAuthorized(req) | 请求→boolean | oauth.verifyAccessToken；允许有效OAuth或当前长期secret，不在这里检查HTTP session归属 |
| rejectUnauthorized(req,res) | HTTP响应 | 401 JSON-RPC错误并附WWW-Authenticate发现地址；requestOrigin决定外部origin |
| requireAuth(req,res,next) | 中间件 | 提取并验证token；失败401，成功写req.mcpPrincipal（OAuth kind+clientId、长期secret kind+密钥的SHA256）再next，GET/POST/DELETE都用它 |
| wantsSse(req) | 请求→boolean | Accept字符串includes text/event-stream，不是完整Accept质量权重解析 |
| sessTouch(req,extra) | 请求/增量→peer记录 | key取keyForReq（已初始化会话的peer），否则取session.sessionKey（按已验证凭据区分的无会话调用者，F71），与extra合并再touch；因此tools/call的callerKey与其后的计数落在同一行，不再另记一条mcp@ip；extra同名key可覆盖预设 |
| incomingSessionId(req) | 请求→trim ID或null | 读取经入口校验的Mcp-Session-Id头；自身不代替认证 |
| hasMalformedSessionHeader(req) | 请求→boolean | 缺省允许；检查rawHeaders重复字段，并要求单字符串、1–512可见ASCII且无逗号；拒绝空值/空白/数组/非ASCII。512和禁逗号是本项目更窄策略，不宣称为MCP通用限制 |
| rejectMalformedSessionHeader(req,res) | 请求→HTTP400 | 在绑定/分配前拒绝畸形头，不回显SID；错误响应只回传本项目有效ID，否则null |
| rejectSessionCapacity(req,res) | 请求→HTTP503 | 全部200会话在途时返回固定容量错误，不驱逐忙会话、不暴露SID |
| bindHttpSession(req,{createIfMissing=false}={}) | 请求→{ok} | ID存在且principal匹配才刷新并绑定；未知/异主体ID在允许创建时返回另一条新会话，不继承原peer，否则false；分配器返回null时返回ok:false/full:true；无ID且不创建也返回true，即兼容部分无会话调用 |
| rejectUnknownSession(req,res) | 响应 | 404、-32001，提示重新initialize；与401认证失败不同 |
| sendJsonRpc(req,res,payload,httpStatus=200) | 响应 | 附会话ID；Accept SSE就发一条event:message并end，其他json；不是持续结果流 |
| rpcId(id) | 值→RPC id | 有效≤256字符字符串或安全整数原样保留（包括0与空串），其他值统一null，不反射非法对象/超长ID |
| invalidRpc(id,message) | 值→错误envelope | -32600，复用rpcId |

HTTP会话绑定认证后的principal，不是原始token：同OAuth client刷新后仍可使用原ID和peer，其他client或新长期secret不可。未知/异主体普通请求同为404；允许创建的initialize或GET SSE可生成新ID，不能修改或冒用旧会话。共享同一凭据且已知真正会话ID的客户端仍无法在此区分，不宣称完整多租户/OS隔离。

## 2. 提示与协议选择函数

- **builtinPrompts()**：每次返回一张connect提示元数据，不执行握手。
- **promptsFromCustom()**：loadCustom已把prompts限制为最多100项且每项只保留有界id/name/content字符串，再map为name=id或name、title、content前120字符的description，拼内置项；历史文件若把已知prompts槽写成错类型会在loadCustom以E_CUSTOM_CORRUPT失败，不进入map。固定形状仍不证明提示内容可信或适用，也未在此要求字符串非空。
- **pickProtocol(params)**：支持2024-11-05、2025-03-26、2025-06-18；initialize请求的协商提案不支持/未给则回2025-03-26；与HTTP版本头不同，后者由protocolForRequest严格验证。
- **remoteToolMode(params)**：_meta.mode或webagentMode转小写；ask/plan/code保留，其余回code。由调用者明确选只读模式，不靠未知模式字符串自动限制。

## 3. handleRpc(req)：每个方法分支

async返回业务result，不加JSON-RPC外壳。

### initialize

选clientInfo，取得已绑定/传入/新建HTTP session ID；复用该会话已有peer key，或独立randomBytes生成公开`peer:<随机hex>`，touch后setHttpSessionKey绑定；公开标签不得包含HTTP session ID。把准入选择的protocolVersion存入私有HTTP会话（直接模块调用用已有版本或pickProtocol）；广播agent_connected，返回协议版本、tools/resources/prompts能力标志、serverInfo和getInstructions。F70起三项能力均声明`listChanged:false`且不再声明`logging`：本服务器从不推送list_changed或notifications/message，logging/setLevel也不改变任何东西；此前宣告true/logging会让客户端等待永远不会来的推送（外部复审P2-7）。

### notifications/initialized、notifications/cancelled、logging/setLevel

initialized和logging/setLevel仍返回{}且不改变日志级别（未声明logging能力，但对仍然调用它的客户端保持兼容）。cancelled从params.requestId取目标，以keyForReq和extractToken构造归属摘要，调用lifecycle.cancel；不返回是否找到目标。通知不会取消其他会话或不同凭据的调用。

### ping / tools/list

ping sessTouch incCall后返回**空对象`{}`**（F70第七批）。MCP规定ping只回空结果，官方SDK客户端用严格EmptyResult校验：旧的`{ok,ts,busy,session,host}`会让client.ping()抛“Unrecognized keys”，官方一致性套件ping场景失败。主机快照仍可从ping工具、workspace_info与GET /mcp取得。tools/list触碰会话后返回getToolList(null,{remote:true})，按本机Read/Edit/Execute/Capture权限过滤；不按单次ask/plan/code模式筛选，也不执行工具。工具执行时仍会再次检查权限。

### tools/call

1. 要求params.name，否则抛协议E_BAD_ARGS。发tool_call_start、计时。
2. resolveToolName归一后为board_create/claim/update、external_request、workflow_request、confirm_connection且keyForReq缺失，先发失败完成摘要再返回isError的E_SESSION_REQUIRED；不进入后面的session/tracker计数。其他工具用session.sessionKey作无会话调用者键：client@ip之后附按req.mcpPrincipal派生的盐化标签（F71），URL密钥与不同OAuth客户端即使同为127.0.0.1来源也是不同调用者；不是初始化peer身份，不以peer:开头。
3. touch记录caller，try await callTool(name,args或{},remoteToolMode(params),options)；options含remote:true、initializedSession布尔值、sess0.key作为callerKey及受限_meta任务关联号。
4. 共享isToolFailure判断显式失败、非零退出、超时、取消和unknown；clipJson结果，更新session调用/失败计数、tracker，广播tool_call_end；字符串原样或JSON.stringify组成第一项text。
5. resolveToolName归一后为run_command且control.permissions().capture允许时，截图辅助collectShot检查command/stdout；有dataUrl则追加MCP image的裸base64/mimeType。截图错误局部吞掉，过大图不附但文字结果保留；截图不会进入eventBus。
6. 返回content与isError。工具抛错走catch：publicError、失败统计、结束事件、isError:true文本。

try也包着预算/统计/广播/序列化，因此工具已成功执行后这些步骤失败也可能转成错误；catch中的tracker再失败还可能向dispatchOne抛出。不能笼统承诺“统计永不影响工具响应”，也没有回滚先前修改。只有这个分支调用tracker.record，ping的session计数不等于用量计数。

### resources/list / resources/read

resources/list返回静态定义；resources/read先由control.assertAllowed要求Read，再以固定{remote:true,callerKey:keyForReq(req)}调用readResource返回contents数组；不信任params中的remote/callerKey/_meta。未知资源抛E_NOT_FOUND。资源层再次检查Read；workspace要求初始化的可信peer、只投影该peer任务且不带全局recentEvents，capabilities复用tools/list远端权限过滤。缺失SID读取workspace为E_SESSION_REQUIRED，未知/已删除SID仍在绑定处404；其他资源的共享工作区信息仍按Read授权。真实磁盘错误由外层处理，不把本次修投影当作新增写权限。

### prompts/list / prompts/get

list/get均先检查Read；list取promptsFromCustom；get connect返回固定user提示与握手步骤。其他在custom.prompts.find按id或name查找，找不到协议E_NOT_FOUND，命中返回content。不渲染模板参数，也不真正开始工具循环。

### 默认方法

抛ProtocolError E_UNKNOWN_CMD，经dispatchOne变成**HTTP 200**上的JSON-RPC `-32601`。方法级错误与“存在tools/call但工具业务失败”不同。

## 4. dispatchOne(req,body,res) 与 handlePost(req,res)

**rpcEnvelopeError(body)**只接受对象、jsonrpc为2.0、顶层jsonrpc/id/method/params；method为1–256字符字符串，params若给则为非null非数组对象。notifications/方法不允许id；其他方法必须有validRequestId。cancelled另要求有效params.requestId；initialize若提供protocolVersion须1–64字符串，clientInfo/capabilities若给须对象。返回固定原因或null；不执行工具。无method的响应envelope属于本服务未接收的非预期客户端响应，400拒绝，不伪装已完成服务端请求。

**protocolForRequest(req,initialization)**检查原始重复版本头及支持集合，getHttpSession只读查当前principal拥有的有效会话。版本优先已协商值，再initialize提案，再显式头，均无则2025-03-26；显式头与已知/提案值冲突、重新initialize变更已有版本均拒绝。未知initialize提案保持旧fallback协商，不代表接受不支持的HTTP版本头。缺省头沿用已知版本，因此不能靠省略头把2025-06-18降为支持batch的旧版。

**postAdmission(req)**验证整份输入：单对象或1–64项数组，逐项rpcEnvelopeError，批内禁止initialize；用JSON.stringify(id)集合拒绝重复，区分数值0与字符串"0"。随后确定版本，2025-06-18不允许任何数组；合法旧版批次仍顺序执行。全份通过才把有效版本写到req.mcpProtocol并允许绑定会话。64/ID长度/安全整数及顶层白名单是本项目收窄策略，不冒称MCP通用上限。

**dispatchOne**只消费已通过准入的成员；无id才为通知，带id的notifications已在准入拒绝。不是公共导出入口；handleRpc直接模块测试本身不代表HTTP准入。

把req.body改成本项；各方法由executionControl.run(bridge)检查跨模式互斥并保留在途租约。tools/call再由lifecycle.run包裹handleRpc，传peer/凭据摘要、RPC id与响应对象，其余方法在该模式租约内直接handleRpc。正常请求返回result envelope/200；通知无论正常或catch错误都不回RPC。异常publicError后，未知方法-32601，其他按protocol→-32602、execution→-32603（err.rpcCode可覆盖），**HTTP一律200**。F70第七批前未知方法回HTTP 404：Streamable HTTP中404表示“会话已失效、请重新initialize”，客户端探测可选方法（resources/templates/list、completion/complete）时会被误导。

**handlePost**先检查会话头，再postAdmission整份预检；失败HTTP400/-32600，错误ID安全投影，不分配/刷新会话、不进入模式租约、不发tool_call_start或写盘。通过后才按单独initialize允许创建/替换；未知会话404，全忙容量503。绑定后beginHttpSessionWork登记在途；保存原req.body，顺序await dispatchOne，每个response收集；finally恢复req.body并单次release。旧版批次全通知与单通知均202空体；有响应的旧版批次200数组；单请求按其状态返回。

整份准入只保证形状、版本、批预算及批内ID错误不会执行前项，不预执行全部工具参数schema/文件预条件、不回滚已执行成员。合法批次中后项业务失败仍可能已有前项成功；同一顺序batch后面的取消不能抢先取消前面，须另发请求。现有在飞owner+typed-id登记保留，批内Set不持久、不跨HTTP请求保留去重墓碑；不是持久exactly-once，也不声称实现所有会话期ID不可重用。

## 5. hostStatus / GET / DELETE 与生命周期回调

**hostStatus()**返回online、产品/工作区、按remote权限过滤的工具名map、资源URI map、会话及支持的传输/认证描述；传输只列`streamable-http`（此前还列未实现的`sse`）。Read允许才给完整instructions，否则给禁止读取的短说明；状态在线不探测外网，也不等于已执行resources/read。

**handleGet(req,res)**先拒绝畸形会话头与不支持/冲突版本头（400，不续期）。随后，**要SSE却不带Mcp-Session-Id**的GET即旧版2024-11-05 HTTP+SSE握手（开流→等endpoint事件→从流上读响应）：本主机未实现该传输（POST就地回答），直接405、`Allow: POST`并给出改用Streamable HTTP的说明，不分配会话、不切换Bridge模式（F70第七批；此前会开流并发endpoint事件，官方SSEClientTransport因此永远等不到initialize响应）。其余GET再调用control.enter(bridge)检查并激活Bridge工作模式、立即release，然后**只绑定、从不分配**会话：未知/过期会话404要求重新initialize（此前会悄悄新建一条未初始化会话并回传其ID），全忙503；模式冲突返回HTTP409。非SSE无session也可读授权后的hostStatus。GET不会像POST工具调用那样在整个响应/流生命期持有模式在途计数，不能把瞬时enter检查写成长流租约。有SSE且当前连接数已32则503；否则计数+1并beginHttpSessionWork持有会话pin，先写一行`: stream open`注释（不再写endpoint事件），15秒interval写注释心跳，10分钟timeout结束。

两个计时器支持unref；心跳/结束回调错误吞掉；res.once(close)回调减少连接数、清两个timer并release会话pin；名为SSE_IDLE_MS但**不是活动重置的空闲计时，而是固定10分钟寿命**。这条GET连接没有注册eventBus监听来推送全部工具日志；POST SSE则是一次响应立即关闭。

**handleDelete(req,res)**先检查会话头与版本，畸形/不支持/冲突400且不删除；再取传入ID并带req.mcpPrincipal调用destroyHttpSession；未知、异主体也统一204且不删他人会话。204不能证明目标曾存在或已删除；不撤销OAuth、不停止进程、不删磁盘任务板，也不主动清展示peer记录。

## 调用计数来源补充
成功、结果式失败和catch失败的tool_call_end均标source=Bridge-Remote；任务板缺少初始化会话而提前拒绝时也发失败完成摘要。缺少工具名而不能识别调用的协议错误、initialize/tools/list不作为已完成工具计数。本地REST tool/call没有该source，不混入Bridge累计。统计只证明主机处理过请求，不证明所有调用来自同一外部产品或当前仍连接。

## 关联元数据
initialize._meta.identity与workspace_info/ping/status一致。tools/call接受受限_meta[webagent/taskId]关联任务；结果_meta.trace和异常_meta.trace返回服务器生成的callId等，不把客户端关联编号当授权。原认证/模式策略保持。

会话前置门槛覆盖board写、external_request、workflow_request、confirm_connection；必须keyForReq取得已绑定HTTP会话，不接受clientInfo自称peer:绕过。工具确认只消费本机随机挑战，不创建凭据或扩大权限。

## 7. requestLifecycle.js逐函数与闭包

`createLifecycle({timeoutMs=300000,limit=64}={})`创建私有active Map；服务器使用默认实例，测试可注入更短期限。没有磁盘持久化、后台重放或自动重试。

- **owner(session,credential)**：两者都有才对JSON元组取SHA256，否则null；Map不存凭据原文。凭据轮换后是不同owner，因此正在运行的调用要用原有效凭据取消，不把“同一账户”推断为同一owner。
- **validRequestId(id)**：导出的共享纯函数，接受最长256个JS字符单元的字符串（含空串）或Number.isSafeInteger；拒绝null/布尔/对象/小数/不安全整数。用于HTTP请求、取消目标及生命周期入口，256/安全整数属于本地可寻址预算。
- **key(owner,id)**：使用validRequestId，JSON元组保持数值0与字符串"0"不同；无owner/不支持ID返回null。
- **cancel(identity,id)**：精确找到在途controller才abort；未知、已完成、错误owner均静默。已完成取消不留墓碑，不污染后续复用ID。
- **run(identity,id,response,fn)**：先拒绝无效ID（不执行fn、不占槽），再检查总64在途与同owner同ID重复；满时E_BUSY、重复E_BAD_ARGS。无已初始化owner但ID有效的兼容调用仍用独立Symbol占容量，不能通过SID寻址取消；不把此次准入修复宣传为强制所有工具先初始化。创建controller与5分钟timer，响应close且尚未正常结束时abort；已destroyed也检查。runWithSignal传播给fn，finally清timer/close监听/Map记录，异常仍向外抛。
- **abort闭包**仅转发信号，不能中断忽略信号的同步代码。期限到达不会把仍执行的调用提前从容量Map删除；等待其真实settle后清理，避免放出无界残留任务。HTTP正常结束不自动取消已返回execId的后台命令；这类操作应使用命令管理接口。

DELETE session仍只删除HTTP会话，不替代工具取消；失去会话后不能寻址原调用，但其断连/期限及工具自有限额仍存在。通知中的reason不用于执行命令或回放。该模块在HTTP dispatchOne层生效；测试直接调用handleRpc不应被当成完整HTTP生命周期。

`mcpCancellation.test.js`用真实认证HTTP和受控可取消工具夹具验证跨会话/未认证拒绝、ID=0、重复ID和释放；`requestLifecycle.test.js`验证不同凭据、数值/字符串ID、容量、期限、异常与断连清理。不是真实Windows进程树或第三方客户端取消验收。

## 主机工作模式与所有者权限

HTTP dispatchOne通过executionControl.run(bridge)保留在途租约；GET只瞬时enter后release检查/激活Bridge，不持有SSE全寿命租约。跨Chat模式返回协议错误，不自动抢占。tools/list按remote权限过滤，工具实际派发仍查标准名；resources/read与prompts/list/get要求Read，Read关时initialize只给禁止读取的简短指令。run_command及归一别名回图前检查Capture。初始化也占用idle，之后空闲不自动让给Chat。验证executionControl真实HTTP；同类型MCP仍可并行，不声称OS资源全隔离。

第40组回归：mcpBoard直接加载真实index，公开peer标签不能重放为会话头并改写他人任务；OAuth跨client复用/删除拒绝、刷新及重新initialize保留归属。mcpCancellation从公开peer尝试取消也被拒，另以同一OAuth client的两个有效token证明取消仍要求原调用具体凭据，而非仅principal相同。刷新撤销旧access后，新token不能取消旧凭据的在途调用；需在轮换前取消或断开原HTTP请求，不把刷新当自动停止。
