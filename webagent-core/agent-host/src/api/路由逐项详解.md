# routes.js：本机 API 的每个路由与回调

## 职责、前置条件与数据流

[routes.js](routes.js)导出Express router，由入口挂在`/api`并先做本机控制面/跨站检查；本文件不是独立对外认证服务。以下路径省略`/api`。依赖模型/工具/配置/隧道/PTY/事件模块，路由主要负责取参、调服务与映射响应。

不要假设所有错误格式一致：有些路由自己try/catch，有些依赖Express错误处理中间件；大多数JSON成功外壳不能取代业务判定。默认JSON body上限由入口设置，本文件导入MAX_TEXT_BYTES但未把它作为统一请求限制使用。

## 1. 全部具名辅助函数

| 函数 | 参数/返回 | 语义 |
|---|---|---|
| publicOrigin(req) | 请求→origin字符串 | 转发proto/host优先、逗号首项，缺省UI端口；当前本文件没有调用它，不是MCP地址的实际来源 |
| mcpOrigin(req) | 请求→origin字符串 | publicTunnelUrl去末斜杠优先，否则本机config.port；参数req当前未使用 |
| isNamedTunnelProvider(provider) | provider→boolean | cloudflare-named或named |
| isNgrokProvider(provider) | provider→boolean | 只匹配ngrok |
| recentToolLogs(limit=12) | 数量→展示日志 | 最近40事件filter tool_call_end，limit限1–40后slice，再map只留type/时间/tool/success/duration；不是所有历史调用 |
| mcpInfo(req) | 请求→本机连接信息 | mcpOrigin+长期secret构URL，规范/mcp另给OAuth；含secretKey、prompt、卡片、pairing、隧道快照。**这个对象有敏感凭据**，不是公网资源 |

## 2. 状态、模型、偏好与日志路由

| 方法/路径 | 参数和调用 | 返回与失败边界 |
|---|---|---|
| GET /status | store.load、工具/任务/Plan/MCP/用量快照、mcpInfo | 大状态对象；工具map去schema，模型map只给hasKey而不发apiKey；但mcpInfo仍有MCP长期secret，不能说此接口整体无秘密 |
| GET /models | store.load | models.map把已有apiKey换成四圆点；其他字段保留。占位符不是可再提交的真实Key |
| POST /models | activeModelId真值更新；models数组整体替换；单model按id findIndex合并或push；multiModel浅合并 | store.save后success；无路由级catch/schema全量转换，不会自动将四圆点占位符还原旧Key |
| POST /providers/probe | body.baseUrl/apiKey→listRemoteModels | success/models，异常400；继承探测函数无显式deadline的现状，不是Chat5分钟scope |
| GET /profile/detect | detectEnvironment/TechStack/listSkills | 环境/技术栈/技能；检测是启发式，不激活Conda |
| GET /customizations | loadCustom | 原定制对象，坏文件回默认策略在模型层 |
| PUT /customizations | body→patchCustom | success+新对象；嵌套覆盖、顺序四文件写入边界保持，非事务 |
| GET /logs | getRecentLogs(80) | 脱敏摘要事件，不是原始完整执行日志 |
| POST /tasks/reset | resetTaskState | 返回新任务状态；不清Plan回合/记忆/命令进程 |

这里每一行对应一个匿名router回调；额外map/findIndex只是格式化/选择，不独立认证用户。

## 3. 文件与技能路由

**GET /files/tree**：调用list_directory，ask模式、根目录、递归深度5；结果直接json，抛错400。UI文件树不是完整磁盘清单。

**GET /files/content**：query.path转String，resolveSafePath同时检查路径与敏感文件；不存在或目录404；readBoundedText读普通文本，computeHash、rememberHash，然后返回path/content/hash/size。size是JS字符串length，不是文件字节数；读请求会更新哈希缓存，不能说绝无持久化副作用。其他异常400。

**PUT /files/content**：要求path真值且content为字符串；write_file带confirm_overwrite:true和可选expectedHash，mode=code；成功返回path/hash。抛E_STALE_FILE或消息含STALE_FILE→409，其他400，带error/code/detail。这是编辑器保存的显式覆盖路径，但不绕过传入旧hash冲突检查。没有自己原样fs.writeFile。

**GET /skills**：listSkills().map取name/path/preview/skillFile/skillFileAbs，向本机编辑器提供定位；包含绝对路径，不是完全匿名化资源。

**POST /skills**：name trim、非ASCII word/连字符替换为`-`、去首尾横线、截40，空则400。body.content假值时用默认模板；写`.webagent/skills/<name>/SKILL.md`，confirm_overwrite:true，code模式；成功返回目录，异常400。名字正规化可造成不同输入落同名，UI不能假设任意中文名原样保存，也不是自动安装扩展代码。

## 4. 工具、共识与 Chat 流

**POST /consensus/run**：body.taskDescription交runMultiModelConsensus，success/result；异常500。实际导出的工具共识入口应接着读tools/index及consensusEngine，不能只凭路由名推断一定调用多个外部模型。

**POST /tool/call**：name/arguments/mode（缺省code）；发start、await callTool、发success:true end，再返回 `{success:true,result}`。**不额外判断result.ok/success=false**，业务失败仍可在成功外壳里；只有抛错走400/失败事件。与MCP isError或runChat.timedTool不同。

### POST /chat 的全部闭包与结束顺序

1. 新建AbortController；**abort()**调用controller.abort；5分钟timeout调用abort。
2. **disconnected()**在res尚未writableEnded时abort；注册req aborted与res close。
3. 设置NDJSON/no-cache/no-transform/X-Accel-Buffering，能flushHeaders则立即发头。后续错误通常已经不能改HTTP状态。
4. **emit(type,data={})**仅在未destroyed/未结束时写一行JSON+换行，类型与data合并；不检测write背压，也不提供逐token模型流保证。
5. body.client严格等于vscode-extension才pty=true；runWithSignal闭包套runWithPty({pty,remote:false,emit})异步闭包，再runChat传mode/message/history/modelId/thinkLevel/planAction/emit。这里直接传mode，没有把agent改code。
6. await正常结束发done；抛错发error。**runChat内部可能已emit error然后返回失败对象，路由仍发done**；done是流处理结束不是业务成功。
7. 清timeout，off两个监听；未destroyed则res.end。

取消只传到实际接入的下层，已经完成的写入不回滚。清理代码在try/catch之后而非finally，若错误emit自身再抛，不保证走完末尾清理；不要把它说成任意异常下都已形式化保证。

## 5. PTY 桥接路由

| 路径 | 行为 | 错误 |
|---|---|---|
| POST /pty/hello | noteClient(body)，成功回快照 | 工作区/client不匹配409 |
| GET /pty/jobs | noteClient(query)，listPending(clientId)+快照 | 不匹配409 |
| POST /pty/jobs/:jobId | noteClient(body)，report(jobId,body,clientId) | 不匹配409，找不到/不可报告任务404，否则ok+out |

这些是本机扩展桥接，不是开放的远程PTY接口。工作区/所有权/审批/过期的状态机在ptyJobs与扩展实现中，路由成功不等于shell命令已经退出。

## 6. Bridge 生命周期及其身份路由

### POST /bridge/start

全局bridgeGeneration先+1并捕获ticket；读配置，loggedIn/deviceAuthorized不满足403。provider优先body、配置、cloudflare；域名允许显式空清除，token只有body非空才覆盖旧保存值，因此空token不是“清除凭据”。store.patch发生在启动前。

将运行状态置false、公网URL置null、设provider、ensurePairing。await tunnel.stopTunnel（它包含ngrok停止），失败记tunnelError；await后ticket过期返回409。无停止错误才按Quick/Named/ngrok分支启动，异常记录而非抛成功；未知provider不会自动启动任意进程。

启动后再核对ticket，过期409；仅无tunnelError且config.publicTunnelUrl有值时bridgeRunning=true，发started/failed，返回success/running/provider/note/error+mcpInfo。可能HTTP200但success=false。日志得URL仍不是从手机到本机的端到端证明。启动前已经保存的provider/token不会因连接失败自动回滚。

### 其他生命周期路由

| 方法/路径 | 执行顺序 | 不应误解 |
|---|---|---|
| POST /bridge/stop | generation++，await stopTunnel，运行false，广播，返回mcpInfo | 停止失败会抛出，不假报成功；不撤销全部OAuth |
| POST /bridge/reset-secret | generateNewSecret，oauth.revokeAll，广播rotated，返回mcpInfo | 同时清OAuth，但新secret写磁盘失败在config内部被吞；success不能证明永久保存 |
| POST /bridge/reset-round | mcpReset，resetHashes，广播，返回空session | 不清Plan回合、用量、记忆、任务板，也不停止所有进程 |
| POST /bridge/login | store.patch为local-demo已授权 | 本机演示标记，不是GitHub登录 |
| POST /bridge/token | github.loginWithToken | 成功对象；错误用err.status或400 |
| POST /bridge/device | github.startDeviceLogin | success+码/授权地址；错误状态及code |
| POST /bridge/device/poll | github.pollDeviceLogin | pending/done对象，不强加success；异常按status或400 |
| POST /bridge/github/clear | clearGithubKeepDemo | 回演示身份，不代表停隧道 |
| POST /bridge/logout | generation++，resetPending，store写未授权，await stopTunnel，运行false | 不调用oauth.revokeAll；若停止失败，身份可能已先改变，不是全事务 |

## 7. 验证与调用链练习

```bat
npm test --prefix webagent-core/agent-host -- --filter=apiFiles
npm test --prefix webagent-core/agent-host -- --filter=bridgeTunnel
npm test --prefix webagent-core/agent-host -- --filter=httpSmoke
npm test --prefix webagent-core/agent-host -- --filter=ptyLifecycle
```

分别看文件hash冲突、假隧道、真实本地HTTP/NDJSON和PTY生命周期断言；真实Windows/供应商/手机仍另验。练习：从编辑器一次保存、Chat一次失败、Bridge两个并发start逐层追踪谁更新了哪份状态，以及哪些成功外壳不能当业务成功。
