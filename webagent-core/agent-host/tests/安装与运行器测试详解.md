### F65：后端依赖fallback的真实准备代码接线

harness另将真实installer/preparation.js装入独立VM，与main共用受控spawn/perf_hooks/timer；即使新增import也不能漏到真实npm安装。harness.children仅为所有夹具spawn的观测列表，不是main的服务器清理所有权表。

新增三个受控时钟负例：必须存在120000ms工作预算；计时器未执行但时间已到的exit0仍拒绝；取消时直接子进程未确认退出，1000ms观察后必须非零/unref且不由main再kill一次。原实现分别缺期限、接受迟到成功或使用服务器清理时序；另四项检查SIGINT/SIGTERM/私有IPC stop/disconnect以及重复停止，按已有preparation策略只发一次SIGKILL并禁止后续agent/editor。这四项是新接线/清理策略合同，不把旧的正常SIGTERM行为单独称为漏洞。

最后通过受控spawn启动真实无害Node保持进程，取消必须等该ChildProcess的退出被观察到；此正例旧实现也通过，不冒充新增缺陷。已有npm成功/失败/取消、认证/健康/启动失败与对无关进程不干预的断言保留。没有真实npm/code-server安装、全部后代清理或Windows桌面验收；准备阶段不回滚部分node_modules。验证：codeServerLifecycle与installerPreparation，再跑完整套件。
