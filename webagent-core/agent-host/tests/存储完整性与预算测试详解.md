## fileReadSafety.test.js

来自并行分支01a0c932，随合并纳入。覆盖文本读取的编码合同与只读Git工具的越权面。

辅助：**check(name,fn)**逐项执行并收集失败名，末尾一次性比对，避免首个失败掩盖后面的问题；**git(args)**在夹具仓库里同步执行Git；**run()**建临时仓库、跑全部场景、清理。

钉住的合同：非法UTF-8（截断序列、过长编码）被拒绝且原字节不变；合法UTF-8连同**BOM与CRLF**都保持字节级hash——解码后重新编码必须还原磁盘字节，否则hash不能代表文件；非法字节被外部改动后不能用旧hash覆盖或打补丁；过期但合法的hash仍然拒绝写入。

Git侧三条是本分支合并时**实测复现后修复**的真实缺陷：①聚合与目录diff（`{}`、`.`、子目录、`stat`）此前只对无路径的情形套敏感规则，显式传目录会绕过过滤；现在一律先枚举元数据再按允许清单取内容，并用`omittedFiles`/`truncated`**显式披露不完整**。②`git mv secret.key public.txt`这类重命名，旧名被排除而新名放行，导致密钥全文以无害新名渲染出来；现在重命名的**两侧任一命中敏感规则就整条withhold**。③工作区是仓库子目录时，`git mv ../outside.txt inside.txt`的跨边界重命名会把父仓库内容带进来；现在任一侧落在工作区外即整条withhold。元数据枚举还固定加`--no-relative`，否则用户本地的`diff.relative=true`会让路径被二次剥前缀、把合法改动全部误删。
