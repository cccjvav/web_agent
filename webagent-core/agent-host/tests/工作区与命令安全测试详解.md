## sensitiveBoundary.test.js

F62独立复审新增。全部在`mkdtempSync`建的临时工作区里跑，不触碰用户仓库或真实秘密文件。

夹具helper：**countIgnoreReads**用替换`fs.readFileSync`的方式统计一次调用里`.webagentignore`被完整读取了几次（只计数，不改内容）；**git**是包装`execFileSync`的小助手，用来在临时目录里造一个真实仓库；**run**建目录、跑全部断言并在finally清理。

覆盖的合同：

- **加载代价**：对一个600项的目录做一次列目录，`.webagentignore`的完整读取次数必须是常数级而不是每个候选路径一次。基线实现是601次（先红后绿的正是这条）。这测的是规则**加载**开销，不是匹配速度，也不证明匹配语义覆盖了所有秘密文件名。
- **即时生效**：缓存按"工作区根 + 规则文件身份（mtime纳秒/大小/inode/ctime纳秒）"判定。测试在同一进程里改写、追加、删除规则文件，要求下一次检查立刻按新规则走——缓存不能让用户刚加的规则晚一步生效。它挡不住刻意保持全部元数据不变的改写。
- **上限**：超过512条模式或64KiB的规则文件按上限截断，`customRuleStatus()`报告`truncated:true`；超字节时最后一行可能被切断，因此整行丢弃，不让半截模式静默生效。基线没有任何上限，一个448KiB的规则文件能把扫描放大约90倍。
- **git越界**：把工作区设为一个更大仓库的子目录，`git_status`/`git_diff`只能报告该子树内的路径；不带路径的diff还要逐条套用与显式diff相同的敏感规则，被排除者以`excludedSensitivePaths`列名。这是逐路径规则的一致化，**不是脱敏导出**。

## textEncoding.test.js

F62独立复审新增，同样只用自建临时工作区。helper **write**按原始字节写夹具文件（绕开字符串转换，才能造出非法UTF-8），**run**跑全部断言并清理。

- 合法内容（ASCII、CJK、emoji、CRLF、BOM）读出的字符串与hash不变；特别构造一个正好跨64KiB读块边界的`中`，要求解码后仍是完整字符——这锁定"先拼齐字节再整体解码"，而不是逐块解码。
- 非法字节一律拒绝并抛`E_ENCODING`：孤立代理半体、截断的多字节序列、overlong的`C0 80`、超范围的`F5`。`classifyToolError`必须把它归为不可重试。
- 关键的版本安全断言：`41 ff 0a`与`41 fe 0a`是不同的磁盘字节，基线宽松解码后同为`A\uFFFD\n`、同一个hash，于是针对前者取得的hash能被用来覆盖后者。现在两者都根本不发hash。
- 合法文件的过期hash仍报`STALE_FILE`且不落盘；`writeFile`与`apply_patch`覆盖非法文件时报`E_ENCODING`，原字节逐字节不变。
- 目录扫描遇到混合编码时仍能命中干净文件——纯扫描路径允许宽松解码，因为它既不取hash也不回写。

这些断言锁定的是"被接受的读取里hash与磁盘字节一一对应"，不是编码探测、转码或字符集猜测能力。

## commandEncoding.test.js

F62第4批新增，全部在自建临时工作区里跑真实子进程，不碰用户仓库。

夹具helper：**dribbleScript(text,stream)**生成一个把给定文字**逐字节**写出、每字节间隔几毫秒的小程序，强制父进程在多字节字符中间观察到分块边界；**run**建目录、跑断言、清理。这不是人造场景：交互式工具、进度条和PTY程序都这样刷新输出。

覆盖的合同：

- 被分块切开的stdout/stderr必须还原成原文且零替换字符。基线下"项目已完成，用时 3 秒 ✅"返回的是一串U+FFFD——模型会据此推理甚至采取行动，所以这是数据正确性问题而非显示问题。
- stdout与stderr各自独立解码：两个流交替逐字节输出时，谁也不能吃掉对方的半个字符。
- 真正被截断的结尾字节（只写了3字节字符的前2字节）必须以替换字符**浮现**，不能静默丢弃。
- 普通ASCII输出、退出码、`status`与非零退出时的stderr语义都不变。
- 大量CJK输出经过尾窗口截断后仍是完整字符：默认`tail`为8000**字符**，用奇数`tail`（501）取窗口也不会在边界切出半个字符。
- `start_command`流式路径同样成立：轮询到done后拿到的仍是完整文字。
- F70（外部复审§5.4-7）：尾窗口按UTF-16单元计数，奇数窗口落在emoji/CJK扩展B字符中间时曾返回孤立低代理项。共享的`sliceTextTail`先做纯函数断言（`'😀😀😀'`取1得空串、取3得一个完整emoji），再端到端取3000个emoji的501单元尾窗，必须恰为250个完整emoji且无孤立代理项；基线executor在该端到端断言红。

**windowsExitCodeContract()**（F70，外部复审§5.4-1，仅win32运行、Linux直接返回）：Windows尾语句的三条合同逐条跑真实powershell.exe——纯cmdlet失败（Get-Item不存在路径）必须非零且status error；原生程序成功后再cmdlet失败仍须失败；cmdlet失败后原生程序成功则为0；`node three.js`保持3；最近一次原生码为准（`three;ok`为0、`ok;three`为3）；成功cmdlet与成功原生程序为0。F62的尾语句只转发$LASTEXITCODE，纯cmdlet失败时它为null，于是整个脚本退出0、主机把失败报成成功。Linux沙箱无powershell.exe，本函数只能由Windows CI三个Node版本真实验证。

它保证的是"跨块不被打碎"，**不**保证程序输出一定是合法UTF-8——程序自己输出非UTF-8字节时仍会得到替换字符，那是被调用程序的编码问题。
