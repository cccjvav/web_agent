[源码](dangerousCommands.test.js)的**req(method,params)**构造直接RPC；**request(server,method,urlPath,body,headers)**本机HTTP，JSON body及长度、额外header，收data/end解析（失败null），网络error reject。**main**遍历六种rm/find删除变体（拆参数/长参数/引号混淆等）isDangerousCommand必须true；echo/npm test/git status false，push/下载管道shell/dd/shred/truncate true。

每个变体本地callTool未确认须publicError E_BAD_ARGS且提示confirm_dangerous；直接远程handleRpc即使confirm_dangerous:true也isError/E_FORBIDDEN。之后真Express装MCP/API随机端口：带secret路径MCP HTTP200但result.isError，API本地未确认≥400并有确认提示；最后安全ping仍200且非错误，防全部请求一刀切。finally关server/删tmp，main.catch exit1。未枚举所有shell等价写法，也不执行已确认危险命令。

## nativeRotationCommands.test.js

先复现原生命令的假成功：真实`activate()`在VM中执行，仅替换vscode与HTTP传输，POST `/api/bridge/reset-secret`回HTTP500时旧实现仍弹“Secret 已重置”（断言0条实际1条）。修后同一夹具验证：

- 轮换POST携带workspaceRoot/hostInstanceId/expectedSecret；HTTP500、请求抛错、空/坏JSON、`success`非严格true（含字符串`'true'`）、密钥未变、`mcpPath`错配、`javascript:`地址、canonical不一致、HTTP502均为“未确认”，不刷新、不提示已重置。
- 未确认/被拒绝/成功的提示都不含新旧密钥正文。
- 模态确认后才发送；dismiss零POST并提示已取消。旧密钥形状未知或工作区不匹配零POST，提示以“未发送密钥轮换”开头。
- HTTP409报“未轮换”（主机在写入前拒绝），与未知区分。
- 写确认后二次读取成功才提示“已重置并核对”；读取500、密钥不符、主机不符或读取抛错仍返回true并提示“已确认轮换，但当前地址未核对”，同时刷新侧栏。
- 原生停止：POST携绑定，只有`success===true && running===false`才刷新；HTTP409报“未停止”，500/`success:true`缺running/`running:true`/字符串success/空JSON/请求抛错报“停止结果未确认”；工作区不匹配零POST。

夹具helper：**main**建tmp并跑全部断言；**clear**复位消息/请求计数与替身应答；**reset**取activate登记的webagent.resetSecret并调用；**notices**汇总info/warning/error文本供断言；**leaked**筛出含新旧密钥的提示，必须为空；**stop**经真实BridgeView receiver发停止消息；**stopError**取最后一条错误文本。结束时dispose activate登记的subscriptions（含5秒状态栏轮询），避免测试进程滞留。夹具是HTTP与VS Code替身，不是真实IDE、真实隧道或Windows弹窗验收；后端绑定/CAS的真实HTTP证据在bridgeTunnel。
