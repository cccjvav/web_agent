# Skill: 项目管家（交接）

来源意图对齐 SkillHub「agent项目管理skill / project-manager-v6」（CONTEXT.md 索引 + 使用手册）。**本目录不是商店 zip 原文**（当时拉不下来），按本仓库工具与文档习惯改写。触发：接手项目、新上下文、了解项目情况、项目管家、更新项目记录、生成手册。

## 原则

1. **先读仓库根 `CONTEXT.md`**，再按里面的链接按需 `read_files`。禁止一上来通读 `架构导读.md` / 全部 README。
2. 产品说明书已经在根目录（`使用指南.md` 等）。手册是**给下一任助手的路标**，不要另写一套和第二份用户指南抢地位。
3. 工作区若不是本仓库根，文件工具进不去 `CONTEXT.md`。那时只根据用户贴的摘要回答，或请他把工作区指到仓库根。
4. 密钥、MCP 完整 URL、`.webagent/config.json` 不要写进 CONTEXT / 手册。

## Ask

只读：`workspace_info` → `read_files` `CONTEXT.md`（没有则说明尚未建）→ 只打开索引里点名的那一两份。禁止 `apply_patch`。

## Plan

列出要补的 CONTEXT 条目或缺的手册段落。仓库不动。

## Code

1. **更新索引**：改仓库根 `CONTEXT.md`。只写：现在在干什么、分支、最近提交主题、该读哪几个文件、不要做什么。单文件保持短（建议 < 80 行）。
2. **手册**：用户要给非开发者看时，更新 `使用指南.md` 或指出已有章节，不要新建第三份「总说明书」。给助手看的交接写在 `CONTEXT.md` 的「下一任」节。
3. 改完若动了「为什么这样装」，按 `docs-sync` 改 `架构导读.md`。测绿再按 `commit-now` 提交当前分支。

对话里说「按 project-manager 做」或「项目管家，更新记录」。
