# 组件说明：从入口到工具、配置和发行

本篇负责**目录定位和模块合作**；为什么这样分层见[架构导读](架构导读.md)，新手按键/命令见[使用指南](../../使用指南.md)，完整函数导航见[技术实现](技术实现.md)与[总览](总览.md)。旧版重复的安装步骤、第三方兼容保证和固定工具计数已移出现行正文，不是隐藏在末尾的更正。

## 1. 三个必须先分清的东西

| 名字 | 含义 | 当前默认 |
|---|---|---|
| 源码仓库web_agent | WebAgent程序本身 | 源码启动也将它作为工作区，可由AI协助自检 |
| 工作区 | 当前文件工具操作的项目根 | 可显式指定另一个已存在项目；安装版使用用户可写workspace |
| 模型/客户端 | 发起任务或工具请求的调用方 | 本机明确选择builtin/API模型，或外部兼容MCP客户端 |

计算器在`examples/calculator/`，不是默认工作区。Code可能修改产品自身；破坏性测试应使用显式临时目录。`.webagent`属于当前工作区，所以源码根作为工作区时它就在源码根下，不再声称“不会出现在根下”。

## 2. 四种界面与两种主机执行模式

| 入口 | 界面与服务 | 是否需要入站隧道 |
|---|---|---|
| `run-webagent.cmd` | 经典工作台3000，host/MCP48271 | 本机Chat不需要；外部云端MCP需要公网路由 |
| `run-webagent-vscode.cmd` | code-server通常3000，host让出工作台端口 | 编辑器本身不需要；外部MCP同上 |
| `install-vscode-extension.cmd` + 已运行host | 桌面VSCode核心扩展，不另占3000 | 本机扩展访问host不需要 |
| `run-webagent-appwindow.cmd` | code-server独立浏览器窗口 | 不是另一套Electron主机 |

端口可配置；同默认端口的经典/code-server入口不能同时启动。程序提供Inno Setup安装器源码/载荷构建，不是“没有exe安装方案”；安装版默认快捷方式走网页VSCode，源码新手入口走经典工作台。下载运行时不进入Git。

主机**Chat/Bridge互斥**；同类型多模型/多Agent并行允许。手机Arena固定Bridge。本机窗口的页签切换、文件编辑和人工审批不等于启动另一类模型。实际模式/后台任务屏障由executionControl负责，不由某一个前端单独决定。

## 3. 如何运行，以及运行后看什么

用户主路径：Windows桌面VSCode集成CMD、Conda、系统Node.js。安装Node/npm或修改PATH后，**完全退出并重新打开VSCode**，不是只新建终端。源码根运行：

```bat
check-env.cmd
run-webagent.cmd
```

另一个项目用显式路径，例如：

```bat
run-webagent.cmd "D:\My Projects\my-app"
```

先核对日志/页面/IDE的工作区与host身份，再允许修改。根源码本身也是合法项目，不要一律禁止打开它。核心扩展不会代你自动启动对应host；空窗口、错误首工作区或错绑必须先解决。

模型缺配置不会自动回退builtin。初次本机探索请明确选择内置探索Agent；它不是通用大模型。远程模型会发送模型请求，本机Chat“不需要入站隧道”不等于“不联网”。手机Arena连接操作、OAuth/密钥、隧道故障按[使用指南](../../使用指南.md)和[隧道指南](../guides/隧道使用指南.md)，不在这里复制厂商可能变动的菜单。

源码测试：

```bat
run-tests.cmd
```

测试需要完整开发依赖（含Acorn）；生产启动安装与源码测试不是同一依赖集合。真实Windows线性验收见[新手验收](../guides/Windows新手逐步验收.md)。可先完成MCP连接，让外部AI协助检查，但需检查实际工具结果。

## 4. 请求怎样穿过模块

### 本机Chat

工作台`js/chat.js`或扩展`extension.js`→本机`/api/chat`→工作区/主机绑定与Chat模式租约→`src/agent/runChat.js`→明确选定builtin或`openai.js`模型循环→共享`tools.callTool`→结果事件。

Ask/Plan只读；Code许可仍受工具安全规则约束。非builtin缺配置或模型服务失败停止，不静默换模型重放。builtin是有限目录/文本探索、显式补丁与测试意图处理，不承诺理解任意任务。完整调度边界见[Agent目录](../../webagent-core/agent-host/src/agent/README.md)。

### 外部入站Bridge

兼容客户端→公网路由→MCP认证/初始化→Bridge模式与主人权限→tools/call→共享工具→MCP内容/isError。session、工具模式和主人Read/Edit/Execute/Capture是不同概念；客户端不能通过Code越过主人权限。

工具错误可能作为业务结果返回，不代表断线；HTTP200也不是成功。文件修改先取得真实内容/hash，STALE_FILE时重读并协调，不能使用报错currentHash强行重试。命令Windows走PowerShell，cwd限制不是OS沙箱；附图和文件读取也分别有权限/预算。见[MCP目录](../../webagent-core/agent-host/src/mcp/README.md)及[工具目录](../../webagent-core/agent-host/src/tools/README.md)。

### 可选出站第三方MCP

本机登记可信服务→initialize/目录发现→Arena经external_request申请→本机批准→WebAgent client调用第三方→operation_result取结果。回环HTTP(S)、显式stdio启动、公网HTTPS是三种传输选择；不自动安装、登录第三方OAuth或免批。出站不是手机连接本机的前提，不自动转发入站密钥，参数正文可能离开本机。见[受控工具详解](../../webagent-core/agent-host/src/utils/受控工具与工作流详解.md)。

### 本机编辑与恢复

经典保存走host文件工具；原生草稿编辑走VSCode编辑API；检查点恢复走本机受保护API及共享write_file。分别保留版本检查，不将这些手工操作叫第二个Chat模型。检查点先全部预检再逐文件恢复，部分失败停止，不自动补偿；具体入口见[使用指南](../../使用指南.md)。

## 5. 为什么这样拆

| 选择 | 原因与不能过度推断的地方 |
|---|---|
| host与多种UI分离 | 模型/文件工具共享；原生PTY和草稿编辑仍有扩展侧职责，不是扩展只会HTTP |
| 控制面仅本机 | 公网只走认证MCP，不开放工作台、API或WebSocket；回环代理仍要检查转发来源 |
| 源码/安装数据分离 | Program Files存程序载荷，用户可写目录存runtime/config；不盲删用户改过的旧版本 |
| 工作区绑定 | 防止IDE显示A却向B派工；不是文件锁或身份认证的替代品 |
| hash与独立审批 | 防止盲写和未批准工具执行；不保证OS并发事务或第三方行为可信 |
| 不复制第三方扩展产品 | 兼容性/权限/许可证需逐项确认；不预先保证Chat Plus或DeepSeek当前可用 |
| 保留冻结原型和历史证据 | 源码/失败可追溯，但旧报告不是最新使用指南 |
| 测试与实机验收分开 | 已有Chromium、跨平台Node和安装构建测试；不代签用户桌面/账户/公网服务 |

### 6.1 host内部的合作

以下路径相对`webagent-core/agent-host/`：

| 路径 | 主要职责 |
|---|---|
| `src/index.js` | 启动入口、双端口、共享控制面门禁与退出生命周期 |
| `src/config.js` | 运行配置、主机/工作区身份与密钥轮换 |
| `src/api/routes.js` | 本机状态、Bridge、Chat、文件、审批/检查点等REST入口 |
| `src/mcp/` | 入站协议/OAuth/会话；另有出站externalClient与HTTPS/stdio传输 |
| `src/tools/` | 工具注册、模式/权限、文件/补丁/命令/工作流、任务板操作 |
| `src/agent/` | 本机Chat模型/确定性探索与图片辅助，不处理入站MCP模型推理 |
| `src/utils/` | 模式租约、审批、事件/追踪、请求取消、路径绑定、回退/检查点等共享机制 |
| `src/tunnel/` | cloudflared Quick/Named及ngrok启动/停止，不自动更换供应商 |
| `src/auth/` | 可选GitHub身份验证，不等于MCP配对或持久登录 |
| `src/models/` | 工作区存储、指令/画像、记忆/检索及规划支持 |
| `src/usage/` | 持久日统计/可选上报；不同于进程内Bridge快照和Tasks |
| `tests/` | 每文件独立进程的产品回归，另有真实Chromium测试入口 |

### 6.2 工作区数据怎么保留

`.webagent`属于当前工作区；源码根有共享Skills，另外项目不会自动获得原项目凭据或用户数据。

| 数据 | 处理原则 |
|---|---|
| config/API密钥/MCP连接密钥 | 本机敏感配置，不提交；已被Git跟踪时须另行处理，ignore不是历史擦除 |
| read-hashes/usage | 读取版本缓存/日统计，不是永久撤销备份；具体清理范围见统计与工具详解 |
| instructions/preference/tech-stack | 用户定制指导；审阅隐私后才主动分享，默认ignore策略见store说明 |
| skills | 可审阅后共享；说明文件不等于依赖安装或执行许可 |
| memory/customizations/board | 用户内容和任务元数据，默认保护；JSON存储不是跨进程/多文件事务 |
| OAuth/审批/出站令牌/检查点 | 各自有界进程内状态，重启重新配对/登记或失效，不当作持久备份 |

逐项说明见[模型与存储目录](../../webagent-core/agent-host/src/models/README.md)、[技能指南](../guides/技能使用指南.md)、[Bridge统计](../guides/Bridge统计与刷新排查.md)。安装升级保留策略见安装器，不手工按旧PID杀未知进程。

## 7. 常见误读

- **分享GitHub链接就能改我电脑？** 不行；必须本机服务运行、网络可达、完成MCP认证且权限允许。不要公开带密钥的连接地址。
- **普通聊天栏贴链接一定建立MCP？** 不行；必须有实际工具连接能力。Arena手机连接按用户报告通过；其他厂商菜单/订阅/版本不可由本项目推断。
- **内置探索就是通用模型？** 不是；复杂推理需要实际模型服务，失败由用户选择后续，不自动回退。
- **code-server和桌面VSCode完全等价？** 不是；扩展/PTY/浏览器限制和实机验收分开。桌面扩展不要求下载code-server。
- **探针鉴定了真实后台模型？** 不是；结果供研究参考，精确Chat API后台身份延期。经典/code-server探针入口未纳入施工。
- **恢复检查点就撤销整个任务？** 不是；只恢复预先选定且仍存在的有界文件正文，可能部分完成，不撤销外部副作用。
- **CI九项绿灯就是我的电脑验收通过？** 不是；CI仅证明该SHA上的明确测试，用户验收单独记录。
