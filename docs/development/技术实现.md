# 技术实现：跨模块链路与关键边界

本文解释当前源码中的主要执行链、状态转换和失败语义，不再复制每个函数的手写行号清单。逐模块职责见目录README，函数与行号见[源码索引](../../docs-site/source-index.md)。旧版本可在Git历史查看，不作为当前契约同时展示。

本次为源码契约复核，不是全部函数的形式化证明或真实平台验收；发现的实现差异见[文档与修复证据](../../review/SEMANTIC_REVIEW_2026-09-16.md)。操作步骤见[使用指南](../../使用指南.md)，设计原因见[架构导读](架构导读.md)。

## 1. 三条调用链：共用工具，不等于共用所有行为

```text
本机工作台 → /api/chat → runChat → runOpenAI或明确选择的builtin → callTool
VS Code Chat → 本机/api/chat → 同一Chat调度 → callTool → 可选PTY任务宿主
外部Agent → 认证/mcp → JSON-RPC tools/call → callTool → 普通工具/命令
```

| 入口 | 模型在哪里调用 | 取消与结果的区别 |
|---|---|---|
| 本机工作台/VS Code Chat | agent-host调用配置的模型 | Chat建立AbortSignal；done只表示流结束 |
| 外部MCP客户端 | 外部客户端调用自己的模型 | MCP工具有isError；初始化会话内按相同凭据与RPC ID匹配取消信号 |
| 本机直接/api/tool/call | 不经过Chat模型循环 | 外包success与MCP共用业务失败判定；HTTP200不等于工具成功 |

工具注册表定义名称、模式、参数说明和handler；callTool做模式/归一/命令检查，不是任意JSON Schema都能执行的验证器。Ask/Plan限制源码写入与命令，但允许特定协作元数据操作，因此不等同“所有状态完全不变”。

### 主机模式与第三方委托

上述入口先经过主机Chat/Bridge互斥检查，同类型可并发；手机Arena固定Bridge。executionControl的租约计数和后台/待批屏障决定能否切换，UI页签不代表切换完成。Bridge Read/Edit/Execute/Capture是主人策略，Ask/Plan/Code不能提升它；任意Execute要求四项允许，不是OS沙箱。

externalClient是另一条出站链：本机登记服务并明确外发/启动确认，外部AI通过external_request提交后，本机逐次批准才发出tools/call，operation_result返回external-reported结果。出站HTTPS经过DNS全答案过滤和固定socket lookup、正常TLS，不跟随重定向或自动重试；它不是手机入站的前提，也不是让host调用Arena模型。见[公网详解](../../webagent-core/agent-host/src/mcp/公网出站详解.md)。

## 2. 启动与端口

Windows薄CMD把模式和工作区交给installer/launch.js。安装版先准备用户runtime；源码模式直接使用checkout。classic使用自绘工作台，vscode交给code-server，app等待健康后开浏览器窗口；完整入口表见[启动说明](../../启动脚本说明.md)。shell入口并不共享全部Windows解析逻辑。

agent-host创建两个HTTP服务器：
- UI默认3000：工作台静态页、本机API和WS。
- MCP默认48271：OAuth、认证MCP，以及仅本机可用的API；不挂工作台页面或WS。

WEBAGENT_SKIP_WORKBENCH=1时后端不占3000，由code-server提供UI。统计后台4174与文档站4173均是独立可选服务。

run-code-oss的健康轮询共享15秒deadline/取消，并处置每个连接；失败、agent退出或停止统一观察本轮直接ChildProcess退出，不按旧PID另起taskkill。9秒宽限保留主机原8秒shutdown预算，再观察force最多1秒；未确认则非零且明确提示，不冒称所有后代/PTY/隧道都退出。ensure/npm准备时间不在这15秒内，health200也不是实例/工作区认证。

config是单例，secret/installId可由工作区config.json恢复。当前直接启动主机也先验证工作区，再初始化身份，不会为了读取配置而创建显式错误目录。Windows安装版默认工作区首次可创建，这是启动器的独立分支；不能推广到显式错误路径。详见[进程组装](../../webagent-core/agent-host/src/README.md)。

## 3. 本机控制面与远程认证

本机API同时检查回环socket、明确本机Host、隧道特征与浏览器Origin；WS在升级阶段检查对应边界。默认回环监听，改变监听地址不等于产品提供了远程工作台登录系统。

MCP的Origin白名单和凭据验证是两层：CORS允许不代表认证通过，无Origin也不代表匿名允许。支持规范/mcp配OAuth/Bearer与兼容带密钥URL；带secret的URL本身是敏感信息。

OAuth流程为注册客户端 → 配对授权/PKCE → token交换 → 刷新轮换。none/basic/post分别按注册方式认证，S256验证后才消费授权码；重放已消费refresh会撤销该客户端令牌。配对/授权码5分钟，access一小时，refresh七天；状态在内存，重启重新配对。

HTTP会话ID关联MCP peer，与用户显示名称及认证凭据不同。修改board需初始化后保留会话，不能仅按同IP和名字归属。更完整的协议与SSE语义见[MCP说明](../../webagent-core/agent-host/src/mcp/README.md)。

## 4. 从读取到安全发布文件

```text
解析工具/模式 → 安全路径与敏感规则 → 规范路径写锁
  → 读当前内容/hash → 冲突/格式校验 → dryRun或临时文件
  → 再检查取消 → 原子发布 → 更新hash缓存/事件
```

读取默认文本上限8MiB，检查普通文件并按块读，严格UTF-8且保留BOM/CRLF；非法编码拒绝而不自动改码。差异展示另有输入/算法/输出预算，在新建父目录或正式写入前完成预检，详见差异展示详解，不能把8MiB读取上限当CPU预算。read_files返回带行号content及完整hash；offset是行号，不是字节。

write_file对覆盖有确认和hash要求，目标已删除时旧hash不允许悄悄重建。apply_patch拒绝短hash前缀，按支持的单文件diff或SEARCH/REPLACE处理；多处匹配需要occurrence，新文件不能把unified diff头误当正文。dryRun不发布修改。

临时文件与目标同目录，保留已有普通权限；新建补丁采用排他发布，避免竞争期间覆盖突然出现的文件。链接写入跟随已检查真实目标，保留链接本身。进程内锁不控制外部编辑器，取消也不是回滚已提交修改。

路径限制作用于本工具实现；运行外部程序仍使用当前用户权限，不能因此声称存在OS级沙箱。详情见[工具说明](../../webagent-core/agent-host/src/tools/README.md)。

### 三种有界恢复，不是通用事务

- 经典editorUndo仅记录有正确版本、已有小文件的一次验证保存；diff预览后明确确认，检查当前保存后hash，一旦发起恢复消费句柄。
- 原生editorReview通过VSCode只读快照diff展示磁盘与草稿，要求信任/范围/版本稳定及自动保存关闭，确认后一次editor.edit设置撤销边界，不主动save。
- fileCheckpoints由本机任务前明确选择1–12个已有文件备份；任务后预览最新ticket，全部预检，再逐文件复查/hash写入/读回。中途失败可能部分完成，保留restored/unknown/not-started并消费，不重放或补偿。

内存TTL/容量、编码与正文预算分别见[编辑回退](../../webagent-core/agent-host/src/utils/编辑回退详解.md)及[原生扩展](../../webagent-core/extension/入口与Webview详解.md)。这些都不恢复全项目删除/重命名、新文件、元数据或外部系统副作用；哈希不检测ABA历史，单文件原子替换不是跨文件事务。

## 5. 搜索、分页与结果大小

目录/搜索有扫描和结果限额；truncated说明结果不完整，不是成功遍历了全仓库。目录列表的截短不一定带可续读cursor。

search_files在最多4个worker中执行，启动预算10秒、ready后扫描另限2秒，可随当前请求信号取消（不是整体仅2秒）；保留查询、单文件、总字节和匹配数预算。正则预检只是启发式，可终止worker是另一层执行限制。分页基于当前扫描结果，不是跨请求固定快照。

MCP预算16k字符、模型工具预算12k字符都是软目标。保持JSON类型、数组成员、标识符和分页字段；非分页文本可显式缩短，仍超预算的对象可标_budgetExceeded。不会在JSON序列化后直接slice；不承诺所有响应严格小于目标或所有返回类型都带相同元数据。

## 6. 普通命令与PTY生命周期

普通命令由executor管理execId、输出、状态和超时。run等待，start返回ID供轮询，stdout/stderr捕获有上限；非零退出、超时或取消不是成功。终止信号及进程树效果需要系统验收，不能把发送kill当成已经退出。

VS Code扩展PTY多一层生命周期：排队 → 绑定workspace/client所有者 → 审批 → accepted重查有效期 → running → 终态。审批窗口90秒；超时或取消后，迟到批准不能复活任务。输出和保留记录有界。

宿主优先node-pty；不可用时只用可观测shell integration捕获输出及执行结束。仍不可用则拒绝，不用不可观测sendText猜测完成。run成功必须结合退出码和捕获状态，不能把终端文字出现当成功。边界与测试见[扩展说明](../../webagent-core/extension/README.md)。

## 7. 模型、工具失败与Plan

普通Chat选中非builtin模型但配置不足时停止；服务调用失败也停止，用户主动选择重试或换模型。builtin是一条明确选择的规则式探索路径，不是自动修改重放。

模型循环最多10轮，每轮最多执行8个工具调用，同时给所有调用ID结果或限额反馈。工具失败可以作为错误结果反馈给模型继续处理；这与模型服务请求失败停止不是同一件事。

Plan的start/branch/merge/reset操作当前共享轮次；至少两支可总结。异步返回时检查原round，merge另检查分支版本，避免结果串入新任务。merge仅明确选中builtin才本机拼接；不存在或非builtin配置不足停止，保留未合并轮次，不自动切换模型。

截图辅助供Chat与MCP共用，路径和6MiB限制一致，附图协议不同；base64不通过eventBus广播。更多见[Agent说明](../../webagent-core/agent-host/src/agent/README.md)。

## 8. 隧道启停与就绪证明

Bridge开始操作等待旧隧道停止，以generation和具体进程引用约束就绪、日志和退出回调。旧事件不能覆盖新进程；stop/logout使旧start最终响应失效。

获得URL才表示客户端隧道就绪，仍不证明公网路由、OAuth及目标请求端到端成功。停止失败会阻断替换，URL被清空也不能证明残留进程一定退出。无隧道只显示本机MCP地址，不代表手机可以访问。完整流程见[隧道模块](../../webagent-core/agent-host/src/tunnel/README.md)。

## 9. 不同存储对象的保证不同

| 数据 | 实现保证与限制 |
|---|---|
| models/store的config.json | 缺文件默认；坏JSON/已检查结构拒绝并保留；临时文件发布、部分权限保护 |
| customizations及派生Markdown | 仅ENOENT回默认；损坏/不可读报E_CUSTOM_CORRUPT并保留原文件；每个文件临时写后rename，但多个派生文件不是整体事务 |
| memory | 校验日期与路径，限量读条目；不是完整知识库 |
| read-hashes缓存 | 辅助缓存，可忽略读写错误；不是不可丢失事务日志 |
| usage | 工作区普通日统计/可选上报；读取失败/在途网络仍有独立边界，不是可信计费账本 |
| admin reports | 仅初次缺失为空表；已知结构/数值/4MiB/10000行检查、坏文件保留、同目录临时发布；不是跨进程锁或断电事务 |
| OAuth/session/Plan/任务内存 | 重启丢失或重建，未全部按客户端隔离 |
| 出站令牌/审批/编辑回退/检查点 | 有界进程内状态，各有期限和一次性语义；不是永久备份或永久去重账本 |

安装器的用户runtime布局不自动改变被编辑工作区中.webagent的全部语义。详细字段和恢复注意见[models](../../webagent-core/agent-host/src/models/README.md)。

## 10. 界面、日志和验证

工作台每tab保留编辑状态，hash冲突/保存失败保留缓冲区；Monaco迟到加载先捕获纯文本编辑。beforeunload只是浏览器提示，不保证崩溃恢复。内置Arena面板只给连接指引，不冒充实际外部客户端。

事件总线的WS/日志副本会脱敏和裁切，但进程内订阅者收到原payload；不应推广成所有模型请求、命令参数或配置自动脱敏。usage当前主要统计MCP工具调用，不是所有入口的统一计费。

测试必须区分静态检查、实际模块fixture、真实HTTP/子进程与真实平台E2E。检查器能证明文档归属/源hash/部分链接一致，不能证明正文语义质量。按风险选择回归见[测试导航](../../webagent-core/agent-host/tests/README.md)，本次发现与未验证项见[文档与修复证据](../../review/SEMANTIC_REVIEW_2026-09-16.md)。
