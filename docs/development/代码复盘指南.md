# 从零复盘 Web Agent：从功能走到每个文件与函数

实际操作入口：[Windows新手逐步验收](../guides/Windows新手逐步验收.md)，不用自行把验收编号拼成执行顺序。


## 1. 这份指南的职责与完成标准

你不需要先读懂整个仓库才能开始使用。先在[Conda 环境说明](../guides/Conda环境说明.md)中跑通自己的环境，再沿这里的顺序复盘。

**目标不是背文件名，而是能回答：某个操作从哪里进入，调用了什么，改变了什么，失败时会怎样，哪项测试提供证据。** 自动符号索引只能定位，不能代替这些答案。已有函数详解与“整篇逐句对照当前源码”是两种进度；下面列学习入口，不把入口存在当作语义审查完成。

如果新增或维护某份源码教学说明，可参考以下提纲；它不是本轮要求给每个源码文件扩写长篇的任务清单：

1. 文件存在的原因、入口/调用方、依赖对象；没有函数的配置文件也要讲。
2. 每个具名函数/类方法的参数、默认值、返回值（同步还是 Promise）、关键步骤。
3. 状态、磁盘、网络、事件、进程等副作用；谁创建、谁清理、谁拥有。
4. 失败、取消、超时、权限、并发、平台分支，以及哪些不适用。
5. 匿名回调按所在流程解释其触发时机、读写状态、成功/失败出口。简单适配器可合并成一段，但必须能指出对应哪些函数，而不是用“其他辅助函数”跳过。
6. 测试文件及其断言类别、未做的真实环境验证；至少一条正常链和一条失败链。

有这些内容也不能自动证明说明正确，还要对照源码阅读。禁止为凑“100%”生成一句话函数翻译、抄行号或自动认证 hash。

## 2. 新手先认识这些词

| 名称 | 可以怎样理解 | 容易误解的地方 |
|---|---|---|
| 进程 | 正在运行的程序实例 | 两个 Node 进程不一定是同一个服务 |
| 入口 | 从这里开始建立对象、监听端口或执行命令 | `package.json.main` 不一定是 `npm start` 的真实入口 |
| 路由/中间件 | HTTP 请求先经过检查，再到处理函数 | `/api`、`/mcp` 有不同信任边界 |
| Promise/async | 结果可能稍后成功或失败 | 启动操作返回不等于任务已经完成 |
| 回调/事件 | 事件发生时再执行的函数 | 监听注册顺序、清理和迟到事件会影响行为 |
| 状态/所有权 | 当前在哪个阶段，谁有权继续或结束 | 全局变量、会话状态、工作区状态不是一回事 |
| wrapper | 外面包一层返回格式 | 包装不能替代业务结果；当前API/MCP已共享失败判定，仍须区分受理、完成和验证 |
| mock/fixture | 用可控制的假服务或样本测试 | mock 通过不等于真实网络/Windows 输入通过 |
| 生成物 | 由源码或文档构建出的结果 | 应改源文件再重建，不能只修生成副本 |

## 3. 推荐阅读顺序与执行链

### 第一步：从启动到页面

```text
VS Code 集成 CMD 激活 Conda 后的环境/PATH（Node 可来自系统安装）
  → run-webagent*.cmd
  → installer/launch.js
  → classic: agent-host/src/index.js → 3000 工作台 + 48271 MCP
  → vscode: scripts/run-code-oss.js → code-server + agent-host + 扩展
浏览器页面 → 本机 /api → 对应路由 → 模型/工具 → 磁盘或子进程 → 页面结果
```

先读[启动说明](../../启动脚本说明.md)、[安装启动逐函数讲解](../../installer/函数详解.md)、[服务入口逐函数讲解](../../webagent-core/agent-host/src/入口详解.md)。从一个你确实运行过的命令出发，比先读所有工具实现容易得多。

练习：不用看答案，解释为什么 Conda 环境里装了 Node，资源管理器双击却可能找不到；为什么两个壳不能同时占用默认 3000；为什么安装版依赖不应写进 Program Files。

### 第二步：从界面操作追到结果

- 编辑保存：`workbench` 文件页 → `/api` → `tools/fileOps` → 路径/敏感文件/版本检查 → 写入 → UI 状态更新。
- 本机聊天：UI/扩展 → Chat 路由 → `agent/runChat` → 模型流与工具循环 → 事件/响应。模型失败、流结束、工具业务失败要分开看。
- 远程任务：外部 MCP 客户端 → 入站路由 → MCP/OAuth/Bridge主人权限 → 会话 → 工具注册表 → 执行器 → MCP结果。手机固定Bridge；Chat/Bridge互斥，同类型并发保留，不公开本机UI。
- 终端：工具执行入口 → 经典子进程，或 PTY 工作队列 → VS Code 扩展 → 可观察终端 → 回传输出/退出码。

先读[技术实现](技术实现.md)与[架构导读](架构导读.md)，再沿同目录 README 的文件职责表进入源码。读到资源生命周期，接着看[取消与有界读取详解](../../webagent-core/agent-host/src/utils/函数详解.md)、[停止隧道进程详解](../../webagent-core/agent-host/src/tunnel/停止进程详解.md)。

### 第三步：补失败路径与验证

每读完一条链，都回答：配置坏了会怎样？取消是否真的传到底层？并发/旧回合如何处理？断线时谁清理？返回成功有没有二义性？依据是源码、自动测试还是人工实测？

测试入口的执行逻辑见[测试运行器详解](../../webagent-core/agent-host/scripts/运行器详解.md)，实际测试职责见[测试目录](../../webagent-core/agent-host/tests/README.md)。从测试断言回到它调用的源码，不要只读 `console.log('passed')`。

## 4. 各类文件怎么读、怎么维护

| 类型/位置 | 应理解什么 | 正确维护方式 |
|---|---|---|
| `.js` / `.cjs` / `.mjs` | 导入、顶层初始化、导出、函数、异步事件、状态所有者 | 源码旁说明 + 函数定位 + 行为测试 |
| `package.json` | scripts、engines、生产/开发依赖 | 改清单后按 npm 流程更新锁文件，验证实际入口 |
| `package-lock.json` | 确定 npm 依赖版本和完整性 | npm 生成，不逐行翻译或手工拼版本；不代表 Conda 依赖 |
| `.cmd` / `.sh` | 参数、cwd、环境传递、错误码 | 两种平台独立解释；不要用 Bash 经验替代 CMD 的 `call`/引号规则 |
| `.ps1` / `.cs` | PS 参数到 C#、Win32 调用、句柄、DPI、输入提交与错误 | 自动索引只到文件级，须读已有逐方法人工详解并区分真实桌面验证 |
| `.iss` | 安装任务、文件白名单、注册表、权限、事件回调与卸载 | 阅读安装定义与 Pascal 回调，不把编译成功当用户安装成功 |
| `.html` | DOM 结构、元素 ID、脚本加载顺序、交互入口 | 对照 JS 的选择器/事件，解释结构和界面关系 |
| `.css` | 布局、主题变量、响应式、焦点、溢出 | 按选择器组解释，并实际查看；不用逐属性机械翻译 |
| `.json` / `.yml` / `.yaml` | 字段来源、默认值、消费者、写入者、约束、敏感性 | 运行配置、构建配置、CI 配置分别解释，示例不放真实凭据 |
| `.svg` 与其他图片 | 用途、尺寸、使用者、来源/许可 | 区分可维护资产与历史截图，不把二进制当函数源码 |
| `.gitignore` / `.gitattributes` / 工作流 | 不入库规则、换行规范、触发条件、验证范围 | 会影响生成/打包/测试，属于需要理解的工程文件 |
| `README.md` / Skill / 管理规则 | 谁读取、在哪个步骤生效、是否被打包 | 权威正文只保留一处，其余链接过去 |
| `docs-site/content.js`、清单和索引 | 由谁生成、输入是什么、为何不得手改 | 改正文/生成器后重建；生成源码快照不是独立产品源码 |
| `extensions-installed`、`bin` | 源码副本与第三方运行时的关系 | 修 `extension` 正本后按同步流程更新；不去改 vendored 内部实现 |
| `examples/calculator`、工作区、`.webagent` | 可选示例、被编辑项目和配置/Skills的不同职责 | 源码根默认也是工作区；共享Skills与私人凭据分别处理，不为测试清理用户数据 |
| `webagent-repro` | 冻结原型与当前入口的区别 | 解释归属与历史用途，不误当运行中的实现 |
| 历史 `review/REPORT*` | 当时发现与上下文 | 不要求全面重新语义认证，不覆盖当前源码与活清单 |

本表是读法，不是“所有类型的每个细节已经写完”。已知自动扫描扩展名与排除理由见[维护规范](../../manager/docs/documentation.md)。未知扩展名、无扩展名工程文件不能因为未被扫描就当作已说明。

## 5. 如何从文件定位函数

1. 在文档站“文件说明”找所属模块 README，先读人工正文。
2. 进入[源码索引](../../docs-site/source-index.md)，按文件与符号定位；站点的源码视图是静态快照，不是运行时调试器。
3. 确认自己阅读的源码与构建版本相同；位置随编辑变化，以当前符号/内容为准，不抄永久行号。
4. 匿名箭头回调通常嵌在 `map`、HTTP 处理器、Promise 或事件注册中，回到父流程看触发条件与闭包状态。
5. 如正文只说“管理工具”而无法解释你眼前的函数，就记为讲解缺口，不能凭索引覆盖把它勾掉。
