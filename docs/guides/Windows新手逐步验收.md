# Windows 新手逐步验收：从打开终端到安全断开 MCP

这是操作顺序手册，不是另一套通过标准。[Windows 验收清单](../../review/CHECKLIST_WINDOWS.md)仍是唯一判定基线；本手册告诉你先做什么、在哪输入、看到什么再继续。没有做的项记录“未执行”，不要统一勾通过。

你的使用方式：**Windows 桌面 VS Code → 集成 CMD → 激活 Conda，Node.js 安装在系统中**。你已反馈完整重启 VS Code 后 npm/npx 恢复，符合旧 PATH 继承问题；这里只记录该问题已解决，不代替 E1 的完整解释器核对或其他验收。

## 最终本机MCP验收：以本项目根目录检查产品

在桌面VSCode“文件 → 打开文件夹”选web_agent仓库根，并信任它；保持已有Conda环境，在集成CMD依次执行：

```bat
cd /d "你的web_agent完整路径"
set WORKSPACE_ROOT=
install-vscode-extension.cmd
```

安装结束后重载VSCode窗口，再在仓库根的集成CMD运行`run-webagent.cmd`（不传参数）。`set WORKSPACE_ROOT=`只清除本终端旧覆盖；有意使用其他项目时不要清除。确认启动打印的Workspace是仓库根。打开本机工作台完成授权，再启动Bridge并按原路线连接MCP；让AI先调用workspace_info并读取README.md、manager/CONTEXT.md，核对项目再做辅助验收。根`npm test`是产品测试，`npm run test:example`才是可选计算器。不要把根目录拿来做破坏性边界实验，下文临时验收目录仍保留。

若VSCode空窗口、首文件夹不是主机根或工作区未信任，点击Bridge启动应弹窗且不启动；先正确打开文件夹，不要绕过提示。为下文临时目录验收时，需要把IDE也打开到那个目录，并停止旧Bridge/主机后带临时路径重启，不能只换IDE目录期待主机跟随。经典页面遇主机重启/项目变化也会拒绝，刷新整页核对后重连。新根工作区不会自动带入旧示例中的模型密钥/账户配置。

### 用户指定的最终验收顺序（待执行，不是已经连接）

**本轮（第七批、F71、F72）的具体步骤与预期结果见[R8本轮Arena实机验收](R8本轮Arena实机验收.md)**：它按下面的顺序展开，补上每批改动在本机能观察到的现象。

2026-09-16用户明确：剩余施工完成后，再通过Arena连接本机WebAgent MCP，工作区选择本项目根目录。现有手机连接报告仍保留；这次新版本验收单列，不重开已关闭的11.3。

1. **本机准备**：保存现有工作，记录`git status --short`与`git rev-parse HEAD`，确认要验收的代码；先完成依赖准备再启动主机。不要在运行中的产品目录盲目重建node_modules或覆盖安装。
2. **确认连接工具**：在Arena的实际MCP连接界面接入；Agent会话必须真的出现WebAgent工具。没有工具就记录“本机连接未建立”，不能用沙箱bash/fetch或自报文字代替。
3. **只读身份核对**：调用`ping`和`workspace_info`。后者返回`root`、`identity.hostInstanceId`、`identity.workspaceRoot`等，与本机工作台主机诊断比较；根必须是所选web_agent仓库。每次主机重启身份会变化，应重新核对。主机ID不是模型身份鉴定。
4. **确认对象**：读取根README.md与manager/CONTEXT.md，核对版本/验收范围；获准Execute后可读取真实Git提交、状态和Node路径。不读取`.webagent/config.json`、环境密钥或完整MCP URL作证据；不要通过命令绕过敏感文件策略。
5. **受控运行**：先运行不修改产品内容的诊断/自动测试；测试通常使用临时目录，但仍会创建临时进程/文件。Playwright测试单独运行并明确浏览器是否已准备，不将npm test通过等同浏览器回归。Bridge不能同时发起本机Chat执行；不通过本机API绕过主人权限或审批。
6. **有限写入验收**：只在事先约定的独立临时文件上测写入、读回与有限检查点。选择仓库根不是授权覆盖源码、未提交改动、清空Git、删除目录或全项目恢复；清理只针对本次明确创建的产物。
7. **转人工的项目**：原生VSCode窗口、PTY、真实桌面截图/键鼠、安装升级卸载等按清单另操作。MCP工具结果不能代签实际窗口；必须停Bridge/换Chat的项目先由操作者切换，断开后的结果不能从原连接猜测。
8. **收尾**：逐项记录通过/失败/未执行、命令退出码、脱敏输出、提交与实际环境；对照Git改动。结束任务并正常停止Bridge；最后断连/进程退出由本机操作者确认，远端失联本身不是停止成功证据。

## 0. 先选路线，并认识两个窗口

- **推荐路线**：第 1–7 步准备、自动测试、本机编辑；再做第 8–11 步可选 MCP 连接；最后按第 12 步停止。第 13–18 步是分开的进阶验收。
- **先连接、再让 Agent 协助**：仍做第 1–4 步；第 5 步可暂缓，但写“自动测试未执行”；做第 6–7 步最小本机检查，再去第 8–11 步。这不是已通过安全验收，也不能省略依赖安装和工作区核对。
- 不要求一晚上做完。每完成一步就记录，遇到错误停在该步。安装器、外部模型、手机、长挂、DPI等可以分天完成。

用 VS Code 终端面板右侧的“+”新建两个 **Command Prompt**，可右键终端名称重命名：

| 窗口 | 用途 | 使用规则 |
|---|---|---|
| CMD-A：启动 | 启动并保持产品运行 | 显示服务日志时不要继续输入本手册的其他命令；停止服务用 Ctrl+C |
| CMD-B：检查 | 读文件、跑诊断、记录结果 | 输入后面的检查命令；需要运行文档服务时它也会被占用 |
| 浏览器 | 打开本机工作台和文档 | 网页输入框不是 CMD，不粘贴终端命令，除非步骤明确说交给 Agent |

命令面板 `Ctrl+Shift+P` → `Terminal: Select Default Profile` → `Command Prompt`；再新建终端。不是 PowerShell。代码块逐行执行，每行回车；不要把标题、解释文字或代码块标记一起复制。`%USERPROFILE%` 等是 CMD 变量，不需要替换。

## 1. 打开源码目录，激活你的 Conda 环境

**位置：CMD-A。** 先列出环境：

```bat
conda info --envs
```

找到平时使用的环境名。下面两行中，`你的环境名` 和 `D:\projects\web_agent` **必须替换成自己的值**。源码根应包含 `run-webagent.cmd`、`docs-site`、`webagent-core`，不是验收数据目录。

```bat
conda activate 你的环境名
cd /d "D:\projects\web_agent"
dir run-webagent.cmd
git rev-parse --show-toplevel
git rev-parse HEAD
```

**预期：** 脚本存在，git 输出仓库路径和一串提交编号。若“找不到文件”或“not a git repository”，停止，先确认源码目录。不要在陌生目录运行 git init 来掩盖问题，也不必重新克隆、切分支或覆盖现有代码。

在 **CMD-B** 中重复激活环境和进入同一源码目录的两条命令。两个终端不会自动共享 `cd` 或 `conda activate` 状态。

## 2. 确认实际程序路径（E1、A1）

**位置：CMD-B。**

```bat
where conda
where python
python -c "import sys; print(sys.executable); print(sys.version)"
where node
node -p "process.execPath"
node --version
where npm
npm --version
where npx
npx --version
git --version
check-env.cmd
```

最后的脚本出现“按任意键继续”时按回车。**预期：** Python 属于所选 Conda 环境；Node 是你选择的系统安装；npm/npx 可用。cloudflared/ngrok 没安装暂时没关系，本机编辑不需要隧道。若再遇到命令找不到，按[Conda 说明第 2.2 节](Conda环境说明.md)排查，不重装整套环境。

## 3. 建立独立、无敏感数据的验收目录

**位置：CMD-B。** 本手册使用新名字，避免覆盖你以前的验收文件。先检查：

```bat
if exist "%USERPROFILE%\WebAgent-acceptance-beginner" echo STOP: workspace already exists
```

**如果打印 STOP，先停止：** 换一个全新目录名，并在后续所有命令中一致替换 `WebAgent-acceptance-beginner`；不要删除旧目录，也不要把重要仓库拿来测试。没有输出才继续：

```bat
mkdir "%USERPROFILE%\WebAgent-acceptance-beginner"
echo LOCAL-CHECK-001> "%USERPROFILE%\WebAgent-acceptance-beginner\acceptance.txt"
type "%USERPROFILE%\WebAgent-acceptance-beginner\acceptance.txt"
if not exist "%USERPROFILE%\WebAgent-evidence" mkdir "%USERPROFILE%\WebAgent-evidence"
notepad "%USERPROFILE%\WebAgent-evidence\manual-results.txt"
```

**预期：** `type` 显示 `LOCAL-CHECK-001`。记事本提示新建时选择新建，在里面写：

```text
日期：
Git提交：
Windows / VS Code / 浏览器版本：
Conda环境名、Python实际路径：
Node实际路径、Node/npm版本：
验收工作区：
终端PATH问题：完整重启VS Code后npm/npx恢复（用户实测）
第2步环境核对：未执行 / 通过 / 失败，实际输出摘要：
第5步自动测试：未执行 / 通过 / 失败，退出码：
后续每一步：编号、操作、实际结果、判定、脱敏截图或错误
```

填入实际情况并保存。这里的“未执行 / 通过 / 失败”只保留真实的一项；不要把模板本身当验收结果。已有记录文件时追加，不覆盖以前证据。

## 4. 安装项目依赖（两条路线都必须做）

**位置：CMD-B，当前目录仍为源码根。**

```bat
npm ci --include=dev --prefix webagent-core/agent-host
echo %ERRORLEVEL%
```

`echo` 必须紧接上一条，期间不输入其他命令。**预期：** 安装结束，退出码 `0`。它会重建这个包的 `node_modules`，不会删除 Conda 环境或验收目录。若网络/权限/锁文件报错或退出非零，记录并停止，不继续启动来掩盖安装失败。

## 5. 推荐先跑自动检查（A10、E4）

**位置：CMD-B。**

```bat
node docs-site/check-docs.js
echo %ERRORLEVEL%
```

退出 `0` 才继续：

```bat
npm test --prefix webagent-core/agent-host
echo %ERRORLEVEL%
```

**预期：** runner 汇总所有测试文件通过且退出 `0`，记录当次文件数。不要只看前几行 PASS。文档漂移时报错，先保留原错误，不要直接运行 `--write` 把它改掉。

若选择先连接路线，在记录里写“第5步暂缓，自动测试未执行”，直接继续第 6 步。自动测试不会由“成功连接 MCP”自动补做，之后需在源码根补跑；远程 Agent 的测试工作区不一定包含产品源码。

## 6. 启动最简单的经典工作台（A3）

先在 **CMD-B** 查看端口：

```bat
netstat -ano | findstr :3000
netstat -ano | findstr :48271
```

没有输出可以继续。有输出时看是否有本地端口 `3000`/`48271` 的 `LISTENING` 行；`TIME_WAIT` 或远端端口匹配不等于被占用。若有监听，不要批量结束 node.exe。记录 PID；不认识进程就先请维护者辨认。

切到 **CMD-A**，确认已按第 1 步激活/进入源码根，然后：

```bat
run-webagent.cmd "%USERPROFILE%\WebAgent-acceptance-beginner"
```

**预期：** 日志打印的 Workspace 正是这个目录，服务启动无致命报错。浏览器未自动打开时，手动输入：

```text
http://127.0.0.1:3000
```

看到 Web Agent 页面和验收文件后继续。此时保留 CMD-A，不同时启动 `run-webagent-vscode.cmd`。页面打不开、目录错误或端口冲突就停止，不打开公网端口“修复”。

### 本次界面修复后，怎样更新并复验

你的第7～10步及11.1、11.2已按用户报告记录完成；第5步自动测试必须另看当次退出码，不从其它步骤成功推定。11.3已按用户2026-09-16确认标记完成/关闭（协作边界说明，不是独立验收项）。第7步此前空模型阻塞已复验完成；帮助入口已有修复/回归，Bridge刷新计数与记录在2026-09-15另获用户确认。新控件和后续版本仍按实际范围验，不把旧记录扩大为全部界面通过。先保存正在编辑的文件；在CMD-A按Ctrl+C停止本次服务，若提示终止批处理，按Y。回到源码根、确认当前分支后更新（不在验收工作区执行）：

```bat
git status --short
git branch --show-current
git branch -vv
git rev-parse --short HEAD
```

上面先检查，不固定拉取旧历史分支。确认当前维护分支、其上游和预期一致且没有未处理源码修改后，才执行`git pull --ff-only`，再核对HEAD并启动；未配置上游或不确定时先请维护者确认来源。有冲突/无法快进就保留报错，不reset/强行覆盖或擅自切main。无需重建Conda、重装Node或重建验收文件。完成上述更新核对后，再按第6步用原验收目录启动；浏览器回到`http://127.0.0.1:3000`，按Ctrl+F5强制刷新。

- 右上按钮切换深/浅色：检查正文、设置页、模型列表和输入框文字清楚。
- 在底部打开Agent模式菜单：靠近底边时应向上展开；窗口较小时可滚动。Escape关闭；改变窗口大小后重新打开检查。
- 点击聊天模型按钮，应看到“内置探索 Agent”及“无需 API Key”。没有出现时先记录截图/控制台错误，不去申请API作为绕过。
- 原先未实现的IDE菜单/附件/仿站登录等已移除；文件、Chat、模型设置和Bridge保留。完整IDE请用桌面VS Code扩展；MCP/挂钩/插件备注在折叠兼容资料中，不会自动执行。

## 7. 先做一次本机编辑和读取（A4、A5内置部分）

1. **浏览器：** 左侧点资源管理器图标展开文件树，再点 `acceptance.txt`，应看到 `LOCAL-CHECK-001`。
2. 在编辑区新增一行 `EDITOR-CHECK-002`，点击编辑区域让它获得焦点，再按 `Ctrl+S`。若弹出浏览器“另存网页”，取消该对话框，记录快捷键未被编辑器接收，不能当作保存成功。
3. **CMD-B：** 执行：

```bat
type "%USERPROFILE%\WebAgent-acceptance-beginner\acceptance.txt"
notepad "%USERPROFILE%\WebAgent-acceptance-beginner\acceptance.txt"
```

4. **预期：** 磁盘和记事本都出现新增行。关闭记事本，刷新工作台，再打开文件确认仍在。
5. **浏览器：** 在输入框下方选择“内置探索 Agent”，再在Agent模式菜单选Ask，发“请只列出当前工作区文件并读取 acceptance.txt，不要修改或运行命令”。**不需要API Key**。展开聊天流里“Read … files / read_files”工具卡，确认返回包含文件名以及`LOCAL-CHECK-001`、`EDITOR-CHECK-002`，不要只看助手最后的概括。内置是确定性探索器，会额外扫描/查Git状态/更新任务元数据，不是通用语言模型；文件选择有上限，不保证每个自然语言要求都遵从。此步不应调用`run_command`或修改验收文件正文；没有读到时记录实际工具和返回内容，不替它伪造成功。
6. 另加一行暂不保存，尝试切文件/关闭标签，观察脏标记和丢弃确认；选择取消以保留编辑，再按保存。不要测试关闭浏览器后的自动恢复，当前未承诺该功能。

**最低继续条件：** 本机页面可用、工作区正确、文件能真实保存和读回。若此处失败，暂不连 MCP。这不是外部模型、PTY或Windows桌面输入的验收。

## 8. 可选：准备公网 MCP 隧道（F1）

只做本机验收可跳到第 12 步。要连手机或远程 Agent 时，先确认它的**当前账号/会话具备 MCP 工具连接能力**。用户已实测手机浏览器Arena可沿用电脑上的WebAgent链接用法，不要求另找特定配置菜单。其他客户端按实际支持的连接流程操作；普通无工具聊天框不能因为收到URL而执行工具。

本手册选 Cloudflare Quick Tunnel，其他模式见[隧道指南](隧道使用指南.md)。**CMD-B：**

```bat
where cloudflared
cloudflared --version
```

已能运行则跳过安装。否则下面命令会安装第三方软件；确认愿意安装后才执行：

```bat
winget install --id Cloudflare.cloudflared --exact
```

若 winget 不存在、安装被管理策略拒绝或网络失败，保留报错并停止，不关闭安全软件、不从不明来源下载。

安装后可能修改 PATH：先按第 12 步安全停本次服务，保存所有文件并完整退出 VS Code，重新打开，重复第 1 步及上述版本检查，再按第 6 步重新启动。**仅新建终端可能仍继承旧 PATH，与你刚解决的 Node 问题相同。** 不需要再次创建/覆盖第 3 步的验收文件。

## 9. 在工作台启动 Bridge（A6、D7）

**位置：本机浏览器工作台。**

1. 左下角齿轮 → 智能体自定义设置 → Bridge。
2. 确认本机演示授权状态；它不是 GitHub 登录。此路线不要求你提交 GitHub token 或模型 API Key。
3. 隧道选择 **Cloudflare Quick Tunnel**，点击 **启动 Bridge**，等待结果。
4. 成功应出现 HTTPS 公网域名；若仍是 `127.0.0.1` 或显示错误，停止并记录，不能拿本机地址给手机使用。
5. 还没有客户端时“等待连接”是合理状态，不等于已经完成任务。

公网隧道不是无风险隔离环境：工作区约束不等于操作系统沙箱，命令/桌面能力可能触及当前用户资源。只连接自己的测试工作区、自己的受信客户端，短时启用。不要映射3000管理页面，不开放 `/api` 或 `/ws`，不要修改本机边界检查/防火墙来让它“连得上”。

## 10. 在实际客户端配置 MCP，而不是发地址给聊天（F2）

1. 在你的 Arena/其他客户端中找到实际提供的 MCP/工具/连接器配置入口。界面名称和账号能力可能变化，本手册不编造固定按钮路径。
2. 如果入口支持 OAuth，先在工作台 BRIDGE 区点“开启 OAuth 配对”（默认关闭），再按它的要求填 Bridge 提供的**规范地址**（以 `/mcp` 结尾），在真实授权页完成配对。配对码只在授权页输入，不发进聊天。
3. 若客户端明确支持带密钥的 MCP 地址，则只在受信连接配置字段填写对应地址；完整 URL 相当于凭据，不贴聊天、截图、Git或工单。不要因OAuth失败就私自改成无认证。
4. 启用该连接/工具后，查看客户端是否实际发现 `workspace_info`、`read_files` 等工具。若当前会话没有这些工具，重试客户端支持的刷新/新会话流程；仍没有就记录“客户端能力/会话工具未接通”，停在这里。

**针对你想让本聊天的 Agent 帮忙：** 若当前会话本身没有你电脑的MCP工具，贴URL不会自动添加。必须由 Arena 的实际工具接入能力把它暴露给执行验收的会话。连接后让 Agent 先真实调用 `workspace_info`，报告调用结果；只有文字声称“已连接”或能打开HTTP地址不算证据。

## 14. 模型、Plan和Monaco进阶（A5外部、B5–B7、D5–D6）

这部分不能让远程MCP执行器替代。先停Bridge和服务。在源码根CMD-B执行下面命令，它会侧载本项目扩展到用户VS Code扩展目录；确认同意后再运行：

```bat

```

记录成功/错误。保存后完整退出VS Code再打开（会关闭集成启动终端，因此随后要重新按第1、6步启动）。在另一个VS Code窗口选择“文件 → 打开文件夹”，打开 **验收目录**，不是源码根；只给自己创建的测试目录Workspace Trust。

确认Web Agent扩展加载、host地址/工作区匹配。使用该扩展的本机Chat发起命令，**不是自己直接在CMD执行来冒充PTY**。需要能遵循命令调用的模型；内置模型不生成该任务、扩展无Chat能力或缺后端时记录阻塞，不把普通MCP结果代入。

下面是给本机扩展Chat的请求，每次一条、检查审批后再允许：

```text
只通过本机PTY执行 node -e "console.log('pty-check'); process.exit(0)"，报告实际捕获的输出、退出码和执行类型；不得改为其他执行路径冒充PTY成功。
```

```text
只通过本机PTY执行 node -e "process.exit(7)"，报告实际退出码和失败状态，不重试。
```

```text
只通过本机PTY执行 node -e "setTimeout(()=>{}, 30000)"。我会在运行中点击本机Chat支持的停止按钮；取消后报告终态，不把超时算取消成功。
```

这些Node命令避免把PowerShell语法误贴进CMD；外层仍应记录PTY实际shell。正常应捕获pty-check/0；第二条应失败/7；第三条取消后任务和真实执行均停止。看不到真实退出码时不通过。

审批测试可用一个仅打印 `approval-check` 的Node命令：先拒绝，核对没有实际执行；另起任务再允许。审批等待后先取消任务，再响应旧审批，不应执行。若策略自动批准、未出现弹窗，则该审批场景尚未测到，不能禁用策略造绿灯。多窗口/工作区隔离和真实进程停止证据不明确时，请维护者逐项辅助，保留未执行状态。

## 17. 桌面输入与长挂是最后的专项（D8、B3–B4）

3. 在VSCode将两文件分别改为`after A`、`after B`并保存。返回工作台预览检查点差异，两文件应有current→checkpoint差异，磁盘仍应是after。
4. 点击恢复但取消确认，磁盘必须仍是after。再确认恢复一次，逐文件结果应是restored；重新从磁盘核对两文件是before，注意不要用未保存缓冲区误判。
5. 刷新检查点列表应仍能看到未过期的consumed结果，不能再次恢复。另建检查点/预览后修改其中一个文件，再确认必须在预检阶段拒绝，两文件都不应被本次恢复改写。
6. 如中途失败出现unknown/部分完成，先保存日志并人工核对，不重放。完成后移除测试检查点和临时文件；不要删除其他数据。主机重启/15分钟过期会丢失检查点，这是明确边界，不是持久备份。

原生草稿diff/Ctrl+Z的独立验证见[扩展详解](../../webagent-core/extension/入口与Webview详解.md#editorreviewjs原生单文件草稿预览与恢复)，不能拿上述磁盘检查点替代原生编辑器验收。


## 隧道残留回收快捷入口（桌面验收待执行）

新版安装包开始菜单中选择 **Web Agent → 隧道残留回收（需确认）**。源码也可在仓库根本机CMD运行 `powershell -NoProfile -ExecutionPolicy Bypass -File installer\tunnel-recovery.ps1`，不传任何参数，不管道喂确认。

1. 确认它打开独立控制台，不启动/停止当前Bridge，不创建工作区或安装npm依赖。
2. 先读预览。只处理有保护记录、身份/父进程核对通过且宿主已死的标准隧道根进程；旧无记录、未知、活宿主项不回收。不用任务管理器按名称批量结束来替代。
3. 需要回收才在60秒有效预览内输入RECYCLE；其他输入或Ctrl+C取消。确认后若断连/关窗，结果可能未知，不自动重放。
4. 仅terminated表示观察到退出，跳过不等于已清理。结果保留到按键关闭窗口；这次按键不确认或重复回收。
5. 同一Windows会话重复点击入口应拒绝第二次启动。该互斥不等于跨会话/同用户恶意代码隔离。真实桌面点击/重复点击/关窗及真实Cloudflare/ngrok仍须记录本机结果，CI不代签。

这只是系统本机快捷入口，不是网页/扩展面板按钮，也不是无需确认的一键全杀；现有工作台/API/权限合同不变。
