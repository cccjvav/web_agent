# Bridge Tasks为什么没显示？（核心0.7.2）

## 工具记录与任务计划是两回事

工具记录说明主机实际接到了哪些工具调用；Tasks显示Agent明确调用set_todos上报的计划。普通聊天、读文件或运行命令不会自动生成计划，工具成功也不会自动把计划标完成。report_progress是单独上报的百分比/步骤，该工具允许Plan/Code、不允许Ask；set_todos允许Ask/Plan/Code。

可以请外部Agent：

```text
先用set_todos上报这次任务的计划，每项填写id、title、status。开始某项时更新为in_progress，完成后再按实际结果更新；失败请如实报告。不要把工具调用成功当成整个任务完成，不要为了显示进度而额外执行修改操作。
```

允许status为pending/in_progress/completed/failed/cancelled/blocked；一次最多50项，每次替换该会话的完整计划，不是追加。同一MCP会话多项工作由Agent自行组织；不是自动从对话语义提取的任务板。

## 这次修了什么

- 旧工作台没有任务就隐藏，还会把本地Chat计划画进Bridge；现在Bridge常显空状态提示，本地与远程分开。
- 旧主机只维护全局单份计划；现在Bridge按服务端调用者归属的会话摘要分组，原始会话键不显示。已初始化的不同MCP会话不会互相覆盖；未初始化兼容请求沿用服务端原有归属，不能保证每个标签独立。
- 工作台每3秒从主机活动快照同步，WS只提前触发，断WS和刷新不丢计划。
- 桌面VSCode、code-server与App入口共用核心扩展；BridgeView每4秒单飞刷新远程任务快照，不再读本地Chat的taskState。来源隔离的工具摘要也不会被大量本地日志挤掉。
- 任务框显示会话和上报状态；“completed”和100%都是Agent报告，不是主机自动验证的事实。请求失败显示当前状态未知，而不是空列表/已完成。

## 保留范围

最多16个远程报告会话，每组50项，标题/消息500字符。30分钟没有更新会过期，主机重启丢失；页面刷新不清除，清工具统计也不清计划。任务报告是进程内观测，不是磁盘持久任务板。清任务报告不取消命令。Agent应及时上报变化，不靠轮询网页延长报告有效期。

## 更新和核对

停止旧主机、拉取更新后，桌面VSCode执行install-vscode-extension.cmd并重载窗口，确认核心0.7.2；code-server启动器同步同版本核心副本。普通工作台重启主机并刷新网页。暂停专项沿用既有0.5.2交付记录，不在本文复核其外部新版本或新增入口。

1. 没有set_todos时，应看见空状态说明，不是一个消失的区域。
2. 让当前MCP会话上报两项任务，Tasks应显示分组和0/2。
3. 上报其中一项completed，应显示1/2；刷新仍在。
4. 本地Chat上报另一份计划，不能覆盖Bridge；第二个已初始化MCP会话有自己的分组。
5. 停主机时显示同步失败/未知；不要把最后的旧快照当成仍在实时执行。
