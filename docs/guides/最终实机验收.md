# 最终实机验收（项目收尾，逐步操作）

这份手册把项目收尾前**还没在你电脑上验过的项目**集中到一处，按顺序做一遍即可。来源：R6 第二期续跑4、第一期 4.7、R5 遗留隧道提示、R8 的 M5（9.2）、F124 验收后的收尾，以及第129–132组只有自动测试、还没实机验过的改动。

**环境：** Windows 桌面 VS Code → 集成 CMD → 激活 Conda，Node.js 装在系统里；工作区用 **web_agent 仓库根目录**。

**规则：**
- 每一步只记录一种真实结果：通过 / 失败 / 未执行。
- 失败就停在那一步，把**步骤编号＋脱敏输出/截图**发给维护者，不要为了往下走而改设置或绕过提示。
- 沙箱里的 CI 全绿不能代替这里任何一步。
- 标“可选”的步骤缺条件时记“未执行”，并写明缺什么。

**绝不外发：** 完整 MCP 地址（`https://…/mcp/一串密钥`）、`.webagent\config.json` 的内容、API Key、隧道 Token、配对码。截图前先遮住。

**顺序有讲究：** 第 2 步（续跑4 第 11 步）要求**没有配置大模型**，第 8 步要求**已经配置模型**。所以按编号顺序做，不要为了第 8 步提前添加模型。

## 0. 准备记录


## 3. 全局 Skill 目录（第131组 C）

**前提：** 侧栏主机卡片是“运行中”。

1. **CMD-B** 先看全局目录里有没有东西：

```bat

```

如果里面**已经有** `fix-tests` 或 `wa-accept-empty` 文件夹，本步记“未执行（已有同名全局 Skill）”，跳到第 4 步，不要覆盖它们。“找不到文件”是正常的。

2. **CMD-B** 复制一份工作区 Skill 到全局目录，再建一个空的 Skill：

```bat
xcopy /e /i /q ".webagent\skills\fix-tests" "%USERPROFILE%\.webagent\skills\fix-tests"

type nul > "%USERPROFILE%\.webagent\skills\wa-accept-empty\SKILL.md"
```

3. 点侧栏齿轮打开“Web Agent 设置”，导航 **技能**，点【重新扫描】。

**预期：**
- 有两张 `fix-tests` 卡片：
  - 一张的灰字是 `workspace:fix-tests · 说明型 · 不自动执行`。
  - 另一张是 `user:fix-tests · 说明型 · 不自动执行 · 被同名的 workspace:fix-tests 遮住，请使用完整ID`。
- 有一张 `wa-accept-empty` 卡片，灰字含 `user:wa-accept-empty`，下面一行是 `不可用（empty）：SKILL.md 是空的：写入用途说明和步骤。`
- 页面任何地方都不出现 `C:\Users\…` 这样的完整用户目录。

4. 在 `user:fix-tests` 卡片上点【查看正文与资源】。**预期：** 阅读区标题是 `user:fix-tests / SKILL.md`，正文与仓库里 `.webagent\skills\fix-tests\SKILL.md` 相同。

5. **收尾（必做），CMD-B：**

```bat
rmdir /s /q "%USERPROFILE%\.webagent\skills\fix-tests"
rmdir /s /q "%USERPROFILE%\.webagent\skills\wa-accept-empty"
```

不要删除 `%USERPROFILE%\.webagent` 本身：Quick Tunnel 的独立配置也放在里面。回到技能页点【重新扫描】。**预期：** 不再有 `user:` 开头的卡片。

## 4. 模型端点网络失败的提示（第131组 B）

**本步不添加任何模型。** 只点【Test】，不点【Add API】。Key 填的是假的，不是你真实的 Key。

设置页导航 **API Provider**，“API Key”框填 `sk-wa-accept`，然后依次在“API Endpoint URL”框填下面的地址，各点一次【Test】。

1. **域名不存在：** `https://wa-accept.invalid/v1`。

   **预期：** 下方状态行是：

   ```text
   模型发现失败，未写入：无法解析模型端点的域名：核对 Base URL 拼写和本机网络。需要手动登记时，请明确填写模型ID后再点Add API。
   ```

2. **端口没人监听：** 先在 **CMD-B** 执行 `netstat -ano | findstr ":59999 "`，确认没有输出（有输出就换一个没人用的端口）。再填 `http://127.0.0.1:59999/v1`。

   **预期：** 状态行是“模型发现失败，未写入：连不上模型端点：确认地址和端口正确、服务在运行，本机网络能访问它。需要手动登记时，……”。

3. **可选，证书过期（需要能上外网）：** 填 `https://expired.badssl.com/v1`。

   **预期：** 状态行含“模型端点的 HTTPS 证书校验失败：证书过期、域名不符或是自签证书；本产品不跳过证书校验。”

**三次都要满足：** 状态行里没有 `sk-wa-accept`，也没有 `ENOTFOUND`、`ECONNREFUSED`、`fetch failed` 这类英文原文；表格里仍是“还没有添加 API”。

如果你用了代理或公司网络，第 1、2 步可能得到别的原因；照实记录原文，不算产品失败，由维护者判断。做完清空 Endpoint 和 Key 两个框。

## 5. 外部 MCP 登记在重启后保留（第132组）

本步用仓库自带的测试用 MCP 服务 `webagent-core\agent-host\tests\httpMcpFixture.js`。它的情况：

- 只监听本机 `127.0.0.1`，只有一个工具 `echo`。
- 每收到一个请求打印一行，从不打印 Token。
- 只用于验收，产品本身不会启动它。

**5.1 启动测试服务**

**CMD-A：**

```bat
node webagent-core\agent-host\tests\httpMcpFixture.js 48390 wa-accept-token
```

**预期：** 打印 `[fixture] HTTP MCP夹具在 http://127.0.0.1:48390/mcp 监听（需要Token）；按 Ctrl+C 停止。`。如果报端口占用，把下面所有 `48390` 换成别的空闲端口。

**5.2 错误 Token 登记被拒**

设置页导航 **工具接入与审批**，按下面填写，然后点【登记并初始化 / 发现工具】：
- “接入名称”：`验收HTTP夹具`
- “明确启用公网HTTPS”：**不勾选**
- “已启动的 MCP 地址”：`http://127.0.0.1:48390/mcp`
- “可选 Bearer Token”：`wrong`

**预期：**
- 结果框是：

  ```text
  HTTP接入登记失败：服务拒绝了凭据：Token缺失、填错或已过期，重新生成后再登记。主机已确认没有登记这个接入，修正后可重新登记。
  ```

- CMD-A 打印一行 `[fixture] POST initialize（Token缺失或错误，回401）`。
- “已登记的接入”里没有新项。

**5.3 正确 Token 登记并保存**

Token 框改填 `wa-accept-token`（登记后页面会清空这个框），再点一次【登记并初始化 / 发现工具】。

**预期：**
- 结果框是“接入 `<ID>` 已确认登记，发现 1 个工具。……已保存到当前工作区配置（含Token，状态里不显示），主机重启后自动重新连接。”。把 ID 的前 8 位记下来。
- “已登记的接入”里这一项：
  - 显示 `"status": "discovered"`、`"saved": true`、`"hasToken": true`。
  - **没有** Token 的值。
  - 下方一行“已保存（含Token），主机重启后自动重新连接。”
- CMD-A 打印 `initialize`、`notifications/initialized`、`tools/list` 三行，每行带“（Token正确）”，**没有** `wa-accept-token` 这串字。

**CMD-B** 核对配置文件里有这一项（只打印名称、地址和“有没有 Token”，不打印 Token）：

```bat
node -e "const c=require('./.webagent/config.json');for(const s of c.externalServers||[])console.log(s.name,s.url,'Token已保存:'+Boolean(s.token))"
```

**预期：** 输出 `验收HTTP夹具 http://127.0.0.1:48390/mcp Token已保存:true`。

**5.4 测试服务开着时重启主机：自动重新连接**

1. 侧栏主机卡片点【停止】，等到“未启动”。再点【启动】，等到“运行中（由插件启动）”。
2. 点【日志】。**预期：** 输出面板“Web Agent Host”里有一行 `外部MCP  恢复已保存的接入 1 个`。

2. 侧栏【停止】再【启动】主机，日志里仍有 `外部MCP  恢复已保存的接入 1 个`。

## 6. 隧道：Quick Tunnel 隔离与启动失败码（第129、130组）

**前提：** 主机运行中，Bridge 已停止。CMD-B 执行 `where cloudflared` 能找到程序。

**6.1 自己的 cloudflared 配置不再影响 Quick Tunnel**

1. **CMD-B：** `dir "%USERPROFILE%\.cloudflared"`。
   - **已有 `config.yml`：** 不要改它，直接做第 2 小步，记录里写“使用已有 config.yml”。
   - **没有：** 建一个临时的。它的意思是“所有请求都回 404”，没有隔离时 Bridge 地址会全部 404：

     ```bat
     if not exist "%USERPROFILE%\.cloudflared" mkdir "%USERPROFILE%\.cloudflared"
     (echo ingress:& echo - service: http_status:404) > "%USERPROFILE%\.cloudflared\config.yml"
     type "%USERPROFILE%\.cloudflared\config.yml"
     ```

     **预期：** 显示 `ingress:` 和 `- service: http_status:404` 两行。记录里写“建了临时 config.yml”，第 9 步要删。

2. 设置页导航 **Bridge**，隧道模式选 **Cloudflare Quick Tunnel**，点【启动 Bridge】。**预期：** 状态变为运行中，出现 `https://….trycloudflare.com/mcp/…` 地址。
3. 只抄出地址里 `https://` 到 `.trycloudflare.com` 为止的部分，后面的 `/mcp/…` 不要复制出去。**CMD-B：**

```bat
curl -s https://你的随机名.trycloudflare.com/health
```

**预期：** 输出 `{"ok":true,"product":…,"version":…}`。新地址刚出现时 DNS 可能还没生效，失败就等 15 秒再试，最多试 3 次。三次都是空白、404 或 Cloudflare 错误页就记失败，附上输出。

4. **CMD-B** 查看 cloudflared 实际用的参数（命令行里没有密钥）：

```bat
powershell -NoProfile -Command "(Get-CimInstance Win32_Process | Where-Object Name -eq 'cloudflared.exe').CommandLine"
type "%USERPROFILE%\.webagent\cloudflared-quick-tunnel.yml"
```

**预期：**
- 第一条输出含 `--config` 和 `cloudflared-quick-tunnel.yml`，以及 `--protocol auto`。
- 第二条显示的文件里有一行 `no-autoupdate: true`。

5. 设置页点【停止 Bridge】，等状态变为已停止。

> QUIC 被网络拦截时，cloudflared 会自动改用 HTTP/2。这只有在 UDP 7844 被拦的网络里才看得到，本手册不专门制造。如果你的网络本来就拦 UDP，第 2 小步能在 25 秒内拿到地址就说明它起作用了。

**6.2 侧栏启动失败显示原因和错误码**

**前提：**
- 从没在设置页成功启动过 ngrok（成功过就说明主机已保存 ngrok Token）。
- CMD-B 执行 `echo %NGROK_AUTHTOKEN%` 原样输出 `%NGROK_AUTHTOKEN%`。

不满足时记“未执行”：这时会真的启动 ngrok。

1. 侧栏 MCP 卡片的“隧道”下拉选 **ngrok**，点【启动 Bridge】。

   **预期：** 弹出的错误框文字是：

   ```text
   ngrok 需要 Authtoken（dashboard.ngrok.com 复制，或设环境变量 NGROK_AUTHTOKEN）。（E_NGROK_TOKEN）
   ```

   点掉错误框后，侧栏 Bridge 仍是停止状态。

2. 把下拉选回 **Cloudflare Quick Tunnel**。不用启动。

**6.3 可选：设置页显示 ngrok 自己的错误码**

**前提：** CMD-B 执行 `where ngrok` 能找到程序。没装就记“未执行”。

1. 设置页导航 **Bridge**，隧道模式选 **ngrok**，域名框保持原样，Authtoken 框填 `wa-accept-invalid`，点【启动 Bridge】。

   **预期（25 秒内）：** 结果行形如：

   ```text
   启动失败（ERR_NGROK_105）：ngrok Authtoken 格式不对：到 dashboard.ngrok.com 重新复制。远程 Bridge 没有运行，也没有自动重试。
   ```

   如果括号里是别的 `ERR_NGROK_` 编号，照实记录编号和整行，由维护者判断。整行里不应出现 `wa-accept-invalid`。

2. 失败的 Token 不会被保存。隧道模式选回 **Cloudflare Quick Tunnel**。

## 7. 遗留隧道的提示与回收（R5）

本步故意强杀主机，让它启动的 cloudflared 留下来，验证下次启动会提示，以及回收脚本只在你确认后才结束它。

1. 设置页 **Bridge** 用 Quick Tunnel 点【启动 Bridge】，等出现地址。
2. 侧栏点【日志】，找最近一行“[host] 主机已就绪：…（工作区 …，主机 pid N，启动器 pid M）”，记下 **N**。
3. **CMD-A：**

```bat
tasklist /fi "imagename eq cloudflared.exe"
taskkill /f /pid N
```

把 `N` 换成上一步的数字，**不要加 `/t`**。等 5 秒后再执行一次 `tasklist /fi "imagename eq cloudflared.exe"`。

**预期：** 主机卡片变为“启动失败”，下面一行写“主机进程意外退出（…），详见“输出 → Web Agent Host”。”（这是强杀造成的，属正常）；cloudflared 仍在列表里，PID 记作 **C**。如果 cloudflared 已经消失，本步记“未执行（强杀主机后没有遗留）”，跳到第 8 步。

4. 侧栏点【启动】，等到“运行中”，最多再等 40 秒。

   **预期：**
   - VS Code 右下角弹出警告：`Web Agent：遗留隧道 1 个。发现上次遗留的隧道进程。请从开始菜单 → Web Agent → “隧道残留回收（需确认）”处理；本提示只读，不会结束任何进程。`
   - 【日志】里有 `遗留隧道  1 个（…）` 一行。
   - `tasklist` 里 C 仍在：提示本身不结束进程。

5. 从源码运行回收入口（本机没装安装版时开始菜单里没有它）。**CMD-A：**

```bat
powershell -NoProfile -ExecutionPolicy Bypass -File installer\tunnel-recovery.ps1
```

   **预期：**
   - 先打印 `Windows tunnel recovery: preview first, then type RECYCLE …`，再打印一张预览表，其中有一行 status 是 `candidate`，对应 C 这个进程。
   - 提示“60秒内输入 RECYCLE 确认回收；其他输入或 Ctrl+C 取消：”。输入 `RECYCLE` 回车，结果表里这一行是 `terminated`。
   - 最后提示 `Press any key to close this window.`，按任意键结束。
   - 输入别的内容时打印“已取消或预览过期，未发送确认。”，不结束任何进程。想验证取消，可以先这样做一次，再重新运行脚本、输入 RECYCLE。

6. **CMD-A** 再执行 `tasklist /fi "imagename eq cloudflared.exe"`。**预期：** “没有运行的任务匹配指定标准”。
7. 侧栏【停止】再【启动】主机，等 40 秒。**预期：** 不再弹出遗留隧道警告。

## 8. 可选：终端确认框、退出码与 PowerShell 命令（R8 M5 的 9.2、第129组）

**前提：** 你在 Web Agent 里配置了**能调用工具的真实模型**。内置探索 Agent 不会运行命令。

- 没有配置时记“未执行”。
- 你本来就打算配置模型的话，现在可以在设置页 **API Provider** 用自己的 Endpoint 和 Key 添加。第 2 步已经做完，添加模型不影响前面的结果。

1. 确认 Bridge 已停止；在侧栏权限卡片里把工作方式切回 **Chat**。
2. 侧栏 Chat 下拉选 **Code**（不要在消息里写 `/code`），发送：

```text
请在终端运行 "C:\Program Files\nodejs\node.exe" --version（按你本机实际Node路径调整），然后运行 node --version。
```

**预期：**
- **第一条命令：**
  - 确认框里的命令应以 `& "C:\…\node.exe"` 开头：主机告诉模型终端是 PowerShell 5.1，带空格的路径要用 `&` 调用。
  - 按钮只有“运行 / 拒绝”，因为 `&` 被当作复合命令，总要单独确认。如果模型没写 `&`，按钮是“运行 / 本会话都允许 / 拒绝”。
  - 两种情况都**没有**“同类都允许”。照实记录确认框里的命令。
- **第二条 `node --version`：** 按钮里有“同类都允许”。
- 两次都点“运行”，两条都打印出版本号。

3. 再发：

```text
请在终端运行一条两行命令：第一行 node -e "process.exit(3)"，第二行 echo after。告诉我工具返回的退出码。
```

**预期：** 确认框只有“运行 / 拒绝”（多行命令总要单独确认）；点运行后，返回的退出码是 **3**，不是 0。

## 9. 收尾（F124 遗留与本手册的临时文件）

1. **重置 MCP 地址：** 确认 Bridge 已停止。设置页导航 **Bridge**，点【重置 MCP 地址】，在确认框里确认。

   **预期：** 结果写“密钥轮换已确认，当前地址已重新读取；旧凭据不再接受新请求，已有任务未被自动停止。”。F124 验收时交给 GitHub 的旧地址从此失效。

2. **删除仓库 Secret：** 浏览器打开 GitHub 仓库 → Settings → Secrets and variables → Actions，删除 `MCP_URL`。维护者这边的权限不能列出或删除 Secret，只能由你来做。已经不存在就记“不存在”。
3. **Arena：** 如果 Arena 里还留着以前接入本机的 MCP 连接，删除或停用它。
4. **临时 config.yml：** 只有第 6.1 步记了“建了临时 config.yml”才做。**CMD-B：**

```bat
del "%USERPROFILE%\.cloudflared\config.yml"
rmdir "%USERPROFILE%\.cloudflared" 2>nul
```

   `rmdir` 只在文件夹为空时删除，里面有别的文件就保留。

5. 侧栏 MCP 卡片的“隧道”下拉确认是 **Cloudflare Quick Tunnel**。
6. **CMD-B：** `git status --short`。**预期：** 没有输出。`.webagent\config.json` 被 Git 忽略，不会出现在这里。

## 验证范围与限制

本手册覆盖上表列出的项目。下面这些不在本手册里：

- **只有自动测试覆盖：**
  - 已保存的**公网 HTTPS** 外部 MCP 重启后要确认才重新连接（需要真实的公网 MCP 服务）。
  - Chat 请求时的模型网络失败提示（需要一个已配置却连不上的模型，设置页没有删除模型的按钮，不为验收制造）。
  - 隧道 25 秒超时、真实 QUIC 回退。
- **Named Tunnel 与 ngrok 正常启动：** 需要你的域名或 Token，流程与第一期相同。
- **安装版（LocalAppData）：** 安装、升级、卸载与开始菜单入口按[新手手册](Windows新手逐步验收.md)第 13–17 步另行验收。
- **多模型博弈：** 留在网页工作台（D4）。
- **MCP 2026-07-28 新旧两代适配：** 仍延后，不在本轮。

测试用 MCP 服务只说明本产品的登记、保存、恢复与重新连接流程在你的电脑上可用，不代表任何第三方 MCP 服务的兼容性。
