# 隧道使用指南（Windows + VS Code 集成 CMD）

云端Arena不能用它自己的localhost访问你的电脑。隧道把本机认证MCP端口（默认48271）映射为公网HTTPS地址；它不是公开工作台UI。本机Chat不需要隧道；手机Arena固定走Bridge。Chat和Bridge执行互斥，同类型仍可多模型/多Agent并发，详见[权限与模式](Bridge权限与工作模式.md)。

本文是[使用指南](../../使用指南.md)的隧道专项步骤。你的环境继续使用桌面VSCode集成CMD、现有Conda和系统Node，不改成venv。第三方Chat Plus/DeepSeek客户端仅是候选，当前兼容性不能由隧道就绪推断，见[Chat Plus说明](网页ChatPlus使用指南.md)、[DeepSeek说明](网页DeepSeek使用指南.md)。

## 1. 先选工作区与提供商

在VSCode打开本项目根目录，集成CMD进入同一目录。示例路径需替换，每条成功再继续：

```bat
cd /d "D:\projects\web_agent"
check-env.cmd
run-webagent.cmd "D:\projects\web_agent"
```

显式参数避免遗留WORKSPACE_ROOT覆盖目标。核对启动打印的Workspace与VSCode首文件夹相同；不能只在IDE切文件夹而不重启主机。普通业务任务可选择自己的项目，最终检查本产品则按用户约定选本仓库根。根目录不是可随意删改的测试场地。

打开本机工作台（默认http://127.0.0.1:3000），保留启动终端。设置→智能体自定义设置→Bridge：核对本机演示授权/设备授权，再保存需要的Read/Edit/Execute/Capture权限。演示授权不是验证GitHub账户。已有执行、后台程序或审批屏障时不能直接跨模式；先结束/取消并核对状态。

| 提供商 | 账号/配置 | 地址 | 本机程序 |
|---|---|---|---|
| Cloudflare Quick Tunnel | 不需Token，临时用途 | 重启可能改变，始终重新核对 | cloudflared |
| Cloudflare Named Tunnel | Cloudflare账号、域名、Public Hostname、Tunnel Token | 配置的固定域名 | cloudflared |
| ngrok | Authtoken，可选配置域名 | 以实际返回为准；域名与套餐由提供商决定 | ngrok |

产品停止并等待旧提供商退出后再启动新实例；并发/旧回调受代次保护。不要另开同一配置的隧道进程或安装重复后台服务，让产品的停止按钮失去唯一管理对象。不是说多个进程必然争用本机监听端口：它们是连接本机端口的转发客户端。

## 2. 安装与PATH

只安装所选提供商，不要求两种都装。先在普通CMD尝试winget；仅安装器明确要求时才提升权限，不为WebAgent默认开放管理员权限。

```bat
winget install --id Cloudflare.cloudflared
```

或：

```bat
winget install Ngrok.Ngrok
```

更改PATH后保存工作并**完全退出并重开 VS Code**，再建集成CMD核对`check-env.cmd`；只新建终端可能仍继承旧父进程PATH。独立CMD用户重新打开CMD即可。已有Conda环境按原方式激活。

winget不可用时从官方发布页面下载适合Windows架构的二进制：

- Cloudflare：https://github.com/cloudflare/cloudflared/releases
- ngrok：https://ngrok.com/download

将程序放入自己管理的工具目录，不建议为此写入System32。下载/版本/签名要在本机核对，本文没有替用户执行安装。可在**启动主机的同一CMD**指定完整路径，例如：

```bat
set "CLOUDFLARED_PATH=C:\Tools\cloudflared.exe"
set "NGROK_PATH=C:\Tools\ngrok.exe"
```

只需设置所选项。check-env只看PATH，可能仍报未找到，但主机支持这些显式路径及部分常见目录；存在文件也不保证它是可运行且可信的正确版本。不要使用npm的ngrok包装包代替二进制。

本机回环服务加出站隧道不要求把工作台改成0.0.0.0，也不应为连通性盲目放开公共网络入站防火墙。

## 3. Quick Tunnel

1. 保持Cloudflare Quick Tunnel选项。
2. 点启动Bridge，默认等待就绪约25秒。
3. 只有成功且公网URL显示后再复制；正常形如`https://随机词.trycloudflare.com/mcp/密钥`。

产品自动执行，用户不必另开CMD重复：

```text
cloudflared tunnel --url http://127.0.0.1:48271 --no-autoupdate
```

地址来自进程日志。出现URL不是DNS/公网端到端可达证明；仍须连接MCP并实际调用。重启后始终核对新地址，不承诺域名永不复用，也不把停止隧道视为轮换MCP密钥。

## 4. Named Tunnel

先在Cloudflare控制台创建Cloudflared隧道，界面菜单可能调整，查找Zero Trust / Networks / Tunnels / Public Hostname：

1. 选自己的账号和域名，创建隧道。
2. 取得Tunnel Token，直接放入本机Bridge密码框，不贴聊天/Issue、不保存无保护的临时记事本。
3. 在Public Hostname设置子域，例如mcp.example.com；类型HTTP，目标为本机实际MCP端口，例如`http://127.0.0.1:48271`。若表单将协议与地址分开，按实际字段填，不重复协议。
4. 本机选择Named，填主机名与Token后启动。

程序规范域名大小写、去协议/路径/数字端口；请直接填主机名避免误会。它不会替你创建DNS记录或修改Cloudflare路由。源码实际命令是：

```text
cloudflared tunnel --no-autoupdate run --token <Tunnel Token>
```

Registered tunnel connection/connIndex日志触发就绪并发布你填的域名，不是对该域名作HTTP探测。缺域名/Token或失败不会自动降级Quick。改AGENT_HOST_PORT须同时修改Cloudflare远端映射。

Token保存于当前工作区`.webagent/config.json`；主机状态不返回配置中的Token原文。cloudflared的Token仍在命令行参数中，有本机进程查看权限的人可能看见。日志对每个stdout/stderr流跨chunk遮盖连续完整Token；末尾可能的Token前缀不输出，编码变形或其它秘密不保证隐藏，勿公开原始日志或进程信息。详情见[安全说明](../../SECURITY.md)。

## 5. ngrok

在ngrok控制台取得Authtoken，选择ngrok后填入密码框；域名可空，也可填自己有权使用的域名。免费/预留域名规则由账号当前套餐决定，不在产品内保证。

Token优先来自本次非空输入，其次保存的工作区配置，再由启动器读取NGROK_AUTHTOKEN。仅写入ngrok自身配置不足以满足产品的显式Token检查；无需额外运行`ngrok config add-authtoken`。若有意使用环境变量，在主机启动前设置，不公开终端记录。

自动执行的命令为：

```text
ngrok http 127.0.0.1:48271 --log=stdout --log-format=term
```

指定域名时追加`--url https://域名`。Authtoken放子进程环境，不放这条命令argv；仍可被有权限的本机进程查看，不是系统密钥库。就绪来源为日志URL/启动消息，不能据此代签账户配额、DNS、访问策略或公网请求成功。日志同样逐流处理跨chunk的完整Token，不是对任意秘密或编码变形的保证。

## 6. 连接、身份与项目核对

本机显示公网MCP地址后，通过Arena实际提供的MCP连接入口接入；若该界面支持连接提示词，可用工作台生成内容。**聊天里有链接不等于当前Agent已获得MCP工具。** 先确认会话列出WebAgent工具，再调用workspace_info核对绝对工作区/主机信息，按返回字段记录；不凭网页Agent自称“已连接”验收。

最终本机验收按用户安排，在剩余施工后选择web_agent项目根目录；先读取README.md与manager/CONTEXT.md、核对当前提交与未提交改动，再安排非破坏性检查。完整URL是凭据，应只交给授权的连接界面，不提交到仓库或报告。当前未接入本机工具的沙箱结果不是这项验收。

ChatGPT自制MCP客户端若使用OAuth，先在工作台BRIDGE区开启OAuth配对（默认关闭，关闭时OAuth地址404），服务器通常填规范`https://域名/mcp`而非带密钥地址，按实际客户端要求注册与本机配对；不保证任何聊天栏直接贴链接就能连接。OAuth状态仅在内存，主机重启需重新配对。持久登录与确切模型后台身份仍不在本次验收结论内。

## 7. 成功、失败和停止怎么判断

`POST /api/bridge/start`的HTTP200可能携带`success:false/running:false`与tunnelError/note，**不是成功**；鉴权/工作区/执行冲突还可能403/409。经典UI会显示具体原因并刷新状态；失败不复制fallback地址。没有公网地址时仅有本机MCP端口可用，不是3000工作台在替代公网MCP。

停止按钮等待服务器业务成功才刷新/灭灯；停止失败或响应丢失要核对主机与实际cloudflared/ngrok进程，不把界面字段清空当作退出证明。强杀主机、断网、关闭浏览器与正常停止不是同一保证；不要根据旧PID盲目强杀其他进程。

停止隧道不撤销Agent已读数据，也不回滚已执行修改；已返回execId的任务应按命令管理接口单独检查。作业结束停止Bridge，不让有修改能力的入口无人值守长挂。

## 8. 排障顺序

| 现象 | 核对步骤 |
|---|---|
| 刚安装但未找到程序 | 完整重启VSCode，核对实际PATH或显式EXE路径；文件存在不等于架构/版本可执行 |
| 25秒无地址 | 看具体tunnelError，检查本机网络/提供商限制；不自动切换其他服务或关闭TLS校验 |
| Named显示就绪却连接失败 | Public Hostname/DNS/端口/访问策略分别检查；注册日志不检查这些配置 |
| ngrok要求Token | 本次输入、工作区配置或启动环境是否有显式Token；账号权限另查，不公开Token |
| 停止失败或替换一直被拒 | 核对旧进程与服务日志，失败停止链可能继续阻止替换；不谎报已关闭或无限重试 |
| Agent工具列表没有WebAgent | 在实际客户端完成MCP接入，确认工具可用；不是多贴一次URL就一定能解决 |
| 工具工作区不对 | 停旧任务和Bridge，重启主机选择正确目录，IDE同步打开并刷新核对；不要在错误目录试写 |

隧道只映射MCP入口。公网请求访问/api或/ws受本机控制面限制；CORS不是认证，完整URL密钥需保管。允许Execute仍是同OS用户级代码执行信任，不保证命令“非破坏性”。
