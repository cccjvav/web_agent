# 插件一键启动实机验收（R6 第一期，逐步操作）

这份手册验收“VS Code 插件不依赖网页工作台”的第一期：**不开 CMD 窗口、不开浏览器，在 VS Code 侧栏点一次【启动】就能连 Arena；关闭 VS Code 后端口和 cloudflared 都释放**。它按你的环境写：**Windows 桌面 VS Code → 集成 CMD → 激活 Conda，Node.js 装在系统里**，工作区用 **web_agent 仓库根目录**，Arena 经 **Cloudflare Quick Tunnel** 连本机 MCP。网页工作台（`run-webagent.cmd`）不受影响，第 7 步专门验证两者并存。

**规则：** 每一步只记录真实结果之一：通过 / 失败 / 未执行。失败就停在那一步，把**步骤编号＋脱敏输出/截图**发给维护者，不要为了往下走而改设置或绕过提示。沙箱里的 CI 全绿不能代替这里任何一步。

**绝不外发：** 完整 MCP 地址（`https://…/mcp/一串密钥`）、`.webagent\config.json`、配对码、令牌。截图前先遮住。

## 本轮要验什么

| 改了什么 | 你在本机能看到的现象 | 步骤 |
|---|---|---|
| 安装脚本在插件目录写 `host.json`（仓库位置＋提交号） | 安装输出显示“来源提交”，与 `git rev-parse HEAD` 相同 | 3 |
| 插件自己启动主机（不开 3000 工作台） | 侧栏“主机”卡片【启动】→“运行中（由插件启动）”；3000 不监听 | 4 |
| 侧栏直接选隧道并开启 Bridge | MCP 卡片有隧道下拉框；Arena 能调用工具 | 5 |
| 关闭 VS Code 时主机和隧道一起退出 | 48271 不再监听，cloudflared 进程消失 | 6 |
| 侧栏【停止】 | Bridge 在运行时先确认；确认后端口与 cloudflared 释放 | 6 |
| 已有 `run-webagent.cmd` 主机时只接管 | 卡片显示“外部启动”；只有一个 48271；插件关闭不影响它 | 7 |

## 1. 停掉旧服务，更新到本轮代码

1. 若旧的 `run-webagent.cmd` 还在跑：先在工作台停止 Bridge，再在它的 CMD 窗口按 `Ctrl+C`，问“终止批处理操作吗”输入 `Y`。
2. **CMD-A 与 CMD-B 都执行**（`你的环境名`和路径换成自己的）：

```bat
conda activate 你的环境名
cd /d "你的web_agent完整路径"
```

3. **CMD-B** 检查有没有本地改动：

```bat
git status --short
git branch --show-current
```

`git status --short` **必须没有输出**。有输出就停下，把列表发给维护者；不要 stash、reset 或删除。

4. 取本轮分支并切换：

```bat
git fetch origin arena/01a0d084-web-agent
git switch arena/01a0d084-web-agent
git pull --ff-only
git rev-parse HEAD
git rev-parse origin/arena/01a0d084-web-agent
```

**预期：** 最后两行是同一串提交号，记到记录里。无法快进就停下报告。

## 2. 依赖与自动测试

**CMD-B：**

```bat
npm ci --include=dev --prefix webagent-core/agent-host
echo %ERRORLEVEL%
node docs-site/check-docs.js
echo %ERRORLEVEL%
npm test --prefix webagent-core/agent-host
echo %ERRORLEVEL%
```

每个 `echo` 紧跟上一条。**预期：** 三个退出码都是 `0`；最后汇总行形如 `113 test files passed`（文件数以你拉到的提交为准，本手册编写时为 113），把实际数字写进记录。其中 `hostLaunch.test.js` 会在你的 Windows 上真实启动、接管、停止一个主机，并验证 `taskkill` 结束进程树。任何一步非 0 就停，保留原始报错。

## 3. 安装插件并核对 host.json

1. **CMD-B：**

```bat
install-vscode-extension.cmd
```

**预期：** 输出含“已安装 Web Agent 插件”、`来源提交 <40位提交号>`、`主机位置 <你的web_agent完整路径>`，下一步说明里写“侧栏‘主机’卡片点【启动】”。来源提交必须等于第 1 步 `git rev-parse HEAD`。

2. 查看写入的文件（版本号以安装输出里的目录为准）：

```bat
type "%USERPROFILE%\.vscode\extensions\webagent.webagent-core-0.7.2\host.json"
```

**预期：** 有 `"format": 1`、`"root"`（仓库路径）、`"commit"`（同上）、`"contentHash"`。

3. **完全退出 VS Code**（文件 → 退出），再从开始菜单打开 VS Code，用“文件 → 打开文件夹”打开**仓库根**并信任。

> 插件用 PATH 里的 `node` 启动主机，和 VS Code 进程继承的环境相同，不经过 Conda。你的 Node 装在系统里，一般不用设置。若第 4 步提示找不到 Node，在**用户设置**搜 `webagent.nodePath`，填 CMD 里 `where node` 显示的完整路径。

## 4. 一键启动（不开 CMD、不开浏览器）

1. 先确认没有旧主机。VS Code 里新建集成 CMD（**CMD-B**，激活 Conda 并进入仓库根），执行：

```bat
netstat -ano | findstr ":48271 "
netstat -ano | findstr ":3000 "
```

**预期：** 两条都没有 `LISTENING` 行（有的话回第 1 步停掉旧服务；不要按进程名批量结束）。

2. **预期：** 右下角状态栏显示 **`Web Agent 未启动`**（▷图标）。
3. 点活动栏 **Web Agent** 图标。侧栏顶部有“主机”卡片，显示“未启动”，有【启动】【停止】【日志】和“启动主机后同时开启 Bridge”复选框（**先不要勾**）。
4. 点【启动】。

**预期：** 卡片先显示“启动中…”，几秒到一两分钟后变成 **“运行中（由插件启动）”** 并显示 `http://127.0.0.1:48271`；状态栏变成 `Web Agent`。点【日志】打开输出面板“Web Agent Host”，应看到 `[host] 主机已就绪：http://127.0.0.1:48271（工作区 你的仓库路径）`。卡片上**不应**有“主机仓库已是提交 …，而插件是从 … 安装的”的提示。

5. **CMD-B** 再查端口：

```bat
netstat -ano | findstr ":48271 "
netstat -ano | findstr ":3000 "
```

**预期：** 48271 有一行 `LISTENING`，**记下最后一列的 PID**；3000 **没有** `LISTENING`（插件启动的主机不开网页工作台）。

6. 可选：Chat 里输入 `@webagent /ask 仓库根目录有哪些文件？`，能正常回答即通过（需要已配置模型；没配置记“未执行”）。

## 5. 在侧栏开启 Bridge 并连 Arena

1. 侧栏 MCP 卡片里有**隧道**下拉框，选 **Cloudflare Quick Tunnel**，点该卡片的【启动 Bridge】。
2. **预期：** 状态变为运行中，出现 `https://….trycloudflare.com/mcp/…` 地址；状态栏变为 `Web Agent Bridge 运行中`。
3. **CMD-B** 记录 cloudflared：

```bat
tasklist /fi "imagename eq cloudflared.exe"
```

**预期：** 至少一行 `cloudflared.exe`，记下 PID（若你本机另有自己的 cloudflared 服务，也记下它的 PID，后面只看新增的那个）。

4. 侧栏点【复制提示词】，到 Arena 按之前的方式连接，让它调用一次读取工具（例如“列出仓库根目录”）。**预期：** Arena 拿到真实目录列表；侧栏工具日志出现这次调用。

## 6. 关闭 VS Code 与【停止】按钮

**6.1 关闭 VS Code 释放端口与隧道**

1. **文件 → 退出**，完全关闭 VS Code（集成终端会一起关，所以下面用独立 CMD）。
2. `Win+R` → 输入 `cmd` → 回车，打开独立 CMD，**等 15 秒**后执行：

```bat
netstat -ano | findstr ":48271 "
tasklist /fi "imagename eq cloudflared.exe"
tasklist /fi "pid eq 第4步记下的PID"
```

**预期：** 第一条没有 `LISTENING`；第二条不再有第 5 步那个 cloudflared（显示“没有运行的任务匹配指定标准”，或只剩你自己原有的那个 PID）；第三条显示“没有运行的任务”。有残留就**不要手动结束**，把三条输出发给维护者。

3. 可选：Arena 里再调用一次工具，应当失败（主机已退出）。

**6.2 侧栏【停止】**

1. 重新打开 VS Code 和仓库根，侧栏点【启动】等到“运行中（由插件启动）”，再在 MCP 卡片开启 Bridge。
2. 点主机卡片的【停止】。**预期：** 弹出模态确认“停止主机会同时停止 Bridge 隧道和正在运行的命令，Arena 等远程连接会断开。确定停止？”；点【停止】后卡片回到“未启动”，状态栏回到 `Web Agent 未启动`。
3. **CMD-B** 执行 6.1 第 2 步前两条命令，预期相同。

## 7. 与网页工作台并存：先 CMD、后插件时只接管

1. VS Code 保持打开仓库根，主机处于“未启动”。**CMD-A：**

```bat
set WORKSPACE_ROOT=
run-webagent.cmd
```

等窗口出现 `MCP` 与 `48271`。

2. `Ctrl+Shift+P` → `Developer: Reload Window`（或直接点侧栏【启动】）。
3. **预期：** 主机卡片显示 **“已连接（外部启动，插件不会关闭它）”**，【启动】【停止】都不可点；【日志】里有 `[host] 已连接 http://127.0.0.1:48271 上服务此文件夹的主机` 或 `已有主机在 … 服务此文件夹`。
4. 重载后 CMD 会重开，**新的 CMD-B**（激活 Conda、进入仓库根）执行：

```bat
netstat -ano | findstr ":4827"
```

**预期：** 只有 48271 一个 `LISTENING`，**没有** 48272 等其他端口（没有启动第二个主机）。

5. `Ctrl+Shift+P` → `Web Agent: 停止主机`。**预期：** 提示“这个主机不是插件启动的（例如由 run-webagent.cmd 启动），插件不会关闭它；请在启动它的窗口按 Ctrl+C。”，CMD-A 窗口里的主机继续运行；浏览器打开 `http://127.0.0.1:3000` 仍是正常的网页工作台。
6. **文件 → 退出** VS Code。**预期：** CMD-A 窗口里的主机仍在运行（没有退出提示，浏览器刷新仍正常）。
7. 收尾：在 CMD-A 窗口按 `Ctrl+C`，输入 `Y`。

> 顺序反过来（插件已启动主机后再运行 `run-webagent.cmd`）会因 48271 被占用而失败，这是预期行为：要用网页工作台，先在侧栏【停止】。

## 8. 可选项

- **自动启动：** 用户设置勾选 `webagent.autoStartHost`，重载窗口。**预期：** 主机自动启动，Bridge **不会**自动开启。验完取消勾选。
- **“启动主机后同时开启 Bridge”：** 勾选后【停止】再【启动】。**预期：** 主机就绪后自动开启 Bridge，隧道类型是**上一次开启 Bridge 时用的那种**（主机记录的，第 5 步用的是 Quick Tunnel），不是下拉框里临时改过但没用过的选项。验完取消勾选。
- **重载窗口：** 插件启动主机后执行 `Developer: Reload Window`。**预期：** 主机随旧窗口停止（输出面板有 `[lifeline]`），重载后卡片显示“未启动”，需再点【启动】（开了 `webagent.autoStartHost` 时会自动启动）。
- **失败提示：** 用户设置把 `webagent.nodePath` 填成 `C:\nope\node.exe`，点【启动】。**预期：** 卡片显示“启动失败”，原因里提到找不到 Node 和 `webagent.nodePath`。验完清空该设置。

## 验证范围与限制

本手册验证第一期的两条完成标准。它不验证第二期的“Web Agent 设置”页（模型、Named Tunnel 域名等仍在网页工作台里配置），也不验证安装版（LocalAppData）的一键启动。使用 Named Tunnel 且 Cloudflare 后台入口写死 48271 时，确保插件主机拿到 48271（卡片会显示实际端口，被占用时有提示）。
