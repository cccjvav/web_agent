## 12. 重载窗口后的主机提示（跟进④）

**12.1 插件启动的主机随重载停止后，新窗口有说明**

1. 确认侧栏主机卡片是“运行中（由插件启动）”，且就是第 5 步启动的那个（PID 为 P1；中途重启过就用 `netstat -ano | findstr ":48271 "` 重新记下 P1）。Bridge 处于停止状态。
2. `Ctrl+Shift+P` → `Developer: Reload Window`。
3. 重载后**等 15 秒**（插件在窗口打开约 10 秒后才检查，给旧主机留出关闭时间），点侧栏主机卡片的【日志】。

**预期：** 卡片显示“未启动”；输出面板“Web Agent Host”里有一行：

```text
[host] 上次由插件在此文件夹启动的主机（http://127.0.0.1:48271，pid P1，启动于 …）已不在运行。插件启动的主机会随启动它的窗口关闭或重载而停止；停止时的[lifeline]记录写在那个窗口的输出面板里，这里看不到。需要时点侧栏【启动】。
```

其中 pid 与 P1 相同。没有这一行、pid 不同或卡片显示“已连接”都记失败，附上输出面板全部内容。

**12.2 用【停止】停掉的主机，重载后不提示**

1. 点【启动】，等到“运行中（由插件启动）”；再点【停止】，等卡片回到“未启动”、结果行显示“主机已停止”。
2. `Developer: Reload Window`，等 15 秒，点【日志】。**预期：** 输出面板里**没有**“上次由插件在此文件夹启动的主机”这一行。

## 13. 关闭 VS Code 时 stdio 程序一起退出

1. 侧栏点【启动】等到运行中；点齿轮打开设置页 → 工具接入与审批，照 9.2 第 2–5 小步再预览并启动一次夹具（确认框点【确认】）。
2. **CMD-B** 执行 `type .cache\stdio-accept\stdio-started.json`，**记下 pid（记作 P3）**。
3. **文件 → 退出** VS Code。在 **CMD-A** 等 15 秒后执行：

```bat
netstat -ano | findstr ":48271 "
tasklist /fi "pid eq P3"
```

**预期：** 第一条没有 `LISTENING`；第二条“没有运行的任务匹配指定标准”。有残留**不要手动结束**，把两条输出发给维护者。

## 14. 收尾与可选项

**收尾（必做）：** 重新打开 VS Code 和仓库根，【启动】主机，设置页 **技术栈** 把“测试命令”恢复成第 7 步抄下的内容（原来是空的就清空），点【保存】。然后 **CMD-B：**

```bat
rmdir /s /q .cache\stdio-accept
git status --short
```

**预期：** `git status --short` 没有输出。

**可选：**

- **API Provider：** 有可用的 Endpoint 与 Key 时，在 API Provider 页填入后点【Test】。**预期：** 显示读取到的模型列表。不要点 Add API，除非你本来就想配置模型（配置后 Chat 改走模型，第 11 步的现象就不再适用）。
- **启动中也能停止：** 主机“未启动”时点【启动】，在显示“启动中…”期间立刻点【停止】。**预期：** 【停止】可点；卡片回到“未启动”，结果行说明已取消本次启动或主机已停止。
- **高对比度主题：** 切到 High Contrast，标签页可读、按钮边框清楚。验完切回。

## 验证范围与限制

本手册验证第二期设置标签页、外部 MCP 迁入与第一期验收的四项跟进。不验证：多模型博弈（D4，仍在网页工作台）；HTTP 方式登记真实的本机或公网 MCP 服务（9.1 只验确认框，自动测试覆盖真实登记）；Named Tunnel / ngrok（需要你的域名或 Token，流程与第一期相同）；安装版（LocalAppData）。标签页只在主机由插件启动或接管时可用；手工设置了 `webagent.agentHostUrl` 时，主机是否服务当前文件夹由你负责。
