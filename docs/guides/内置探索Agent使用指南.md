# 内置探索 Agent 使用指南（新手版）

## 1. 它是什么，先别把它当大模型

把它理解成一个**按固定清单检查项目的小助手**：列文件、看 Git 状态、找关键词、读文件，再整理结果。它不需要 API Key，也不需要开启 Bridge 或隧道；但本机 agent-host 必须已启动。

它不是本地部署的 ChatGPT，也不会因为你装了 Skill 就理解任意复杂任务。它不能凭一句“修好整个项目”可靠地生成修复方案。项目里的这个功能与正在 Arena 对话中帮助你修改仓库的 Agent 不是同一个东西。

## 2. 在哪里找：两种界面不要混淆

### 自绘工作台（源码新手入口 run-webagent.cmd）

1. 沿用你已经完成的 Windows + Conda 启动流程，不必重装环境，也不要同时启动另一个占用相同端口的工作台。
2. 查看当前工作区路径，确认指向你要检查的项目。
3. 在右侧 Chat 的模型按钮里选择 **内置探索 Agent**。
4. 模式选择 **Ask**。模型选择和模式选择是两件事。
5. 按下面的例子发送消息。顶部 **帮助(H)** → “内置探索 Agent：第一次使用”也有操作步骤。

### VS Code / code-server 的 Web Agent 扩展面板

打开 Web Agent 的 Chat 面板，顶部展开 **内置探索 Agent 使用帮助**。在 Agent 菜单切到 **Web Agent Ask**；该扩展面板没有自绘工作台那样的独立模型选择器，使用所连接 agent-host 当前选择的模型（初始默认 builtin）。**切到 Ask 不等于切换成内置模型**，已配置并选中远程模型时仍可能走远程模型。

VS Code 自带 Chat、其他 AI 扩展和 Web Agent Chat 不是同一入口。若看不到新增帮助，先更新本分支并重启对应服务/重新加载扩展；不要把“我打开了 VS Code”当成已启动或更新 agent-host。环境步骤见 [Windows新手逐步验收](Windows新手逐步验收.md)。

## 3. 第一次照着做：只读，不改文件

先确认工作区根下确实有 README.md，然后选择内置模型与 Ask，发送：

```text
读取 `README.md`
```

正常应看到列目录、Git 状态、查找/搜索及 Read 工具卡；展开 Read 核对路径、正文和错误。回答会引用读取证据。**明确指定文件只限制正文读取的候选，仍会扫描目录、查看 Git 状态和搜索。**

想看实现文件时发送（路径换成你项目里真实存在的文件）：

```text
读取 `src/app.js`
```

在本 Web Agent 仓库可发送：

```text
读取 `webagent-core/agent-host/src/agent/runChat.js`
```

中文或带空格的文件名请用反引号包住，并写相对工作区的路径。一次最多识别六个文件，正文读取每文件最多120行；最终回答摘录还会进一步截短。**读到开头不等于读完整个文件，更不等于审完项目。**

试着读取一个不存在的文件：

```text
读取 `not-existing-demo.txt`
```

应说明“未读取”，而不是编造正文。如果工作区不是Git仓库或未安装Git，git_status正常返回available:false；其它Git错误仍可能报错，都不表示普通文件一定不能读取。

## 4. Ask、Plan、Code 怎么选

| 模式 | 内置模式下的实际行为 | 新手建议 |
|---|---|---|
| Ask | 固定扫描、搜索、读取、整理；不写项目文件、不执行测试命令；会更新进程内待办等状态 | 先用这个 |
| Plan | 根据本机读取事实生成规则式草案/分支 | 不是多个真实模型独立推理，也不保证计划正确 |
| Code | 可识别明确的写入代码块、SEARCH/REPLACE补丁；探测到测试命令时可执行 | 会产生实际修改/命令副作用，不当只读模式用 |

本机 Code 不等同于第三方 MCP 的“逐次审批队列”。写入格式可能覆盖现有文件，补丁不要省略目标文件，不建议新手拿正式文件练习。先使用 Git 或副本备份，并检查实际 diff；停止/取消不等于撤销已经写下的内容。

测试命令来自技术栈声明，或存在 tests 目录时按包管理器猜测；它不会深入理解所有项目。**显示命令不等于命令有效，没执行更不等于测试通过。**本仓库根package.json已提供转发：`npm test`即运行agent-host测试，也可显式用`npm test --prefix webagent-core/agent-host`；筛选可用`npm test -- --filter=文件名子串`。先安装该包开发依赖；计算器示例是另一个入口，不代替产品测试。维护环境仍使用桌面 VS Code 集成 CMD + Conda。

## 5. 为什么它的回答像模板？什么时候用真模型？

这是设计限制，不是少填了某个隐藏 API Key。需要解释复杂业务、推导修改方案、按自然语言编程时，在 API Provider 配置真实模型，再明确选择那个模型。远程模型可能接收读取的项目内容；不要向不信任的服务发送秘密。模型失败会明确停止，不自动换模型重放修改。

Skill 是给模型看的作业说明书，不是“给内置探索器安装大脑”；详见 [技能使用指南](技能使用指南.md)。Bridge 是让外部网页 AI 通过认证访问本机工具的连接通道，也不是内置探索器的启动开关。

## 6. 看不懂结果时按这个顺序检查

- 没模型选项/没新帮助：是否更新了当前分支？是否还开着旧服务、旧扩展或另一种界面？
- 文件读错：回答的工作区路径是否正确？路径是否相对这个工作区？
- 内容不全：先看 Read 工具结果；本功能有截断上限，不能要求它自动把所有文件读完。
- Code 没修复：自然语言愿望不等于明确补丁；检查工具是否失败、测试命令是否真实存在，不以待办勾选代替证据。
- 没有 Bridge 调用计数：本机 Chat 与远程 MCP 调用是不同链路，不能拿 Bridge 计数判断本机 Chat 是否读过文件。

## 7. 想看代码怎么配合

`models/store.js`登记builtin选项 → `agent/runChat.js`分流内置/真实模型 → `runBuiltin`与`explore`安排固定工具步骤 → `tools/index.js`按模式执行 → `timedTool`把成功/失败传回界面 → `summarizeAsk`整理摘录。

这些路径都在 `webagent-core/agent-host/src/` 下。细读见 [Agent执行链路说明](../../webagent-core/agent-host/src/agent/README.md)；想知道近期增强了什么，见 [借鉴优化说明（新手版）](../development/借鉴优化说明（新手版）.md)。
