# Bridge 工具统计与刷新排查（新手版）

## 1. 哪些操作应该清零？

| 操作 | “本轮外部工具调用”的预期 |
|---|---|
| 只按浏览器F5刷新 | 不清零；重新读取同一个主机进程的统计 |
| WebSocket断开/事件流重连 | 不清零；每3秒HTTP同步仍可恢复 |
| 统计接口暂时失败 | 显示同步失败；本页已经取得的数字保留，尚未取得则显示“—”，不能冒充0 |
| 关闭CMD中的主机，再运行run-webagent.cmd | 新主机进程，内存统计重新开始，hostInstanceId变化 |
| 点击Clear log/清除本轮 | 清MCP展示/HTTP会话、重置计数/摘要及读取hash缓存，客户端可能需重新initialize；主机ID不变，本轮起点/原因更新 |
| 停止/重新开启Bridge隧道但主机未退出 | 本身不清除本轮统计 |

“本轮外部工具调用”统计已完成的Bridge-Remote工具调用，包括成功/失败；不是当前正在执行的请求数，也不是活跃连接数。只聊天、发现工具或调用别的服务，不会增加本机工具计数。

## 2. 原反馈、修复与已确认结果

用户反馈：重新运行 `run-webagent.cmd "%USERPROFILE%\WebAgent-acceptance-beginner"` 后，外部AI调用计数增加，但刷新页面后消失。这个反馈已记录，**不能仅凭它断定你重启了服务，也不能拿以前的浏览器测试通过否定现场现象**。

源码检查确认了几处显示问题：Bridge摘要把完成调用误称为“活动请求”，而且只随一般状态请求更新；一般状态响应还会覆盖统计同步说明；首次加载直接显示0，无法区分未获取与真实清零。本轮统一摘要与计数的数据来源，保留统计同步说明，未获取显示“—”，增加明确的主机启动/本轮起点信息及手动重新同步按钮。HTTP统计请求显式禁用缓存；无效快照报错而不是静默接受。未增加浏览器持久计数或跨重启日志存储。

这些显示缺陷已有修复。**用户在2026-09-15已确认：刷新后外部工具计数与记录都保留，此项复验通过**（见[人工清单](../../review/CHECKLIST_WINDOWS.md)的该日记录）。以下步骤用于未来再次出现异常时排查，不把已确认项永久列为待复验；也不扩大为所有窗口/客户端/生命周期已验。

## 3. 再次异常时的复验顺序，不用重装Conda

1. 在产品源码目录确认使用当前分支/最新代码。若原服务还在运行，先在它的CMD按Ctrl+C结束；这一次结束本来就会丢掉旧进程的本轮统计。
2. 在桌面VS Code集成CMD、原Conda环境中运行：

   ```cmd
   run-webagent.cmd "%USERPROFILE%\WebAgent-acceptance-beginner"
   ```

   保持这个CMD运行。使用它实际打印的UI地址，不同时开启第二份占相同端口的工作台。
3. 打开右侧Bridge页，外部AI完成一次本机工具调用。记下“本轮外部工具调用”、主机ID、启动时间、本轮起点；无需记录或公开MCP密钥。
4. **只在浏览器按F5**，不要重跑启动命令。统计同步成功后，数字和对应日志应恢复；期间可能先显示“—”。
5. 若显示同步失败，点“重新同步统计（不清零）”。如果仍失败，保留错误说明；不要为了试一试而点Clear log。
6. 对比主机ID和本轮起点：ID改变说明不是同一个主机进程；ID相同但起点原因是“操作者清除本轮”，说明服务端发生了明确重置；身份和起点都相同仍少计数，则需要继续排查。

## 4. 仍异常时，如何区分服务端与页面问题？

在同一浏览器打开当前UI地址下的 `/api/bridge/activity`。例如默认UI为 `http://127.0.0.1:3000` 时，地址是：

```text
http://127.0.0.1:3000/api/bridge/activity
```

这里只在你的本机打开，不需要把管理面暴露公网。

- `stats.calls`仍有数字，而页面没有：倾向页面显示/同步问题。
- `epoch`或`identity.hostInstanceId`变化：主机进程换了。
- `resetReason`为`operator-cleared`：本轮被明确清除。
- 返回错误页面/404/无法连接：核对是否旧服务、另一个端口/入口，记录HTTP状态；不要按无效JSON当作0。

反馈时只需提供刷新前后计数、主机ID是否相同、起点是否变化，以及页面错误文字。截图遮挡公网MCP地址、令牌、账户与不想公开的本机路径，不必贴完整接口JSON。

## 5. 不要把两种统计混为一谈

- **本轮外部工具调用**：主机内存中的本轮完成数与最多100条完成摘要，刷新可恢复，重启不保留。
- 设置里的**今日Bridge工具调用**：现有 `.webagent/usage.json` 用量汇总，按UTC日期分日，随一般状态刷新；不是本轮实时计数，也不是逐条日志备份。

这次没有改变用量上报、持久登录或日志保留策略。源码见 `src/utils/eventBus.js`、`src/usage/tracker.js`（均位于agent-host），页面同步见 `webagent-core/workbench/js/bridge.js`。回归覆盖刷新、统计暂时失败、手动/自动恢复、主机快照未被刷新重置，以及明确清除。
