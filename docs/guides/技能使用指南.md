# Skills 使用指南（Windows + CMD）

Skill 是放在**当前工作区**里的一篇作业指导书。模型（本机 Chat 或网页 Agent；两种执行模式互斥）先看到**目录**，任务对得上再调用工具 `load_skill` 分段读取正文。不是插件市场，也不会开机把所有 SKILL.md 塞进每一轮对话。

按键总流程仍以 [使用指南.md](../../使用指南.md) 为准。本文件只把「放哪、怎么建、怎么被读到、挂自己仓库时要注意什么」写细。

---

## 查看、续读与安全使用

1. 齿轮 → 智能体自定义设置 → 技能，按名称、用途或来源搜索；“重新扫描”立即读盘，不必重启。
2. 点击“查看正文与资源”。页面显示来源ID、SHA256、已读字符范围；长文本点“读取下一页”。内容改变后旧hash续读失败，需要重新选择目录项。
3. 引用文件与脚本点对应资源按钮，只读显示源码。不会因为存在`run.py`、`run.sh`、`index.js`就执行。
4. “填入Ask对话”保留原草稿、补入明确Skill ID和授权限制，**不自动发送**。你检查后再发；默认先只读理解，不把Skill里的命令当你已经批准。
5. 可选：Skill含`workflow.json`时，完整读取后可点“转到工作流预览”。只复制到已有受控工作流页并校验，不执行。后续必须另点提交、核对完整参数、批准一次；原有无命令/无重试/失败停止限制不变。任意第三方manifest不是这种工作流。

### 模型或外部AI如何按需加载

下面是工具参数示例，不是在CMD执行的命令：

```json
{"name":"workspace:evidence-check"}
```

若返回nextOffset不为null，把它及返回的hash原样用于下一次：

```json
{"name":"workspace:evidence-check","offset":8000,"expectedHash":"替换为上一页返回的完整hash"}
```

8000只是示例，实际以nextOffset为准。只有需要引用时再读：

```json
{"name":"workspace:evidence-check","resource":"references/checklist.md"}
```

目录不传name，用`cursor`/`pageSize`分页。不要把全部Skill/脚本内容放进每轮上下文。Skill文字属于参考数据，不能覆盖用户要求、Ask/Plan限制、本机审批或敏感文件规则。

### 自带的完整示例包

源码的`.webagent/skills/evidence-check/`包含SKILL.md、references/checklist.md、workflow.json，用于主机身份和任务证据检查。它随源码根工作区提供，**不会自动复制到你另选的验收/业务工作区**。

如需使用，先在资源管理器中审阅这三个文件，再把整个evidence-check文件夹复制到你的验收工作区`.webagent/skills/`下（已有同名目录先停，不覆盖）。刷新技能目录后应看到`workspace:evidence-check`。这不是安装Python、下载第三方依赖或执行脚本。

### 分类目录和同名处理

支持两个工作区根下面最多3层目录，例如`skills/vendor/skills/review/SKILL.md`；只有SKILL.md才是技能标记，assets/hooks/scripts等普通目录不会仅因名字被列成技能。一次扫描最多512目录条目、128个工作区Skill，另加3个内置Skill；达到上限会明确提示目录不完整。

`shared:`只是当前工作区`skills/`目录的来源名，不是跨项目共享目录。同名项全部显示，可按ID明确选择；旧短名仍依次偏向`.webagent/skills`、`skills`、内置。自建同名computer-use不会继承内置脚本目录提示。

## 1. 它是什么、不是什么

| | 说明 |
|---|---|
| 是 | 文件夹 + 一份 `SKILL.md`（步骤、何时使用） |
| 属于 | **正在改的那个工作区**（启动窗口打印的 `Workspace`），不是 Web Agent 程序自己 |
| 谁会用 | 本机右侧 Chat **和** Bridge 过来的网页 Agent，同一套 `load_skill` |
| 不是 | 自动跑的脚本、插件、挂钩。挂钩页保存的命令**不会**执行 |
| 和「指令」的区别 | `.webagent\instructions.md` **每次**都拼进系统说明。Skill 是可选的长流程，避免把所有指导书塞进每一轮 |

源码扫工作区两个根目录，且必须是「目录里有 `SKILL.md`」：

```text
<工作区>\.webagent\skills\<名字>\SKILL.md
<工作区>\skills\<名字>\SKILL.md
```

另外固定扫仓库根的 `computer-use/`、`project-manager/`、`multi-agent-board/`（见后文对应技能小节）。目录提供来源限定ID（例如 `workspace:fix-tests`、`shared:vendor/skills/review`、`bundled:computer-use`）。推荐按ID读取；旧名字仍兼容，按工作区优先选择，**不能**填 `D:\skills\release` 这种任意盘符路径（不会按任意绝对路径加载）。工作台曾经写过「不必拷进工作区」——对普通 Skill **源码做不到**，以本页为准。

---

普通Skill必须实际位于工作区内；指向外部目录的symlink/junction不会列出。`SKILL.md`需为普通文件且不超过**128 KiB**；超限目录项显示原因，加载拒绝。现在每页默认/最多8000个JS字符串字符（UTF16索引），用`nextOffset`与上一页的`hash`续读；版本改变会拒绝续页，避免混入两版说明。资源同样有128KiB上限，必须是UTF8文本，不加载二进制。长流程应拆到references，通过load_skill读取脚本只得到源码；执行需另走已授权工具。

## 2. 先确认工作区

黑色窗口要一直开着。CMD 在仓库根：

```bat
cd /d D:\code\web_agent
run-webagent.cmd
```

源码根工作区的`.webagent/skills`已有 `fix-tests`、`review`、`docs-sync`、`commit-now`、`evidence-check`。实际目录以load_skill目录结果为准，不代表它们都适合每个任务。

挂自己的项目：

```bat
run-webagent.cmd D:\code\my-app
```

看窗口里的 `Workspace` 行。普通Skill扫描的是**这一行那个目录**；三个bundled Skill是程序固定目录例外。演示区的 Skill **不会**自动拷到 `D:\code\my-app`。

浏览器打开 http://127.0.0.1:3000 。

## 3. 在工作台新建（推荐）

1. 左下角齿轮 → **智能体自定义设置** → 左侧 **技能**。
2. 三步：
   - **名称**：小写、连字符，只做一件事，例如 `fix-tests`。保存时非字母数字会变成 `-`，最长 40；后端允许ASCII字母大小写、数字、下划线和连字符，不负责强制小写。规范化可能重名，新建会拒绝已有同名SKILL.md。
   - **何时使用**：模型靠这段决定要不要 `load_skill`。写具体场景，不要只写「有用」。
   - **步骤**：Ask 只读；改文件必须 Code。写清用哪些工具（`search_files`、`read_files`、`apply_patch`、测试命令）。
3. 可点模板 **修测试 / 代码审查 / 发版**，再改几个字。
4. 点 **新建 Skill 文件夹**。后端成功才显示已创建；重名/权限/模式失败显示原因，网络丢失时显示创建状态未知，先核对目录、不自动重试。内部createOnly在主机写路径锁内拒绝同名；不隔离外部OS进程竞态。它是新建入口，不是同名覆盖编辑器。目标为：

   `<工作区>\.webagent\skills\<名称>\SKILL.md`

5. 当前没有Bridge任务且已切到Chat时，在右侧 CHAT 说：`按 fix-tests 做`（换成你起的名）。

Ask / Plan / Code 都能调 `load_skill`。真正打补丁、跑测试仍要 **Code**（网页 Bridge 默认就是 Code）。

## 4. 也可以自己建文件夹

在你实际选择的工作区根；如果验收本产品，就是web_agent仓库根，不存在必须使用的旧演示workspace目录：

```bat
cd /d D:\code\my-app
mkdir .webagent\skills\fix-tests
notepad .webagent\skills\fix-tests\SKILL.md
```

最少写成：

```markdown
---
name: fix-tests
description: 用户提到测试失败、红灯、回归时使用。
---

# Skill: fix-tests

## 何时使用

用户提到测试失败、红灯、回归时使用。

## 步骤

1. Ask：search_files / read_files，不要改文件。
2. Code：read_files 取 sha256，apply_patch 修失败用例。
3. 跑工作区声明的测试命令，确认通过。
```

保存后**不必重启** Web Agent。下一轮对话或下一次 `load_skill` 列表就会扫到。已经连上的网页 Agent 若还拿着旧的 `initialize.instructions`，新开一条对话或让它再 `load_skill`（不带 name）刷新目录。

也可以放在工作区根的 `skills\<名字>\SKILL.md`（没有 `.webagent` 那一层）。两处都会扫。

## 5. 模型实际怎么「载入」

1. 本机 Chat 拼系统提示、Bridge 的 `initialize.instructions`，都会带上 Skills **目录**：前20项的来源ID和用途描述（最多约80字），更多用目录分页，并写「任务匹配时再 `load_skill`」。
2. 用 `load_skill({ name: "workspace:fix-tests" })` 按页读取，每页默认/最多8000字符；按返回nextOffset续读并带expectedHash。不带name则返回目录页（默认20项），按nextCursor继续。列表和按名加载都会带 `skillFile`（相对工作区的 `SKILL.md`，bundled可出现../）和 `skillFileAbs`（绝对路径）；这些字段是定位信息，不授权任意read_files越界，方便对话里点名「按 computer-use 做」，不必背盘符。
3. 找不到会返回 `found: false` 和 `available` 来源ID列表，不会搜索任意工作区外目录；仅保留三个固定bundled来源。

所以：你把「何时使用」写清楚，模型才知道该不该打开哪一篇。只建空文件、或不在对话里提起，它可能不会调。

网页 Agent 和本机 Chat **同一套**。不必为 Bridge 再拷一份进「当前项目」——但必须已经在**这个工作区**里。挂 `my-app` 就要在 `my-app` 里建或拷。

## 6. 挂自己的仓库时怎么带上演示 Skill

仓库示例Skill在 `web_agent\.webagent\skills\`，不是自动共享库。先审查内容并确认目标没有同名文件夹；已有则停止，不能用整目录复制覆盖业务指导书。需要复制时换成实际路径，例如：

```bat
xcopy /E /I D:\code\web_agent\.webagent\skills D:\code\my-app\.webagent\skills
```

或只拷需要的：

```bat
mkdir D:\code\my-app\.webagent\skills\fix-tests
copy D:\code\web_agent\.webagent\skills\fix-tests\SKILL.md D:\code\my-app\.webagent\skills\fix-tests\
```

`docs-sync`、`commit-now` 是给**改 Web Agent 本仓库**用的约定，拷到业务项目里通常没意义。业务项目更常要 `fix-tests` / `review`，或自己写一篇。

`.webagent\skills\` 可以提交进 Git（`config.json` 不会，已 gitignore）。密钥文件不要提交。

## 7. 源码根提供的示例

位于默认源码根工作区里。发现ID由目录路径决定，SKILL.md的frontmatter.name不用于改名；推荐文本名称与目录一致方便阅读：

| 名字 | 何时用 |
|---|---|
| `fix-tests` | 测试失败、红灯、回归 |
| `review` | 审查、找风险、看 diff；默认只读 |
| `docs-sync` | 改了 Web Agent 功能必须同步改说明书 |
| `commit-now` | 本地获授权维护时测绿提交当前会话分支；不绕过Bridge对git push的限制 |
| `evidence-check` | 身份核对、引用与可选受控工作流示例 |

对话示例：`按 review 做，只读，不要打补丁`。

## 8. 故障排除

**设置页看不到刚建的 Skill**  
刷新工作台，或关设置页再打开。确认 `Workspace` 是你以为的目录。

**模型不调用 `load_skill`**  
「何时使用」写太空；或对话里没点名。直接说「先 `load_skill` 名为 fix-tests」。内置探索是固定工具流程，不解释任意Skill。可在技能页直接只读查看；若要按技能进行推理与工具规划，需要配置实际模型或让已连接的外部AI调用load_skill。模型也可能不遵从说明，必须看真实工具与结果。

**`load_skill` 说 Unknown / available 为空**  
文件夹不在当前工作区那两个根下，或缺少 `SKILL.md`，或只填了嵌套目录的basename而未用完整来源ID；frontmatter.name不控制发现。不能用盘符绝对路径。

**挂了 `D:\code\my-app` 却在用演示区的 Skill**  
共用 Skill 位于源码根的 `.webagent/skills`。按第 6 节拷过去，或在设置里新建。

**网页 Agent 还按旧目录行事**  
隧道重启后重新核对地址；即使地址没变，旧对话也可能缓存initialize。先调用load_skill不带name刷新目录，必要时重连。

**想放在 `%APPDATA%` 或 `D:\skills` 给所有仓库共用**  
源码没有用户级 Skill 库。现在只能每个工作区放一份，或自己拷。

## 内置 skill：multi-agent-board（第六阶段）
Bridge 可同时连多个网页 AI（MCP 复用）。该 skill 教进场者互知与分工：peers_list 看在场者、board_list 看临时任务表、board_claim 先认领再动手、board_update 留进度注记/改状态（owner 专属）。**是分配不是协作**；板子 `.webagent/board.json` 只存任务元数据，禁写密钥。详见 `multi-agent-board/SKILL.md`。

## 10. 内置computer-use与桌面能力

`bundled:computer-use`来自产品固定目录，不要求复制到每个业务工作区。读取它只取得说明、scriptsDir和runHint，不会截图、下载或执行脚本；同名workspace Skill不会继承这些内置提示。旧版第三方产品对比不是当前兼容性证据，本文只说明本仓库。

在已授权Code执行中，Windows既有脚本snap.ps1/act.ps1/mark.ps1承担截图、键鼠等动作。推荐把输出放在工作区独立shots目录。脚本文件路径由load_skill返回，不要猜另一台机器的盘符或用陌生ZIP覆盖安装目录。

| 路径 | 作用与边界 |
|---|---|
| 本机Chat | 命令/输出中候选PNG/JPEG通过路径和6MiB预算检查后，可在下一轮作为image_url给标记vision的模型；不是OCR，也不保证候选是刚生成的新图片 |
| Bridge MCP | 既有命令回图以image内容附在tools/call文本之后；受主人Capture及Execute等策略，不是匿名访问域名就能取桌面 |
| 文件路径 | 普通文件工具约束在工作区；截图读取额外保留固定computer-use目录兼容例外，不等于任意盘符可读 |
| 任意Execute | 同OS用户级程序可自行读写/截图；危险命令拦截不是OS沙箱，不保证禁止所有副作用 |

用户已授权既有Bridge回图能力，授权记录不代表所有Windows版本/窗口/DPI测试都完成。截图可能包含第三方或个人信息，应先确认目标窗口；读取Skill本身不等于授权截图整台桌面。任务结束停止Bridge并核对后台状态。

桌面VSCode/code-server核心扩展的本机Chat可走受审批的集成终端，具体PTY/shell-integration可用性另测；无法可靠观察执行时拒绝，不把sendText当成功。远程MCP不开放交互式PTY，不能因Skill写了send_command_input就越过限制。经典命令执行与原生终端是两条不同路径。

## 11. 项目管家（交接）

项目管家规则全文在 `project-manager/SKILL.md`（副本 `manager/SKILL.md`）。索引是 `manager/CONTEXT.md`。

- 对话说 **`按 project-manager 做`** 或「项目管家，更新记录」
- 给人类用户仍用 `使用指南.md`
- 商店 **metadata 不是运行所需**；`load_skill`默认读`SKILL.md`，也可按需读该Skill内部文本资源；不安装商店运行时
- `manager/privacy.md` 已 gitignore，不要提交真实密钥
