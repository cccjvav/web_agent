# Skill: 文档同步

改代码或用户要求README/说明书时，先读仓库根的 `manager/docs/documentation.md`（唯一规范）。本文只保留操作流程，不复制规范；旧的强制手抄全量行号规则已被自动AST定位与关键逻辑解释取代。

1. 读取将改源码、同级README以及必要的上级架构文档。
2. 新目录先补README，说明职责、文件分工、执行流、错误/取消/安全边界及测试。根脚本归启动脚本说明；例外以documentation.config.json为准，不自行忽略文件。
3. 改正文时直接纠正旧契约，不在旧错误后仅追加补充。复杂函数解释关键分支，简单函数可合并，不杜撰未实现行为。
4. 从仓库根运行 `node docs-site/check-docs.js --write`，再运行 `node docs-site/build.js`；检查前者为0退出以及完整npm test。生成区块不是语义认证，需审查正文是否仍符合代码。
5. 更新阶段记录，说明本次语义审查范围、测试及未验收内容。不要求每次改动都更新重复的用户手册，设计理由变化才更新架构导读。

Ask/Plan仅阅读与提出计划，不落盘。Code按上述流程实施。不要修改冻结原型源码或把发行副本当规范源码。工具沙箱工作区必须允许访问产品仓库，默认示例workspace目录未必允许访问这些路径。
