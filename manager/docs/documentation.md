# 代码文档维护规范与最终落地方案

状态：2026-09-12实施。本文是唯一规范；AGENTS、CONTRIBUTING和docs-sync Skill引用本文，不复制另一套要求。

## 1. 取舍

保留旧方案的源码旁README、模块执行流和关键分支解释；采用新方案的完整清单、内容hash、静态解析、索引生成和持续校验。不把正文全部迁移至镜像docs目录，不要求Agent先把全部解释写成JSON，不把JSON/行号有效当作业务解释正确。

根README是产品入口；总览负责导航和模块关系；架构导读解释设计原因；目录README负责本模块；技术实现负责跨模块专题，逐步消除逐函数重复；docs-site只展示这些正文。不要新建第二份用户手册。

## 2. 覆盖边界

`docs-site/documentation.config.json`定义源码扩展名和带理由的排除项。扫描git已跟踪及未忽略的新文件，重新发现真实文件后与清单比较，而不是只遍历旧清单。文件内容按UTF-8、CRLF归一到LF计算SHA-256，避免跨平台换行误报。

每个直接含纳入源码的目录必须有同级README。根脚本归启动脚本说明，根其他源码归根README。纯组织目录可由上级导航负责。发行副本、第三方运行时、冻结原型、用户工作区、生成物和依赖锁文件按明确规则排除；不扫描秘密配置正文。新增语言必须先补sourceExtensions和验证方式；不声称覆盖未知语言。

README前半部分为人工维护正文，自动导航区只由工具更新。文件名出现在导航中仅代表归属登记，不是语义审查通过。

## 3. 正文模板

1. 职责与非职责：本目录解决什么、不解决什么。
2. 文件分工与入口：每个文件的作用，复杂模块可拆分详解，但只能有一个主解释位置。
3. 执行流程：真实调用关系、输入输出、副作用、持久化或事件。
4. 关键边界：错误、取消、超时、权限、兼容性；没有实现的不要编造。
5. 验证：测试命令、覆盖点、尚未做的平台实测。

简单函数可以合并解释；复杂状态机、安全校验和磁盘修改路径必须解释关键分支。禁止仅在旧的错误正文后追加“新说明”而保留相互矛盾的契约。旧README的手写行号在逐模块审查时迁移，不宣称本次已重审所有历史段落。

## 4. 自动事实与索引

`check-docs.js`用Acorn AST提取JS/CJS/MJS函数、类、箭头函数及参数语法和位置；嵌套作用域作为符号ID，匿名节点用位置消歧。匿名节点移动不保证ID稳定。参数片段是语法，不是推断出的运行时类型。TS、PowerShell、C#、配置、HTML等目前只做文件级登记，不冒称符号完整性。

生成物：documentation-manifest.json（来源hash、文档归属、符号及排除理由）和source-index.md。行号对应hash快照，不承诺永久链接。文档站提供静态源码快照视图，符号索引可跳到相应行并高亮；源码用textContent展示而非作为HTML执行。测试fixture只保留hash与结构索引，不嵌入可能随安装包分发的源码快照。仓库Markdown的文件行号链接是否定位仍取决于查看器。目录README通过受管理区块获得文件导航。文档站自动发现README，保留既有页面ID，额外收录规范和符号索引。

每项semanticReview固定为not-certified，表示生成流程不提供语义认证。无需用自动更新“已审查hash”假装审查完成；实际解释/行为变更在PR或阶段记录说明依据与测试。

## 5. 开发闭环

安装依赖（从仓库根）：

```sh
npm ci --prefix webagent-core/agent-host
```

修改源码或新增目录后：

```sh
node docs-site/check-docs.js --write
node docs-site/build.js
node docs-site/check-docs.js
npm test --prefix webagent-core/agent-host
```

先编辑正文再生成导航；--write只更新结构产物，不生成或认证业务解释。禁止手工修改自动区、清单和索引。新增、删除、移动、重命名文件都重新生成。无需正文变化时，在变更记录说明原因，不能只因为README时间戳变了就认为审查通过。

## 6. 门禁与不能证明的事情

阻断：缺少同级README、源码/清单hash漂移、自动导航漂移、JS解析失败、受检Markdown内联本地文件链接不存在、损坏的受管理标记、文档站生成物漂移。校验默认只读，--write显式写生成物。fixture必须包含新增/删除/改动/链接失效等负例。

检查范围是纳入源码归属README及额外收录维护文档的内联本地文件链接；暂不认证引用式链接、外部HTTP可用性或各Markdown渲染器的标题锚点。链接检查并非全站所有历史文档的完整lint。生成目录导航不等同解释了全部符号；没有统一“文档质量100%”指标。

统计分列：纳入源码数、文档归属数、排除项、JS结构提取范围。语义准确性由维护者结合源码与测试审查。未审查的历史文档、其他语言的符号级定位和外部链接巡检继续明确标为未验证，不以工具绿灯关闭。

## 7. 面向初学者的逐文件/逐函数讲解（2026-09-12补充要求）

模块摘要和自动索引不足以完成代码复盘。当前产品自有代码按[复盘指南](../../代码复盘指南.md)的标准，逐文件解释调用方/依赖、每个具名函数和类方法的输入输出、步骤、副作用、错误/取消/超时/并发与验证依据；匿名回调可在父流程内合并解释，但必须说明触发条件和状态。配置/HTML/CSS/安装声明等按字段或逻辑组讲解，不能因为没有JS函数就跳过。

复杂文件可在同目录使用详解文档，README必须链接，并加入文档站extraSiteDocs；主说明位置唯一。禁止将仅有符号索引的文件算为“已逐函数讲完”。已有首组展开与剩余缺口分别列在复盘指南，后续逐批推进，历史审计报告不要求全量重写。

环境文档支持Windows Conda，不强制venv；主程序Node依赖与被编辑Python项目环境分开解释。人工验收需写操作、预期、证据、清理与平台范围，以review/CHECKLIST_WINDOWS.md为活入口；未执行不可继承旧报告结果。
