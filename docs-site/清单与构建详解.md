# 文档站清单与构建：逐函数解释

覆盖[check-docs.js](check-docs.js)、[build.js](build.js)。核心区别：清单是结构证据，人工讲解才承担语义解释；semanticReview始终not-certified，不能把AST符号数量当成审核通过率。

## 1. check-docs.js基础函数

| 函数 | 输入/返回 | 作用与边界 |
|---|---|---|
| digest(text) | 文本→SHA256 | 哈希UTF8内容 |
| normalized(text) | 文本→文本 | CRLF改LF，避免Windows签出行尾导致伪漂移 |
| posix(text) | 路径→斜杠形式 | 按当前系统path.sep替换 |
| safe(root,rel) | 根/相对路径→完整路径 | 拒绝空、绝对、任何..分量；已有路径realpath必须仍在root边界；不存在文件只能词法检查 |
| extractSymbols(source) | JS→符号数组 | Acorn先module再script，latest/位置/hashbang/函数外return支持；内部walk递归见下 |
| inventory(root=DEFAULT_ROOT) | 仓库→清单+config | Git文件集合、归属及符号提取，见下 |
| link(from,to) | 两路径→相对URL | path.relative→posix，逐分量encodeURIComponent |
| block(doc,entries) | 所属文档/记录→Markdown区块 | map出源码名和符号计数/仅文件声明，用START/END包围 |
| replaceBlock(text,generated) | 文档/区块→新文档 | 数标记，缺一/重复/反向抛错；零标记末尾追加，否则只替换标记中段 |
| checkLinks(root,doc,text) | 路径/文本→undefined | 去围栏代码，用正则matchAll找内联文件链接；跳外部协议/hash，去query/hash并decode，safe+exists；不认证远端URL、锚点或全部Markdown语法 |
| run({root,write=false}={}) | 参数→统计 | 生成预期输出、检查链接、比较/写入，见下 |

**extractSymbols内部walk(node,scope,parent)**：识别函数声明/表达式/箭头/类；优先node.id，其次变量声明/属性owner，最后anonymous@行:列。scope拼ID，重复追加位置；记录kind/startLine/endLine及参数源切片。Object.entries递归对象/数组，忽略loc；数组forEach承接父node。这是语法遍历，不展开HTML模板内的字符串脚本，也不理解PS/C#函数。

**inventory**：root realpath，读配置仅version1；每条exclusion需reason和path/prefix并safe。execFileSync git ls-files cached+others+exclude-standard、NUL分隔、Set去重排序。跳manifest自身和非sourceExtensions；显式排除优先，锁文件按规则排除；工作树已删文件跳过，非普通文件抛错。归属根级源码用rootDoc/根脚本rootScriptDoc，子目录用相邻README；缺README失败。JS家族extractSymbols，其他file-only；全部记录LF hash/lineCount/not-certified。返回files/excluded/config，不为排除项生成假符号。

**run**：按doc分组，替换README自动块；复制data去config成为manifest；逐源生成source-index含hash/行号和符号ID（去反引号），无符号给文件声明。先checkLinks所有预期Markdown及extraSiteDocs，再比LF规范后的当前内容。write=true仅改漂移文件；否则任何stale抛错列路径；返回files/directories/excluded/updated。没有跨文件原子事务，中途磁盘失败可能部分已写。CLI仅允许零参或一个--write，异常打印/exitCode1；导出供测试隔离仓库使用。

## 2. documentation.config.json与生成物

配置version控制schema版本；sourceExtensions列接受的JS/JSON/HTML/CSS/Shell/PS/C#/Inno等；exclusions每项path/prefix+reason说明冻结副本/构建物等；rootDoc/rootScriptDoc定义根文件归属；extraSiteDocs的id/path/group定义人工正文导航；sourceSnapshotExclusions只禁止特定路径正文嵌入站点，不从清单删除该文件。

[documentation-manifest.json](documentation-manifest.json)保存文件hash/所属doc/行数/符号；[source-index.md](source-index.md)是生成导航；[content.js](content.js)是window.DOCS赋值的浏览器载荷，不手改。JSON配置本身也受清单管理，所以修改routes后先check --write再build。

## 3. build.js发现与链接函数

顶层FILE_DOCS保留旧稳定route；manifest.files.map(doc)去重排序得到目录说明，未登记者用doc路径SHA256前12位造directory-id。extraSiteDocs检查同ID不同path冲突并按path去重；不是完整schema验证。读取配置/清单失败直接终止构建。

| 函数 | 输入/返回 | 行为 |
|---|---|---|
| readUtf8(rel) | 路径→Markdown | ROOT相对read，去首BOM，错误抛 |
| escapeHtml(s) | 值→字符串 | 转义&尖括号双引号，供当前HTML片段使用 |
| slug(text) | 标题→ID | trim小写，去文档符号/反引号，保留字母数字/中文/点斜杠横线，其他合横线并裁80；不自动给重复标题去重 |
| rewriteHref(href) | href→站内hash或原链接 | 借activeDocPath解析相对路径；源码优先转source路由，固定根正文map其次，FILE_DOCS查path/后缀；外部HTTP/mailto原样；不是所有协议安全白名单 |
| inline(text) | 行内文本→HTML | 手写扫描反引号、双星、链接，未匹配普通文本escape；粗体/链接标签递归inline，外部HTTP加_blank/noopener；链接括号嵌套不完整解析 |

activeDocPath是构建过程的当前文件，不在浏览器读磁盘。href decode坏编码可抛；重复标题和自定义Markdown语法不能由slug/inline自动解决。

## 4. build.js Markdown与结构函数

**mdToHtml(md)** CRLF规范→行数组、out、inList。内部**closeList()**依据ul/ol输出尾标签并清状态；逐行识别：

1. 围栏：收集至下个```；内容escape；mermaid仅生成mermaid-src pre，不运行绘图库。
2. 表格：表头/分隔识别后收连续竖线行；内部**parseRow(row)**去边竖线、split竖线、map trim；head.forEach→th，body.map/forEach→td。不能识别代码内/转义竖线，所以人工表格避免未转义的分隔冲突。
3. 横线、标题（slug ID）、引用（去>后递归mdToHtml）、ul/ol按类型切换；空行closeList。
4. 其他收连续段落至下个结构，空白合并后inline。不是完整CommonMark嵌套列表/HTML解析器。

**tocFromMd(md)**每行识别2–4级标题，去反引号并slug；不跟踪代码围栏，代码示例里的标题也可能进入目录。**extractLayer(body,label)**用动态正则提取粗体标签后到下一粗体标签等的段落。**parseGuide(md)**按二级标题拆intro/sections，调用extractLayer抽人话/比喻/源码/行业名词，有些标签允许备用名，分别mdToHtml同时保留全文。**parseTerms(md)**找编号术语对照章节，截到下一编号章，逐表行split/map trim，跳表头/分隔，取前两列。

## 5. build.js顶层输出

读四篇根正文；逐FILE_DOCS设activeDocPath，生成title/toc/html；恢复根路径。逐manifest源码读LF正文重算sha256，任何漂移失败并要求先重建清单；snapshot exclusion匹配时保存sha256/omitted而不嵌正文，否则text/sha256。payload包含guide/impl/overview/workflow/terms/files/fileIndex，不再携带随当天变化的builtAt；同输入可重复构建；JSON.stringify写成window.DOCS赋值并打印字节数。

构建不启动HTTP、不安装依赖、不认证源码语义；生成物包含可发布的源码快照，排除测试正文避免把测试里的攻击fixture作为站点内容散发。源码哈希保护一致性，不是签名/可信发布者证明。

## 6. 验证

```bat
node docs-site/check-docs.js --write
node docs-site/build.js
node docs-site/check-docs.js
npm test --prefix webagent-core/agent-host -- --filter=documentation
npm test --prefix webagent-core/agent-host -- --filter=docsSite
```

测试守卫与实际人工解释分开。当前文件明确列出解析器缺口，不通过“全自动文档覆盖率”掩盖非JS未做符号解析的事实。

readUtf8在任何Markdown解析前统一CRLF为LF（同时去BOM），而非仅在mdToHtml里转换，避免tocFromMd/parseGuide在Windows产生不同目录或章节。

## anchors.js与Markdown片段导航

职责：把当前仓库常用ATX标题的GitHub风格片段转换为文档站真实id；不是完整GFM解析器，不宣称覆盖HTML显式锚点、Setext标题、复杂内联链接、重复标题编号和所有Unicode平台差异。

- **slug(text)**保持原文档站标题id算法：去指定图标/反引号、小写，保留字母数字/中文/点/斜线/连字符，其余归一为连字符、去首尾、80字符上限。从build迁入共享模块，不修改现有id规则。
- **githubSlug(text)**为本仓库常用纯文本/代码/简单强调标题生成兼容别名：去反引号/星号/波浪号，去标点符号（保留下划线/连字符），空白变连字符。不是对所有GitHub Markdown行为的模拟。
- **headingTargets(markdown)**遍历ATX标题，跳过反引号/波浪号围栏内伪标题；站点slug和常见GitHub别名都指向实际站点slug，重复键保留首项，不新增重复标题id后缀。声明的范围内可识别目标，不证明链接文字的语义准确。
- **resolveFragment(markdown,fragment)**安全解码百分号，无法解码或找不到返回null；识别时返回实际id，不编造目标。

build的**rewriteHref(href)**对Markdown目标先尝试上述转换；无法识别仍保留旧片段，不让构建器静默删除片段冒充修复。纯`#标题`使用activeDocPath自身，不再错误解析为父目录。新增**renderDocument(docPath,render)**在生成每份根文档时显式设置上下文，finally恢复原值；避免复用最后一个子文档路径，让根文档相对链接/标题解析串到错误目录。其它普通文件和源码路由逻辑保留。

### documentationLinks.test.js验证

**read(name)**读取仓库文件，**checkLinks(documentPath,markdown)**只对选定现行根导航及语义台账的常用行内链接检查：目标存在且不出仓库，有Markdown片段时必须可解析。不是全仓链接爬虫，不请求第三方URL，不认证其内容。错误文件和不存在标题有负例；围栏伪标题、UTF-8百分号及非法转义有明确断言。

测试另外加载真实生成的content.js：总览指向原生草稿章节的href，必须对应目标文档实际生成id。通过VM提取实际rewriteHref代码测试同文档片段；只运行函数，不执行完整build或写文件。新守卫首次发现上一批组件说明引用不存在的computer-use/README.md，改到实际computer-use/win/README.md，未通过跳过该文件放宽测试。

既有docsSite CRLF夹具现在用module.createRequire(buildPath)解析真实构建器的相对模块（如anchors），只对fs保留换行/写入拦截。不用测试文件目录错误解析构建器依赖，仍逐字节比较CRLF构建结果，未跳过漂移断言。

导航测试续作中的insertAdjacentHTML/remove/outerHTML分别模拟搜索结果插入、移除、替换；getElementById/scrollIntoView记录真实render函数选中的目标。route/$/pageChrome注入最小界面上下文，测试畸形编码、中文/斜线锚点和搜索清空/无匹配/转义，不宣称该VM就是真实浏览器。
