# 文档站浏览器与静态服务：逐函数/事件讲解

覆盖[app.js](app.js)、[serve.js](serve.js)及[index.html](index.html)装配。与产品工作台的app.js不同，这里只读构建时嵌入的window.DOCS，不调用MCP来执行任务。

## 1. app.js作用域与基础函数

匿名IIFE创建私有作用域，末尾render()首次绘制。**$(sel,el=document)**首节点；**$$(sel,el=document)**节点数组。PAGES列八种页面route/label/hint；hint字段不自动等于实际搜索索引。

| 函数 | 输入/返回 | 行为与边界 |
|---|---|---|
| route() | 无→page/rest/raw | location.hash缺省#/map，去前缀再split；rest未统一decode，交具体页处理 |
| go(to) | 路由→undefined | 写hash，触发浏览器hashchange；同hash不保证重触发 |
| renderNav(active) | page→undefined | 保存旧搜索值，重建nav、PAGES.map按钮，input绑定onSearch，forEach按钮click→go |
| escapeText(s) | 值→HTML安全文本 | null空，转义&尖括号双引号 |
| escapeAttr(s) | 值→字符串 | 仅替换双引号，当前搜索框双引号属性用途；不要当通用HTML转义 |
| pageChrome(title,kicker,extra='') | 片段→顶部HTML | 直接插参数，要求调用者使用可信文字/已安全片段 |

## 2. 全景与流程图

**renderMap()**用静态模板画层级、三路径、补丁流程和边界列表；初始化paintPath('a')/paintPatch。data-jump元素forEach绑click→go；data-path按钮click内forEach改on后paintPath。

PATHS.a是工作台Chat→API→runChat→callTool；b是外部Agent→隧道→MCP→callTool；c是code-server/扩展→本机API。**paintPath(id)**按固定数组map step/箭头，**paintPatch()**同样map名称数组，不运行补丁，不监听实时工具进度。

全景图是静态说明，不是服务器发现结果。本轮纠正两处陈旧文字：arenaConnect如今仅显示指引、不调用本机MCP；网页VS Code扩展走本机Chat API，不等于外部Agent的B路径。源文件沙箱也不等于任意shell命令的操作系统沙箱。

## 3. 正文与目录显示

**renderGuide()**取DOCS.guide、route.rest合并后decode；内部**compact(s)**去非字母数字/中文，便于模糊锚点匹配。sections.map出导航、四层卡片和details全文；若focus有值，find首个compact标题/ID包含者，scrollIntoView smooth。这里decode没有局部catch，坏编码可能阻断渲染；标题来自受控仓库构建，不是任意用户HTML净化通道。

**renderProsePage(key,title,kicker)**通用impl/overview/workflow，toc.map锚点，插doc.html；route第一个rest按DOM id滚动，无匹配不动。

**renderFiles()**从fileIndex取route ID或第一个，未知ID回首文档；Set分group，filter/map生成文档按钮，点击go(files/id)；正文显示path、toc.map章节链接、doc.html；anchor decode异常置空，有目标才滚动。不存在的route不是HTTP404，只在客户端回退。

**renderTerms()**terms.map生成词卡；并非外部词典查询。

**onSearch()**读q trim小写；forEach导读标题、技术实现toc、fileIndex path/id、术语文本生成hits；非空且≥2字符、hits非空才插/替search-hits，最多20。没有全文源码/所有正文检索；清空/无匹配时直接返回，旧结果不一定移除；不自动导航到首结果。

## 4. 源码快照与总分派

**renderSource()**decode路径失败置空，在DOCS.sources查固定key；构页面，路径/hash用textContent。无text但omitted给排除原因，没有源则提示去索引。range解析L起止，source.text.split换行forEach创建span，ID source-LN，行号补5位，textContent写源码；范围内加背景，起行存在则居中滚动。不从浏览器路径读取真实磁盘，也不eval源码。

**render()**route.page不在PAGES.some就map；renderNav后if分派上述各页面。window.hashchange→render；document.click委托closest站内#/链接，preventDefault后写location.hash。外链保留浏览器默认行为。

window.DOCS里的html是构建器生成的受控内容；部分标题/术语插值未独立转义，不可直接把服务接成不可信用户Markdown上传站。

## 5. serve.js顶层与匿名回调

启动先spawnSync当前Node运行build.js，失败exit（因此serve不是单纯复用旧content）。DOCS_PORT默认4173、DOCS_HOST默认127.0.0.1；开发预览可显式0.0.0.0，但只用于文档，不改变产品API绑定。

http.createServer回调：设Cache-Control:no-store；URL解析/路径decode/NUL检查失败400；根路径换index.html；path.join+resolve后检查ROOT或ROOT+sep前缀，越界403；fs.readFile回调错误一律404，成功按TYPES扩展MIME或octet-stream返回200/data。没有目录列表/写文件API/鉴权；路径检查是词法前缀，不是读取前realpath，别把文档根里的外部符号链接当成安全公开资源。请求方法未显式限定GET/HEAD，所有方法同一读取处理；没有读体逻辑。

server.listen回调打印实际端口（支持PORT=0测试随机端口）与绑定地址；显示本机URL不代表只监听本机，须看bind行。无显式SIGINT清理，因为主要资源是HTTP server，由进程退出释放。

## 6. index.html与content.js加载契约

HTML lang=zh-CN/UTF8/viewport，head引styles.css；aside.nav由renderNav填，main.main先显示加载提示；普通script依次content.js再app.js，保证IIFE读取DOCS前赋值已完成。没有fetch JSON，所以旧提示“浏览器会拦本地JSON”不准确，本轮改成推荐HTTP并检查两个脚本是否加载。

content.js是生成物，含window.DOCS的源码快照、HTML、路由和UTC构建日期，不在此手写内容；styles.css承担布局与颜色，完整CSS语义另行展开。浏览器加载失败不会自动执行npm或重建Markdown。
