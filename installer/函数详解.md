# 安装打包与启动：逐函数讲解

## 职责、依赖与阅读方式

本篇是[安装模块 README](README.md)的细化，解释 `launch.js` 与 `package.js`，不替代[Conda 操作说明](../docs/guides/Conda环境说明.md)。两文件只使用 Node 标准库；运行时依赖的安装与它们自身是否依赖 npm 包是两件事。

本篇按具名函数及其匿名回调解释；定位见[源码索引](../docs-site/source-index.md)，不维护容易过时的手写行号。Inno 全部事件的逐函数解释不在本篇范围。

## 1. launch.js 的主执行流程

```text
CMD 传 mode / workspace
 → main
 → recovery先检查本机交互门禁，走launchRecovery后返回（不走以下工作区/服务分支）
 → 其他模式：userHome / prepareRuntime
 → resolveWorkspace
 → 构造继承自父进程的 env
 → ensureDependencies（extension 模式除外）
 → appWindow 或 spawn 模式对应入口
 → 子进程 error/exit 决定启动器退出状态
```

顶层 `sourceRoot` 是启动器所在仓库/安装目录的父路径，不是当前工作目录。`require.main === module` 区分“作为命令运行”与“被测试 require”；后者只得到导出函数，不自动启动产品。

### hash(data)

输入字符串或 Buffer，返回 SHA-256 十六进制摘要；无磁盘副作用。`prepareRuntime` 用它计算清单版本目录和文件完整性。摘要说明内容是否一致，不证明发布者身份。

### userHome(env = process.env)

输出绝对路径：优先 `WEBAGENT_DATA_HOME`，否则 `LOCALAPPDATA/WebAgent`；无 LOCALAPPDATA 则退到用户主目录下 `.local/share/WebAgent`。函数只算路径、不创建目录；自定义相对路径由 `path.resolve` 相对调用进程 cwd 解释。调用方是 `main` 和 `prepareRuntime` 的默认参数。

### safeRelative(rel)

输入打包清单的一项路径，合法时原样返回，不合法时抛错。要求是非空字符串、使用正斜杠的相对路径，拒绝非法分隔、绝对路径和空/当前/父目录片段；`split('/').some(...)` 匿名回调逐片段检查。这里只验证名字，实际文件的真实性和内容还由下一个函数检查；不要单靠这一步推断磁盘对象正确。

### prepareRuntime(source = sourceRoot, home = userHome())

输出 `{root, installed}`。同步函数，但包含实际磁盘读写。

1. `source/installation.json` 不存在：视为源码 checkout，返回 source，`installed:false`。
2. 存在：读取 JSON，要求 format 为 1 且 files 是非空数组；读取/JSON/格式失败直接抛出。
3. 对清单原始字节求 hash，决定 `home/releases/<hash>`。目标存在 `.ready` 时直接复用；**此分支没有逐文件重验**。
4. 建 releases 和临时目录。每项先 `safeRelative`，再确认实际路径留在来源根内且是普通文件；读 Buffer、比较清单摘要，匹配才拷到临时目录。
5. 全部成功写 `.ready`，再 rename 发布。如果 rename 竞争失败但目标已有 `.ready`，接受并发产生的目标；否则重新抛错。
6. `finally` 清理临时目录，不论成功失败。返回安装版运行路径和 `installed:true`。

这不是升级用户工作区的迁移器，也不删除旧版本运行目录。它使用同步 I/O，复制期间会阻塞启动器；并不是面向每个 HTTP 请求运行的函数。

### resolveWorkspace(value, cwd, fallback)

输入显式路径、调用者 cwd 和默认路径，输出目录绝对路径。`Boolean(value)` 决定是否视为显式指定；相对路径以 cwd 解析。路径是现有文件时取父目录；显式目录不存在就抛错，默认目录不存在才递归创建；最后确认是目录。创建目录是本函数的副作用，不能把它描述成纯字符串转换。不会自行移走原数据或激活 Conda。

### ensureDependencies(root,{timeoutMs=120000,signal}={}) / abortedLaunch() / checkLaunchSignal(signal)

定位 `root/webagent-core/agent-host`。若 `node_modules/express` 存在即 resolve；这只是快速存在检查，**不检查所有依赖版本或 Acorn**。否则异步 spawn 同一组 `npm ci --omit=dev --no-audit --no-fund`，保留 ChildProcess，不把 timeout 交给 npm 当包脚本上限。Windows 调 `npm.cmd` 且 `shell:true`，只为定位命令。

内部 finish 单次清计时并退订 abort；失败时 releaseLive 对仍未退出的保留句柄 unref，避免放弃后把启动器挂住，**unref 不是退出证明**。send 只向仍未退出的保留句柄发信号。armEscalation 会先清掉上一轮期限和升级计时，再安排 1 秒后 SIGKILL、再 1 秒无 exit 才拒绝，超时和取消重叠不会留下旧计时器补发信号。到期先 SIGTERM，错误含 `npm ci 超时`、期限和目录，code 为 ETIMEDOUT。取消同样先停保留子进程，再抛 abortedLaunch() 的 `启动准备已停止`；Node 默认 AbortError 不当作用户原因。非零退出抛 `npm ci失败，请检查Node/npm与网络`。非法期限在 spawn 前拒绝。部分 node_modules 留给下次运行，不自动回滚。Windows shell 可能留下本句柄不拥有的孙子进程，不按名称或端口补杀。

abortedLaunch()生成固定停止错误；checkLaunchSignal(signal)仅检查 aborted，不取 reason。因此用户开发/文档测试要主动运行带开发依赖的 `npm ci`，不能依赖启动器自动装全。这里的 npm 由 PATH 选择，和运行启动器的 `process.execPath` 不一定天然是同一套安装；Conda 用户要核对两者。

### appOrigin(env = process.env) / ready(origin) / appWindow(root,workspace,env,home) — 代理

launch.js内为无副作用的延迟代理，实际实现在[appWindow.js](appWindow.js)。本节仅保留调用关系：appOrigin读CODE_SERVER_PORT，ready检查/healthz，appWindow负责启动确认与浏览器打开；真实校验、身份绑定、IPC与清理见下节appWindow.js。

## 1.1 appWindow.js 的全部函数与启动确认

本模块为app窗口启动的独立实现，默认只读、不发凭据；就绪元数据不是同用户恶意进程的认证。所有网络入口固定本机只读。

| 函数 | 输入/返回 | 关键实现与边界 |
|---|---|---|
| portValue(env,name,fallback) | env/名/缺省→端口 | 读环境变量，缺省3000/48271；必须是1–65535十进制，否则抛错；供appOrigin与端口一致性检查 |
| appOrigin(env) | env→origin | 调portValue得到CODE_SERVER_PORT，返回http://127.0.0.1:port；非法直接抛错 |
| aborted() | 无→Error | 生成ABORT_ERR，用于主动取消；不是HTTP状态 |
| checkSignal(signal) | signal→undefined | 若已abort则抛signal.reason或aborted()，防止取消后继续触网/开浏览器 |
| probeJson(url,{signal,timeoutMs=1500}) | url/选项→{state,value} | 固定只允许http://127.0.0.1的/healthz与/api/diagnostics，无查询/hash/凭据；agent:false独立socket；state分ok/occupied/absent/unknown；限制64KiB、UTF-8 fatal、JSON解析；任何阶段都可abort/timeout并销毁req/res释放socket，不跟随重定向，不发凭据 |
| validHealth(value) | 值→布尔 | 要求{status:alive/expired,lastHeartbeat:>=0整数}且仅两字段 |
| normalizedWorkspace(value) | 路径→规范化/null | 绝对路径、长度、NUL检查，resolve后Windows小写归一；**不realpath/stat**防UNC跟随 |
| hostIdentity(value,expected) | 响应/期望→{hostInstanceId,startedAt,version,mcpPort,workbenchPort,workspaceRoot} | 校验UUID、startedAt、version、mcpPort、workbenchPort等于本次codePort，以及规范化工作区；否则抛错且不停止已有服务 |

| ready(origin,options) | origin/选项→布尔 | probeJson /healthz后validHealth |

| supervise(child,expected,controller) | 子进程/期望/控制器→state | 监听error/exit/disconnect提前失败；message需严格匹配prepared/released及workspace/端口；fail仅在未transferred/stopping时abort控制器；state含prepared/releaseRequested/released/transferred/stopping |
| fail / onAbort / onExit / onError | 内部回调 | fail在未移交时abort；onAbort/onExit/disconnect转失败；message分支区分prepared与releaseRequested |
| sendControl(state,type,signal) | state/类型/signal→Promise | 仅对保存对象发IPC，release时先置releaseRequested；监听abort，send回调失败转错误；不自动重试 |

| detach() | 无→undefined | 尝试disconnect再unref，避免编排自身被挂住；不是终止证明 |
| openBrowser(url,env,signal) | url/env/signal→Promise | 只接受http、hostname为127.0.0.1、无用户信息、无hash；folder查询参数允许。选Edge/Chrome绝对路径或rundll32；detached、shell:false、stdio ignore；失败不重放 |

| appWindow(root,workspace,env,home) | 路径/env/home→Promise | 校验workspace与版本/端口；expected含origin/codePort/mcpPort/workspace/version/hostOrigin。主机身份的workbenchPort必须等于本次codePort。比较工作区用normalizedWorkspace，接受末尾分隔符，不realpath。120秒总期限独立timer与onSignal；先inspectPair，若非ready且非absent则拒复用；冷启动建home、打开startup.log fd 0600，spawn run-code-oss workspace，env加WEBAGENT_APP_BOOTSTRAP=1，stdio含ipc，detached；supervise后循环等prepared再inspect；再pin确认identity未变；URL加folder参数，openBrowser。浏览器spawn成功后在同一期限内反复inspectPair：waiting/absent不是身份变化，不因此提前stopOwned。hostIdentity抛错，或ready但identity与pin不一致，才不release并提示窗口可能已打开。确认后才sendControl release并等released；transferred后disconnect/unref；catch中abort并尝试stopOwned，未确认则带清理未确认信息抛错；finally清timer/abort监听与信号监听；不按端口杀已有服务，不保证全部后代退出，浏览器打开不证明工作流通过 |

### main()

读取 `process.argv[2]` 模式和 argv[3] 工作区。recovery首先进入下述独立launchRecovery并返回；合法普通模式映射 classic/vscode/admin/extension，app 是单独分支。未知模式先抛错，不继续准备运行时。

调用 home/runtime/workspace 函数后，以 `{...process.env, WORKSPACE_ROOT: workspace}` 构造环境。安装版另设 code-server/admin 用户数据路径。除 extension 外，main 建 AbortController，onSignal 把 SIGINT/SIGTERM 转成 abort，await ensureDependencies，finally 移除监听。失败只抛错，不启动窗口。app 委托 `appWindow`。其他模式用 `process.execPath` 启动相应入口，cwd 为 runtime.root，stdio 继承；仅 vscode 还把 workspace 作为位置参数。

- child error 回调打印消息，设父进程 `exitCode=1`。
- child exit 回调复制子进程退出码；因信号退出无 code 时设 1，不能把 `signal` 参数当退出码。
- 顶层 `main().catch(...)` 打印拒绝原因并设 exitCode 1。

`main` 中 spawn 成功不等于子服务就绪，普通模式也没有 ready 等待。进程是否留下由子进程及退出路径共同决定，需人工验 A11。

## 2. package.js 的函数与固定配置

`files` 是显式单文件白名单，`trees` 是允许递归的产品目录，`extensions` 进一步限制树内文件类型，`forbidden` 屏蔽依赖/用户数据/缓存目录。新增发行材料要解释为何应入包，不能改成“递归整个仓库”。

### digest(data)

将 Buffer/文本变成 SHA-256 十六进制字符串，用于每个发布文件的清单项。与 launch 的 hash 同算法但职责在构建侧；不读取磁盘、不签名。

### collect(source = root) 与嵌套 add(rel)

返回排序去重的相对路径数组，不复制文件。

`collect` 建立 out，遍历显式 files 和 trees 调用 `add`。`add` 的闭包读取 source、out 与白名单：

1. `lstatSync` 检查对象；软链接直接抛错，避免打包时跟随链接收进无关文件。
2. 目录按名称排序遍历，跳过 forbidden 名称及点开头目录项，再递归。
3. 普通文件需要是显式列入项或扩展名受允许；额外排除日志、临时/密钥后缀与 privacy.md，再加入 out。

缺失必需文件、读目录错误等不被吞掉。收集时就校验，防止 stage 先删旧输出再发现输入列表不合法；但这不是内容敏感性万能扫描，白名单中的正文仍需作者审查。

### stage(source = root, target = installer/output/payload)

返回 `{format:1, files:[{path, sha256}, ...]}`，同时创建实际 payload 和 installation.json。

先绝对化路径，拒绝 target 与 source 相等或 target 是 source 的祖先；默认 target 在 source 的 installer/output 下是允许的。调用 collect 完成输入枚举，然后**删除并重建指定 target**，逐文件复制并记录 digest。不要给这个函数随便传自己的数据目录作为 target；它不是通用无损拷贝工具。

之后写入中性的 code-server 配置（本机监听、密码认证、禁用遥测/更新检查），而非拷贝操作者本地口令；配置本身也计入摘要。最后写 installation.json。复制中途 I/O 失败会抛错，stage 不保证保留旧 payload 或自动清理半成品；这是构建目录，不是用户数据事务。

CLI 成功打印打包文件数；catch 打印错误并设 exitCode 1。require 时只导出 collect/stage/digest，测试可以传临时目录验证。

## 3. 验证与不能证明的事

仓库根执行：

```bat
npm test --prefix webagent-core/agent-host -- --filter=installerPackaging
```

该测试验证白名单、清单、运行目录和重要安装声明等；实际断言以测试源码为准。还必须跑全量测试检查文档/发行副本一致性。Windows CI 的编译是另一层；用户权限、Conda-only Node、升级数据、卸载/PATH、应用窗口的实效按[人工清单](../review/CHECKLIST_WINDOWS.md) D/E 项验证。

复盘练习：分别从“显式工作区不存在”“npm 返回非零”“已有 `.ready`”“另一个服务占了 3000 且返回 200”出发，指出哪个函数停止或继续，以及为什么不能用一次启动成功覆盖所有分支。

### bundledDocs(source) 与 rewritePackagedMarkdown(rel,text,selected,docs)

bundledDocs读取预构建content.js的JSON赋值正文并JSON.parse，绝不eval生成脚本。rewritePackagedMarkdown仅在载荷副本处理行内Markdown链接：实际入包目标保留；缺失源码/正文若有快照则转到相对docs-site/index.html的路由；有意不发行的历史/示例/图片改为明确“仅源码仓库”的不可点击说明。源码原文不改。该正则不承诺支持Markdown所有扩展语法。

### launchRecovery()

仅win32、stdin/stdout均TTY且argv只有node/launch.js/recovery三个元素才继续；额外工作区/PID/路径/--yes、管道和其他平台退出2，且在准备runtime前拒绝。不解析/创建工作区、不安装依赖、不读HTTP状态或启动任何服务。

通过后复用prepareRuntime：源码直接使用根，安装版按清单复制/复用用户运行目录。用当前process.execPath和单独参数数组启动固定`scripts/tunnel-cleanup.js`，shell=false、stdio继承、cwd固定runtime.root；不经CMD拼接、不喂RECYCLE、不设置workspace/env。不接受外部脚本路径；含空格/&/%/!的路径仍是单个字面参数。辅助CLI仍自行验证Windows/TTY并持有稳定句柄/确认租约；没有预览自动执行。error通用提示，整数退出码原样传播，信号/无整数码为1；不自动重放。不把0概括为全部残留已清理，逐项结果看原CLI。

### tunnel-recovery.ps1与Inno快捷入口

`webagent.iss`只在开始菜单加“隧道残留回收（需确认）”，启动系统WindowsPowerShell固定脚本，-NoProfile、不提权；不添加安装后自动运行或桌面自动回收，也不改远程网页/扩展/MCP接口。PS脚本零参数且Console输入/输出均非重定向，失败退出2，在锁/Node解析前拒绝。

从当前WindowsIdentity取用户SID构造Local会话命名Mutex，WaitOne(0)不等待：已有窗口就拒绝再次启动；异常退出留下的abandoned锁允许新预览，但仍须重新输入确认，不能重放旧动作。锁保持到用户按键关闭结果窗口，在嵌套finally释放/Dispose，WindowsIdentity也Dispose；锁是同会话快捷入口的重复点击保护，不是跨用户/跨会话隔离或恶意同用户防护，直接CLI仍有自身租约保护。

Get-Command仅选择当前PATH中的node.exe应用，不接受PowerShell alias/function、工作区参数或用户指定程序。选择受本机用户PATH控制，不宣称二进制签名认证或隔离同用户恶意代码。以调用运算符和分离参数执行固定launch.js recovery，不用Invoke-Expression/拼接命令/自动答复；缺Node不下载、不激活/创建Conda、不npm安装。结果窗口保留，关闭提示不是确认回收；输入RECYCLE只在原CLI预览提示处有效。关窗或断连发生在确认后时效果仍可能未知，不能自动重试。
